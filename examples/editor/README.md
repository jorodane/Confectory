# Confectory Editor ProjectPack

An ordinary `Confectory.Editor` ProjectPack composes ProjectManager/Execution, EditWorkspace, SourceEditor, ElementView, Save/ChangeSet, BaseUI, UINavigation, RuntimeBase, RealTimeUpdate and Window/RenderInput. Core resolves public namespace+elementID contracts; there is no special editor/engine host in Core. No Agent, Helper, multiplayer, Stage, physics or rig dependency is selected.

Linux: from the checkout, with .NET 8 on PATH and an actual X11 DISPLAY, run `bash examples/editor/run-editor.sh`. If needed set `CONFECTORY_DOTNET` to your existing SDK8 dotnet executable. Windows: run `powershell -ExecutionPolicy Bypass -File examples/editor/run-editor.ps1`. These scripts build existing solution/tool hosts and launch the Editor; they do not install tools. SDK8 `global.json` stays in force. Native Windows checks remain user spot checks until recorded. Override `CONFECTORY_EDITOR_STORAGE` to an owned settings/project-parent directory; default `.confectory/editor`. Recent settings and saved drafts remain local and ignored by Git.

The first home card has New and Open folder halves, recent projects follow. The optional Agent sidebar states offline status; no account is required. New requires a human name and supports multiline intent. Choose the parent with the real directory picker; creation rejects existing folders. Open selects a folder or ProjectPack manifest without executing it. Projects have stable workspace models and borrowed Element Views.

In a project, Elements/+ chooses owned declared IDs or creates an object. Source is the general fallback; scalar Properties uses public SchemaEditing inspection and revision-checked application. Click a text field; F4 selects all, F3 applies the source, arrows/Home/End/Backspace/Delete edit, Tab traverses form/buttons and inserts indentation in source, Enter applies a single-line scalar/name field or activates a focused button on release. Escape leaves text focus. UTF16 caret/selection are public SourceEditor snapshots. This starter has no clipboard/IME/completion/search/large-editor feature claim. Linux inherits the existing primitive X11 text renderer.

Apply edits only a local draft. Save persists differences; it does not replace final source. Review lists dirty IDs with explicit checkboxes (including registration when creating elements). Confirm validates/builds selected candidates before replacing matching final baselines. Compiler errors and external/stale conflicts retain drafts and final bytes. Explicit “Open latest final - keep previous saved draft” saves the old work context and opens latest source in a fresh remembered context; archive retrieval UI is a later feature, and old saved contexts remain in `.confectory/edit-workspaces`. Run is enabled only for confirmed project data; it starts the selected ProjectPack entry in an owned child. Stop targets that child. Logs drain bounded public output.

Shared View opens a second persistent native window borrowing the same workspace. Native close releases its control/Runtime owner and ElementView subscription; reopening creates fresh visual resources while application-held pending text buffers are retained. Clean sibling buffers refresh from shared revisions, dirty sibling buffers remain and CAS rejects stale application. Closing all windows or SIGINT cancels and joins the owned job, stops child executions and disposes workspaces, retained buffers and native sessions. Background commands are serialized; rendering reads cached immutable snapshots and never inspects filesystem or compiles per frame. RealTimeUpdate keeps variable/presentation/fixed cadence explicit (60Hz here, at most4 catch-up steps with remainder/interpolation separate); this editor does not run game simulation inside its UI.

`verify.cpack` exercises create/edit/Save/restart/Review/Confirm/child run-stop and borrowed lifetime. `verify-errors.cpack` exercises compiler/stale/external conflicts, recovery/restart, separate projects and overwrite guards. `verify-contracts.cpack` exercises new generic controls, focus/release ownership, Unicode snapshots and source-free folder pages. The actual X11 workflow is `tests/gui/editor_x11_workflow.py <CLI-build-report.json>`; it sends real window pointer/key events and writes private evidence to /tmp.

Android profile is managed compilation only. Android needs app-owned touch/surface lifecycle, authorized storage picker, authoring/build and execution providers; common desktop editor source cannot manufacture those capabilities. No APK/runtime coverage or native multiwindow parity is claimed, and absent SDK/JDK/adb prerequisites are not installed by these launchers.

Buttons now use BaseUI::Button/ButtonInput for actual shared presentation/hit/state/activation. Main retains geometry/text/palette/action configuration and public frame forwarding only. `examples/button-game` proves the same widget works with no editor dependency. Field/Lines text presentation and layout remain local helpers, backed by SourceEditor mechanics/Snapshot/Refresh; extracting them is distinct next work.
