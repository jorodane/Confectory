# Local authoring workbench

This ProjectPack composes disposable property views, YogiBox, AlgorithmProjection and ExecutionComparison through their public contracts. Supply an explicit local harvest-game source ProjectPack with `CONFECTORY_WORKBENCH_PROJECT`. It borrows one edit workspace, owns its views, jobs and child execution session, and serializes slow inspection/build actions off the native window loop. An empty package seal fails visibly without closing the app. Closing either tool window or SIGINT cancels/joins owned work, closes views and stops owned comparison children.

Select Plant or Recipe. Yield +/- edits the same draft seen by normal object Views. New resource creates a declared resource and manifest draft, then points the reusable plant and recipe at its ID. Confirm validates/publishes local selected drafts; Run A/B launches independent models/windows with different gravity and independent input. Ctrl+Y captures selected semantic IDs/metadata. LookAtYogi captures only the displayed owned table region. Remove, seal/unseal, draft discard and a sealed drag to the explicit local inspector drop zone are available. Delivered cloned receipts survive draft discard. Composer text uses a local preset; general text/IME widgets remain an earlier open gate.

Read projection displays a C# syntax explanation of Throw. Edit throw arc changes its selected C# body, then completes one human functional maintenance batch locally. No code is generated by the projection and no AI service is called. Descriptions retain existing declaration syntax. The table definition does not own row data, locks or models; its cache is display-only. This is a bounded example workbench, not a full editor.

Configure installed SDK and built host DLLs:

```sh
export CONFECTORY_DOTNET=/workspace/toolchains/dotnet-8.0.425/dotnet
export DOTNET_CLI_HOME=/tmp/confectory-dotnet
export CONFECTORY_ELEMENT_AUTHORING_HOST=/workspace/Confectory/targets/element-authoring/bin/Release/net8.0/Confectory.ElementAuthoring.dll
export CONFECTORY_PROJECT_EXECUTION_HOST=/workspace/Confectory/targets/project-execution-host/bin/Release/net8.0/Confectory.ProjectExecutionHost.dll
export CONFECTORY_WORKBENCH_PROJECT=/workspace/Confectory/examples/projects/harvest-game/project.cpack
"$CONFECTORY_DOTNET" src/Confectory.Cli/bin/Release/net8.0/Confectory.Cli.dll build examples/authoring-workbench/project.cpack linux > /tmp/workbench-build.json
python3 -c 'import json,subprocess; subprocess.run(json.load(open("/tmp/workbench-build.json"))["run"],check=True)'
```

Use a normal desktop DISPLAY. The native gate clones the game to a private fixture before authoring. Windows uses the windows managed build profile and the same host configuration adapted to installed local paths; actual user-OS testing remains separate. Android's named profile is managed compilation only, not an APK or an available native authoring/child-process provider.
