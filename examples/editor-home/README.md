# Fresh entry/home ProjectPack

`Confectory.EditorHome` is a new production entry/home composition from design section8. It does not derive its screen from the CP13/14 temporary functional editor and does not register that consumer, SourceEditor, Agent, Helper or multiplayer. The existing `examples/editor` and root `run-editor-windows.bat` remain the separate integration workflow.

Linux: with an existing SDK8 and X11 display, run `bash examples/editor-home/run-home.sh`. `CONFECTORY_DOTNET` may point to an existing SDK8 dotnet executable. Windows: double-click repository-root `run-home-windows.bat`; it uses CMD, existing SDK8 and `.confectory/home-launch.log`. Native Windows verification is asynchronous and was not run here. No tools or accounts are installed. First pack compilation can take several minutes.

The sequence presents Confectory/action hint, then optional Agent connection/Later. Later opens offline projects; connection presentation states that connection is unavailable rather than manufacturing a provider/session. The title moves to the upper-left. Sidebar management and two-column cards follow; New/Open are halves of the first card. New requires a name, focuses errors, accepts multiline intent, selects a parent folder and enters a bounded project landing. Open browses folders/pages without required pasted paths and validates a ProjectPack before registration. Existing cards reopen, open a folder through the OS and explicitly remove only a listing after confirmation. Project files and saved drafts are retained. Tab/Shift-Tab and button release activation use the shared navigation/control contracts; text fields use shared measured Field frames.

Settings default to ignored `.confectory/editor-home`; set `CONFECTORY_HOME_STORAGE` for an owned alternative. A saved local `ProjectInfo` draft retains title/intent through existing EditWorkspace/Save contracts; project creation does not silently Confirm changes or launch code. Repeated route changes/resizes preserve controls and text tokens. Public project/filesystem work runs on one owned background task while rendering uses cached snapshots; shutdown joins work and releases the session/Owner/buffers/controls/native surface.

This bounded slice stops at the project landing. The original project workspace, chat/log tabs, grievance/run/navigation composition and live Agent connection are later slices. Original logo image, exact subtitle, colors, fonts and transition timing are absent from available source assets. Current text wordmark/action hint and generic P marker are functional fallbacks, not pixel-faithful approved artwork. Screenshots and behavior checks are separate from original-design fidelity acceptance. Desktop resize acceptance is 960×700 and 640×520; extreme compact sizes and OS DPI/accessibility remain separate work.

Android is required but this desktop entry is only managed-profile compile coverage. Its equivalent must use one app-owned surface, logical responsive regions, touch pointer identity/cancel and app resume/pause/destroy, granted storage folder picker and text/IME providers. No native desktop multiwindow parity or APK/runtime claim. Existing workload is installed; JDK/javac, sdkmanager and adb are absent and were not installed.

Verify model behavior using `verify.cpack`; native acceptance is `tests/gui/entry_home_x11.py <build-report.json>`. `EntryHomeTests` checks offline selected closure, independent Grid consumer/provider locality, actual Linux flow/lifetime, presentation locality and managed Windows/Android profiles. Private screenshots/logs remain outside Git.
