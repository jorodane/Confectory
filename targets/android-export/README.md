# Android project preparation

This tool exports a buildable SDK project candidate for the engine's app-owned surface counterpart. It uses the existing core's ordinary ProjectPack resolution, Android body selection, independent contract/implementation compilation and actual provider bindings. No Android policy is added to the core. This is currently an explicit preparation tool, not a completed protocol-1 APK target provider.

The Android ProjectPack in `examples/engine-android` selects `android` target bodies. The installed .NET tool compiles the shared managed contracts and providers using its portable CLR profile. This verifies C# contracts/body selection, not Android native compatibility. The exporter copies each separate compiled contract/provider assembly and generates the real adapter source/facade; it does not collapse all packs into one shared implementation assembly. The native SDK app project references those separate assemblies.

```
dotnet build Confectory.sln -c Release
dotnet targets/android-export/bin/Release/net8.0/Confectory.AndroidExport.dll examples/engine-android/project.cpack /absolute/new/export-directory
python3 tests/android/compile_api.py /absolute/new/export-directory /workspace/toolchains/dotnet-8.0.425
dotnet build /absolute/new/export-directory/Confectory.Android.csproj -c Debug
```

Output must be a new directory; existing exports are preserved. Generated binaries stay local and outside Git. Export reports distinguish managedCompiled, androidAppCompiled and apkProduced. The output facade is generated from public function IDs/contracts and actual plan bindings; no reflection into private implementation classes is used. Window's own native adapter source and this tool's Activity template provide the Android OS callbacks.

One native Android SurfaceView displays two independent logical Views. Primary pointer IDs, inside release/cancel, multi-touch pinch and drag are normalized; keyboard input is optional. DPI conversion happens in the adapter. Common BaseUI supplies control behavior and models, and common RealTimeUpdate supplies independent cadence/camera intents. Activity pause stops frame callbacks; surface destruction disconnects subscriptions; resume/recreation reconnects and reads live model state. Activity destruction releases subscriptions/Owners/context registration. Saved configuration state contains scalar data, not native objects/delegates/DLL instances.

## Project-owned export settings and unsigned packaging

Register `Confectory.AndroidExport.Settings` and declare one project-owned object extending `Confectory.AndroidExport.Settings::Defaults`. App ID/title, display version, numeric version, `packageFormat` (`apk` or `aab`), and nonsecret key-generation defaults live in that ProjectPack object. No settings sidecar, keystore, keystore path, or password field exists. Unknown fields fail before compiling. Existing projects without the settings object retain compatibility defaults. Defaults are metadata only: exporting never creates a key.

`AndroidExport <ProjectPack> <new-output-directory>` exports managed source; append `--package` to invoke the actual installed Android packaging tool for the selected format. The generated project retains the chosen format and escaped app information. The Home adapter selects the native Activity and Core metadata Parser reference; the existing engine sample retains its SurfaceView adapter.

Packaging uses public `Package` in Release with `BuildingInsideVisualStudio=true` and `AndroidKeyStore=true`; ordinary non-IDE Build in the installed SDK would sign automatically. A generated guard rejects debug-key generation and signing targets. A successful package report requires an actual selected-format artifact and always records `signed=false`. Credentials never enter the invocation. There is no credential form, signing execution, or key-generation action in this increment. User-approved ephemeral signing remains a separate future action. Unsigned artifacts cannot be treated as installable/signed distribution releases.
