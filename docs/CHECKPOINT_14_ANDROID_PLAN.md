# Android Field equivalent and open gates

Desktop two OS windows correspond to two independent logical UI contexts in one Android app-owned surface, not two pretend native windows. Existing targets/android-export/templates/MainActivity.cs already uses one SurfaceView, density-normalized primary touch/pointer identity, two logical regions, bounded cadence/camera snapshots, retained RuntimeBase Owners and unsubscribe/reconnect across surface destruction/recreation. This is existing preparation evidence, not a built/running APK in this workspace.

CP14 generic BaseUI text buffers/Fields can borrow those separate contexts, but the native Android Field integration is not implemented. Current Window MeasureText.android/DrawText.android explicitly reject absent app-owned text providers. Required work:

- Extend the app-owned renderer bridge to expose MeasureText and clipped full-run DrawText roles using the same native font/Paint/style. Return the shared UTF16 scalar-boundary metric schema in logical units; native text painting must use the identical font/run, origin and clip.
- Compose generic Fields/Stack/Buttons in an ordinary Android ProjectPack consumer with separate control surfaces and buffer/model ownership for the two regions. Surface loss closes transient UI/pointer state and subscriptions, preserving model/buffer Owners until Activity destruction; recreation invalidates geometry and reconnects fresh controls.
- Route primary touch to FieldInput without reinterpreting pointer IDs as modifier flags. Existing bridge emits pointer ID in flags; generic pointer down now starts its own range anchor. Keep pinch/camera policy separate from text-range gestures and cancel the old gesture on pointer source replacement/lifecycle loss.
- Complete keyboard/Unicode/IME normalization. Existing template maps only Enter/Space/Tab/arrows to Win32-style logical values and emits no text-scalar/IME editing path. CP14 generic text retains legacy Windows/X11 key translation; Android needs an explicit adapter policy before native Field editing is claimed. Backspace/Delete/Home/End, modifier metadata and composition need verified native handling. Do not present the current managed desktop-named profile as that integration.
- Provide app-owned dimensions/safe-area/style/DPI policy; desktop SurfaceDimensions still correctly rejects Android callback-owned geometry.

Prerequisites: existing Android workload is present, but JDK/javac, SDK manager and adb are absent. No tools or licenses are installed/accepted without authorization. Managed target compilation, lifecycle/export fixtures and explicit provider rejection remain the available gates. Later native verification must cover actual glyph/caret pixels, touch selection/scroll/cancel, soft keyboard/IME, pause/resume, surface replacement/rotation, retained independent models and cleanup. No APK/runtime/Android Field acceptance is claimed for CP14.
