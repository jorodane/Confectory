# Actual common Workspace increment

The ordinary EditorHome ProjectPack imports `workspace.js` and `workspace-host.js` through its normal pinned resource bundle. Actual windows and note/group/child Workspace nodes use one runtime for selection, focus, drag, resize, pan/zoom, box selection and mixed Delete. The window map is the runtime's map. The adapter's detached DOM cache contains the same window records, not a second geometry or selection owner.

## Domain and storage boundary

The adapter retains actual editor DOM while moving between private Workspaces. Primary raw input, description/field input maps and existing independent source-view inputs retain their original revisions. A cold restart reopens existing view slots by actual object ID and mode through the original `openEditorView` contract. Only transport `stale_revision` rejections, which precede invocation, are retried for read/view ownership recovery. Source revisions, Save, Review/Confirm tokens, ordered source groups and input rejection contracts are not bypassed. Failed rebinds are reported and retain recovery input; they are not successful editors.

`savePresentation` uses the existing Model.Command/FileSnapshot/WriteAtomic ports. Version 1 JSON is stored under the configured private Home storage in `presentations/<SHA256(project identity)>.json`, independent of project source files and browser origin/HTTP port. It records layouts, private note/group/portal data, active/visited Workspaces, camera view, selection and pending recovery inputs. No source edit, Save, Review or Confirm is issued by this persistence operation. The presentation payload and parent graph are validated within bounded storage/transport limits. This is local presentation/recovery data, not semantic objects or a project manifest extension.

Closing a child tab preserves its Workspace. Portal deletion requires the existing confirmation; cancellation preserves the mixed selection and all records. Confirmation removes presentation nodes and closes affected UI, carries retained editors/input to hidden parent windows, and does not remove actual objects, files or domain editor ownership. Actual view release remains the original explicit action.

The reference runtime has optional consumer lifecycle hooks; its reference-only default remains independent of product behavior. Actual window creation converts viewport placement into world coordinates, and reopening an offscreen editor reveals it. Restoring windows cannot overwrite saved geometry with constructor defaults. Hidden/removed nodes lose selection classes as well as registry membership. Empty move requests are rejected. The existing consumer navigation menu height limit is retained.

## Scope and unfinished work

Terminal object editors and the issue inbox were not redesigned. Home was not rewritten. Source/Properties, existing independent editor slots and declared target choice are connected to their real services. Other cold-restored window kinds can report unavailable rebind support instead of inventing domain success; Review requires a fresh real review/token, and Worker/AI/Yogi-specific cold rebind remains outside this increment. Browser instances/hierarchy, actual pack catalogue and Run viewport remain later migration work. No AI account/model call, Site change or device execution is included. Standalone WASM publication retains its previously documented blocker.
