# 줄 끝 반환과 기존 본문 전환

2026-10-17 사용자는 미할당 반환을 각 실행 줄의 끝에서 경고하고, 기존 C# 본문 전체를 단일 코드 노드로 옮기는 방향을 선택했다. `88e7536` 이후 구현이다. [앞선 호환성 조사](EDITOR_V480_COMPATIBILITY_REVIEW.md)는 결정 전 시점의 기록이다.

`sync-acyclic-implicit-v1`은 연결하지 않은 `next`·`true`·`false` 포트와 연결 없는 시작점을 실행 종료로 처리한다. 현재 외부 ABI의 반환값 `return`에 대해 모든 선행 경로의 할당 여부를 분석한다. 각 종료 포트에 누락된 이름·타입, 일부 경로에서만 할당했는지와 graph상의 미할당 경로 예시를 기록한다. 합류 뒤 종료에서도 누락된 분기를 보여준다. 잘못된 타입·참조·값 가용성·순환·누락 본문·C# 오류는 계속 오류다.

미할당 경로도 실행할 수 있도록 구현에서 선택한 최소 정책은 C# 타입 기본값이다. 수치형은 `0`, bool은 `false`, 문자열·배열은 `null`이다. 이 구체적인 기본값 목록을 사용자가 먼저 지정한 것으로 취급하지 않는다. 편집기의 명시적 profile 전환 검토에 이 정책을 표시한다. `GRAPH_RETURN_UNASSIGNED` 경고는 일반 C# 경고를 끄지 않으며 Build/Check 결과의 `blueprintWarnings`와 graph receipt에 남는다.

기존 `sync-acyclic-v1` graph는 읽기나 일반 프로젝트 열기로 바뀌지 않는다. “줄 끝 반환 방식 검토”에서 정책을 읽고 명시적으로 공유 초안에 적용한다. 기존 실행 연결과 반환식을 유지한다. “반환값 할당 노드”는 현재 단일 반환의 구조 노드이며 별도 C# 파일·Task·함수 참조를 만들지 않는다. 해당 값과 실행 연결을 적용한 뒤 일반 Review/Confirm으로 확정한다.

## 기존 본문 전체를 옮기는 흐름

1. “기존 C# 본문 전환”에서 현재 ProjectPack 소유 구현 ID와 정확한 본문 대상(`common` 등)을 고른다. 기존 구현·부모·본문·계약·등록에 적용 중인 초안은 먼저 확정해야 한다.
2. 현재 본문과 가져오기 별칭·명시적 scope·본문 출처를 읽는다. 읽기는 전환 초안이나 최종 원본을 만들지 않는다. 본문 내용과 보존 범위를 확인한 뒤 별도의 전환 동작을 선택한다.
3. 선택한 구현의 해당 타깃만 `blueprint`로 바꾸고, graph와 전체 본문이 들어 있는 독립 노드 파일을 공유 초안에 함께 만든다. 비어 있지 않은 반환은 구조적인 할당 노드에 연결한다. **코드 노드는 하나**이며 자동 분해나 다른 함수 참조 wrapper가 아니다.
4. 구현 선언·graph·독립 본문 3개를 함께 Review/Confirm한다. 기존 C# 파일, 함수 원문, 다른 타깃과 부모 선언은 보존한다. 상속한 C# 타깃을 고르면 현재 구현에 그 타깃의 로컬 graph 재정의를 추가한다.

원래 본문은 기존 구현 클래스의 public `Invoke` 메서드 문맥에서 컴파일한다. graph 진입점은 명시적 `IInvoke.Invoke`이며 일반 연결부도 인터페이스를 통해 진입한다. 따라서 graph는 독립 본문을 호출하면서 원래 `calls`, `IImports`, `this`, 직접 `Invoke` 재귀, 구현 매개변수 이름과 가져오기 범위를 유지한다. graph의 입력은 외부 함수 인수와 위치로 맞춘다. 원래 CRLF·UTF-8 본문과 한글 파일명을 포함한 호출자 파일 식별자도 유지한다. C# 편집창의 변경 없는 적용은 textarea의 줄바꿈 정규화로 원문을 바꾸지 않는다.

일반 코드 노드는 기존 정적 독립 함수로 남는다. 기존 본문 문맥을 그 노드에 공유하지 않는다. 전환된 노드의 현재 정의·본문 해시와 실제 compiler 결과를 별도로 검증하며, 독립 probe는 본문을 호출하지 않는다. 기존 별칭·범위의 변경은 문맥 불일치로 거부한다. 원래 별칭을 유지하면서 가져오기를 추가하는 편집은 허용하지만, 현재 전체 문맥의 정의 해시가 바뀌므로 본문을 재검토·적용해 새 compiler 증거를 받아야 한다.

전환 준비는 원본 본문·구현/부모 선언·계약·등록 파일의 raw SHA-256을 관찰한다. 소유 소스의 리비전·내용 CAS, 링크와 대상 충돌, 64개 원본·파일/전체 읽기 예산을 검사한 뒤 하나의 소유 상태 변경으로 적용한다. private `conversionOrigin`을 cold 복원과 Review 및 compiler 검증 뒤 Commit 직전에 다시 검증한다. 누락·위조·변경된 origin, 필수 그룹의 부분 확정과 바뀐 원본을 덮어쓰는 동작은 거부한다. 전환은 소유 원본 종류와 경로를 바꾸므로 일반 Undo/Redo의 소유 경계이며, 최초 Confirm 전 원래 코드 노드만 제거하는 동작도 거부한다.

## 검증과 범위

새 엔진 검증은 실제 .NET 10 compiler/runtime으로 다음을 확인한다.

- 분기별 미할당 종료, 합류의 must/may 할당과 미할당 경로 예시, 8개 타입의 빈 시작 기본값, void와 잘못된 타입·값 참조·포트·순환·C# 오류.
- 원래 scoped import의 실행값 `4`, 다른 타깃의 `28`을 전환 전후 보존. `this`/직접 재귀·별칭·인수 이름 차이·CRLF verbatim 문자열·CallerFilePath와 원래 내부 식별자를 함께 사용한다.
- 새 import 추가 뒤 stale 본문의 재검토, 원래 import scope 변경의 거부, 호출 없는 독립 compiler probe.
- 공개 편집 API의 원본 변경 CAS, 정확한 3개 소스 그룹, 정당한 reviewed changes를 전달한 직접 부분 Confirm 거부, 변경된 원본의 Review 이후 확정 거부, origin 없는 복원 거부, 실제 cold 복원과 전환 전후 실행값 `5` 보존.
- Chromium에서 명시적 profile 전환·포트별 경고·구조적 출력·본문 미리보기·전환·변경 없는 CRLF 편집 적용·cold 복원·별도의 compiler Review/Confirm. AI, 프로젝트 Run과 Task를 자동 시작하지 않는다.

단계별 통과·실패·재검사 로그, 고정 소스 해시와 일반 체크아웃/리소스 검사는 [검증 근거](evidence/v480-integration/implicit-end-body-conversion.json)에 기록한다. 중간 실패를 숨기거나 중첩된 실행의 통과 수를 합산하지 않는다.

이 단계의 외부 계약은 기존 기본 타입·배열과 단일 반환, 동기·비순환 실행, `next`/bool 분기다. 임의 다중 반환·ref/out·enum 계약, 중첩 graph·로컬 변수 수명·임의 실행 포트·async/loop·물리 파일 삭제는 추가하지 않았다. 전환은 명시적으로 고른 현재 프로젝트 구현의 게시 C# 타깃에 적용하며 일괄 자동 이관이 아니다. 임의 reflection으로 생성 클래스 구조를 관찰하는 모든 C# 프로그램의 동등성을 보장하는 검증으로 확대하지 않는다. Linux/Chromium과 관리 대상 컴파일의 증거이며 native/device, 실제 계정·유료 모델·사용자 PC 설치 검증은 아니다.

최종 고정 소스의 집중 검증은 **9 passed / 0 failed / 0 skipped (220.804초)**이며 Windows/Android 관리 코드 컴파일은 별도 **1/0/0 (121.123초)**다. 그보다 앞선 같은 구현의 기존 엔진 21건·UI 9건·Home/Workspace 4건도 통과했다. 이 이전 묶음은 마지막 원본 경로 복원 보호·파일 예산·한글 line mapping·종료 개수 표시 전 결과로 구분하며 최종 9건에 중복 합산하지 않는다.

검토 과정의 소유 fixture에서는 원본 C#이 graph 폴더 안에 있을 때 위조된 저장 노드의 경로와 기존 baseline을 이용해 백업 파일을 덮는 미게시 코드의 결함을 실제로 재현했다. 최종 복원은 원래 노드의 경로·missing baseline과 보호 대상 원본 내용을 검증하고, Review/Confirm도 보호 원본을 대상으로 한 변경을 거부한다. 해당 위조 복원과 과도하게 커진 escaped node JSON의 거부를 공개 API 회귀에 포함했다. 정상 전환의 cold 복원·원본 바이트·compiler Confirm·실행값은 다시 통과했다.

구현 커밋 `759e4310fe581ac68c889a64867aef1644dd2de9`의 일반 Git 체크아웃 검사도 **1/0/0 (7.317초)**로 통과했다. 속성 적용 뒤 CRLF가 남아 있는 작업 사본과 새 LF 체크아웃에서 33개 정적 리소스·실제 Home 시작·리소스 변조 거부를 확인했다. 별도 증거 커밋은 이 검사 결과만 추가하며 제품/테스트 소스 해시는 유지한다.


이후 이름 있는 out 출력은 별도 v4 profile에서 연결했다. 위 단일 반환/ref-out 미지원 표시는 이 문서의 v3 구현 시점 범위다. [후속 계약과 원본 보존 갱신](BLUEPRINT_NAMED_OUT_OUTPUTS.md)을 참고한다.
