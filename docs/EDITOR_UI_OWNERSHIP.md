Generic Field/layout remain local Main presentation and are a separate shared-contract gap; no complete general widget library or reuse percentage is asserted.

Source field→Save: BaseUI::ButtonInput dispatches all-control hits through ControlInput and filters button activation, establishing logical focus; UINavigation::Route consumes eligible navigation first; SourceEditor::Input edits the View buffer. A Save action captures SourceEditor::Snapshot on the UI thread, passes text+revision to the owned job, then Editor::Command invokes EditWorkspace::SetTextIfRevision and Save::Write. Final files remain unchanged. Main renders the returned cached snapshot while preserving unapplied text/caret.

Review/Confirm: Editor::Command reads public EditWorkspace::Changes and ChangeSet::Review. Main draws its own rows/checkboxes and owns the selected-ID HashSet only; ChangeSet owns baseline validation/candidate build/replacement. Confirm passes selected IDs to ChangeSet::Confirm on the serial job. Errors/conflicts retain the draft; native View objects and presentation keep running.

Run/Stop: Main chooses the current project context and dispatches Editor::Command. Existing ProjectManager::Launch starts that ProjectPack's confirmed entry in its owned execution session. ProjectExecution::Observe/Output refresh the cached status/log projection; Stop targets its execution handle. No game simulation or compiler is embedded in BaseUI.

The production consumer does not inspect another pack's private arrays/types, scan implementation source for UI metadata, or directly read/write authored final source. Own Editor session state uses its own opaque token and cached projection. Path construction/selected-folder detection and tool host paths are consumer wiring; source content editing flows through public workspace/schema/save/review contracts. Tests inspect/change only owned temporary final files to verify conflict/retention. Relevant outside implementation reads and why the signatures were insufficient are listed in CHECKPOINT_13_WORK_LOG.md; no Core/native implementation edits occurred.

Remaining coupling/gaps: generic Field/row layout and basic property presentation are local Main code rather than reusable BaseUI widgets. Button has been extracted and independently consumer-tested; Review row labels/selection remain editor configuration/domain intent on the shared Button. ElementView Create/Close is used for borrowing/lifetime, but its existing fixed Labels/Layout do not supply these screens; Editor explicitly projects public workspace Read and SchemaEditing Inspect into its cached JSON. That duplicates some presentation/projection responsibilities, not domain state/Confirm semantics. SourceEditor text mechanics remain reused. Editor::Command's string operations/JSON payload and public string[] result interpretation lack compile-time typed UI projection contracts. Provider bindings repeat in entry/consumer declarations; scope locality is tested, but assembly declarations can be simplified later. Scalar property editing is a starter fallback, not inherited-schema/custom-View/semantic-discovery/full-IDE coverage.

Next work should extract Field and reusable layout/typed projection contracts against at least Editor and the next semantic entry-point consumer, with consumer/locality gates. Button already provides the minimal independently reusable widget boundary. Do not silently migrate domain models into table/widget ownership, replace the existing public registry with UI scans, or label manual drawing as finished widget reuse. Android needs app-owned surface/touch/lifecycle and granted storage/authoring/execution providers; desktop window equality is not claimed.
