# 같은 계약 본문 저장과 기존 forwarded/opaque 호출 원본

고정 [정보 편집7/8행](V536_I5_6_REMAINING.md)의 같은 정보 창·한 Save 흐름이다.
[원래 잔여 대조](V536_I5_6_RESIDUAL_RECONCILIATION.md), [기존 private 호출자](V666_RETAINED_NESTED.md),
[기존 후처리](V666_RETAINED_WRAPPERS.md), [native import](V666_NATIVE_BODY_IMPORTS.md)를
기준으로 이미 있는 전달 호출과 opaque C# 문맥을 보존한다. 원래 v666의
`renderFeatureDefinition`/`openOwnFunctionPopover`와 기존 본문 편집·저장·검토를 사용한다.
새 UI·문법·receipt·권한·provider 선택이나 C# 추측/변환을 추가하지 않는다.

게시 `f56f28faaaa3df8b39135baab8db958b619cb9fb`에서 원래 프로그램81은 정상이다.
공유 caller의 depth1/depth2 전달 호출과 native 원문을 lift한 별도 opaque caller를
함께 사용한다. native 본문 두 개만 명시 편집하지만 공동 후보와 단일 후보가 각각
그룹 문맥 제한 및 불필요한 opaque 본문 계획 요구로 거절된다. 함수와 native 매개변수의
이름·타입·역할·순서·수·반환과 caller/import 계약은 이 단위에서 바꾸지 않는다.

직접 소유 native 함수2~8개의 같은 계약 본문 저장에서 기존 forwarded graph/call과
직접 opaque code 문맥을 읽기 전용으로 유지한다. 전달 graph와 opaque 구현 헤더·graph·
C# record는 정확한 원래 draft/original을 요구한다. caller의 private 입력/출력·지역값·
실행선·ID·C# source/helpers·별칭·기존 위치별 import 표기는 보존하며 새 쓰기 후보로
넣지 않는다. 기존 단일 준비와 최종 조립 C# 컴파일을 통과한 원래 후보만 결합한다.
정·역순 결과와 원래 hash는 같아야 한다. 예의 두 본문을 덧셈에서 뺄셈으로 직접 편집하면
원래81은41이 된다. 이름 변경 자체에 의미를 부여하거나 opaque C#를 자동 재작성하지 않는다.

opaque 문맥의 import 이름은 원래 `arg0/arg1`일 수 있다. 계약 불변 준비에서도 이를
공개 입력 이름으로 교체하던 동작은 원래 문맥과 충돌했다. 원래 위치 표현을 그대로 두고
전후 definition hash·source-ready·전체 C# 조립을 검증한다. 명시적으로 계약/본문을
바꾸는 기존 경로는 기존 계획을 계속 요구한다. 공개 입력 이름이나 타입·역할을 바꾸는
다른 forwarded/opaque ABI closure를 이 지원으로 간주하지 않는다.

기존 version3 readGuards와 Save/CAS·cold Review·최종 source lease가 전달/opaque
헤더·graph·C# record를 지킨다. Save 전, Save 후 재시작/Review 전, Review 후 원본
변경은 전체 거절하고 checkpoint·peer 원문·두 편집 입력을 유지해야 한다. 원문을 정확히
복원한 뒤 새 Review/Confirm으로 진행한다. 후속 owner 설명 Save도 같은 원래 읽기 해시를
유지한다. 기존64-member Review·240 read/write·2048 known source·Tree 예산과 부모/
외부 소유권·override 계약·권한은 그대로다. 외부 원문 직접 쓰기 거절은 정상 보호다.

[검증 기록](VALIDATION_V666_RETAINED_FORWARDING.md)은 게시본 재현, 개발 실패 원인,
최종 신규/재사용, LF/CRLF·취소/Undo·쓰기 실패·경합·응답 유실·늦은 입력·재시작과
새 패키지/전체 복원을 구별한다. latest/직전 정상 rollback2세대와 증거를 보관한다.
고정7/8행의 실제 계약 변경·선택된 native callee 의존성 합성·새 import/alias 편집과
등록 외부 관측 결합 등 다른 원래 source closure는 별도 잔여다. 가능한 조합을 새 필수로
늘리거나 닫힌 M11/M12/M4를 다시 열지 않는다. 구 Reference reader 제약은 같은 게시
세대 도구 사용으로 구분하며 자동 migration/downgrade는 없다. 초기 간헐 빈 #app 원인은
미확정이다. 실제 Windows/WebView2·물리 기기·IME·GPU/audio·전체 UI 전수 검증과
Linux native/Chromium 자동화·교차 패키징은 별도다.

이 같은 계약 forwarded/opaque 원본 보존 단위의 [최종 신규 39·재사용0 검증과 보관](VALIDATION_V666_RETAINED_FORWARDING.md)을 마쳤다.
