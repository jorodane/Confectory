# v480 Home 전용 저장과 카드 조회

이 후속은 `work/current@928ff64`의 Home 검색/그룹 보존에서 이어진다. 레퍼런스는 보존한 `main@32dd44f`의 v480 ZIP이다. 프로젝트 presentation에 Home 상태를 섞지 않는 범위에서 호스트 저장을 구현하도록 승인받았다. 레퍼런스의 demo DB나 첨부 문서의 지시를 실행 계약으로 사용하지 않는다.

## Home 전용 저장

기존 호스트 저장 폴더의 프로젝트 목록 `projects.json`, Helper 선택 파일, 프로젝트별 `presentations/`와 구분해 `home-preferences.json`을 둔다. 새 `HomePreferences` 함수는 버전 1의 정해진 필드만 받는다. 프로젝트/팩 탭, 프로젝트 검색, 팩 그룹 4개, 그룹별 미적용 입력·적용 검색·정렬·선택을 저장한다. 문자열은 256자, UTF-8 자료는 16KiB로 제한한다. 임의 키·경로·명령·프로젝트 핸들·서비스 권한을 설정으로 받지 않는다.

원본 파일이 없으면 기본값을 읽으며, 단순 시작/조회로 빈 설정을 쓰지 않는다. 저장은 기존 `FileStream.WriteAtomic`의 임시 파일/rename을 사용한다. 성공한 뒤에만 모델과 UI의 저장 완료 상태를 갱신한다. 읽기 전용 파일 등의 실패는 기존 파일과 저장된 모델 값을 유지하고, 화면에는 미저장 입력과 다시 저장 버튼을 남긴다. 잘못된 버전·필드·크기·JSON·읽기 실패 자료는 사용할 수 없음을 표시하고 자동 덮어쓰기를 거부한다. 기존 자료를 복구한 뒤 보존한 입력을 다시 저장할 수 있다.

화면은 변경을 모아 직렬 저장하며, 저장 중 추가 입력은 다음 저장에 반영한다. revision 불일치로 실행 전에 거부된 저장만 최신 상태를 읽고 최대 3회 시도한다. 쓰기 실패를 성공으로 표시하지 않는다. 프로젝트를 여는 등의 명시적 동작 전에도 보존한 Home 변경의 저장을 시도한다. 시작 시 이미 팩 탭이 선택돼 있으면 초기 mount의 busy 구간이 끝난 뒤 로컬 inventory를 읽어 목록을 복원한다.

Home 상태를 저장하기 위해 프로젝트를 열거나, 프로젝트의 소스/draft/chat/presentation을 저장하지 않는다. 현재 설정은 호스트 저장 위치의 Home 소비자가 소유한다. 여러 호스트 사이의 설정 병합이나 외부 파일 변경의 실시간 구독은 추가하지 않는다.

## 카드 통계의 근거와 범위

포함 팩·마지막 편집의 미지원 상태는 아래 최초 구현 시점의 기록이다. 이후 [실제 포함 집합·성공 편집 사건 후속](V480_HOME_INCLUSION_AND_EDIT_EVENTS.md)에서 desktop Home의 두 조회를 연결했다.

| 항목 | 구현/판단 | 근거와 제외 범위 |
|---|---|---|
| 객체 | 확정 ProjectPack manifest의 `object` 선언 수 | 기존 `SemanticCatalog list(kind=object)`의 `total`이다. 32개 페이지의 표시 행 수로 계산하지 않는다. 의존 팩·schema·등록되지 않은 파일·미확정 초안·실행 인스턴스는 제외한다. UI tooltip에 이 범위를 표시한다. |
| 팩 | 미지원, `—` | 기존 registry inventory는 등록한 로컬 manifest 목록이다. 사용자의 포함/설치 팩 목록이나 특정 타깃의 실행 포함 집합과 같지 않다. 의존성 키 개수나 registry 개수를 대신 넣지 않는다. 포함 팩의 집계 범위를 정한 실제 조회가 필요하다. |
| 마지막 편집 | 미지원, `—` | 기존 draft Undo 이력과 Confirm/CAS는 편집 시각의 영속 기록을 제공하지 않는다. 열기/조회/현재 시각·파일 mtime을 편집 시각으로 간주하지 않는다. 어떤 편집 이벤트를 세는지와 영속 시각 기록이 필요하다. |

Home은 이미 등록된 최대 32개 카드의 root manifest만 기존 metadata 조회로 읽는다. 프로젝트 편집 세션이나 선언 본문을 자동으로 열지 않는다. 한 프로젝트가 없어지거나 읽히지 않으면 해당 카드만 `unavailable`로 표시한다. 유효한 0개와 조회 불가를 구분한다. 경로·모델 예외·핸들은 공개 카드 통계에 포함하지 않는다. Home을 열 때 다시 읽으며 파일시스템 실시간 집계라고 표시하지 않는다.

## 검증 경계

새 실제 UI 검사는 호스트 프로세스와 브라우저 context를 모두 새로 시작한다. 따라서 같은 origin의 localStorage나 프로젝트 presentation으로 복원을 흉내 내지 않는다. 그룹별 적용/미적용 검색·정렬·선택, 반복 탭 전환, 프로젝트 왕복, 읽기 전용 실패/재시도, 손상 자료 보존/복구, 프로젝트별 1/41개와 조회 불가를 확인한다. 모델 검사는 unknown/초과 입력 거부, 실패 시 디스크/모델 보존, 41개 전체 집계, manifest 변경 후 0개와 파일 삭제 후 조회 불가도 확인한다.

최종 고정 원본·실제 메서드·결과·구현 커밋의 일반 checkout 검사는 [검증 JSON](validation/v480-home-storage-counts.json)에 기록한다. [Home 팩 복원](validation/v480-home-state.png)과 [실제 카드 조회](validation/v480-home-counts.png)는 공통 Chromium UI 캡처다.

계산식 overflow의 정책 답변, 포함 팩/편집 시각의 미지원 계약, 도킹 전 native Undo 이력과 브라우저 grouping/필드/참조/문서 링크의 추가 대조는 구분해서 남긴다. main·원본 ZIP·Android 설정은 보존한다. 관리 프로필 컴파일로 native OS/장치나 사용자 PC 설치를 검증했다고 주장하지 않으며 실계정 연결·유료 호출을 하지 않는다.

최종 제품·테스트 원본은 **21개**다. 실제 Chromium 영향 회귀는 **6/0/0, 120.529초**, 모델/프로젝트 수명 회귀는 **2/0/0, 135.747초**, Windows/Android 관리 프로필 컴파일은 **1/0/0, 135.143초**로 통과했다. UI 검사 뒤에는 제품과 UI 검사를 바꾸지 않았고, 모델 self-test의 잘못된 닫기 확인 요청 한 곳만 기존 idle close 절차로 고쳐 모델 회귀를 다시 실행했다. 각 단계의 원본 hash와 차이는 검증 JSON에 구분한다. 초기 실패/집중 검사나 반복된 메서드를 최종 수에 더하지 않는다. 구현 커밋 HEAD에서 일반 Git checkout·보존 CRLF/새 LF·37개 리소스·실제 Home 시작·변조 거부를 별도로 확인한다.
