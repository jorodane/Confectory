# v536 독립 기능 요소 헤더 glyph

기준은 `882b5c5`와 저장소 `196c605`의 v536 ZIP이다. 원본 공통 요소 헤더의
아이콘 `편집`은 기능 요소에서도 `editObjectIcon → editIconValue`로 이어진다.
이번 최소 단위는 **프로젝트 브라우저에서 직접 소유 기능 정의 열기 → 헤더 아이콘
기호/이모지 선택 → 설명과 함께 Save → 재시작 → Review 취소/명시적 Confirm**이다.
정보 화면의 contained 함수 카드와 독립 기능 요소 헤더는 별도 조작이다.
부모 없는 직접 소유 기능만 수용하며 상속 기능·함수/서명 핀·로컬 이미지는 포함하지 않는다.

## 연결과 경계

원래 팝오버를 `glyph-popover.js`로 공유해 기존 정보·객체·함수 카드와 같은 DOM·CSS·
포커스·단일 활성 팝오버 수명을 유지한다. 헤더 팝오버에는 원래 없던 해제 버튼을
추가하지 않는다. 기존 `editorIcon` value 문법과 description만 저장한다.
함수 ID·서명·반환·typed import·구현·C# 원문·원본 주석·등록은 그대로 유지한다.
부모/외부 원본·다른 창/프로젝트 입력과 기존 권한은 변경하지 않는다.

표시 입력은 기존 owner 입력 맵과 owner 저장의 한 후보/최종 CAS·checkpoint·저장
기록/응답 조회를 재사용한다. owner context의 함수 읽기는 기존 namespace/출처/전체
관측/물리 원본 검사를 유지한다. 함수에 허용되는 새 후보는 정확히 glyph/설명 1~2개뿐이다.
생성·삭제·계약·raw source·copy/slot 배정으로 이 경로를 사용할 수 없다. 함수 원본의
부모가 있거나 다른 identity·namespace이면 거절한다. 실행 권한·Helper 권한은 늘리지 않는다.

기존 기능 설명 입력이 있으면 사용자의 glyph 적용 때 같은 owner 입력으로 보존한다.
Undo/Redo는 glyph와 함께 보관했던 입력을 복원한다. glyph 뒤 입력한 설명을 전체 맵 복원으로 지우지 않도록 Undo는 변경한 키만 되돌린다. 같은 키가 이후 바뀌었으면 덮어쓰지 않고 거절한다. 같은 창이 다른 함수/프로젝트로 바뀌면 Undo 기록을 새 문맥에 섞지 않는다. 입력은 원래 owner 맵에 남기고 재진입 때 복원한다. 저장 중 새 설명은 수락 결과의
정확한 hash/receipt로 별도 입력에 보존하며, 재시작 뒤 새 명시적 Save만 반영한다.
미적용 실패 기록은 삭제하지 않고 적용 여부가 불명확하면 기존 결과부터 조회한다.
저장 실패·충돌은 원문과 입력을 보존한다. 부모·외부·다른 소스는 쓰기 대상이 아니다.

기능 계약/본문 편집과 표시 편집의 임의 조합은 이번 단위로 확장하지 않는다.
이전 계약 입력을 먼저 저장하도록 안내하며 그대로 보존한다. 표시 입력이 있는 상태에서
직접 작성을 열면 그 표시 저장을 먼저 검증하고 기존 본문 편집기로 이어진다.
개인 파일·이미지 생성·외부 업로드·유료 모델·사용자 프로젝트 실행은 하지 않는다.

## 원본 요구 대조와 검사

초기 조사에서 Blueprint 루트 및 모바일 카드 입력의 `data-signature-icon`을 살폈지만,
v536 원본 CSS도 해당 버튼을 숨긴다. 이를 새 필수 기능으로 노출하지 않았다.
관련 미게시 실험 소스와 실패 증거는 scratch의 `v536-root-input-glyph/unpublished-scope-audit`
및 각 검사 phase에 보존했다. 그 루트 핀/backend 변경은 게시 대상에서 복구해 제외했다.
원래 존재하는 독립 기능 헤더 버튼만 연결한다. 원본 요구를 조합 수로 늘리지 않는다.

격리 fixture는 typed caller import, 상속 객체/다른 target, 별도 C# 구현, 정확한 수치를
포함한다. 원본 ZIP의 실제 팝오버 10영역과 치수·위치·스타일을 대조한다. 취소·부적합
입력·Undo/Redo·저장 전후 재시작·checkpoint 쓰기 실패·실제 source 충돌·응답 유실·
늦은 설명·Review 취소/명시적 compiler Confirm을 분리해 검사한다. 최종 Confirm의
실제 파일 변경은 선택 함수 한 개의 glyph·설명뿐이어야 한다.

초기 화면 검사에서 재시작 뒤 배경 브라우저가 저장 버튼을 가리는 경우는 검사 시작 때
사용 완료한 브라우저를 닫는 원래 조작으로 해결했다. 관련 변경 검토의 별도 명시적
Review 단계를 건너뛰지 않도록 검사도 맞췄다. 이를 제품 통과나 검사 완화로 계산하지 않는다.
최초 실패/수정 로그·fixture·프로필·화면은 scratch에 보관하고 Git에는 넣지 않는다. 늦은 입력 검사의 최초 실행은 의도적으로 보류한 요청 뒤에서 검사 flush를 기다려 교착했다. 확인한 해당 테스트 PID만 SIGINT로 종료해 증거를 보존하고, 보류 요청을 먼저 해제하도록 검사 순서를 고쳤다. 제품 저장 실패나 통과로 계산하지 않는다.
함수 전환 검사에서는 브라우저 상태 읽기와 F2 선택이 경합하면 `stale_revision` 뒤 기존 함수 창에 머무는 실제 누락을 확인했다. 기존 `readCurrentView`의 제한된 읽기/선택 admission 재시도를 재사용하고 원래 프로젝트·generation·미적용 소스 가드를 유지했다. 소스 mutation은 재시도하지 않는다. 서버가 첫 선택을 실제 거절하게 한 뒤 F2 재시도·다른 함수 Undo·원래 함수 재진입·입력 보존을 검증한다.
명령·종료·확인 수·원본/소스 SHA·공간/메모리는 아래 evidence를 따른다.

## 공간과 실제 잔여

이번 단계는 기존 자료를 추가 삭제하지 않았다. 앞선 네 폴더 승인은 소진됐다.
이 검사가 직접 만든 임시 복사본만 증거 보관 후 기존 수명관리로 정리한다.
보관 빌드·SDK·Git·사용자 자료·로그·프로필·고유 버전 파일은 보존한다.

I6 자체 중첩 정의·원본에서 실제 노출되는 나머지 핀/다른 요소/동작 카드·로컬
PNG/JPG/WebP 선택·프로젝트 자산 저장/복원과 부모 있는 기능 헤더는 남는다.
원본의 정상 숨김과 외부/상속 읽기 전용을 미구현으로 늘리지 않는다.
forwarded 부모·opaque/import 영향 결합, 고정 8행 공유 문맥·9행 타입/표시명,
B2 실제 배지, M4 async·M11 C#→graph·M12 Root 실행 분기도 별도 잔여다.
전체 UI·실제 Windows/WebView2·모바일 기기·Library 전달은 미완료다.

집중 7흐름 37확인, 순수 후보 3확인, 기존 contained 함수 카드·새 객체 속성·기존 정보 속성 glyph와 생산 final CAS 영향 회귀 32확인이 통과했다. 원본 팝오버 10영역과 75개 리소스 바이트/SHA가 일치하고 CSS·원래 숨긴 핀/입력 계약 코드는 바꾸지 않았다.
