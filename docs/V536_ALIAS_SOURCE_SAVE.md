# 기존 값 이름과 C# 본문의 결합 저장

고정 v666 `blueprint.js::renderFunctionBlueprint/openPinEditor`는 기존 출력 저장소의
`variable.name`과 명시한 동작 본문을 같은 함수 초안에 보관한다. 고정 잔여의 핀 표시명·
혼합 저장 경계에 해당하며, 이미 지원한 한글 별칭 편집이나 M11/M12/M4를 다시 구현하지 않는다.

게시 bc8e743a의 실제 UI와 native 요청은 별칭 이름·연결과 C# 본문의 동시 Save를 차단한다.
첫 지원 범위는 직접 소유한 동기 ordinary root의 기존 `code next` 본문 하나와 기존
별칭 계획 하나다. 별칭의 기존 입력/출력 저장소와 타입·ID를 보존하고, 해당 계획이 이미
지원하는 값 소비자 연결을 함께 검증한다. 입력 계약/핀 ID·공개 override 계약을 바꾸거나
C# 본문을 이름에 맞춰 자동 재작성하지 않는다. 기존 화면과 편집기/팝오버를 재사용한다.

저장 요청은 source → aliasPlan 순서이며, 임시 소유 후보에서 명시 C#과 이름/연결을 검사한 뒤
완성 후보와 원래 전체 초안 source proof/checkpoint CAS를 한 번 저장한다. 물리 원본은 이때
쓰지 않으며 초기 초안 Save는 외부 물리 변경을 남긴 채 보관될 수 있다. 물리 반영은 최종
Review/Confirm CAS에서 별도로 검증하고, 실패 뒤 수정의 baseline 재사용은 물리 원본까지
같아야 한다. 잘못된 이름·저장소·연결이나
쓰기가 실패하면 둘 다 적용하지 않는다. 같은 receipt의 확인/응답 유실, 입출력 보존·지역 입력·
공유 Undo/Redo·cold·Review 취소/Confirm·최종 물리 CAS를 유지한다. 실패 후 수정은 원래
미적용 결과와 같은 저장소 ID/타입/source·연결을 입증했을 때 이름과 C# 텍스트에만 허용한다.

copy/slot/private frame·whole-body/전달 문맥·속성 관측/Set 결합·비동기/공개 실행 분기 계약은
이번 결합 경계 밖이다. 기존 단독 편집과 명시 거절은 그대로이며 이를 모든 조합의 새 필수
작업으로 늘리지 않는다. 나머지 고정 혼합 저장·고급 타입/신원 권한·정보 종류 정책은 별도다.

새 저장 문법이나 profile은 없다. 대표 fixture의 기존 switch profile과 함수/노드/핀·C# 선언을
유지하며, 기존 별칭 계획의 정해진 profile 규칙만 사용한다. 이전 runtime은 확정 원본/기존
별칭 graph를 읽지만, 새 2행 결합 author-attempt의 미확정 복구는 지원하지 않는다. 이전판으로
자동 분해·순차 적용하거나 미확정 입력을 버리지 않으며 현재판에서 저장 결과를 먼저 확인한다.

LF/CRLF·새 교차 패키지/전체 복원과 보관 결과를 최종 기록에서 마감한다. 실제 Windows/

미확정으로 유지한다. 실제 로그인/추론·외부 권한/계정 변경은 수행하지 않는다.
