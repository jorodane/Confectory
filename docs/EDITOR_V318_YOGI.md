# YogiBox domain-owned persistence increment

The ordinary YogiBox pack now provides Open/Save/Close/Clear/Revalidate and a pure storage validator. Legacy Create remains ephemeral and legacy Discard remains an ephemeral-release operation; a bound package requires explicit Clear or Close. The ordinary EditorHome Main and VerifyShell select the new providers through normal role declarations. No special ProjectPack or EditorHome build exception is used.

Open binds the actual EditWorkspace manifest/root/participant, selected durable project identity and owned semantic namespace. Its directory must be that actual project’s `.confectory/yogi`; a SHA256-derived project/owner/manifest filename separates owners. Existing links in the storage path/file are rejected. Load uses the general FileStream BoundedSnapshot with a 5 MiB byte bound read from one file handle, preserving Snapshot’s exact-byte hash/text semantics. The general reader has a 16 MiB maximum caller limit and reads at most limit+1 bytes before rejection. Save uses the ordinary root-constrained Commit/exact-hash CAS. No arbitrary UI snapshot import, localStorage package or guessed transfer URL is used.

The storage envelope validates schema, project/owner/manifest/namespace, allowed/required properties, duplicate JSON keys, maximum depth 24 and 8192 nodes, 32 total semantic/image/pending/interrupted items, two total captures, unique GUID item identities, selected metadata (16 fields/64 KiB per item), 4096-character text and 512×512 RGB images. Pixel length, encoding, scope and SHA256 are checked before loading. Malformed/foreign/excess records are rejected before a live box is installed; existing files are retained. A CAS conflict retains both the writer’s disk file and the live local package. Explicit Clear rolls live contents back on failed persistence. No automatic merge, overwrite or conflict-resolution policy is added.

Exactly records actual ID/kind/revision/state/selected metadata plus baseline/content hashes, without archiving implementation source. Revalidate uses the actual owned workspace Read/Inspect ports and compares ID resolution, kind, revision, hashes and selected metadata. The original metadata/revision remain historical; availability labels are current/stale/deleted observations of the working copy, not rewritten records or fabricated objects. Removed owned references remain visible as unavailable/deleted. Source/draft Save/Review/Confirm remain separate.

Open restores text, item identity and sealed data directly after validation. It does not invoke Exactly, Seal, Reserve/CompleteCapture, Receive/Handoff, approval, AI or delivery. Stored pending captures move to interrupted records with the same identity and scope; the live pending-ticket map stays empty, so an old ticket cannot complete or recapture. Interrupted records count toward capacities and block Seal until explicitly removed. Existing images are validated historical local pixels and are shown only through explicit image preview, not recaptured or claimed as current render output. Sealed status is local package data, not permission or delivery authority.

The consumer persists mutations through the domain Save port. Window/presentation close and project hiding keep the package; full project/session close saves dirty bound contents and releases the owner through Close. Persistence failure retains the live resource rather than silently discarding it. The existing user discard operation uses explicit Clear. A retained UI owner must resolve storage conflicts explicitly; merge/reload-overwrite policy remains undecided. The default receiver remains refusing, and EditorHome adds no send/recipient action.

Private Workspace presentation stores only open intent, viewport position and active tab; pending description stays in the existing private input map. It stores no package snapshot, image bytes, permission or handle. Each ProjectPack/Workspace gets its own presentation intent while the actual package belongs to project/owner. Restore calls the bound domain query and repositions the presentation; it does not select objects/capture/unseal/send. Restoring a sealed package does not auto-unseal it. Closing/hiding retains description input. A rejected storage load shows an explicit unavailable panel rather than a fake empty package.

## Augment follow-up boundary

Existing Augment Command custom/skip can be reused: custom adds an explicit bounded local idea with actual semantic scope; skip records a reason and clears the current batch. ProjectAI currently keeps its Augment handle private and has no public local custom/skip forwarding port. A normal project/Helper/owner-bound local lifecycle plus explicit forwarding methods can expose those operations without a provider request, raw-handle access or a dummy paid-model binding. Preserve CAS, command identity and scope checks; custom does not imply task execution and skip does not automatically fetch the next offer. Generic discard versus skip of an unselected batch, and cancellation of an executing/staged task, remain separate decisions. Existing task cancel is limited to selected work before staged/confirmed source and cannot stand in for general proposal discard. No discard/cancel/merge/billing/transmission policy is decided here.

## Remaining v318 boundaries

External Yogi recipients, attachment delivery retention and merge/conflict policy remain unsupported. Augment local custom/skip bridge and discard/task-cancel policy remain unfinished. Run render embedding, pause/step, standalone build and cross-host execution rebinding remain unsupported. Helper rich profile/image/history, cold AI output/preview/approval owner, Agent account/usage, co-worker membership, global chat ownership and marketplace/install/update/publication remain unsupported. Prior standalone WASM publish performance remains a separate blocker. This is a scoped persistence increment, not full v318 parity.
