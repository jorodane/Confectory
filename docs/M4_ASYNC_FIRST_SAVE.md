# M4: 첫 생성 Save 전 입력과 명시 Task 결합

저장소에 보관한 v666 `dist/blueprint.js`의 새 동작·C# 편집·명시 async 메뉴와
기존 `createDeclaration`/`readFeature`/`createFeature` 흐름을 연결한다.
기능이나 동작을 만들기 위해 빈 본문을 먼저 Save하고 다시 편집할 필요를 줄인다.
프로토타입의 C# 자동 재작성은 채택하지 않는다. Task 본문도 사용자가 작성하며
동기 호출자는 명시적으로 전환하기 전까지 기존 오류를 유지한다.

## 지원 범위

- 새 직접 소유 전역 함수: 미할당 graph의 Root/기본 동작 메뉴, 원문 입력,
  생성 전 재시작, 첫 Save, 전체 Review→Confirm, 실제 Task 실행.
- 정보가 직접 소유한 함수의 첫 graph: 기존 owner 증명을 보존한다. 원본의 직접 작성
  진입이 보관하는 구현 checkpoint는 유지하고 첫 Blueprint Save에 본문/전환을 결합한다.
  명시적인 생성 API의 checkpoint 지연도 같은 소유 증명으로 지원하며 별도로 검증한다.
- 기존 직접 소유 Root의 새 ordinary 동작: 생성·지역 핀/값·시작/다음 연결·표시·원문과
  Task 선택을 같은 후보에 결합한다. 이미 소유한 내부 본문의 원문/표시/전환도
  같은 전체 물리 Root 거래에 포함한다.
- 전환 입력 하나는 마지막에 적용한다. 새 동작 생성과 지역 핀 변경, 표시/값,
  원문을 먼저 검증한다. 원문을 기록한 뒤 정의 hash를 바꾸는 순서 오류를 피한다.
  다른 독립 구조 계획이나 중복 전환은 입력을 버리지 않고 전체 거절한다.

새 함수 선언 자체를 아직 checkpoint하지 않았어도, 열어 본 정확한 선언·manifest
관측을 개인 입력에 보존한다. 복구 시 같은 ProjectContext/namespace, 원래 manifest의
물리 hash와 초안 hash, checkpoint, ID와 새 소유 경로를 모두 다시 확인한다.
기존 Create/SetText 계약으로 **메모리 초안만** 복구하며 파일이나 checkpoint를 쓰지
않는다. 부모/제공 구현이 있는 선언, 예약된 ID, 다른 경로·링크·충돌 파일은 덮어쓰지
않는다. 기존 메모리 초안이 다르면 그대로 보존하고 정확히 일치하는지 결과만 돌려준다.

## 저장·복구 경계

첫 graph 할당의 이전/이후 source closure를 실행 중 소유 관측에 연결한다. 원래
checkpoint와 전체 선언/등록 입력이 일치하는 경우에만 해당 생성의 입력 proof를
현재 후보에 연결한다. 생성 응답 유실과 실제 저장 응답 유실을 구분한다. 저장 receipt가
있으면 이전 결과만 조회하고, 실행되지 않았음이 전체 원래 관측으로 확인되는 경우에만
새 Save를 허용한다. 다른 편집자의 변경에 입력을 자동 재기준화하지 않는다.

생성 중 추가한 C# 입력은 이전 Save의 캡처와 구분해 유지한다. 실패·cold 뒤에도
현재 입력과 이전 시도를 보존한다. 같은 생성 대상이 하나인지 명시적으로 확인하며
여러 target을 자동 선택하지 않는다. 부분 Review·불완전 후보와 최종 CAS 실패는
원본을 쓰지 않는다. 실제 파일 변경은 기존 전체 Review→Confirm에서 수행한다.

## 남는 고정 범위

이 단위는 `root-parameters` 공개 IO 변경 거래나 별도 Set/property/실행 분기 계획을
async와 임의로 합치지 않는다. 특히 새 함수의 Blueprint Root 핀 계약 변경은 기존
Root 계약 거래가 아직 Confirm한 원본을 요구하는 실제 경계다. 이는 정상 영구 UX
정책으로 확정한 금지가 아니며, 고정 입력/출력 계약 편집의 다음 구현 범위로 남는다.
생성 전에 선언 편집기로 적용한 IO의 정체성과 원문은 이번 복구에서 보존한다.

비소유 부모·외부 원본 쓰기, override 공개 IO 변경, ref async 거절, 선택적인 legacy
자동 migration은 새 미구현 요구로 늘리지 않는다. M11/M12는 회귀가 없는 한 닫힌
상태를 유지한다. V2–V9·별도 팩/backend/종류 호환성 결정과 실제 기기·전체 UI·Space
전달의 기존 잔여는 별개다. 최종 검증과 보관 결과는
[검증 기록](VALIDATION_V666_ASYNC_FIRST_SAVE.md)에 확정한다.
