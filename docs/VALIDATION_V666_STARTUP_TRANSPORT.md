# 초기화 HTTP 전송 정체 검증

[구현 범위와 한계](V2_STARTUP_TRANSPORT.md).
최종 독립 LF/CRLF·새 패키지/전체 복원 검증은 진행 전이며 아래는 조사/집중 검사다.

- runtime `87e62a3d` 보관 패키지의 실제3D reload24회는 통과했다. 현재 `c88fd6b`와
  runtime/검사/도구가 동일하며 차이는 문서뿐임을 확인했다.
  기록 `74352046e446459ea3a63c260be9ff6a`; 요청/응답/실패·페이지 수명과 원문/입력을 보존했다.
- 같은 패키지의 실제 읽지 않는 이미지 소켓은 다른 창 초기화를3초 넘게 막았고,
  연결 종료 후 Broken pipe로 호스트가 종료됐다. 기록 `b590b73d20c443d69c08653046437958`.
  이 controlled stall을 과거 빈 `#app` 실패의 동일 원인으로 간주하지 않는다.
- 수정된 exact Serve body의 실제 HTTP probe는 느린4MiB 응답/부분 POST 격리,
  세션/Origin 거절·Unicode 보존·원래 owner 스레드/중복 실행 없음,
  32개 제한/실제30초 만료·종료 시 취소와 owner1회 해제를 통과했다.
  집중 기록 `736403b679904d3c8777021081d48d89`; owner는 test double이다.
- 첫 집중 시도는 검사 환경의 DOTNET_CLI_HOME 미지정으로 build 전에 실패했다.
  다음 시도에서 HTTP 초과 연결의 빈200 응답을 발견해503으로 바로잡았다.
  두 실패의 로그/증거는 보존하고 최종 통과 수치에 재사용하지 않는다.

최신/롤백 보관본과 기존 자료는 유지한다. 자체 RAM 검사 공간만 승인된 절차로 정리한다.
라이브 AI/자격증명·과금·외부 grant·main 변경은 없으며 실제 장치/전체 UI는 미검증이다.
