# V6 자료 정렬의 입력·수명 보호

고정 v666 ZIP `Confectory-v666/dist/app.js::renderResourceBrowser`의 네 선택
`기본 순서`, `이름 오름차순`, `이름 내림차순`, `최근 생성순`과 현재 선택의 체크 표시를
그대로 사용한다. 기존 실제 native 생성 시각·폴더 우선·숫자 이름 비교·원래 import 순서는
변경하지 않는다. 기존 개인 `sort` 필드와 레이아웃을 사용하며 새 저장 형식은 없다.

게시 dbffa359의 실제 UI에서 정렬 버튼의 pointer가 미저장 Data 설명을 blur하여 native
저장을 유발하는 경로와, 보관된 메뉴 callback이 더 최근 정렬 선택을 덮어쓰는 결함을 재현했다.
이번 유한한 단위는 두 경로를 기존 자료 종류/이름/설명 입력 보호와 같은 기준에 연결한다.

미확정 import·이름/구조·설명과 inline 이름 편집 중 정렬을 적용하지 않으며 pointer는
해당 입력의 focus를 옮기지 않는다. ready 상태의 현재 프로젝트·창·native revision,
선택 serial·폴더·종류·배율·확정 검색과 미확정 검색을 캡처하고 명시 메뉴 선택 시 재확인한다.
새 메뉴/선택·검색·종류·자료 변경·다른 편집 focus·창 숨김/폐기·프로젝트 이탈 뒤에는
오래된 callback이 정렬을 적용하지 않는다. 정상 선택은 기존 선택 ID/검색 입력을 보존하고
대기 중 상위 카테고리 열기를 폐기하며 기존 keyboard 대기 확인의 serial 보호를 재사용한다.

정렬은 개인 표시 동작이다. 자료/원본 bytes, 공개/override 계약, native 권한·원자 저장·
Review/Confirm·최종 CAS는 바꾸지 않는다. 명시 Save/change·동일 command 재시도·cold 복구·
동료 충돌과 입력만 취소는 기존 저장 경로를 그대로 사용한다. 입력 보호가 필요한 동안
정렬 버튼이 차단된다는 이유로 원본의 정렬 기능 자체를 미지원으로 바꾸지 않는다.

최종 코드는 독립 LF/CRLF·실제 정상/차단/쓰기 실패/충돌/cold 및 기존 자료 회귀, 새 교차
패키지와 전체 복원으로 마감한다. 원래 네 정렬의 수명 보호를 넘어 크기/형식 조합을 새
필수 항목으로 늘리지 않는다. 더 큰 자료/보관·실제 신원/그룹 권한 backend·정보 종류의
C# 표현/사용중 삭제 정책과 물리 출력/기기·전체 UI·초기 빈 화면 원인 미확정은 별도다.
완료된 M11/M12/M4와 기존 자료 필터/키보드 흐름은 회귀가 없는 한 다시 열지 않는다.
