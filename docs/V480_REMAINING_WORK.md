# v480 남은 작업과 다음 구현 묶음

이 문서는 `work/current@9784761`의 필드 비교와 후속 브라우저 원자적 채우기를 기준으로, [현재 상태 표](EDITOR_V480_STATUS.md)의 남은 범위를 구현 묶음으로 정리한다. 우선순위는 기존 사용 흐름의 완결성, 이미 있는 소유/편집 계약의 재사용 가능성, 새 실행 의미와 외부 의존성의 크기를 기준으로 정했다. 구현 계획이며 이 목록의 기능을 이번에 추가하거나 전체 회귀했다고 주장하지 않는다.

브라우저 Data의 명시적 객체/필드 비교·셀 Apply·다중 행 원자적 채우기와 후속의 명시적 선언 계층 탐색은 현재 구현 범위다. 정확한 JSON, 원래 source/schema CAS, private 입력·선택·콜드 복원, 기존 Save/Review/Confirm을 사용한다. 자동 계산 열과 임의의 선택 확장은 포함하지 않는다. 이후 작업은 작은 클릭 감사를 반복하기보다 아래 완료 기준 하나를 끝까지 구현·검증하는 방식으로 진행한다.

## 따로 남기는 정책과 의도적 경계

- **int/long 계산식 overflow**의 오류/wrap 정책은 아직 사용자 답변 대기다. 기존 C# 연산을 보존하며 enum의 int32 항목 범위 검사와 혼동하지 않는다. 정책이 필요한 계산식 실행 의미만 보류하고 위의 독립적인 탐색·저장·문서 구현까지 막지 않는다.
- 자동 전체 필드 합집합·사용자 계산 열, 선언 삭제/참조 대체와 소유 집합 생성·삭제 전체 Undo는 기존 셀/채우기의 지원을 확대한 것으로 간주하지 않는다. 삭제는 참조 무결성·등록·원자적 역변경의 별도 설계와 compiler/CAS 회귀가 필요하며 P0 탐색 완료 뒤 편집 수명 묶음으로 진행한다.
- 이 목록의 내부 데이터 투영·영속 형식·명령 설계는 사용자에게 저장소 설계 질문으로 넘기는 차단 사유가 아니다. 새 실행 의미와 사용자 정책, 외부 서비스 권한, 실제 환경이 필요한 검증을 구분한다.
- main·원본 ZIP·Android 설정 보존, 실계정·유료 호출 금지를 유지한다. 과거 엔진/UI 검사 수를 이번 채우기 검사의 고유 수에 합산하지 않는다.
