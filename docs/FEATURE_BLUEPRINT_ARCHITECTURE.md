# 기능 내부 Blueprint와 노드 파일

2026-10-15 확정된 구현 방향이다. 기존 개념/기능/모듈, 팩과 기능 외부 입출력 계약을 유지한다. 기능 내부의 원본은 graph와 노드별 파일이다. 기능은 외부 계약과 실행 흐름을 소유하는 래퍼이며 각 노드는 독립 함수다. 자연어 노드는 기존 프로젝트 계약과 함께 해석해 구현한다. 노드의 의미상 크기나 코드 줄 수에 따른 자동 분해 규칙을 두지 않는다. 사용자가 필요할 때 다이브하고 분해한다. 기존 기능은 같은 외부 계약을 통해 다른 기능의 노드에서 호출할 수 있다.

이 문서는 확정 방향과 단계별 경계를 기록한다. 아직 graph 실행·조립의 구현 완료 증거가 아니다. 최신 live Site를 임의로 수집해 새 전달본으로 대체하지 않는다. 현재 v424의 비충돌 영역을 연결하며 새 기능 화면은 다음 명시적인 레퍼런스 전달에 맞춘다.

## 원본과 소유권

| 대상 | 원본과 수정 주체 | 검증과 산출물 |
|---|---|---|
| 기능 외부 계약 | 기존 qualified feature ID와 팩/I/O 선언. 명시적인 계약 편집 | 현재 파서·계약 검증을 유지. 계약 변경 시 graph·호출자·구현 영향 확인 |
| 기능 graph | 실행선·분기·노드 호출·순서. 독립 편집 단위 | graph 버전과 참조 노드/외부 계약 버전을 고정해 조립 |
| 노드 정의 | 안정된 node ID, 자연어 의도, 입출력·호출 대상 | 구현이 어떤 정의·계약 버전용인지 기록 |
| 노드 구현 파일 | 해당 노드의 독립 구현. 사람 또는 범위가 제한된 Worker | 변경 파일의 리비전·내용 해시를 확인. 변경 없는 구현 재사용 |
| 최종 C# | 시스템이 graph 진입 흐름과 노드 함수를 조립한 기능 단위 파생 산출물 | 원본과 별도 관리. Worker가 직접 편집하거나 함수 영역을 패치하지 않음 |
| 화면 배치 | 노드 위치·창·줌 등 presentation | 실행 흐름·노드 구현과 분리. 배치 변경이 구현 재생성을 뜻하지 않음 |

graph 연결/순서 변경과 노드 구현 변경을 별도 편집 단위로 둔다. 자연어 의도·입출력 변경이 기존 구현의 유효성에 미치는 영향도 명시한다. 기존 구현 파일을 삭제하거나 새 AI 요청을 자동 재실행하는 방식으로 오래됨을 처리하지 않는다.

AI는 미구현 또는 변경된 노드의 구현을 담당한다. 일반 compiler는 확정된 graph와 code를 빌드한다. 구현 생성, 조립/검증, 빌드, 실행과 완료 증거를 구분한다. Unreal식 명시적 실행선에 대응하는 통합 조립·검증·빌드 동작을 제공한다. UI 버튼 이름은 아직 확정하지 않았으며 ‘완성’을 내부 계약이나 저장 형식의 고정 이름으로 사용하지 않는다.

## 호환과 단계적 전환

1. 기존 CELEM 기능·구현·C# body는 기존 방식으로 계속 읽고 빌드한다. 읽기나 일반 프로젝트 열기만으로 변환하지 않는다. 기존 파일을 제거하거나 동일 경로에 파생 C#을 덮어쓰지 않는다.
2. 선택한 기능에 대한 graph/node 원본과 별도 파생 산출물의 소유·버전 계약을 추가한다. 기존 기능의 graph 연결은 명시적인 변경으로 검토한다. 레거시 소스는 보존한다.
3. 새 graph 경로의 Worker에는 지정된 노드 원본 수정 권한만 준다. graph topology, 다른 노드와 최종 파생 C#은 별도 권한이다. 현재 일반 Workspace Worker를 새 경로의 안전한 node Worker로 표시하지 않는다. 기존 넓은 도구 범위를 생성 산출물에 그대로 적용하지 않는다.
4. 조립은 하나의 고정된 입력 묶음을 읽는다. graph, 노드 정의·구현, 외부 계약과 compiler/target profile의 버전·해시를 산출물 manifest에 기록한다. 조립 도중 원본이 바뀌면 해당 조립 결과를 현재 결과로 채택하지 않는다.
5. 검토·확정과 프로젝트의 일반 빌드/실행 경로에 연결한다. 기존 Save/Review/Confirm, source CAS와 별도 AI 내용·사용량 승인은 유지한다. 일반 체크아웃에서도 원본에서 동일한 산출물을 재생성할 수 있게 한다.

바로 적용할 원본 표시는 `legacy-source`와 `blueprint-source`처럼 구분할 수 있다. 실제 저장 필드와 이관 명령은 해당 소유 계약 검증 후 확정한다. 사용자 소스의 자동 대량 변환, 생성 파일을 새 원본으로 취급하는 복원, 과거 모델 요청 재생은 이 전환에 포함하지 않는다.

## 조립·검증의 검토 기준

- 고정된 원본을 읽고 정렬·이름·출력 형식을 결정적으로 생성한다. 시간, 임시 경로, 순회 우연성으로 산출물 내용이 달라지지 않게 한다.
- graph 수정으로 노드 구현을 재요청하지 않는다. 변경된 정의·계약에 맞지 않는 구현은 오래됨으로 표시하며, 기존 파일을 보존하고 새 구현 또는 명시적인 검토를 요구한다.
- graph의 존재·연결, 타입·호출 계약, 구현 가용성, C# 구문/컴파일을 각각 검증한다. 구현 파일 존재나 AI 응답 완료를 빌드·실행 완료로 표시하지 않는다.
- 진단을 node ID, 원본 파일/리비전과 원본 위치로 되짚는다. 시스템 생성 진입 코드의 오류는 관련 graph/edge와 고정된 graph 버전에 연결한다. 파생 C# 경로만 제시하고 원본 대응을 잃지 않는다.
- 실행에 쓰는 산출물은 확정된 입력과 연결한다. 원본과 결과가 바뀌거나 유실된 상태, 빌드 실패·취소·재시작을 명시한다. 부분 조립 결과를 현재 성공으로 게시하지 않는다.
- 파일 전송·저장·compiler의 실제 자원 한도는 명시적으로 처리하되 이를 노드의 의미상 크기 제한이나 자동 분해 규칙으로 바꾸지 않는다.

## 실행 의미에서 확인할 사항

현재 언어의 외부 FunctionSignature는 primitive와 배열 타입을 사용한다. 기존 C# 구현은 일반 C# 구문과 typed imports를 사용한다([선언/파서](../src/Confectory.Core/Declarations.cs), [해결](../src/Confectory.Core/Resolution.cs), [컴파일](../src/Confectory.Core/Build.cs)). 이 사실만으로 새로운 graph scheduler 의미가 정해지지는 않는다.

| 항목 | 확인·보고할 경계 |
|---|---|
| 순차 실행·분기·합류 | 명시적 실행선, 조건·출력 타입, 모든 경로의 값 가용성과 반환. 암묵적 기본값이나 fan-out 실행을 추가하지 않음 |
| 루프·재귀 | 노드 내부의 기존 코드/기존 feature 호출과 graph 차원의 반복·재진입을 구분. 종료·상태·제한 의미는 계약 근거를 확인 |
| 비동기·동시 실행 | 현재 외부 ABI와 런타임 소유자에 근거해 검토. 임의 Task 타입이나 병렬 실행을 도입하지 않음 |
| 예외·취소 | 현재 코드의 예외와 graph 차원의 처리/중단/재시작 의미를 구분. 실패 후 노드·외부 I/O 재생을 추정하지 않음 |
| 상태·노드 간 데이터 | 호출 단위 상태, 공유 값, 분기 합류와 소유권을 검증. schema 메타데이터를 임의의 런타임 객체 타입으로 바꾸지 않음 |

이 중 미정 의미에 의존하는 동작을 성공으로 구현해 표시하지 않는다. 기존 계약 근거를 먼저 확인하고, 되돌리기 큰 선택이나 새로운 공개 의미가 필요한 지점을 보고한다. 확정 방향과 독립적인 UI/기존 계약 연결은 계속한다.

## 현재 작업에 미치는 영향과 다음 체크포인트

현재 추가 중인 선언 편집은 외부 signature·모듈 연결·설명·표시 이름과 공유 초안/View의 편집이다. 내부 graph나 파생 C#의 원본 지위를 정하는 구현은 아니다. 리비전과 표시한 내용의 해시를 함께 확인하고, 미적용 입력·독립 View·재시작과 compiler-backed Confirm을 회귀 검증한다. 이 계약 편집 경계는 새로운 구조에서도 유지하며 graph가 연결되면 계약 변경 영향 상태를 연결한다.

현재 AlgorithmProjection은 기존 C#의 설명용 projection이다. 이를 실행 원본 graph로 승격하거나 그 화면의 JSON을 새 프로그램 원본으로 취급하지 않는다. 새 graph/node 원본·조립 계약을 명시적으로 추가한다.

다음 체크포인트는 현재 선언·View/취소·이력 연결의 검증 결과와, graph/node/파생 산출물의 소유·버전 및 기존 소스 호환 경계다. 이후 고정된 입력으로 조립·컴파일·오류 매핑과 변경 없는 노드 재사용을 소유 fixture로 검증한다. 실제 사용자 계정·토큰·유료 AI 호출이나 외부 배포는 별도 권한이며 fixture 결과와 구분한다.
