# 기능 내부 Blueprint와 노드 파일

2026-10-15 확정된 구현 방향이다. 기존 개념/기능/모듈, 팩과 기능 외부 입출력 계약을 유지한다. 기능 내부의 원본은 graph와 노드별 파일이다. 기능은 외부 계약과 실행 흐름을 소유하는 래퍼이며 각 노드는 독립 함수다. 자연어 노드는 기존 프로젝트 계약과 함께 해석해 구현한다. 노드의 의미상 크기나 코드 줄 수에 따른 자동 분해 규칙을 두지 않는다. 사용자가 필요할 때 다이브하고 분해한다. 기존 기능은 같은 외부 계약을 통해 다른 기능의 노드에서 호출할 수 있다.

이 문서는 확정 방향과 단계별 경계를 기록한다. 각 구현 단계의 실제 compiler·소비자 증거와 남은 범위는 아래에 구분한다. 최신 live Site를 임의로 수집해 새 전달본으로 대체하지 않는다. 새 기능 화면 기준은 2026-10-16 사용자가 전달한 v480이다.

## 원본과 소유권

| 대상 | 원본과 수정 주체 | 검증과 산출물 |
|---|---|---|
| 기능 외부 계약 | 기존 qualified feature ID와 팩/I/O 선언. 명시적인 계약 편집 | 현재 파서·계약 검증을 유지. 계약 변경 시 graph·호출자·구현 영향 확인 |
| 기능 graph | 실행선·분기·노드 호출·순서. 독립 편집 단위 | graph 버전과 참조 노드/외부 계약 버전을 고정해 조립 |
| 노드 정의 | 안정된 node ID, 자연어 의도, 입출력·호출 대상 | 구현이 어떤 정의·계약 버전용인지 기록 |
| 노드 구현 파일 | 해당 노드의 독립 구현. 사람 또는 범위가 제한된 Worker | 변경 파일의 리비전·내용 해시를 확인. 변경 없는 구현 재사용 |
| 최종 C# | 시스템이 graph 진입 흐름과 노드 함수를 조립한 기능 단위 파생 산출물 | 원본과 별도 관리. Worker가 직접 편집하거나 함수 영역을 패치하지 않음 |
| 화면 배치 | 노드 위치·창·줌 등 presentation | 실행 흐름·노드 구현과 분리. 배치 변경이 구현 재생성을 뜻하지 않음 |

graph 연결/순서 변경과 노드 구현 변경을 별도 편집 단위로 둔다. 자연어 의도·입출력 변경이 기존 구현의 유효성에 미치는 영향도 명시한다. 기존 구현 파일을 삭제하거나 새 AI 요청을 자동 재실행하는 방식으로 오래됨을 처리하지 않는다.

AI는 미구현 또는 변경된 노드의 구현을 담당한다. 일반 compiler는 확정된 graph와 code를 빌드한다. 구현 생성, 조립/검증, 빌드, 실행과 완료 증거를 구분한다. Unreal식 명시적 실행선에 대응하는 통합 조립·검증·빌드 동작을 제공한다. UI 버튼 이름은 아직 확정하지 않았으며 ‘완성’을 내부 계약이나 저장 형식의 고정 이름으로 사용하지 않는다.

## 호환과 단계적 전환

1. 기존 CELEM 기능·구현·C# body는 기존 방식으로 계속 읽고 빌드한다. 읽기나 일반 프로젝트 열기만으로 변환하지 않는다. 기존 파일을 제거하거나 동일 경로에 파생 C#을 덮어쓰지 않는다.
2. 선택한 기능에 대한 graph/node 원본과 별도 파생 산출물의 소유·버전 계약을 추가한다. 기존 기능의 graph 연결은 명시적인 변경으로 검토한다. 레거시 소스는 보존한다.
3. 새 graph 경로의 Worker에는 지정된 노드 원본 수정 권한만 준다. graph topology, 다른 노드와 최종 파생 C#은 별도 권한이다. 현재 일반 Workspace Worker를 새 경로의 안전한 node Worker로 표시하지 않는다. 기존 넓은 도구 범위를 생성 산출물에 그대로 적용하지 않는다.
4. 조립은 하나의 고정된 입력 묶음을 읽는다. graph, 노드 정의·구현, 외부 계약과 compiler/target profile의 버전·해시를 산출물 manifest에 기록한다. 조립 도중 원본이 바뀌면 해당 조립 결과를 현재 결과로 채택하지 않는다.
5. 검토·확정과 프로젝트의 일반 빌드/실행 경로에 연결한다. 기존 Save/Review/Confirm, source CAS와 별도 AI 내용·사용량 승인은 유지한다. 일반 체크아웃에서도 원본에서 동일한 산출물을 재생성할 수 있게 한다.

바로 적용할 원본 표시는 `legacy-source`와 `blueprint-source`처럼 구분할 수 있다. 실제 저장 필드와 이관 명령은 해당 소유 계약 검증 후 확정한다. 사용자 소스의 자동 대량 변환, 생성 파일을 새 원본으로 취급하는 복원, 과거 모델 요청 재생은 이 전환에 포함하지 않는다.

## 조립·검증의 검토 기준

- 고정된 원본을 읽고 정렬·이름·출력 형식을 결정적으로 생성한다. 시간, 임시 경로, 순회 우연성으로 산출물 내용이 달라지지 않게 한다.
- graph 수정으로 노드 구현을 재요청하지 않는다. 변경된 정의·계약에 맞지 않는 구현은 오래됨으로 표시하며, 기존 파일을 보존하고 새 구현 또는 명시적인 검토를 요구한다.
- graph의 존재·연결, 타입·호출 계약, 구현 가용성, C# 구문/컴파일을 각각 검증한다. 구현 파일 존재나 AI 응답 완료를 빌드·실행 완료로 표시하지 않는다.
- 진단을 node ID, 원본 파일/리비전과 원본 위치로 되짚는다. 시스템 생성 진입 코드의 오류는 관련 graph/edge와 고정된 graph 버전에 연결한다. 파생 C# 경로만 제시하고 원본 대응을 잃지 않는다.
- 실행에 쓰는 산출물은 확정된 입력과 연결한다. 원본과 결과가 바뀌거나 유실된 상태, 빌드 실패·취소·재시작을 명시한다. 부분 조립 결과를 현재 성공으로 게시하지 않는다.
- 파일 전송·저장·compiler의 실제 자원 한도는 명시적으로 처리하되 이를 노드의 의미상 크기 제한이나 자동 분해 규칙으로 바꾸지 않는다.

## 실행 의미에서 확인할 사항

현재 언어의 외부 FunctionSignature는 primitive와 배열 타입을 사용한다. 기존 C# 구현은 일반 C# 구문과 typed imports를 사용한다([선언/파서](../src/Confectory.Core/Declarations.cs), [해결](../src/Confectory.Core/Resolution.cs), [컴파일](../src/Confectory.Core/Build.cs)). 이 사실만으로 새로운 graph scheduler 의미가 정해지지는 않는다.

| 항목 | 확인·보고할 경계 |
|---|---|
| 순차 실행·분기·합류 | 명시적 실행선, 조건·출력 타입, 모든 경로의 값 가용성과 반환. 암묵적 기본값이나 fan-out 실행을 추가하지 않음 |
| 루프·재귀 | 노드 내부의 기존 코드/기존 feature 호출과 graph 차원의 반복·재진입을 구분. 종료·상태·제한 의미는 계약 근거를 확인 |
| 비동기·동시 실행 | 현재 외부 ABI와 런타임 소유자에 근거해 검토. 임의 Task 타입이나 병렬 실행을 도입하지 않음 |
| 예외·취소 | 현재 코드의 예외와 graph 차원의 처리/중단/재시작 의미를 구분. 실패 후 노드·외부 I/O 재생을 추정하지 않음 |
| 상태·노드 간 데이터 | 호출 단위 상태, 공유 값, 분기 합류와 소유권을 검증. schema 메타데이터를 임의의 런타임 객체 타입으로 바꾸지 않음 |

이 중 미정 의미에 의존하는 동작을 성공으로 구현해 표시하지 않는다. 기존 계약 근거를 먼저 확인하고, 되돌리기 큰 선택이나 새로운 공개 의미가 필요한 지점을 보고한다. 확정 방향과 독립적인 UI/기존 계약 연결은 계속한다.

## 현재 작업에 미치는 영향과 다음 체크포인트

현재 추가 중인 선언 편집은 외부 signature·모듈 연결·설명·표시 이름과 공유 초안/View의 편집이다. 내부 graph나 파생 C#의 원본 지위를 정하는 구현은 아니다. 리비전과 표시한 내용의 해시를 함께 확인하고, 미적용 입력·독립 View·재시작과 compiler-backed Confirm을 회귀 검증한다. 이 계약 편집 경계는 새로운 구조에서도 유지하며 graph가 연결되면 계약 변경 영향 상태를 연결한다.

현재 AlgorithmProjection은 기존 C#의 설명용 projection이다. 이를 실행 원본 graph로 승격하거나 그 화면의 JSON을 새 프로그램 원본으로 취급하지 않는다. 새 graph/node 원본·조립 계약을 명시적으로 추가한다.

다음 체크포인트는 현재 선언·View/취소·이력 연결의 검증 결과와, graph/node/파생 산출물의 소유·버전 및 기존 소스 호환 경계다. 이후 고정된 입력으로 조립·컴파일·오류 매핑과 변경 없는 노드 재사용을 소유 fixture로 검증한다. 실제 사용자 계정·토큰·유료 AI 호출이나 외부 배포는 별도 권한이며 fixture 결과와 구분한다.

## 첫 실제 compiler 경로

`sync-acyclic-v1` 프로필을 일반 Builder에 연결했다. 구현이 `blueprint <target> "graph.json";`을 명시적으로 선택하며, 기존 `body`와 같은 target/common 선택·중복 검사를 사용한다. graph의 코드 노드는 `{schema:1,node,definitionHash,source}` 형태의 별도 파일을 참조한다. source는 노드의 완전한 독립 함수 본문이다. 최종 C#은 기존 생성 artifact 저장소에 조립하고 원본 경로에 쓰지 않는다. [일반 ProjectPack 예제](../examples/feature-blueprint/README.md)는 기존 typed Add 기능을 호출하고 결과 5를 출력한다.

실제 구현은 graph·정의·계약·본문 해시, 순차 실행/bool 분기와 합류의 값 가용성, 누락·오래된 노드, 정적 독립 함수와 명시적 typed imports를 검사한다. 기존 Registry/Planner/provider/일반 compiler를 거쳐 빌드한다. .NET compiler가 노드 본문 구문·경계·진단 지시문을 검사하며, 외부 변수 캡처와 잘못된 반환/타입은 실제 C# 컴파일에서 거부한다. graph 루프·비동기 scheduling·예외 라우팅은 이 버전에 포함하지 않는다. 노드 내부 일반 C# 루프/예외를 노드 크기 정책으로 제한하지 않는다.

빌드 보고서는 graph/node/계약 입력의 원시 해시, compiler identity·target과 노드 ID/본문 해시/JSON `/source` 위치를 기록한다. 조립과 compiler 반환 후, 최종 결과 게시 직전에 관찰한 입력을 재확인한다. 일반 소스 lease에 참여하지 않는 외부 파일 쓰기까지 단일 원자적 파일시스템 snapshot이라고 주장하지 않는다. 입력 변경 검출 시 현재 결과를 게시하지 않고 이전 성공 결과를 유지한다. 서로 다른 작업 경로에서 생성 DLL의 바이트 재현성도 소유 fixture로 확인했다.

graph/node는 `blueprint`/`blueprint-node` 원본 종류로 기존 공유 초안·Save·복원·compiler Confirm을 사용한다. `DevelopmentTools.OpenNode`는 한 노드와 실제 정의·관찰한 graph/계약에 한정된 새 capability다. 해당 도구의 list/read/stage/changes는 다른 노드·graph·선언·생성 C#·Confirm·실행을 허용하지 않으며 표시한 내용 해시와 리비전을 확인한다. Worker에 지정 노드의 의도·시그니처·사용 가능한 계약만 제공한다. 기존 넓은 도구는 graph/node 파일을 자동으로 받지 않는다.

이 단계는 일반 compiler·원본·초안·한정 도구 경계의 구현과 실행 증거다. 새 기능 화면, graph 신규 생성/전환 UI, node 전용 Task 계획/실제 Agent dispatch/adoption 공개 연결은 계속 구현 중이다. 실제 계정·유료 모델·native device 검증으로 확대하지 않는다. [검증 기록](evidence/v424-integration/blueprint-compiler.json).

노드 정의 조회는 topology 연결 완료와 분리한다. 연결 전 노드도 자신의 의도·입출력·계약으로 준비할 수 있으며, 실행 시에는 entry에서 도달하는 노드와 값 경로를 검증한다. compiler 진단 marker는 기능 ID·노드 ID·본문/정의 해시를 포함하고 원본 경로·JSON 위치·본문 줄/열로 대응한다. 일반 `check` 결과에도 컴파일된 Blueprint 증거가 포함된다.

## 2026-10-15 추가 확정 경계

## 노드 Task 공개 연결 검증 중

ProjectAI.NodeTask는 현재 graph/node 원본의 실제 정의·시그니처·사용 계약과 노드 소스 해시를 읽고, 표시한 assignment hash로 로컬 준비 작업을 기록한다. 모델 전송은 별도 연결과 정확한 Task·assignment·모델·endpoint·내용/사용량 승인 후에만 시작한다. 일반 Worker의 넓은 도구와 일반 복구 경로는 노드 Task를 거부한다. 실제 노드 capability의 list/read/stage/changes 네 역할만 전달하며 Helper 기억은 이 노드 요청에 보내지 않는다.

노드 정의를 수정한 graph와 새 노드 구현은 사용자가 함께 Review/Confirm할 수 있다. 선택에는 반드시 배정된 노드가 있어야 하며 나머지는 계획에 기록한 관련 graph/구현/계약으로 제한한다. 함께 검토한 사용자 변경은 Task 원본 기여와 구분해 채택 기록에 남긴다. Worker가 graph나 다른 원본을 수정할 권한은 늘어나지 않는다. 실행 완료는 검증 대기이며, 실제 compiler 결과와 사용자 목표 수용 후에 작업 완료를 기록한다.

준비 작업 취소는 실제 WorkerTasks의 controller lease와 ready-only 취소를 사용한다. 취소/실패 후에는 현재 노드와 남은 초안을 다시 읽고 새 작업을 명시적으로 배정한다. cold 복원은 권한·전송을 재생하지 않는다. 실제 공통 Home UI와 로컬 Responses 프로토콜·compiler 채택까지 연결한 검사가 1/0/0, 59.984초로 통과했으며 영향 회귀를 진행 중이다. 새 v480 기능 작업 화면·graph 신규 생성/전환과 전체 지도는 별도 진행 범위다.

추가 동시 편집 검사에서 승인 뒤 다른 View가 바꾼 본문이 read/changes에 반환되는 것을 실제 Agent·공유 초안으로 재현했다. OpenNode가 시작 본문 해시를 함께 고정하도록 보완했다. 조회 결과의 실제 본문을 검사한 뒤 반환하고, stage는 다른 작성자의 변경을 거부한다. 이 capability 자신의 성공한 stage만 본문 해시를 갱신한다. 노드 정의와 본문 scope가 다른 시점에서 읽힌 검사도 거부한다. 일반 capability의 기존 동작은 유지한다. 수정 후 엔진과 실제 로컬 Responses UI가 통과했으며 일반 도구·관리 프로필 검증을 마저 진행하고 있다.

## 기존 graph의 실제 편집 화면

PackWorkspace.Blueprint는 기존 소유 graph와 독립 노드 본문을 기능 화면에 연결한다. 현재 외부 계약을 읽고 시작/입력·실행 레일·분기·출력 경로를 표시한다. 설명·인수·실행 경로·노드 본문은 EditWorkspace.EditBatch로 모든 관련 소스의 리비전·내용 해시를 함께 확인한 뒤 적용한다. graph locator와 기존 소유 코드 노드 파일이 다르면 본문 편집과 노드 capability를 거부한다. 노드 본문 적용 시 사용자가 현재 정의를 명시적으로 수용하며 최종 C# 조립은 계속 시스템의 역할이다.

배치·확대·입력은 private presentation이며, 원본 읽기 basis와 AI/실행 권한을 프로세스 복원에 저장하지 않는다. 읽기와 source-ready 표시는 C# 컴파일을 뜻하지 않는다. 실제 Review·전체 소스 확인·Confirm은 기존 compiler 경로를 사용한다. [v480 연결·검증과 남은 범위](EDITOR_V480_INTEGRATION.md). 새로운 노드 파일의 할당·삭제, 기능 생성/전환·참조 wrapper와 확장 profile은 별도의 소유·원본 트랜잭션으로 이어서 연결한다.

## 독립 노드의 실제 컴파일 경계

정의가 현재인 독립 노드 본문은 연결 전에도 정적 지역 함수로 컴파일한다. 실행 경로는 그대로 유지하며 독립 노드를 호출하지 않는다. 연결되지 않은 미작성·오래된 본문은 실행 빌드를 막지 않지만 compiler 검증된 노드로 기록하지 않는다. 순수 조회의 `compilationEligible`, 실제 조립의 `includedInSource`, 실제 컴파일 후 `compilerValidated`를 구분한다. 생성기는 `feature-blueprint-source-v2`이며 실행 profile과 외부 ABI는 `sync-acyclic-v1` 그대로다. 원본 해시 입력은 기존 `inputs`에 유지하고, 없는 노드 파일은 별도 `missingInputs`로 관찰한다. 컴파일 중 파일이 나타나면 새 결과를 게시하지 않는다.

일반 빌드가 타깃별 다른 본문을 선택할 수 있으므로, 노드 Task 채택은 `Builder.CheckBlueprintNode`로 배정된 body target의 정확한 본문을 별도로 컴파일한다. 인수 연결이나 entry 실행 없이 노드 선언·사용 계약을 검사한다. 선택된 Review 원본만 임시 소유 후보에 덮어쓰며 원래 파일은 기존 Confirm에서만 반영한다. 완료 증거는 정의·원본 파일·compiler identity·artifact·assembly/reference 해시를 보존하고 `executed:false`로 한계를 표시한다. 현재 정의·본문 stamp와 보존된 독립 compiler 증거가 없는 미완료 Task는 일반 compiler 검사나 복구 동작으로 완료되지 않는다. 기존 완료 기록은 다시 실행하거나 새 증거로 바꾸지 않는다.

노드 capability와 기존 graph 편집은 엄격한 독립 노드 JSON 형식 및 구현→graph→노드 파일의 현재 소유 관계도 확인한다. locator가 바뀐 초안은 예전 소스 capability를 재사용하지 않는다. [단계별 검증 기록](evidence/v480-integration/independent-node-compiler.json).

## 기존 graph의 독립 노드 생성·제거

새 코드 노드는 현재 graph·구현·관련 계약·노드 원본의 표시한 버전을 함께 확인해 만든다. graph의 새 선언과 별도 미게시 노드 원본을 같은 소유 초안 트랜잭션으로 추가하며 경로는 소유자가 할당한다. 처음의 빈 본문과 미설정 정의 stamp는 구현·컴파일 완료가 아니다. 사용자 본문 작성 또는 한정 노드 작업, Save/복원, graph·본문의 명시적 그룹 Review/Confirm으로 이어진다. 새 노드가 기존 외부 입력을 받고 기존 노드에 값을 공급하는 실행도 같은 profile의 타입·가용성·compiler 검증을 사용한다. 미완성 연결은 초안으로 남을 수 있으며 잘못된 타입은 진단과 실제 Confirm에서 처리한다.

제거는 시작·실행선·인수·출력의 참조를 먼저 해제하고 현재 본문과 제거 범위를 명시적으로 검토한다. 기존 본문에 미확정 변경이 있으면 거부한다. 기존 파일은 보존하고 graph의 노드와 그 편집 소유 ID만 제거한다. 미게시 생성 취소는 확인한 공유 본문 초안도 함께 제거하며 외부 파일이 나타나면 거부한다. 이 소유 변경은 단순 원본 Undo/Redo로 되돌렸다고 표시하지 않는다.

제거된 원본의 기존 구독은 마지막 표시를 보존하며 종료 상태를 알린다. 같은 live 소유자에서 ID 재생성·원본 복원·재발견의 리비전은 이전 값을 재사용하지 않는다. 생성과 일반 편집은 변경 후에도 읽기 예산 안에 들어가는지 먼저 확인한다. 따라서 새 원본을 추가한 뒤 화면이 더는 읽지 못하는 부분 적용을 허용하지 않는다. 신규 기능/graph 자체의 등록, 레거시 전환, 참조 wrapper와 확장 profile은 별도 남은 범위다. [연결·검증 기록](EDITOR_V480_INTEGRATION.md).
