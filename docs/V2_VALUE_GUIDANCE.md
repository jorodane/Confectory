# V2: 값·연산식과 핀 연결 안내

보관한 `reference/site-ui/Confectory-Editor-Prototype-v666.zip`의
`Confectory-v666/dist/blueprint.js` 94–95행은 값 선택·논리 연산과 0 나눗셈 거절,
547–548행은 값/실행 연결의 구분과 역방향 실행 연결 거절,
1308행은 상수·연산식의 값·자료형 확인을 안내한다.

이 사용자 흐름에 대응하는 native의 지정 안내 15개를 “주십시오/습니다” 문체로 맞춘다.
[허용 목록과 원본 대응](v666-value-guidance-copy.json)은 원본의 문장을 그대로 복사한
경우로 오인하지 않도록 모두 native 조건을 보존하는 문체 적용으로 표시한다.
원래 native의 정수 범위·배열·입력 크기·표현식 깊이 제한과 ref 저장소·분기 범위·
자기 참조/출력 전용 핀 보호는 그대로다. backend 진단은 번역하거나 치환하지 않는다.

값/연산식 선택·잘못된 값 거절·입력 보존·취소·구조 Undo/Redo·재시작과 명시 수정,
저장·Review/Confirm·최종 원문 충돌 거절·실제 실행을 연결하여 확인한다.
개발 검사에서 직접 소유 루트의 값 전용 저장이 체크포인트 쓰기 실패 뒤 개인 입력을
잃을 수 있음을 확인했다. 이 경로만 기존 authorBatch의 원자적 체크포인트/CAS/receipt
수명에 연결한다. native 진입도 값 전용 묶음을 받아 직접 소유 root code·원본 proof·
checkpoint CAS를 확인하도록 제한한다. 부모/참조/외부·private/copy 문맥이나 다른 종류의
편집 권한을 확대하지 않는다.

제품 변경은 지정 문자열·UI/native의 값 전용 원자 저장 진입 조건·해당 JS 자산 canonical 크기/SHA다.
기존 C# 원문·핀 ID·
타입·연결·권한·실행 순서·원자성·저장 수명·레이아웃은 바꾸지 않는다.

[최종 검증](VALIDATION_V666_VALUE_GUIDANCE.md)에 실제 엔진·통제 provider·새 패키지/
전체 복원과 미실행 범위를 구분한다. M11/M12/M4의 완료 경계를 다시 열지 않는다.
V2의 나머지 계약 편집·일반 저장/검토·탐색/시스템 안내와 V3–V9·기존 팩/backend/
종류 결정·실제 기기/전체 UI/Space 전달은 고정 잔여로 유지한다.

기존 값 전용 레거시 Save의 실제 쓰기 실패 결함과 수정 전 자료를 보존한다. 실패 후
입력 보존을 없애거나 검사 기대를 완화하지 않는다. 단, 물리 원본 충돌을 개인 초안
Save에서 무조건 거절하는 새 정책은 만들지 않으며 최종 Confirm의 원본 CAS를 유지한다.
다른 일반 편집의 레거시 Save 경로는 이번 값 전용 수정/실패 주입 범위가 아니다.
