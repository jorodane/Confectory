# Private 본문과 공개 입력 이름의 공동 저장

고정 v666 [정보7/8행](V536_I5_6_REMAINING.md)의 기존 private C# 본문·보조 함수 편집과 다른 소유 함수의 공개 값 입력 이름 변경을 한 정보 창·한 Save에 결합한다. [기존 private 본문 공동 저장](V666_PRIVATE_BODY_GROUP.md)의 계약 불변 경계를 이 명시 pin 대응만큼 확장한다. 정보별 C# struct·종류 enum·모듈 interface, 명시 async 전환 전 sync caller 오류와 기존 권한·Review/Confirm·최종 CAS를 유지한다.

유한 종료 기준은 같은 정보의 직접 소유 private 코드/helpers와 다른 함수의 일반 native 본문을 편집하며 `amount → receivedAmount`를 명시 선택하고, 실제 공유 Blueprint 호출자의 원래 바인딩을 같은 pin으로 보존해 원래40과 직접 편집한20을 실행하는 한 흐름이다. private 함수·프레임·노드의 공개/native ABI, nativeAmount/nativeCount, 인자 타입·역할·수·순서와 반환·출력/연결/정확한64비트 local·배치·독립 원문을 보존한다. 호출자 import의 위치형 `(long, long)` 표기도 원문 그대로다. 호출 노드의 해당 입력 이름과 서명만 원래 pin 대응에 따라 갱신한다.

기존 단독 계획과 전체 assembled C# 검증을 먼저 통과해야 한다. 이 공동 분기는 기존 private/whole 행의 공개 계약을 그대로 요구하고, 일반 native 행에 한 개의 기존 값 입력을 새 공개 이름으로 바꾸는 명시 대응만 허용한다. 기존 이름과의 교환, 타입/역할/핀 수/반환 변경·wrapper·copy/상속·새 import나 외부 쓰기는 별도 계획 없이 받지 않는다. 사용자가 작성하지 않은 C#·helpers·binding·형변환을 만들지 않는다. 현재 네이티브 이름을 새 공개 이름으로 정규화하지 않는다.

기존 version3 `nativeBodyContexts`와 전체 읽기 관측을 사용하며 새 schema·receipt 필드를 추가하지 않는다. 후속 설명/본문 저장과 cold 재검증은 원래 before/after·pin 대응·function/source/flow hash로 각 단독 후보를 재생한다. 저장 뒤에는 현재 pin identity로 명시 본문을 다시 편집하되, 캡처한 최초 이름 대응과 원래 원본 기준은 유지한다. 한 scope가 그대로 관측한 공유 source는 다른 scope의 검증된 명시 변경과 결합할 수 있고, 서로 다른 두 변경 결과는 거절한다. 최종 모든 원본/읽기 CAS가 권위다.

취소·Undo/Redo·실패/재시도·응답 유실·독립 창·프로젝트 경계·늦은 입력·후속 Save와 Review 취소/Confirm, private graph/node/독립 원문·공유 caller·바뀐 함수 원본 경합을 검증한다. LF/CRLF restore/build·새 package와 전체 ZIP 복원, 기존 계약 불변 private/retained·등록 helper 및 native import 회귀를 구분한다. 이 한 흐름을 마치면 가능한 타입/문맥 조합으로 새 매트릭스를 늘리지 않는다.

직전 온전한 패키지의 단독 계획·원래 실행과 공동 거절을 새로 재현한다. 새 pending 계획의 구 reader 수용 여부도 같은 추출본에서 실제 측정한다. 이전 바이너리를 고치거나 데이터·Reference를 낮은 타입으로 바꿔 호환된다고 표시하지 않는다. 구 Reference parser 제약·일반적인 migration/downgrade는 별도 잔여이며, 새/구 reader 전체 UI 교환을 완료로 세지 않는다. 실제 Windows/WebView2·물리 기기·IME/GPU/audio·전체 UI는 미검증이고 과거 초기 빈 화면 원인은 미확정이다. 원본·latest/rollback·증거와 기존 정리 범위를 보존하며 main은 사용자 검토/merge에 남긴다.
