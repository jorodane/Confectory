# v536 입력 이름·출력 정의 결합 — 2026-10-26

정보 창의 기존 함수 상세창에서 값 입력 이름과 출력 추가·삭제·void 반환 전환을
편집한 뒤 창의 임시 저장을 한 번 누르는 동작을 연결한다. 기존 단일 함수 후보는
유효하지만 여러 함수의 그룹만 거절하던 경계를 수정 전에 재현했다.

## 지원 범위와 보존

직접 소유한 일반 Blueprint 함수 2~8개, 기존 code/export leaf와 call/export
직렬 caller 및 이미 지원한 고정 로컬 import 경계다. 입력 이름 전용 함수와 출력
정의를 바꾼 함수를 함께 저장하거나 같은 함수 안에서 두 종류를 결합한다. 기존
scalar out/비void 반환 타입 변경도 원래 writer 계획으로 함께 검증한다.

값 입력의 타입·수·역할·상대 순서는 유지하며 명시한 원래 이름→새 이름만
사용한다. 각 caller의 새 입력 이름은 원래 바인딩을 가리켜야 하며 새 값 선택이나
해제를 추가로 허용하지 않는다. 이름 전용 행은 기존 before/args 두 항목만
사용하고 모든 출력과 연결을 그대로 둔다.

출력 정의 편집은 모든 원래 writer/exit 삭제, 새 배치의 값·삽입 위치·다음 경로,
호환 소비 대응을 기존 outputGraphs로 명시한다. 유지 출력의 이름/역할/상대
순서를 보존한다. 새 출력은 자동 공개하지 않는다. C# 매개변수·본문, 정확한
64비트 값, 함수/구현/기존 노드 ID와 설명은 바꾸지 않는다.

모든 단일 closure를 원래 스냅샷에서 먼저 검증하고 내부 overlay에서만 합친다.
사용자 원래 hash·물리 파일 관측·단일 후보/CAS·receipt·Review/Confirm은
그대로다. 실패나 경합에서 앞선 함수/선언/caller를 부분 저장하지 않는다.
새 UI·레이아웃·권한·계약 ID·기본값 추정·C# 자동 재작성은 추가하지 않는다.

## 실제 fixture와 검증 경계

원래 두 함수는 `(long amount,double real,out long count,out long stable)`이며
공유 caller의 A.count→B.amount, B.count→caller 반환이 연결된다. count에는
실제로 두 writer가 있다. amount를 leftAmount/rightAmount로 명시 변경하고
count의 전체 배치를 삭제한 뒤 fresh를 생성한다. fresh의 값은 23과 정확한
9223372036854775806이며 기존 long 소비를 명시한 호환 출력에 연결한다.

이름 전용 A+출력 정의 B, 같은 함수의 이름+출력 정의, 양방향 void 전환과
유지 출력/반환 scalar 타입 편집을 구별한다. 순수 후보는 편집 역순의 동일 결과,
원래 hash, 모든 원문과 연결, 누락/잘못된 이름·값·writer·출력 소비·삽입 경로의
전체 거절과 실제 물리 파일 경합을 확인한다.

초기 cross 검사의 기대값은 변하지 않은 A.count 연결을 stable로 잘못 가정했다.
실제 후보가 원래 count를 보존함을 확인하고 fixture 기대값을 바로잡았다. 제품
검사를 완화하지 않았으며 실패 로그와 ZIP도 보존한다.

## 승인된 공간 정리

이번 사용자 승인으로 기존 모듈 검사에 남은 패키지/런타임 9세트의 정확한
18개 하위 폴더만 정리했다. 전체 파일 집합·SHA-256, 보관 원본/SDK 존재,
소유권·링크 경계와 실행 중 엔진/검사 부재를 재확인했다. 실제 회수량은
2,009,817,088바이트이며 직후 여유는 2,097,717,248바이트다. 각 상위 폴더의
로그/프로필/스크린샷/fixture, 보관 패키지·엔진 캐시·과거 출력·원본·Git·사용자
자료는 유지했다. 이 승인을 다른 기존 파일의 정리로 확대하지 않았다.

새 검사 증거는 이번 실행이 만든 임시 fixture만 ZIP/manifest의 파일 집합·권한·
전체 바이트/SHA-256과 대조한 뒤 해당 소유 복사본을 정리한다. 이전 증거는
변환하거나 삭제하지 않는다. 환경 복구 때 초기화된 /tmp의 옛 runtime fixture를
재사용했다고 주장하지 않으며 패키지 검사는 새 SDK 없는 소유 복사본으로 확인한다.

## 정확한 잔여

8행 전체 완료는 아니다. 입력 정의와 출력 타입/정의/반환의 결합, 입력 타입과
출력 정의/반환의 결합, ref·역할·매개변수 순서, 수동 C#/혼합 native·중첩/private/
whole/postCall, 같은 원래 계약의 copy/상속/등록/소유 정보 속성 혼합과 scalar
밖 함수 타입은 별도다. 이미 지원한 입력 이름/출력 타입 및 이번 입력 이름/출력
정의·void 전환을 다시 미완료로 분류하지 않는다.

7행 오버라이드는 원래 매개변수·출력 계약을 유지하며 위반 거절은 정상 보호다.

편집은 유지한다. 9행 정보/참조/외부 함수 타입과 표시명/native 식별자 분리는
별도다. 전체 v536 UI, 실제 Windows/WebView2·모바일 기기 실행 및 Library 전달
완료를 의미하지 않는다. 사용자 프로젝트·실제 계정·유료 추론은 사용하지 않는다.
