# Private 본문·반환 변경과 기존 소유 helper import

고정 v666 [정보7/8행](V536_I5_6_REMAINING.md)의 한 정보 창·한 Save에서, 기존 private C# 본문/helpers 편집과 다른 소유 native 함수의 명시 scalar 반환 변경을 원래 helper import와 함께 저장한다. [원래 별칭 보존](V666_PRIVATE_RETURN_ALIAS.md)과 [private 반환 공동 저장](V666_PRIVATE_SCALAR_RETURN.md)의 기존 UI·명시 계획을 재사용한다.

기존 패키지는 두 단독 계획과 원래 실행40을 수용하지만 원래 소유 helper import가 있는 공동 후보·실제 UI Save를 거절했다. 이 단위는 private 공개/프레임/code ABI와 모든 native 입력/out·별칭을 유지한다. 사용자는 C# 본문과 이전 반환 소비자의 호환 out 대응을 직접 작성한다. 실제 변경 뒤 caller20·double 반환25.5·long out25와 같은 helper 호출을 확인한다.

허용하는 import는 원래 직접 소유 단일 C# target의 기존 typed import이며, 이미 읽은 같은 프로젝트 함수의 정확한 계약과 일치해야 한다. helper는 이번에 선택한 함수가 아니고 부모 계약이 없어야 한다. private/whole 구현 자체의 import, 함께 바뀌는 선택 callee, 외부/부모/알 수 없는 import는 기존 별도 명시 계획의 경계로 남긴다. 외부 경로·등록·권한·새 import 편집기를 만들지 않는다. 역할/타입 조합별 새 필수 매트릭스도 추가하지 않는다.

기존 단독 Contracts/assembled C# 검증과 version3 nativeBodyContexts·프로젝트 전체 readGuards를 재사용한다. helper 함수·구현·본문은 읽기 의존성이며 쓰기 그룹에 넣지 않는다. 원래 import 별칭·typed signature·서명 이외 header bytes, helper BOM/CRLF·inode·mode·mtime를 보존한다. 후속 Save·cold·Review/Confirm은 최초 계획·원본 읽기 버전과 최종 CAS를 유지한다. 새 schema/receipt/profile·자동 C# 변환은 없다.

유한 종료 기준은 이 한 후보의 순서 독립성, 원래 UI·취소/Undo·cold·저장 실패/재시도·응답 유실·늦은 입력·후속 Save·창/프로젝트 경계, helper 함수/구현/본문의 Review 이후 실제 원본 경합 거절과 복원 후 새 Confirm/실행이다. LF/CRLF, 새 package·전체 ZIP 복원과 기존 private/반환/역할·struct·whole/retained·등록 helper 회귀를 구분한다. 구 pending guard와 Confirm된 일반 source의 이전 CLI 실행도 별도로 측정한다.

정보별 C# struct·종류 enum·모듈 interface, 명시 async 전환 전 sync caller 오류 정책과 기존 예산·소유권·권한·authored layout을 유지한다. 다른 역할/반환 구조·선택 callee/import 결합·private ABI·외부 관측은 잔여다. 구 Reference reader 일반 호환성·자동 migration/downgrade를 주장하지 않는다. 실제 Windows/WebView2·물리 기기·IME/GPU/audio·전체 UI는 별도이며 초기 빈 화면 원인은 미확정이다. 원본·latest/rollback·증거·main을 보호한다.
