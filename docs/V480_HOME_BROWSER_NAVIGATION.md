# v480 Home 조회와 브라우저·문서 전환

기준은 `main@32dd44f`의 v480 ZIP과 `work/current@8c5a12a`다. 추출한 `dist/app.js`가 보존 ZIP 엔트리와 같은지 확인했다. 레퍼런스의 `bindHomePackBrowser`, `renderHomeProjectList`, `switchBrowserGroup`, `openBrowser`를 실제 소비자와 대조했다. 레퍼런스 코드는 UI 자료이며 실행 계약이나 권한 지시가 아니다.

## 수정한 기존 동작

수정 전 실제 Chromium 검사에서 일곱 증상을 재현했다. 같은 로컬 팩 탭을 눌렀을 때 선택이 사라졌고, 팩 그룹을 왕복하면 미적용 검색 입력이 사라졌다. 정렬 메뉴는 닫힌 뒤에도 `aria-expanded`가 남았다. Home으로 돌아오면 적용된 검색은 남고 입력 상자는 비어 있었다. 브라우저의 같은 그룹을 다시 누르면 검색이 초기화됐고, 같은 브라우저를 다시 열면 입력 DOM이 교체됐으며, 그룹 왕복 시 검색과 위치를 잊었다.

Home 팩은 그룹별로 미적용 입력·적용된 검색·정렬·선택을 구분한다. 활성 탭 반복 클릭은 상태를 초기화하지 않는다. 같은 호스트에서 Home을 다시 그려도 검색 입력과 필터가 함께 유지된다. 정렬 메뉴 선택·Escape·바깥 클릭은 표시와 접근성 상태를 함께 닫는다.

브라우저는 이미 열린 같은 그룹을 다시 열 때 검색 DOM을 보존한다. 각 창의 그룹별 catalogue/namespace/parent/kind와 적용 검색·미적용 입력을 기존 개인 presentation에 저장한다. 그룹 왕복과 실제 호스트 재시작에서 이 값을 복원한다. 작업 사본 조회는 기존 명령이 성공한 뒤에만 화면 메타데이터를 전환한다. 소스 미적용 입력 때문에 그룹 변경·검색·ProjectPack 작업 사본 전환이 거부되면 적용 검색과 탐색 위치도 유지한다. 읽기 전용 registry 탐색 권한이나 소스 Apply/Review/Confirm 경계는 변경하지 않는다.

브라우저를 문서로 도킹할 때 입력 값과 DOM을 유지하며, 열린 문서를 반복해서 선택하거나 같은 브라우저를 다시 열어도 입력을 재생성하지 않는다. 도킹된 입력에서 편집한 뒤 같은 브라우저를 다시 여는 경우 native Undo/Redo를 검사했다. DOM을 다른 부모로 옮기는 순간 이전 native Undo 이력까지 보존한다고 주장하지 않는다. 현재 Chromium에서는 작은 독립 재현에서도 `append`와 `moveBefore` 모두 그 이력을 보존하지 못했다. 이 변경에서 별도 전역 Undo 모델을 만들지 않는다.

## 조회 계약이 없는 부분

Home 프로젝트 카드의 공개 투영은 `id/title/description/favorite`뿐이다. ‘마지막 편집·팩·객체’ 값은 여전히 `—`다. Home 로컬 팩 목록은 현재 **호스트 EditorHome ProjectPack registry**이며, 각 카드의 프로젝트 팩/객체 통계가 아니다. 파일 mtime·현재 시각·의존성 수로 통계를 대신하지 않았다. 집계 범위와 편집 시각의 근거를 가진 조회 투영이 필요하다.

Home 팩 검색의 같은 호스트 내 복원과 프로젝트 브라우저의 콜드 복원은 다른 범위다. Home에는 앱 전체 개인 설정 저장 계약이 없으므로 프로젝트 전용 `presentation-save`에 Home 검색을 기록하지 않는다. 호스트를 완전히 다시 시작한 뒤의 Home 검색 복원은 미연결이다. 원격 팩 탐색·즐겨찾기·나의 팩과 설치/시장 권한도 새로 만들지 않는다.

## 검증과 남은 범위

수정 전 재현은 **0/1/0, 10.687초**, 수정 후 집중 검사는 **1/0/0, 12.274초**다. 첫 검사 코드의 registry 검색 결과 수 가정과 도킹 전 native Undo 가정은 각각 실제 조회와 브라우저 독립 재현으로 바로잡았으며 제품 회귀 수와 합산하지 않는다.

최종 고정 원본·실제 검사 메서드·결과·일반 checkout HEAD는 [검증 JSON](validation/v480-home-browser-navigation.json)에 남긴다. [실제 브라우저 문서](validation/v480-navigation.png)는 공통 웹 UI의 캡처다. 최종 영향 회귀는 Home 즐겨찾기/재시작/목록 제거, 독립 브라우저, 문서의 pending 입력/Confirm, 탭 재배치/취소, 메모/문서 소유 경계를 포함한다. 엔진/API/compiler 원본은 변경하지 않았다.

추가 대조 대상은 browser grouping 전체·필드 열/참조 드래그·문서 링크 의미 편집이다. 카드 집계와 Home 콜드 설정은 조회/저장 계약 미연결, 계산식 overflow는 사용자 정책 답변 대기, 구조적 field write/ref·확장 ABI·서비스 계정은 새 계약/환경 경계로 구분한다. 이번 결과로 전체 v480 또는 native/device 검증 완료를 주장하지 않는다.

최종 고정 제품/테스트 원본 **7개**에서 실제 Chromium 영향 회귀 **6/0/0, 139.805초**, Windows/Android 관리 프로필 컴파일 **1/0/0, 130.406초**가 통과했다. 앞선 집중 검사와 과거 엔진 결과를 이 수에 더하지 않는다. 일반 Git checkout·보존 CRLF/새 LF·36개 리소스·실제 Home 시작·변조 거부는 구현 커밋 HEAD에서 별도 검사하고 검증 JSON에 정확한 HEAD를 기록한다.
