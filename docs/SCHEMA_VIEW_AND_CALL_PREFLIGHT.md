# Schema View model and function preflight without layout changes

Continuation of direct `.celem` milestone 522aa6c. The user authorized remaining internal pack work while retaining the actual EditorHome layout and forbidding arbitrary runtime invocation authority. This increment prepares reusable data/field and function input models and explicit path editing; it creates no new screen or function executor.

## Existing boundary established before implementation

Core already supports schema fields, object data, inheritance, primitive and qualified references, independent function signatures, exact implementation associations and target-specific/common bodies. SchemaEditing::Call exposes parser/formatter/effective metadata; PackWorkspace provides owned drafts, source revision checks and pinned Review/Confirm. Existing ElementView borrows the EditWorkspace model for independent cards/tables; it does not own object semantics. Its current Labels/Layout/Input are scalar/preset source projections, not a typed schema property inspector.

`packs/project-execution/Capabilities.csbody` explicitly advertises `runtime-call:unavailable` and `runtime-inspection:unavailable`. Launch executes an explicitly chosen ProjectPack entry, not arbitrary schema function values with typed arguments. The extracted design baseline section6 specifies schema/general/compound/function distinctions and independent call/return contracts, but leaves generic/async/error/cancel/permission/side-effect expression unsettled. Representation approval therefore does not authorize inventing an invocation provider or using reflection to run arbitrary implementations.

## Completed public pack contracts

The existing Confectory.SchemaEditing pack now owns four common-body functions, each with a replaceable function-declared default provider:

| Public element ID | Signature | Behavior |
|---|---|---|
| Confectory.SchemaEditing::DescribeInputs | `(string signature) -> string` | Describes ordered parameter names/index/type/cardinality/input kind and return type/cardinality. No default values or UI geometry. |
| Confectory.SchemaEditing::ValidateArguments | `(string signature,string arguments) -> string` | Validates explicit positional JSON arguments against those types, counts, numeric ranges and finite values; rejects null/coercion/nested incompatible arrays. |
| Confectory.SchemaEditing::DescribeView | `(string metadata) -> string` | Projects deterministic qualified field/path rows, current data, presence/invalid/unset state, origins, schema validation, nested groups/lists and function input metadata. No table model, file/compile work or subscriptions. |
| Confectory.SchemaEditing::CheckCall | `(string view,string path,string arguments,string target) -> string` | Checks one declared function field/list item, validated source/association, explicitly registered target, target-specific/common body and arguments. Always `executionAuthorized:false`. |

Function validation returns status/code/message and input/return descriptions; valid arguments are echoed without replacing false/0/empty values. Arrays use the existing public function contract grammar, not a new generic type system. Parameters are bounded to64, signature to64KiB, argument data to1MiB. Schema projection is bounded to512 rows/64 nested levels and rejects an oversized model explicitly.

Rows have stable IDs from qualified source ID plus typed path while that path remains present. Inline repeated items use array indexes, without inventing independent item identity across a reorder. A caller scopes row/control identity to its own project context/View. No instance state is kept in the projection pack; card, property or future table Views can consume the same model while retaining existing Owner/subscription/control lifetimes. Schema rows are separate from their objects' source data and from rendering geometry.

`pathWritable`/`requiresExplicitParentOverride` describe whether a nested data path has an explicitly declared current parent. Inherited compound data remains inherited until an explicit whole-parent override; this increment does not silently materialize or merge it. Reference rows expose identity/type and whole-source diagnostics; they do not recursively traverse/edit referenced objects.

## Actual product commands and editing

Actual `Confectory.EditorHome.Model::Command(session,"workspace",payload)` routes through the same PackWorkspace and selected owned unit:

- `schema-view`: returns `workspace.schemaView`, `effective.schemaModel`, selected revision and all contributing owned draft revisions/manifest revision. No source edit or Review mutation when no separate `text` edit is requested.
- `data-path`: `{id,path:[field,index-or-field,...],value,expectedRevision}` replaces exactly the requested present compound/list location. A one-step path explicitly sets a whole field. Parent data must already be explicitly declared, existing list index must be in bounds; no implicit parents, append/removal/default/null policy is invented.
- `call-check`: `{id,path:[...],arguments:[...],target,expectedRevision}` returns `workspace.callCheck` plus a fresh current schema View. Exact source ID/context/revision guards reject stale or different selected units. Wrong source is rejected before any optional raw-text edit. Read-only validation failures preserve the current Review token and drafts.

The existing optional `text` property still requests a separate raw source edit before an action. Typed controls should send only typed payloads; flush pending raw source deliberately as a separate edit and refresh its revision before checking/committing typed intent. A successful path edit uses the same SetTextIfRevision and invalidates Review, then Save/Review/grouped Confirm use their established exact-scope contracts. A failed path/format edit preserves the reviewed source.

SchemaEditing::Call's `effective` request enables the additional descriptor with `schemaView:true`. Only that mode resolves nested compound definitions, function signatures and implementation association declarations through public Registry APIs; body bytes are not read, Bind/Plan/Build are not invoked. Existing effective-only requests preserve their narrower reads. The descriptor records current source validation rather than authorizing execution. Implementations are checked for declared contract identity/signature and target metadata; a body declaration is not proof of successful compilation or a running instance.
