# v536 부모 있는 직접 소유 기능의 헤더 glyph

기준은 `54e9193`과 저장소 `196c605`의 v536 ZIP이다. 원본의 공통 헤더
`editObjectIcon → editIconValue`는 선택한 요소의 표시만 바꾸며 부모 유무로 막지 않는다.
기존 화면도 부모 있는 기능의 헤더 버튼을 표시하지만 UI 가드와 표시 후보의 일괄
부모 거절이 연결을 막고 있었다. 이번 최소 흐름은 **Browser 기능 탭 → 기존 부모
펼치기 → 직접 소유 자식 기능 F2 → 헤더 기호/이모지·설명 → Save → cold →
Review 취소 → 새 명시적 Confirm**이다. 새 메뉴·레이아웃·핀 노출은 추가하지 않는다.

## 저장 경계

기존 `functionPresentation`의 정확한 glyph/description 1~2개 변경만 사용한다.
선택한 프로젝트의 등록된 직접 소유 함수만 갱신하며, 부모 참조가 있다는 이유로
표시 편집을 일괄 거절하던 조건만 제거했다. 기존 metadata 검증은 부모의 kind·해결·
관측 문맥을 확인한다. `MergeFunction`은 같은 ID/kind/parent를 요구하고 기존
signature·provide·import·구현·C#·다른 value·주석을 보존한다. 부모나 외부 원본은
수정 대상이 아니다. 공개 오버라이드의 입출력 계약 변경이나 독립 계약 복제는 허용하지 않는다.

owner 입력·불확실 요청 결과 조회·한 후보/최종 CAS·원자 checkpoint·Review/Confirm은
기존 경로 그대로다. 선택 함수 원본이 바뀌거나 후보 검증 뒤 부모의 물리 원본이 바뀌면 전체 후보를 거절하고
입력·원래 기준을 cold까지 보존한다. 저장 중 새 설명은 정확한 수락 결과를 조회한 뒤
별도 입력으로 유지하며 다음 명시적 Save로만 저장한다. 부모를 바꾸거나 raw source·
slot/copy·계약 편집을 이 표시 후보에 넣는 것은 계속 거절한다. 실행/Helper 권한도 늘리지 않는다.

## 실제 격리 검사

fixture는 기존 typed caller와 구현·다른 target을 포함한다. 부모는 별도 glyph/설명을
가지며 자식은 로컬 glyph와 정확한 `9223372036854775805`를 가진다. 소스/등록/부모·
구현/참조는 Confirm 전까지 byte 그대로이고, Confirm 후에도 자식 표시·설명 한 파일만
달라야 한다. 원래 팝오버 10영역의 치수·위치·글꼴·패딩·배경을 대조한다.

정상·checkpoint 쓰기 실패·적용 응답 유실·선택 함수 충돌·부모 원본 충돌·명시적 변경
취소·늦은 입력·다른 함수 전환과 Undo를 분리한다. 각 흐름은 Undo/Redo·팝오버 취소·
부적합 glyph·재시작·원본 보존을 확인하며 성공 경로는 Review 취소와 compiler Confirm까지
검증한다. 새 native 후보는 부모/공개 계약 변경·불명확한 identity·외부 namespace·마지막
잘못된 입력을 거절해야 한다. 기존 부모 없는 기능과 contained 함수 카드·final CAS는
영향 회귀로 유지한다. 사용자 프로젝트·AI 호출·개인 이미지·외부 자료 업로드는 하지 않는다.

부모 경합의 최초 검사는 후보 조회 전의 무관한 부모 주석 변경을 실제 후보 충돌로 간주했다. 기존 저장은 시작 시 현재 관측 문맥을 읽으므로 이를 정상 조회했다. 검사를 약화하거나 새 부모 고정 정책을 만들지 않고, 후보가 작성된 뒤 최종 CAS 직전에 변경을 주입해 전체 미적용·cold 입력 보존을 확인한다.

첫 화면 검사는 자식 기능을 Root 목록에서 찾으려다 실패했다. 원래 hierarchy가 자식을
부모 아래에 두는 정상 동작이므로 기존 `바리에이션으로 이동`과 breadcrumb를 통해
접근하도록 검사 경로를 고쳤다. 실패의 로그·fixture를 보존하며 제품 통과로 계산하지 않는다.

## 공간·수용 제한

사용자가 승인한 정확한 두 `Windows-x64` 검사 복사본만 보관 원본/전체 파일 SHA·
링크 경계·관련 소비 프로세스 부재를 다시 확인하고 정리했다. 나머지 원본/보관 빌드·
상위 폴더·로그·프로필·Git·사용자 데이터는 보존했다. 실제 여유 증가와 전체 증거는
`scratch/v536-approved-cleanup-remaining-2/result.json`에 있다. 다음 작업 예산은 기존
200MiB+안전64MiB 그대로이며 낮추지 않았다. 후속 기존 자료 삭제 승인은 없다.

이번 단계는 부모 참조를 유지하는 선택 자식의 로컬 표시 편집만 마감한다. 자체 중첩
정의·원본의 실제 노출되는 다른 핀/요소/동작 카드·로컬 PNG/JPG/WebP 프로젝트 자산은
기존 I6 잔여다. 원래 CSS가 숨긴 루트·모바일 입력 아이콘은 새 필수 기능이 아니다.
forwarded 부모/opaque/import 영향 결합·8/9행·B2·M4/M11/M12와 전체 UI는 별도 잔여다.
실제 Windows apphost/WebView2·모바일 기기·Library 전달은 미완료다. 새 RAM 교차 패키지는
검증 증거를 보관한 뒤 이번 임시 사본만 수명관리로 정리하며 전달 성공으로 표현하지 않는다.

집중 8흐름 41확인, 순수 상속 기능 후보 3확인, 기존 부모 없는 native/화면·contained 함수·생산 final CAS 영향 회귀 24확인이 통과했다. 원본 팝오버 10영역과 75개 리소스 바이트/SHA가 일치한다. CSS·공통 팝오버·루트 핀 코드·기존 F2 선택 가드는 변경하지 않았다.
