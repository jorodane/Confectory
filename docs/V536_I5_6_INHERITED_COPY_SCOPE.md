# 고정 7행: 직접 상속 C# 구현의 소유 복사 편집

`V536_I5_6_REMAINING.md` 7행의 기존 명시적 복사 진입을 정보 자체 함수에 연결한다. 이번 검증 범위는 **직접 소유한 정보 함수·같은 공개 ABI·상속 C# 본문의 선택한 실행 대상**이다. 부모를 직접 수정하는 기능이나 새 편집 화면을 추가하지 않는다.

| 사용자 조작 | 연결한 경로 | 보존/제한 |
|---|---|---|
| 정보 자체 함수의 상속 구현에서 편집 누르기 | 실제 provider의 `parent`/`bodyOrigins`를 읽고 기존 구현 선택창으로 이동한다. 기본/독립 정보 창에서 같은 복사 편집기를 사용한다 | 선택한 자식 구현 ID와 실제 본문 부모 ID를 구분한다. 원본·부모·기존 호출자·함수 선언을 바꾸지 않는다 |
| 실행 대상을 명시하고 C# 본문을 복사해 편집 | 기존 immutable private snapshot에 자식/부모 header·본문 관측을 결부하고 새 소유 ID에 편집을 보관한다 | 원본의 C# 매개변수·CRLF 본문·정확한 수치·출처를 유지한다. 복사본의 사용자 편집만 저장한다 |
| 임시 저장·취소·실패·재시작·Review/Confirm | 기존 슬롯 후보/CAS·저장 journal·완료 조회·복구 가능한 초안·compiler Review/명시 Confirm을 재사용한다 | 잘못된 선택/현재 부모 변경은 전체 미적용이다. 응답 유실 후 정확한 완료 조회로 확인한 결과만 복구하며 재생성하지 않는다 |
| 저장한 복사본 본문 다시 편집 | 같은 공개 ABI와 명시된 소유 copy 증거로 새 본문만 후보에 담는다. 미사용 상속 정의는 그대로 둔다 | 위조된 계획으로 부모 header/body를 바꿀 수 없다. 상속 정의의 공개 ABI 변경 검사는 완화하지 않는다 |
| 이전 엔진의 모듈 복사 초안 재개 | 기존 module requirements/범위 식별자를 유지하고, 직접 소유 정보 함수의 copy 요청에만 별도 fallback을 적용한다 | `SlotContext` 함수 소스와 기존 module requirements/범위 계산은 그대로다. 정보 UI에 모듈을 자동 배치하지 않는다. 상속/외부 함수의 소유권을 승격하지 않는다 |

직접 소유 판단은 서버의 현재 `ownFunctions`에서 origin·writable·선언 경로를 확인한다. 복사 전·후 후보가 모두 이 판단과 유효한 provider를 만족해야 한다. 표시를 숨기는 것으로 서버 검사를 대신하지 않는다.

## 고정된 잔여

- 상속 정의를 등록한 채 **공개 함수 계약도 동시에 변경**하는 전체 후보는 아직 연결하지 않았다. 지금은 ABI가 정확히 같은 본문 편집만 허용하고, 다른 변경은 원문과 입력을 보존하며 거절한다.
- 새 미확정 copy와 계약 동시 편집, 외부 함수 ID copy, 여러 target copy의 전체 함수 계약 편집 제한은 기존 7행에 남는다. 일반 직렬 Blueprint 부모의 정보 창 수용 검증도 이번 C# 단위의 완료로 처리하지 않는다. 기존 backend가 지원하지 않는 그래프 모양은 그대로 거절한다.
- 8행 여러 함수가 공유하는 caller와 9행 고급 타입·표시명/native ID 분리는 별도 후속이다. 새로운 사용자 설계 결정이 필요한 것으로 자동 분류하지 않는다.

전체 I5-6/v536 UI 복원 완료가 아니다. 원본 v536 HTML/CSS/레이아웃·권한·부모/외부 원본·사용자 데이터·main·Android를 보존한다. 실제 Windows/WebView2·모바일 기기·실제 계정/추론·사용자 프로젝트 실행·Library 전달은 미검증이다.
