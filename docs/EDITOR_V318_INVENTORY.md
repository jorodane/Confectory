# v318 actual local inventory and independent browsers

The ordinary EditorHome ProjectPack exposes the existing SemanticCatalog through `localInventory`, Model.Command and the normal pinned resource manifest. The v318 Home pack browser markup and stylesheet are reused; simulated marketplace rows and actions are not imported. Local means the current host ProjectPack's validated registry, not an installed-package database or user ownership claim. Home queries EditorHome's actual registry; project pack management queries the selected actual ProjectPack.

The service uses the ordinary Registry validator and confirmed manifest/declaration readers. It returns namespace, version, description, declaration count, direct dependency expectations, safe warning codes and confirmed declaration IDs/kinds. It bounds registry and declaration inventory and validates locator identities. Actual parent metadata is read for the selected owner's semantic declarations, without reading implementation bodies. Transport publishes a deliberate projection without paths, private handles, exception text or credentials. An unavailable catalogue is reported as unavailable.

Browser namespace prefixes are navigation derived from registered namespaces; they are not invented semantic categories. Actual owned parent declarations with children provide inheritance navigation. Category creation/reparenting is unsupported. Registered external pack declarations are read-only; selecting one displays its confirmed identity/kind and does not acquire an editor, stage a draft or change ownership. Existing actual owned declaration terminal editors, source Save/Review/Confirm and inbox remain unchanged. The inventory is a confirmed-file view, so staged declarations not yet registered can still be found in the ordinary working-copy browser.

Independent browser instances use the common Workspace window map and lifecycle. Each retains namespace/parent, namespace expansion, group, pending search input, applied search, sort and density in private presentation storage. Namespace traversal/search operates over the real bounded inventory; catalogue instances do not page or filter the primary domain workspace. The primary ProjectPack breadcrumb returns to the original working-copy filter; the catalogue does not hide the existing staged-declaration workflow. Creation is disabled in foreign namespaces and inheritance navigation where no consumer creation contract is connected. Existing primary source browser paging remains the original contract. Releasing or hiding presentation nodes does not release source drafts. Home listing and Workspace recovery contracts remain authoritative.

The project pack window also reuses the v318 pack-row layout. Its disabled checkboxes show actual root/direct-dependency declarations, without claiming build inclusion. Cold restoration re-queries the actual inventory. Catalogue navigation and search use the last explicit confirmed-file read; opening pack management or the Home pack tab refreshes that read. Local pack search and default/name/numeric-version sorting are connected. Direct dependencies and versions are real manifest values. Marketplace exploration, purchases, accounts, installation/update/removal, publication, pack favorites and a user-owned pack list have no connected policy; their UI reports that boundary rather than simulating success. Worker/AI/Yogi-specific cold recovery and Run viewport migration follow this increment. Real accounts/models, devices and user PC remain held; existing standalone WASM publish blocker is unchanged.
