# Private 본문·선택 callee 값→out 공동 저장

고정 v666 [정보7/8행](V536_I5_6_REMAINING.md)의 한 정보 창·한 Save에서 private C# 본문/helpers와 원래 호출하는 다른 직접 소유 함수의 값→out 전환·수동 C#을 결합하는 유한 단위다. [기존 값→out 계획](V666_PRIVATE_VALUE_OUT.md)을 [선택 callee 원본 결합](V666_PRIVATE_CALLEE_RETURN.md)에 연결한다.

callee의 기존 long 값 입력 count 하나만 out으로 명시 전환한다. long 타입·이름·순서·반환과 nativeAmount/nativeCount·private/frame/code ABI는 유지한다. private ordinary call의 원래 상수0과 공유 caller의 원래 count 입력을 각각 명시 해제하며 기존 반환 대응은 identity다. typed import와 call의 해당 역할·입력 해제 외 연결·별칭·locals·좌표·독립 원문은 보존한다. 사용자가 out 할당과 두 C# 본문/helpers를 직접 작성한다.

온전한 직전 package에서 원래 실행40과 두 단독 계획이 유효하고 공동 후보만 거절되는 경계를 먼저 측정한다. 실제 UI의 scoped caller가 있는 callee에서 매개변수 역할 입력이 읽기 전용으로 거절되고 원본/입력이 유지되는 경계도 기록한다. 종료 기준은 정·역순 동일 후보, 두 원래 caller의 정확한 입력 해제, 실제 실행15·직접 native 반환25/out5, 후속 Save/cold의 최초 source/flow/import·값→out 계획·물리 읽기 버전 보존이다.

기존 ValueOut·단독 Contracts/Graphs·assembled compiler가 각 원래 계획과 최종 후보를 검증한다. 해당 선택 callee 그룹은 같은 원래 snapshot에서 source closure를 검증하고 결합한다. unchanged 관측은 한 명시 변경과만 결합하며 서로 다른 변경은 거절한다. 현재 편집 receipt는 이미 재생 검증한 pending graph의 같은 노드와 일치해야 하고, 캡처한 최초 whole/source hash는 바꾸지 않는다.

UI는 기존 구현 선택기·C# 매개변수 영역을 사용한다. scoped caller가 있는 이 경로는 원래 값 입력 하나의 out 전환만 허용하고 ref·추가 역할·native 이름/타입 변경을 거절하며 입력을 보존한다. 첫 owner Save 전 코드 재진입은 같은 원본 hash/path·서명과 명시 out 계획에 한해 native 인자명·역할·원문을 유지한다. readonly 본문 draft에도 기존 parameters marker를 보관해 fresh 재진입을 검증한다. 범용 native 타입/역할 available과 권한은 바꾸지 않는다. out 할당·C#·바인딩·형변환·새 import·연결을 추론하지 않는다.

취소/Undo·실패/재시도·응답 유실·늦은 입력·독립 창/프로젝트·Review 취소/Confirm과 실제 경합을 검사한다.
