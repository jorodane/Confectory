## Send and permission boundaries

An explicit normal Send prepares the exact message and existing global Helper profile/completed history, then starts that exact prepared token. It does not open a redundant checklist for the fixed existing global Agent rights. There is no blanket persistent consent: the current Send supplies the per-request choices for the known content/usage and existing owned CLI execution/account/configuration/storage requirements. Agent ID, model, account fingerprint when present, Helper, conversation and empty project scope must still match. A stale/unavailable connection blocks dispatch. The generic Authorize and provider verification/tool restrictions were not weakened.

Unexpected permission IDs or extra common-memory content require the existing conditional consent modal; those choices are never selected automatically. Project scope in a global request or an unexpected Agent/model/account is rejected. Project file/tool scope continues through its separate explicit review path, with Draft Review/Confirm safeguards. No project files, project memory, native tools, external relay or plugin rights are added by normal global Send.

Per-Helper pending state prevents duplicate submits. A rejected `stale_revision` can refresh and re-prepare at most twice because the rejected action was not executed. The previous owned Agent must finish cleanup before preparation can continue. Actual model start is not automatically replayed: an uncertain acknowledgement is checked against the same request token. Error/cancel restores the submitted draft only if no newer edit replaced it. Streaming and provider errors use the existing message area; actual history-save failure is reported through the existing notification surface, not silently treated as saved.

## Data preservation and recovery

Draft edits are automatically saved after a short debounce and drained on normal native shutdown through the existing presentation-flush handshake. A failed flush keeps the native window open. Per-Helper buffers survive switches. The stored presentation version/six value fields remain unchanged; `draftRevision` is computed metadata. A draft update changes only `globalDraft`, uses a text-specific hash/CAS, and preserves independent profile edits. Same-text retry is idempotent after an uncertain save acknowledgement.

An actual draft conflict preserves the stored bytes and current input. The existing modal offers an explicit choice; X/Escape/backdrop defer without silently overwriting either value. [Conflict render](helper-chat-v508/draft-conflict.png) shows the exceptional state. Old conversations, settings and drafts are not deleted. History remains bounded by the existing backend limits and is read on scroll without extra paging controls. A journal CAS failure retains the original file and received output in the active owner, with a warning; it does not claim persistence succeeded.

Normal engine restart was tested after automatic draft acknowledgement, including independent drafts for two Helpers. Abrupt process/power loss before a write acknowledgement is not claimed to be lossless. Browser unload uses the pending-input guard; native Windows flush integration is cross-compiled but has not been executed here.

## Verification and practical limits

The production UI contract checks original frame geometry at 1440/600, Korean composition, duplicate submits, partial output, same-slot cancellation/newer input preservation, conditional additional rights/memory, unexpected project/Agent rejection, uncertain acknowledgement without replay, failure retry draft and typing during delayed saving. Its API is in memory; it is not a provider success test.

The real engine + controlled HTTP test checks five provider requests: normal response, HTTP failure, retry of the same message, cancellation and journal-CAS failure. It also checks two Helper switches, delayed autosave, both conflict choices, actual engine process restart and history restoration, with zero page errors or external requests. The test waits for the visible Send state before requesting a new turn; clicking a visible Stop control is cancellation, not another send. Backend tests retain explicit grant failures, global/project/private-memory isolation and draft CAS invariants. Agent-aware project/pinned cold-restart coverage retains explicit project consent, Worker identity/recovery and unchanged project source bytes. Nine representative Codex setup/connection cases use an owned fake CLI through the production Provider; actual OAuth or paid inference is never used.

Windows x64 apphost/WebView2 host are cross-published as `Builds/Windows-x64/Confectory.exe`. Keep the entire result folder; .NET Desktop Runtime 10 x64 and WebView2 Runtime are required and are not installed automatically. Package checks exercise current source composition, all 50 resource responses, unrelated-working-directory startup with a runtime-only .NET copy, profile preservation and tamper/missing-dependency rejection. Actual Windows double-click, native WebView2, user OAuth and live model success remain unverified. The original v508 reference, main, Android and user data are preserved.
