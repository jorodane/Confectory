# Agent common consent and project placement

Baseline `a10caf7c6aef6a319c08352e36a9bd360693a388`.

Codex common use is now accepted once in Agent settings with **동의하고 연결 완료**. Technical login/readiness alone does not register a new Agent or create consent. The existing modal explains the selected provider/account, global Helper messages/profile/history/selected memory, executable/configuration/storage use, possible charges and lack of a monetary cap. The original layout/styles remain; no checkbox list or separate contract screen was added. Agent settings owns **대화 사용 해제**. Helper settings no longer offers a duplicate common-use permission.

Owned global Helpers, including a newly created `fff` and a second Helper on the same Agent, send directly under that Agent receipt. They do not select/open a project or obtain project tools. Project creation's existing Helper roster explains its extra context/memory/draft-query/edit scope. Inside a project, the existing Helper **+** reuses that same original roster/form in placement mode; unrelated creation fields are read-only and **배치 적용** applies the selected roster. Cancel retains local input without changing access. Remove-all retains the project and Helpers but revokes its project receipts. No final Confirm, project execution or other-project access is granted.

The server checks an Agent receipt plus an exact project/Helper/manifest/namespace/category/tool-schema receipt for project chat. Placement uses a short-lived server-owned plan, pinned to context, roster, prior selection and bindings, and grants only after its explicit apply action. Pure tool schema description starts no workspace/provider/model. Actual query/draft execution still uses the original ownership and per-call tool guards. Global turn guards use the Agent receipt and carry an exact transient conversation with zero project tools. Revocation interrupts queued/future work, including when storage compare-and-swap fails; it does not recall already transmitted content.

A stable account/runtime/effective-policy fingerprint binds common use; readiness lease IDs and benign expiry do not expire consent. Unsupported evidence or an actual request-time identity/configuration mismatch blocks dispatch. A successfully observed material boundary change retires the prior scope. An unsupported failed check can retain an on-disk receipt that is unusable until matching valid evidence exists; do not equate failure diagnostics with an unconditional permanent revoke or an approved new account. Unknown rights/tool additions fail closed. Public legacy per-message acceptance/Helper revoke and internal authorize/placement actions are not public grant routes. Responses behavior is unchanged; no account identity contract was invented.

Existing users explicitly accept common use once in **Agent settings**. Existing global Helpers then chat directly. Existing projects apply the desired roster once through **Helper + → 배치 적용**; old combined receipts/readiness are preserved as history and never promoted into new permission. New projects apply the selected scope as part of their creation action. Missing common consent is checked before native project creation, preventing a migration failure from creating a project first. The technical account/install/login steps retain their separate necessary consent and checks.
