# Intro connection success enters Home

Baseline: `6954a80ce4ee21a241b34eaab9b81b5fd2b3d3a7`. A new verified connection made from the initial **AI Agent 연결** screen now automatically enters the main project list once. The existing startup connection check and **나중에** path remain. A registration row, completed installation or completed login alone is not treated as a usable connection.

The startup session observes the server's registered readiness. It requires `ready`, checked account metadata and the pinned identity, and rejects offline/unverified/progress/failure states. Currently Codex supplies that contract. Responses configuration alone has no verified-account/readiness contract and is not turned into an invented success; Later remains available. No paid inference or extra login is used to manufacture readiness.

Opening Agent settings from Intro carries a short-lived startup context. Only that context can complete the intro after its selected Agent becomes usable. Home/project settings do not carry it and stay open when ready. The existing cancellation/cleanup barrier completes before removing the connection form and starting the original animation. The parent rechecks current readiness and startup/view/project identity. Duplicate clicks/events share one attempt. Manual close/navigation invalidates the attempt even if successful cleanup is already pending, so a late ready reply cannot redirect the user. A later explicit reopen can complete normally. A separately reproduced Stop/ready race is also fixed: Stop synchronously cancels automatic navigation before its asynchronous cancellation reaches the backend. A later explicit retry restores the user’s intent to complete the intro.

Animation cleanup releases startup-owned `inert`, retains a newly opened modal's own `inert` and focus, and restores Home keyboard focus when the former startup target was removed. No CSS, original v508 layout, window size, backend authentication, registration, consent, scoped use grant, tool security, Android source or original reference archive was changed. The future move of Agent-common consent to explicit registration is separate and is not implemented here. This transition consumes registered readiness rather than raw OAuth/installation completion, so it can remain after that future registration boundary.
