# 여러 C# 본문 저장과 기존 호출자의 실행 분기

고정 [정보 편집8행](V536_I5_6_REMAINING.md)의 한 정보 창·한 Save를 잇는다.
저장소 v666 ZIP `7b6b4ba585fc46843f09d8bcd15072b704cc2dc994988400b0a25061e0400d23`의
`app.js::openOwnFunctionPopover`, `renderFeatureDefinition`과
`blueprint.js::blueprintDefinitionBranches`, `bindOwnedBranches`의 기존 사용자 흐름이다.
현재 runtime의 bool 분기·Result 실행 선택기는 이미 있는 계약이며 정보 종류의
EnumValue 데이터 타입이나 선택 대기 중인 고급 핀 CLR 표현과 구별한다.

게시 `8c27651e`에서 원래 분기 호출 프로그램은41을 반환하고 각 C# 본문 편집은
개별 후보로 유효하지만 두 본문의 공동 후보만 next-only caller 제한으로 거절된다.
같은 계약의 직접 소유 단일 native target 본문2–8개를 명시 편집할 때, 변경하지 않은
직접 소유 일반 Blueprint 호출자의 기존 code next/branch/switch를 보존한다.
일반 call/export는 기존 next 경계를 유지한다. 분기를 새로 만들거나 고르는 편집,
호출자 C# 자동 재작성·public/override 계약 변경·실행 의미 변환은 추가하지 않는다.

기존 그래프 전체의 typed 입력/출력·source-ready·definition hash·assemble 검증을
그대로 수행한다. 실행 분기의 ID·이름·정수값·primary·포트·종료점·연결, 호출자의
코드 원문·정확한 지역값은 읽기 의존성이다. 의미가 같은 코드 기록은 원래 바이트를
유지하며 쓰기 footprint에 넣지 않는다. 수정한 두 callee 본문만 새 source가 된다.
기존 version3 readGuards·cold header/graph 조회·240 source/경로·읽기 예산과
원자 checkpoint/CAS·Review→Confirm의 최종 source lease를 재사용한다.

기존대로 거절한다. 그 거절을 가능한 조합별 새 의무로 만들지 않고 기존7/8행의
실제 source closure 잔여와 한 번만 관리한다. M11/M12/M4를 다시 열지 않는다.
신규 metadata·receipt 문법·native ABI·권한·화면 컨트롤·배치는 바꾸지 않는다.
