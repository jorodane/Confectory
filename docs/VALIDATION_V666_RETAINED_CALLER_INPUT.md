# 공유 retained 호출자 입력 타입 공동 저장 검증

UI/UX 기준은 [v821](V821_UI_BASELINE.md)로 변경됐다. 이 문서는 기존 Blueprint UI에서 독립적으로 마무리한 계약 저장 검증이며 새 수직 셀의 구현·검증이 아니다. 기준 게시본 `8ea5f0254f37d02386225e9556e4f569e1dae989`와 영구 증거를 보존하고 runtime `ba352b4c8d91f17ff1a81ead2dbb13728e828d7a`를 신규 38·재사용 0·실패 0으로 검증했다. 독립 LF 17·CRLF 13, 새 패키지·전체 ZIP 복원 8건이다. 각 clone/checkout·restore·Release·MCP·Linux engine과 package/restore는 모두 새 실행이며 개발 검증은 이 수와 구분한다.

ordinary retained caller의 한 scalar 입력 타입 변경과 직접 소유 native callee의 입력 이름·수동 C# 본문을 같은 정보 창 Save에 결합했다. 원래42와 두 개별 후보가 유효한 상태에서 온전한 직전 패키지의 공동 후보 거절을 재현했다. caller amount는 long→string, callee amount는 rightAmount로 바꾸고 callee는 사용자가 뺄셈 본문을 작성했다. 바깥 caller에는 문자열을 직접 지정하고 옛 long 연결 해제를 명시했다. caller 내부의 옛 amount 사용처에는 long30을 직접 선택했다. 새 문자열은 숫자로 자동 해석하지 않는다. 결과22는 이 명시 대체값과 수동 본문의 결과다.

원본의 두 단일 closure를 먼저 증명한 후, 원본 hash를 가진 caller 타입/사용처/호출자 대체 계획부터 적용하고 callee 이름 변경을 내부 overlay에 이어 적용한다. 같은 원본 계획의 요청 순서를 바꿔도 후보 전체가 같다. 실제 사용자 선택이나 최초 before/hash를 바꿔 맞추지 않고 graph 문자열을 임의 필드 병합하지 않는다. 기존 단일/일반 그룹과 이전 이름 변경 그룹의 준비 순서는 유지한다. caller 입력 수·이름·값 역할·반환, callee nativeAmount/nativeCount 별칭·타입·역할·반환, retained C# source/record bytes·mtime와 exact64 local9223372036854775806·좌표·실행선·출력을 보존했다. 선택 밖 C#·원래 csbody와 owner 상속/읽기 전용 함수도 유지했다.

기존 Linux engine/Chromium의 460px 정보 창과 독립 창에서 타입 picker·문자열/기존 long 사용처 값·연결 해제를 직접 선택하고 callee 계약/본문을 편집했다. 상세창/본문 취소·재진입·Undo/Redo·미저장 cold, 한 Save·cold·Review 취소·새 Confirm 뒤22를 확인했다. 저장 실패는 전체 미적용·입력 보존 뒤 같은 입력의 재시도를 허용했다. 응답 유실은 cold 뒤 정산하고 applySlots를 재발행하지 않았다. 동일 namespace 프로젝트 전환과 stale 상세창 적용 차단, 신뢰된 실제 click 경합의 checkpoint/입력 보존도 통과했다. 늦은 설명은 지연된 Save 응답 뒤 보존되고 cold·두 번째 명시 Save·Review 취소·Confirm 뒤에도 남았다. 새 패키지와 전체 ZIP 복원에서도 정산·독립 창·늦은 입력/확정을 확인했다. 이번 실행의 실제 입력 대응 및 정보 창 화면을 직접 확인하고 `resumed-visual-review.json`의 두 이미지 SHA를 최종 evidence와 대조했다. 기존 개발 화면 확인 SHA는 `eb0c4680d588ba8b4701ea4aa76698cdfe98cf263cc29bcc28a9526510d3470e`이며 신규 검사 수와 구분한다. 모의 DOM/순수 metadata 검사와 실제 Linux 실행을 구분하며 Windows 기기 실행을 주장하지 않는다.
