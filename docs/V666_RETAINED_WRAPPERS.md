# 여러 본문 저장과 기존 호출 후처리

고정 [정보 편집8행](V536_I5_6_REMAINING.md)의 한 정보 창·한 Save에서 여러 직접 소유
함수의 같은 계약 C# 본문을 편집할 때, 이미 있는 serial After와 실행 enum wrapper를
보존한다. 기준은 저장소 v666 ZIP
`7b6b4ba585fc46843f09d8bcd15072b704cc2dc994988400b0a25061e0400d23`의
`app.js::renderFeatureDefinition`/`openOwnFunctionPopover`, `blueprint.js`의 기존
기능 호출/원본·After 편집과 [원래 후처리 계약](V536_I5_6_NESTED_SCOPE.md)이다.
새 wrapper 작성 의미·권한·레이아웃이나 닫힌 M11/M12/M4의 재구현은 추가하지 않는다.

게시 `c28851e9`에서 두 함수의 단일 본문 후보와 원래 wrapper 프로그램42는 유효하다.
기존 구현 선택창에서 실제 함수 본문을 각각 선택할 수 있지만 공동 후보/UI Save는
wrapper 제한으로 전체 거절된다. 같은 계약의 native 본문만 명시 편집한 뒤 기존
After·helpers·출력 공개와 native-return 매핑·원래 실행 enum/포트/연결을 보존한다.
검증 표본은 serial After 뒤 기존 enum wrapper를 호출한다. 원래42는 positive17,
편집 뒤29는 negative-3 경로를 사용한다. 반환 데이터22와 실행 값-3을 서로 바꾸지 않는다.

기존 직접 소유 native 그룹2–8함수와 모든 명시 target, ordinary/private caller의
같은 계약을 대상으로 한다. call next의 기존 serial After 또는 call switch의 기존
execution-enum만 수용한다. typed graph·원래 publication/wrapper 증거와 source-ready를
그대로 확인하고, wrapper가 있는 graph는 전체 조립 C#도 컴파일한다. 틀린 원문·증거·
매핑·분기·공개 출력·현재 계약은 전체 거절한다. 변경 없는 graph의 C#/helpers·계약
hash를 자동 갱신하거나 재직렬화해 새 쓰기 대상으로 넣지 않는다.

루트에 code/locals/private graph가 없고 호출 후처리만 있어도 이미 알고 있던 소유
원문을 기존 version3 readGuards에 결부한다. 후처리 graph와 공개 출력 선언을 포함해
Save/CAS·cold Review·최종 source lease를 유지한다. 후속 owner 설명 Save도 원래 그룹과
읽기 해시를 보존한다. 기존64-member Review·240 read/write·2048 known unit과 Tree
예산, 원자 checkpoint·Undo/취소·응답 유실 복구·Review→Confirm은 유지한다.

검증의 enum wrapper는 기존 native-data 완료의 `OriginalResult.NoBranch`를 명시한다.
그것을 공개 실행 분기 결과로 추측·변환하지 않는다. 다른 실제 public/native ABI
closure나 copy/whole/forwarding 원문은 기존7/8행의 같은 잔여로 관리하며 가능한 조합을
새 의무로 늘리지 않는다. 부모/외부 원본·override 계약과 새로운 접근 권한은 건드리지
않는다. 일반 입력/out 표시명 및 고급 정보·참조 핀 CLR 표현은9행의 별도 잔여다.
고급 핀의 공통 값/참조 타입 대 정보별 생성 타입은 사용자 답변 대기다.

독립 LF/CRLF·기존 중첩/여러 target·새 패키지/전체 복원과 보관 결과는
[신규43단계·재사용0의 마감 기록](VALIDATION_V666_RETAINED_WRAPPERS.md)을 따른다.
기존 단일 target/빈 guard 기록의 회귀와 모든 구 reader 교환을
혼동하지 않는다. 초기 빈 화면 원인은 미확정이고 Linux native/Chromium 격리 fixture와
실제 Windows/WebView2·모바일·물리 기기/전체 UI 검증은 구분한다.
