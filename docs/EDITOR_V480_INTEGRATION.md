## 기존 graph의 실제 기능 화면

소유된 기존 `sync-acyclic-v1` graph에 기능 탭, 시작·입력 영역, 실행 레일과 독립 노드, 출력 영역을 연결했다. 설명·인수·실행 경로·시작/반환 경로와 노드 C# 본문은 해당 공유 초안에 적용하며, 노드 Task는 별도 계획·승인 화면으로 이동한다. 위치·확대와 미적용 입력은 private presentation이다. 복원한 입력에는 적용 가능한 basis를 저장하지 않으며 현재 원본을 읽고 사용자가 기준을 다시 검토해야 적용할 수 있다.

원본 편집은 graph·구현·관련 계약·노드의 리비전과 해시를 함께 확인하는 기존 원자적 EditBatch를 사용한다. 현재 graph의 코드 노드 locator와 기존 소유 파일이 다르면 본문 편집·Task capability를 거부한다. 해당 경계는 실제 실패를 먼저 재현한 뒤 수정했고 기존 노드/일반 capability와 Node Task 소비자 **2/0/0, 48.581초**로 확인했다. 신규 화면의 실제 UI·compiler Confirm은 **1/0/0, 50.922초**, 기존 Blueprint/Task/Home/Workspace/이력/독립 선언창/소유 범위/관리 프로필 영향 회귀는 **18/0/0, 732.036초**로 통과했다. 관리 프로필은 컴파일 검사이며 장치·native 픽셀 실행 결과가 아니다. 마지막 문서 탭 유지·배치를 바꾸지 않는 실제 맞춤·별도 Task 창의 미적용 노드 입력 감지 검사는 **1/0/0, 55.449초**로 통과했다. 18개 영향 회귀 이후에는 새 Blueprint 표시 모듈과 그 고정 리소스 해시만 바꿨으며, 수정 전 회귀와 최종 UI를 합산하지 않는다. [단계별 증거](evidence/v480-integration/blueprint-editor.json), [실제 Home 화면](evidence/v480-integration/blueprint-editor.png). 구현 커밋 `0687bee42c4a64b3b70e83f014ef29819552c941`의 일반 Git 체크아웃·CRLF/LF·27개 정적 리소스·실제 Home 시작·변조 거부 검사는 **1/0/0, 74.714초**로 통과했다.

## 독립 노드 compiler 증거 보완

정의가 현재인 연결 전 본문이 빌드에서 무시되는 문제, 배정 후 정의가 바뀐 독립 노드의 완료 처리, 다른 타깃 본문 선택으로 배정된 노드의 컴파일을 건너뛰는 문제를 실제 실패로 재현했다. 현재 정의의 준비된 본문은 호출하지 않는 정적 함수로 컴파일한다. 미작성·오래된 독립 본문은 실행 빌드를 막지 않으며 검증 완료로 표시하지 않는다. 노드 Task 채택은 배정된 body target을 명시해 실제 독립 컴파일을 수행하고 기존 source Confirm과 사용자 목표 수용도 요구한다. 구현→graph→노드의 소유 관계와 엄격한 노드 원본 형식도 확인한다.

실제 독립 probe·기존 노드 도구·공개 채택 소비자는 **3/0/0, 64.851초**로 통과했다. 이후 locator 확인을 포함한 영향 회귀는 **13/1/0, 760.508초**였고, 유일한 실패는 여러 실제 compiler 호출을 포함하는 소비자의 기존 15초 실행 제한 초과다. 이 소비자에만 180초 제한을 적용했다. 이어 공개 완료 검증기가 불완전한 보존 노드 증거를 받아들이는 실제 실패도 재현해 수정했다. 필수 증거 누락·proof 불일치 거부, 실제 채택·cold/idempotent 재시도와 일반 작업의 다섯 지점 중단·복구 검사는 **2/0/0, 155.042초**로 통과했다. 이전 묶음과 합산하지 않으며 [각 실패·수정·통과 경계](evidence/v480-integration/independent-node-compiler.json)에 기록한다. 실행 profile과 CELEM ABI는 기존 `sync-acyclic-v1` 그대로다. 새 원본 생성·삭제, 기능 생성/전환과 확장 profile은 남은 범위다.

완료 검증기 수정 후 실제 로컬 Responses 노드 Task UI·v480 graph 편집 UI·Windows/Android 관리 프로필 컴파일은 **3/0/0, 211.270초**로 통과했다. 이 결과도 장치 실행·네이티브 픽셀 캡처 또는 v480 전체 구현 완료를 뜻하지 않는다.

독립 노드 compiler 보완 구현 `b6290c7`의 일반 Git 체크아웃·CRLF/LF·27개 정적 리소스·실제 Home 시작·변조 거부는 **1/0/0, 7.338초**로 통과했다. 최종 UI/관리 프로필 검사 이후 제품·테스트 소스는 바뀌지 않았다.

## 기존 graph 안의 코드 노드 생성·제거

현재 외부 계약을 유지하며 독립 노드의 ID·설명·입력 매개변수·반환 타입·다음/분기를 선택해 공유 초안에 추가한다. graph와 소유자가 할당한 별도 노드 원본을 원자적으로 만들고, 빈 본문은 구현·컴파일 완료로 표시하지 않는다. Save/복원은 최종 파일을 만들지 않는다. 새 본문과 변경된 graph를 함께 명시적으로 Review/Confirm해야 하며, 직접 Confirm을 호출해도 이 그룹을 건너뛸 수 없다. 생성 입력을 복원하면 현재 원본 읽기와 기준 재검토가 필요하다. 다른 창의 입력과 다른 작성자의 변경은 그대로 보호한다.

노드 제거는 현재 의도·본문과 보존 범위를 별도로 표시하고 새 확인을 받는다. 시작·실행선·값 참조가 있거나 기존 본문에 미확정 변경이 있으면 거부한다. 기존 본문 파일은 보존하며, 미게시 생성의 명시적 취소만 그 공유 본문 초안을 함께 제거한다. 제거된 원본의 구독과 View는 마지막 표시를 유지하고 종료 상태를 알린다. 같은 live 소유자의 재생성·복원·재발견은 이전 리비전을 재사용하지 않는다. 새 원본과 일반 편집 모두 변경 후 읽기의 64개 원본·2MiB 예산을 먼저 확인한다.

첫 영향 회귀는 **19/2/0, 844.123초**였다. 한 실패는 미완성 초안도 즉시 타입 검증해야 한다고 잘못 가정한 시험이고, 다른 하나는 옮긴 검토 오류 문구에서 마침표가 빠져 기존 Home의 고정 오류 코드가 달라진 실제 호환 문제였다. 초안 진단과 실제 compiler Confirm 거부를 검사하도록 시험을 고쳤고 기존 문구를 정확히 복원했다. 제거된 원본 구독의 예외도 실제로 재현해 보완했다. 최종 생성·구독·기존 EditWorkspace/ElementView 검사는 **3/0/0, 153.708초**, Home·신규 UI·Windows/Android 관리 프로필 검사는 **3/0/0, 446.536초**로 통과했다. 이후 65번째 원본을 추가하면 실제 읽기가 막히는 실패를 재현해 변경 전 예산 검사를 추가했다. 최종 공개 엔진 검사는 **1/0/0, 95.381초**이며 개수·바이트 한도의 무변경 거부, 직접 Confirm 그룹 검사, 연결한 새 노드의 실제 소유 fixture 결과 `25`와 제거 후 `5`, 실제 cold 복원과 본문 보존을 포함한다. 각 단계는 중복 검사이며 합산하지 않는다.

## 신규 기능 계약과 graph 등록

소유 ProjectPack에서 새 기능 선언을 만들고 기존 타입 편집기로 입력·반환 계약과 설명을 적용한 뒤, 현재 계약과 등록부를 읽어 미구현 Blueprint를 명시적으로 생성한다. 함수의 기존 표시 정보와 계약을 보존하며 해당 함수의 기본 제공 구현, 별도 구현 선언·graph·독립 본문 원본과 manifest 등록을 같은 공유 초안 트랜잭션에 연결한다. 첫 본문은 빈 상태와 미설정 정의 stamp다. 원본 C#을 복사하거나 0을 반환하는 구현으로 완료를 가장하지 않는다. 기존 게시 기능·상속 또는 이미 구현이 지정된 기능은 이 신규 생성 경로에서 전환하지 않는다. ProjectPack compiler 문맥이 없는 단독 팩은 변경 전에 거부한다.

새 함수·구현·graph·노드 원본·등록부는 함께 명시적으로 Review/Confirm해야 한다. 직접 Confirm도 이 그룹을 생략하지 못한다. 현재 계약·등록부의 리비전과 해시를 생성 및 본문 편집에서 확인하며, 등록부는 일반 EditBatch에서 변경 없이 관찰할 수만 있다. Save와 cold 복원은 최종 파일을 쓰지 않는다. 복원된 본문 입력은 현재 원본 읽기·기준 재검토 후 적용한다. 새 기능 노드 Task의 네 도구 권한은 그대로이며 등록 의존 원본은 사람의 명시적 검토 대상으로만 추가한다.

새 구현을 하위 폴더에 둔 실제 compiler 검사에서 편집기의 본문 경로와 compiler 경로가 달라 실패했다. 편집기 소유 원본 발견·재발견과 팩 구문 검사를 기존 compiler의 소유 pack manifest 기준에 맞췄다. graph 내부 노드 경로는 graph 기준이다. 기존 파일은 이동하거나 복사하지 않는다. 수정 뒤 공개 엔진·실제 Home UI는 **2/0/0, 73.901초**로 통과했다. 공개 엔진은 다섯 원본의 부분 검토/직접 Confirm 거부, 링크·외부 파일 출현·동시 등록 변경 보존, 실제 cold 복원, 미구현 compiler 거부와 새 함수의 기본 구현을 호출한 소유 fixture 결과 `11`을 확인했다. 실제 UI는 타입 계약·미구현 표시·복원 입력 재검토·다섯 원본의 명시적 compiler Confirm과 기존 원본 보존을 확인했다. [계약 확인](evidence/v480-integration/feature-contract.png), [실제 생성 기능](evidence/v480-integration/feature-creation.png). 단계별 실패·수정·검증은 [별도 증거](evidence/v480-integration/feature-registration.json)에 보존한다.

## 기존 기능의 참조 호출과 typed 가져오기

소유 ProjectPack의 게시된 기능을 검색·페이지 선택하고 실제 현재 입출력 계약·설명·호출 scope를 읽은 뒤, 새로 확인한 계약으로 참조 호출을 명시적으로 만든다. graph의 호출 노드와 구현 선언의 typed 가져오기는 같은 CAS 초안 배치다. 대상 함수·본문을 복사하거나 별도 노드 C# 파일을 만들지 않는다. 인수와 실행 경로는 기존 편집으로 연결한다. 호출 노드에서 기존 기능 원본으로 이동할 수 있으며 코드 노드용 본문 편집·Task 권한은 주지 않는다.

compiler와 편집기가 같은 결정적 별칭을 사용한다. 유효한 기본 import가 있으면 정확한 scope와 다른 기존 별칭을 보존한다. 기본 import가 없는데 같은 기능의 다른 별칭이 있거나 기본 별칭의 대상·타입이 다르면 자동 변경하지 않고 명시적인 검토를 요구한다. 복원은 입력만 보존하며 현재 계약 읽기와 새 확인이 필요하다. 사용자 확인과 조회·초안 적용은 실제 compiler 성공과 구분한다.

공개 엔진은 graph/import의 원자적 Undo/Redo·실제 cold 복원, 함수·구현의 같은 의미를 유지한 원본 변경도 거부하는 CAS, 복원 ID 불일치·중복·잘못된 분기·미게시 대상의 무변경 거부를 확인했다. 연결 전 실제 fixture 결과 `5`, 기존 Double을 연결한 `7`, 제거 후 `5`, 기존 명시적 scope의 구현을 사용한 `23`을 확인했다. 64개 원본에서 이미 관찰한 기능은 읽을 수 있으며 새 65번째 계약과 2MiB를 넘는 요청은 미리보기와 직접 소유 API 모두에서 부분 graph/import 적용 없이 거부한다. 해당 확대 검사는 **1/0/0, 104.750초**로 통과했다.

이후 영향 회귀는 Blueprint·PackWorkspace·EditWorkspace·이력 **17/0/0, 569.622초**, 기존 Home·노드 Task·이력·두 graph 화면·신규 기능 생성·Windows/Android 관리 프로필 **7/0/0, 543.738초**로 통과했다. 이 결과는 아래 마지막 별칭·표시 수정 전이며 관리 프로필은 컴파일 검사다. 초기 UI 실패 두 건은 뒤에 놓인 복원 창을 직접 누르거나 닫힌 창이 삭제된다고 가정한 테스트였다. 실제 도구 모음으로 열고 표시 상태를 검사하도록 고쳤다.

마지막 검토에서 유효한 기본 import 옆의 기존 별칭을 불필요하게 거부하는 문제와 복원 호출 창의 잘못된 제목을 실제 재현했다(**0/2/0, 91.717초**). 유효한 기본 import를 먼저 확인해 모든 다른 별칭을 보존하도록 고쳤고, 호출 창 제목과 계약 확인 체크박스 배치도 바로잡았다. 기존 별칭이 공존하는 scope의 실제 `23`, 앞선 전체 엔진 경계 및 현재 제목·체크박스 크기·cold 확인·그룹 compiler Confirm·원본 보존을 포함한 최종 공개 엔진/실제 Home UI는 **2/0/0, 149.590초**로 통과했다. 각 단계는 중복 검사이며 합산하지 않는다. [단계별 증거](evidence/v480-integration/call-wrapper.json), [현재 계약 확인](evidence/v480-integration/call-contract.png), [실제 참조 호출](evidence/v480-integration/call-wrapper.png).

UI는 변경된 graph와 import를 함께 검토한다. 실제 파일에 필수 import가 없으면 graph만의 Confirm은 compiler가 거부한다. 일반 원본 부분 선택 모두에 신규 파일 등록 그룹을 강제한다고 표시하지 않는다. 현재 범위는 소유 ProjectPack의 기존 기능이다. 임의 외부 registry 선택, 레거시 자동 전환, 별도 부모 재사용·모듈 화면과 새 실행 profile/ABI는 남은 범위다. main·원본 ZIP·Android 설정을 보존했으며 실제 계정·유료 모델·사용자 PC 설치·네이티브 픽셀/장치 실행은 수행하지 않았다.

참조 호출 구현 `e3921396c1eea7877d02b35fff1c928ff4d11b14`의 일반 Git 체크아웃·CRLF/LF·27개 정적 리소스·실제 Home 시작·변조 거부는 **1/0/0, 7.470초**로 통과했다. 최종 공개 엔진/UI 검사 뒤 제품·테스트 원본 18개의 해시는 유지했다.

## 모듈 요구 계약과 기본 구현

별도 모듈 인터페이스에서 요구 기능의 입력·반환 계약, 직접 기본 구현, 상속·포함 출처와 기본 후보를 볼 수 있다. 계약과 기본 구현은 기존 module 선언의 같은 공유 초안에 원자적으로 적용한다. 상속된 요구 계약에 기본 구현만 바꾸면 요구 계약을 복사하지 않는다. 직접 지정 제거는 부모·포함 모듈의 원본을 보존하고 기존 구성을 다시 드러낸다. 현재 기본 타입/배열·단일 반환 계약을 사용하며 모듈의 실행 graph나 C# 본문을 만들지 않는다.

현재 구성 읽기는 선언만 조회한다(`bodyReads: 0`, `providerSelection: not-performed`). 후보 표시는 소비 문맥에서 구현을 선택하거나 실행했다는 뜻이 아니다. 저장·복원한 private 입력에는 적용 기준을 보존하지 않는다. 현재 구성 읽기와 기준 재검토를 거친 뒤 소유 리비전·원본 해시를 확인해 적용하며, 최종 파일은 명시적인 Review/Confirm에서 실제 compiler가 검증한다.

## 배치된 노드에서 글자 찾기

`Ctrl+F`, Workspace 탐색 메뉴와 Blueprint 도구 모음에서 현재 배치된 노드의 글자를 찾는다. Workspace는 현재 하위 공간의 배치된 창·메모·그룹을, 활성 Blueprint는 시작·내부 노드·반환 영역을 대상으로 삼는다. 현재 표시된 글자와 입력값을 대소문자 구분 없이 읽고, Enter/Shift+Enter로 결과를 순환한다. 숨긴 창·숨김 요소·비밀번호 및 식별 가능한 secret 입력은 제외한다. 별도의 원본 파일이나 registry를 검색하지 않는다.

검색 결과로 이동할 때 Workspace의 private 카메라나 Blueprint의 스크롤만 바뀐다. 이미 읽은 graph를 다시 읽으면 새 DOM에서 결과를 갱신한다. graph 교체·창 닫기·Workspace/프로젝트 이동 시 해당 검색을 닫고, 검색어와 결과 권한은 cold 복원에 저장하지 않는다. 소스 적용·Review/Confirm·실행·AI 호출을 수행하지 않으며 graph/node 원본과 최종 C#의 기존 소유 관계를 유지한다.

첫 실제 UI 검사는 팝업이 Blueprint의 닫기 버튼을 가려 실패했다(**0/1/0, 116.188초**). 팝업을 제목줄 아래로 옮겼으며 도구 모음·단축키가 같은 활성 Workspace 범위를 확인하도록 맞췄다. 다음 검사는 이동한 메모 위를 빈 배경으로 가정한 테스트의 우클릭 단계에서 실패했다(**0/1/0, 43.360초**). 실제 빈 지점을 찾아 일반 우클릭하도록 고쳤다. 확대된 Workspace에서 화면 밖 노드 찾기 검사를 추가하면서 좌표에 바깥 배율을 반영했다. 세 번째 검사는 스크롤 끝에서도 정확한 중앙 정렬을 요구한 테스트였다(**0/1/0, 9.739초**). 기존 graph 배치를 보존하며 스크롤 범위 안에서 결과 노드 전체가 보이는지를 검사하도록 고쳤다.

## 메모 글자·제목 서식과 private 원문

기존 일반 메모는 읽기·복원만으로 전환하지 않는다. 메모의 Aa 또는 문맥 메뉴에서 **메모 서식 편집**을 명시적으로 선택하면 인라인 서식 편집기로 전환한다. 글자 굵기·기울임·밑줄·취소선·목록·크기·색상과 서식 지우기를 지원하고, 제목 크기·색상은 별도의 미리보기/적용·직접 서식 제거를 사용한다. 메모·그룹·포털 제목은 private 배치에 속한다. 일반 원본 선언이나 graph/node 파일을 수정하지 않는다.

메모의 `richText`와 검색·호환용 `text`는 같은 private 항목이다. 선택과 native 편집 이력을 유지하며 실제 편집 후 두 값을 함께 갱신한다. 서식만 바뀌어도 입력 저장 대상으로 분류한다. 기존 일반 메모와 보존된 v318 workbench의 동작은 유지한다. 복원한 HTML은 inert template에서 텍스트와 허용된 글자/목록 스타일만 복사한 뒤 표시한다. 이벤트·링크·스크립트·리소스 요소와 URL 스타일을 활성 DOM에 넣지 않는다. 붙여넣기/드롭도 같은 경로를 사용하며 읽기만으로 저장한 private 원문을 고치지 않는다. 명시적 편집 때 정리된 새 원문을 저장한다.

첫 실제 UI 검사는 제목 모서리의 리사이즈 핸들을 문맥 메뉴 클릭 위치로 사용해 실패했다(**0/1/0, 91.744초**). 일반 제목 부분을 클릭하도록 고쳤다. 두 번째는 메모도 창처럼 포털로 이동한다고 잘못 가정했다(**0/1/0, 12.469초**). 현재 runtime의 포털 전송은 창만 지원한다. 메모를 스크립트로 옮기지 않고, 루트와 하위 Workspace에서 각각 편집한 메모가 탐색·cold 복원 후 유지되는 검사를 사용했다. 세 번째는 굵은 메모의 텍스트를 바꾼 뒤 native 편집기가 유지한 유효한 굵기 HTML을 허용하지 않은 테스트였다(**0/1/0, 12.458초**). 실제 plain mirror와 이전 원문·URL·script 제거를 확인하도록 고쳤다.
