# V8 실행창 최대화와 복원

원본 `reference/site-ui/Confectory-Editor-Prototype-v666.zip`의
`Confectory-v666/dist/app.js` `enterRunFullscreen`/`exitRunFullscreen`과
실행창 `data-run-maximize` 버튼을 현재 실제 Run 창에 연결한다.
`setupRunDeveloperMenu`의 해상도·오디오·렌더 디버그 제어는 별도이며, 내장 renderer가
없는 현재 호스트에 모의 scene/FPS나 실행 권한을 추가하지 않는다.

## 이번 지원 경계

- 원래 버튼·표시·CSS로 문서 탭/플로팅 Run을 화면 크기로 최대화하고, 버튼·Esc로
  동일 DOM·원래 탭/레이어·창 크기와 입력으로 복원한다. 브라우저 전체 화면은
  지원할 때 요청하고 거절/미지원이면 원본의 CSS 최대화를 유지한다.
- 최대화는 실행 명령을 만들지 않는다. 실제 재생·Pause·Step·Stop/Close는 기존
  ProjectContext·view/lease/handle·프레임 ACK 검증을 그대로 사용한다.
- 원래 화면 위치/크기를 최대화 동안 저장값으로 덮어쓰지 않는다. resize/배경 갱신은
  최대화 창을 원래 레이어로 재배치하지 않으며, 복원할 때 기존 창 맞춤 규칙을 사용한다.
  뷰포트 크기가 바뀌었다면 기존 규칙대로 정상 창을 현재 화면에 맞춘다.
- native 창의 inline z-index 위에 최대화가 표시되도록 CSS 우선순위를 적응했다.
  문서 탭의 닫기 버튼은 최대화 동안만 표시한다. 기존 닫기/권한 검사로 연결하며
  문서 탭 밖에서 원래 노출된 접기 기능도 그대로 사용한다.
- 접기/닫기·탭 숨김/재도킹·프로젝트/세대 변경에서 overlay와 native 전체 화면을
  정리한다. 닫기 거절은 창·실행·입력을 유지하고 명시적 재시도를 허용한다.
- 지연된 native 전체 화면 응답은 취소된 창을 다시 열지 않는다. 같은 프로젝트의
  명시적으로 선택한 다른 Run으로 전환한 경우에만 현재 표시를 유지한다.
  다른 구성요소가 소유한 전체 화면을 임의로 종료하지 않는다.
- fullscreen·프로세스/lease는 개인 레이아웃에 저장하지 않는다. 엔진 재시작은
  원래 창과 입력만 복원하며 프로세스를 자동 실행하거나 권한을 되살리지 않는다.

원본과 부모/외부 데이터·C# bytes·공개/override 계약·권한·Review→Confirm·저장 CAS는
이번에 변경하지 않는다. 완료된 M11/M12/M4·일반 저장 복구를 다시 잔여로 열지 않는다.
3D/권한 별도 팩·이동과 실제 실행의 분리 규칙도 유지한다.

[정확한 소스 delta](v666-run-fullscreen-delta.json)를 따른다. [최종 검증](VALIDATION_V666_RUN_FULLSCREEN.md)은 **총 35단계(신규 35·재사용 0)** 통과했다.
원래 Run을 열어도 최대화 버튼이 없음을 실제 엔진에서 먼저 확인했다.
새 기능 검증 중 재생 버튼을 가리는 쌓임 순서와 플로팅 resize 재배치 결함을 재현하고
동일 범위의 native 창 연동을 보강했다. 창 전환 검사의 동적 locator 문제는 고정 ID로
수정했으며 제품 문제와 구분해 증거를 보존한다.

실제 프레임 실행을 종료한 검사가 남기는 Unix 제어 소켓도 검증 수명관리에서 다룬다.
이번 실행에 등록된 임시 runtime 디렉터리·inode/UID와 모든 검증 worker의
자식 회수 증명을 확인하고, 커널의 bound endpoint 목록에 없는 정확한 frame socket만
내용을 읽지 않고 metadata로 보존한다. 활성/출처 불명/종료 미확인 소켓이나 커널 목록을
읽을 수 없는 경우에는 보관·정리를 거절한다. 기존 디렉터리를 정리 대상으로 채택하거나
FD/maps 제한을 우회하지 않으며, 성공/실패 fixture·활성 소켓 거절·압축 복원을 검증한다.

## 남은 고정 범위와 검증 한계

원본 개발 메뉴와 실제 실행 프레임/ACK 표시는 [후속 진단 연결](V8_RUN_DEVELOPER.md)을 따른다.
해상도/preset·오디오·디버그 렌더 정보는 여전히 실제 surface/audio backend 선행 범위다.
모바일 가로 방향 자동 회전은 실제 렌더 크기·기기 capability와 함께 검토하며, 현재
브라우저 viewport 검사를 실제 모바일·물리 Back/방향 잠금 검증으로 표현하지 않는다.
실제 Windows apphost/WebView2·모바일·전체 UI·Space 전달은 별도 검증/전달 항목이다.
혼합 저장은 재현 기반 조사 후보이고, V2 후속·V3–V9 및 종류 호환성/사용중 삭제 결정은
기존 고정 목록에 남는다. 각 가능한 저장 조합을 새 필수 요구로 만들지 않는다.
