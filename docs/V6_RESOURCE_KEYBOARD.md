# V6 자료 탐색 키보드

고정 v666 ZIP `app.js::renderResourceBrowser`의 body keydown이 기준이다.
현재 표시 목록의 Ctrl/Meta+A 전체 선택, Enter 선택 자료 열기/카테고리 진입,
Delete 기존 확인 후 삭제, F2 단일 항목 인라인 이름 변경, Escape 선택 해제를 연결한다.
기존 단일 카드 Enter/Space·우클릭·필터·경로·원본 레이아웃은 유지한다.

각 동작은 현재 ProjectContext/창 수명과 보이는 native metadata를 사용한다. 선택 묶음
열기도 기존 소유 ID/hash의 미리보기/카테고리 경로를 재사용한다. 선택 순회 중 source가
폐기되면 남은 열기를 멈춘다. 새 형식 미리보기나 외부 OS 경로 열기는 추가하지 않는다.

입력·버튼·contenteditable·도구/경로/계층과 IME 조합은 네이티브 편집을 유지한다.
미확정 자료/이름/설명 요청 중에는 목록 명령을 적용하지 않는다. 반복 키의 Enter/Delete/F2를
재실행하지 않고 대기 삭제 확인은 합친다. 대기 뒤 새 검색/선택/포커스·창/프로젝트 전환은
오래된 확인창을 만들지 않으며, 폐기된 확인은 현재 선택에 적용하지 않는다.

기존 인라인 초안·저장/실패/동일 receipt 재시도/cold·동료 변경 CAS와 원자 삭제 확인을
재사용한다. 목록 Escape가 편집 입력/미확정 저장을 취소하지 않는다. 취소는 해당 폼의
기존 명시 동작을 사용한다. 기본 C#·계약·팩·권한/Review/Confirm·자료/개인 저장 형식과
예산은 바꾸지 않는다. 전체 선택은 보이는 행만 대상으로 한다. 선택한 카테고리의 하위 삭제는 기존 전체 집계·확인 안내를 유지한다.

이 다섯 원래 명령과 기존 영향 회귀를 유한한 완료 기준으로 삼는다. LF/CRLF·새 교차
패키지/전체 복원·실패 수명/최신롤백 보관으로 마감하며, 실기기/전체 UI·큰 보관·실제 신원
권한 및 기존 정보 종류 정책·초기 빈 화면 원인 미확정은 별도다.

일반 검사 뒤 실패 복구에서 차단된 Delete가 전역 Workspace 삭제로 전파돼 자료 창을
닫는 현상을 확인했다. 목록 명령은 차단 중에도 소비하고, 계층/버튼·IME/반복 Delete도
자료 body 밖의 창 삭제로 넘기지 않는다. 실제 입력란의 Delete 편집과 자료 창 밖의
Workspace 삭제 동작은 유지한다. 이는 원본 데이터 삭제를 허용하는 새 권한이 아니다.
