## 보존한 이전 실패의 재검증

- 전환 저장 응답 유실 후 새 입력의 후속 Save 차단: cold 복원에서 이미 확인한 source proof를 현재 화면과 대응시키는 맵을 후속 입력 재바인딩에서 누락했다. 현재 원본과 일치하는 proof 또는 그 검증된 맵의 proof만 자기 저장 결과로 갱신한다. 다른 source/계약을 임의로 새 버전에 올리지 않는다. 실제 응답 유실/cold/새 입력/재시도/컴파일 Confirm 3건을 재검증했다.
- 구현별 입력 renderer의 마지막 요청 assertion: `text` 필드가 없는 argument 요청의 `.get('text')` 결과 `[None]`을 빈 배열로 잘못 기대했다. 필드 부재와 정확한 `valueJson`/요청 대상·다른 입력 보존을 각각 검증하도록 고쳤다. 기존 보호나 실제 payload 검사를 제거하지 않았다.
- 직렬 canvas 검사: root plug의 실제 역할은 자료형 선택인데 이를 연결 핸들로 눌렀다. raw port도 해당 컨트롤 아래여서 정상 클릭 경로가 아니었다. 원본 값 선택 메뉴로 같은 루트 입력 연결을 검증한다. 호환되지 않는 native 타입은 메뉴에서 제외되는 실제 동작, provider 쓰기 없음, Save의 정확한 argument payload 및 나머지 동작을 함께 검사한다.

정확한 실행 결과·한계는 `VALIDATION_V536_HELPER_FORMS.md`에 기록한다. 이전 실패 로그와 `PAUSED_FOR_V536.txt`를 지우거나 실패를 v536 화면 차이로 소급하여 설명하지 않는다. 전체 UI 수용 후에만 도우미의 편집·저장 기능 누락을 별도로 감사·확장한다.

최신 전체 완료/부분/backend 부재와 검증 가능한 중간 빌드 준비 순서는 [V536_UI_CONNECTION_STATUS.md](V536_UI_CONNECTION_STATUS.md)에 한 번 정리했다. 영역별 통과가 전체 복원 완료를 뜻하지 않는다.
