# V821 — independent reference save and selector

기준: b8b2f628020f9c35f92d24b9c6db0a2ee55301f9. Linux 실제 EditorHome 호스트 + Chromium, 합성 프로젝트(40/400 객체), 별도 기준/후보 호스트와 authoring 바이너리. UI 리소스 해시는 각 호스트에 맞는 정확한 소스로 되돌려 교차 실행했다.

## 변경

- 참조 선택에 필요한 definitionTypes를 기존 project-scoped inspectEffective 스트림에서 같은 소스 관측/전체 투영으로 조회한다. ID/kind도 확인한다. 캐시된 목록을 무조건 반환하지 않으며 소유권과 원래 sourceFingerprint 검증을 유지한다.
- 400개 compact clean 독립 창의 단일 직접 reference 편집에서만 repeat proof를 요청한다. 도구는 기존 before/after 전체 의미 검증을 실행하고 정확한 전체 관측 및 소유권 경로 집합이 같을 때만 증명을 반환한다. 원래 및 후보 Context, 최종 inspectEffective와 실제 경로/해시 검사 유지; 동일한 mixedOwnerCopyEdits 재호출만 대체한다. 이전 도구, dirty draft, 증명 불일치, 지원되지 않는 형태는 원래 재검증 경로.
- 독립 reference도 검증된 스칼라의 서버측 owner settlement를 사용한다. 별도 capability, 현재 일반 로컬 프로젝트, 단일 root data, 해당 view binding, checkpoint, 정확히 두 source proof(대상과 변경되지 않은 manifest), reference=true, 새 revision/hash 확인을 요구한다. 같은 서버측 settledSlots 검증을 갱신 전후 두 번 실행한다. 실패 또는 구 호스트는 기존 클라이언트 복구 경로. 최종 directPropertyConfirm의 review token, reference read proof 재검증, 실제 파일 CAS, 충돌/권한/외부 변경/창 binding 보호는 변경하지 않는다.

## 보호 동작 및 검증

- 실제 최종 후보/기준 교차 세트 38회, 복원/구형 Review 추가 7회, 별도 정확한 settlement 증명 1회 성공. 단계별 시도도 포함해 보존된 격리 로그 115개(112 성공, 3 실패). 중간 실패는 테스트 locator 중복, 비동기 invoke 응답 형식 가정, 기준선 리소스 pin 불일치였으며 각각 수정하여 동일 경로 재실행 성공.
- controlled core: reference detached, fallback(구 도구 증명 없음), 외부 변경, dirty draft 테스트 모두 성공. 실제 준비 이후/최종 확인 직전 외부 변경, 권한, 대상 누락, 원본 소유자 변경, 다른 창 미저장 입력, 혼합 및 미입증 direct reference의 명시 Review, 응답 유실과 재시작 복구, 독립 창 binding, 외부 지도/저장 작업 사본 필터, Worker Review, 삭제/복구 및 동일 ID 프로젝트 격리 확인.
- 일반 40/400 reference 및 scalar, picker, reopen, deletion/recovery compiler/project DLL 0. 명시 Run은 실제 compiler 7회, DLL 84회 및 변경된 참조 데이터 사용 확인. 모든 브라우저 격리 로그 remaining=0, 마지막 프로세스 점검에서 Chromium/Playwright 잔류 없음.
- 남은 병목은 독립 400의 apply 약 325ms 및 실제 최종 확인 약 120ms, 기타 UI/서버 왕복. 수십 ms 전체 목표 미달. Windows 실기 미검증. 실제 사용자 데이터, main, 배포 변경 없음.
