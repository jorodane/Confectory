# v821 문서형 수직 셀 첫 단위

## 범위와 보존 계약

기준은 [v821 UI/UX 기록](V821_UI_BASELINE.md)의 확인된 소스 동작이다. 같은 엔진 graph와 기존 authoring adapter 위에 ‘논리 코드’를 기본 보기로 연결한다. 실제 `next` 연결을 따라 위에서 아래로 읽고 입력은 왼쪽, 출력은 오른쪽에 둔다. 조건 분기 탭·그룹 접힘·상위 셀 접힘은 원본에서 확인된 구분을 따른다. 분기 설명 행을 추가하지 않는다.

이름·typed 값·보호된 C# 본문 편집은 기존 입력·저장 경로를 사용한다. Blueprint 보기 전환으로 기존 노드/좌표/연결/정확한 숫자/공유 초안/구조 Undo를 보존한다. 접힘·분기 탭 선택·보기·스크롤만 개인 presentation에 기록하며 graph schema나 엔진 실행 의미를 바꾸지 않는다. 기존 원문·권한·Review/Confirm·최종 CAS와 정보별 C# struct, 종류 enum, 모듈 interface, 명시적 async 정책도 유지한다.

실제 첫 권한 실패 재현에서 기존 이름+값 혼합 Save가 `argument`·`rename`을 live 초안에 순차 적용한 뒤 `saveDraft` 실패에도 개인 입력을 지우는 결함을 확인했다. 이 단위는 직접 소유한 같은 일반 `code/next` 노드의 이름 1개+기존 argument 1개만 기존 `authorBatch` 후보·원자 checkpoint 경로로 연결한다. 다른 노드/프레임, 미소유 필드, private/forwarded/slot 계약으로 확대하지 않는다. 해당 receipt를 Export에서 보존하며 원본 CAS는 그대로다. 실패하면 두 입력·기존 live 초안·checkpoint·원문을 보존하고, 성공하면 두 변경의 Undo/Redo를 같은 공유 이력으로 이동한다.

## 검증 구성

`tests/web/v821_function_document.py`는 검사 전용 provider로 기본 보기, 배열 순서와 다른 실제 실행 순서, 좌우 핀, 접힘·재진입·보기 상태와 적용 전 값 선택기 텍스트 보존, 정확한 long 토큰, 기존 구조 Undo/Redo와 C# 편집 취소를 검사한다. 이 테스트를 실제 엔진 실행 증거로 사용하지 않는다.

`tests/web/v821_function_document_ui.py`는 복제 프로젝트의 실제 Linux 엔진과 Chromium으로 다음을 검사한다.

- 기본 수직 순서, 좌우 핀, 기존 그래프 전환과 authored 배치 보존.
- 이름·값의 동일 공유 초안, 원본 미수정과 재시작 후 개인 입력 복원.
- 한 번의 명시적 Save, checkpoint 권한 실패와 입력 보존·재시도·cold 복원.
- Review 취소, 원문 변경 후 최종 CAS 거절, 새 Review/Confirm과 실제 .NET 결과 12.
- 실제 execution-enum 조건 이름, 그룹/상위 셀 접힘의 차이와 재시작 복원, 기존 분기 실행 결과 보존.

기존 `v666_node_names_recovery_ui.py`는 상위 탭에서 Blueprint를 명시적으로 선택해 원래 좁은 화면 편집·원자 Save·Undo/Redo·cold·Review/CAS 동작을 회귀 검사한다. 기본 보기 변경에 맞춘 테스트 진입점 수정이며 제품 저장 계약을 바꾸지 않는다.

`tools/verify_document_cells.py`는 같은 고정 commit의 독립 LF/CRLF 체크아웃을 새로 빌드하고, 위 검사와 기존 보기 회귀를 수행한다. 새 패키지의 manifest와 실제 Linux 엔진, 전체 압축 복원 바이트 및 복원 후 UI, 패키지 실패 수명을 검사한다. 기존 관리 store의 인증된 latest/rollback 보존과 증거 보관 후 해당 실행이 만든 작업공간만 정리한다. 이전 38단계는 이 결과에 재사용/합산하지 않는다.

최종 실행 결과는 아래에 기록한다. 구현 중 검사에서 UI 리소스의 기존 pinned 크기/해시 불일치를 확인해 새 JS/CSS를 manifest에 등록했다. 보호 검사를 완화하지 않았다. 실제 분기 cold 검사에서 개인 레이아웃의 metadata 허용 목록이 새 보기 상태를 누락하는 결함도 확인해, `functionDocumentViews`를 목록에 추가했다. graph·초안 포맷은 변경하지 않았다. 또한 검사 좌표가 창 크기 조절 핸들을 눌렀던 실패는 실제 제목 클릭으로 고쳤으며 제품 결함으로 분류하지 않는다.

재진입 시 이미 로드된 문서 CSS가 기존 그래프를 숨긴 다음 사이드바 폭을 측정해, 저장 폭 250px가 화면에서 120px로 줄어드는 결함도 재현했다. 그래프를 숨기기 전에 기존 폭을 계산하도록 순서를 바꾸고, 저장된 250px와 보기 상태를 재진입·전환에서 확인한다. 실제 숨겨진 창을 다시 열 때도 폭을 0으로 측정하고 보기 초기화를 건너뛰어 두 보기가 함께 보이는 경우를 추가 확인했다. 측정 불가 시 기존 폭을 유지하고, 보기의 DOM 상태는 즉시 설정하되 모델 렌더링·뷰 콜백은 현재 소유 창이 보일 때 활성화한다. 이 제품 수정 이후에는 앞선 UI 검사 4개를 새 제품 검증으로 재사용하지 않고 LF/CRLF를 새로 실행한다.

좌표 회귀 검사의 최초 비교는 아직 사용자 배치가 없는 노드의 자동 entry-rail 배치까지 같은 inline style을 요구해 실패했다. 이는 사용자 배치 보존 판정에 맞지 않아, 기존 드래그 핸들로 실제 좌표를 만든 뒤 left/top을 비교하도록 고쳤다. 사이드바는 원래 키보드 조절기로 변경하고, 실제 창 재열기와 보기 전환의 탭·숨김 상태도 함께 확인한다.

## 남은 범위

함수 전체의 생성 C# 미리보기는 비활성 탭에 경계를 표시한다. 네이티브 정의의 직접 편집 화면은 아직 연결하지 않았으며 기존 명시적 Blueprint 전환을 유지한다. 새 문서 보기의 생성·순서 변경·연결/계약 구조 편집은 기존 Blueprint에서 수행한다. 비활성 이동 표시를 실제 드래그 구현으로 표현하지 않는다.

현재 구현 환경은 첨부를 직접 받지 못했다. 별도 환경에서 확인된 압축 파일 SHA와 소스/브라우저 단언을 근거로 구현했으나, 그 환경의 Chromium은 시작 전 소켓 제약으로 실행되지 않았다. 목업과 픽셀·전체 동작 대조, `bb7b920f`/`6ed92688`의 전체 앱/배포 차이, 전체 CHANGES 백로그 대조는 남아 있다. v822로 자동 변경하지 않는다.

실제 Windows apphost/WebView2·물리 기기·전체 UI·모바일 기기 검증은 수행하지 않는다. 과거 초기 빈 화면과 최초 복원 시간 초과 원인은 미확정이다. 이번에 확인한 리소스 거절을 과거 빈 화면의 원인으로 소급하지 않는다. `main`과 Sites는 변경하지 않는다.

## 새 기능의 첫 논리 코드 작성

등록만 된 새 기능은 아직 실제 graph의 `nodes`가 없고 기존 편집기가 첫 작성용 임시 셀을 투영한다. 해당 문맥에서 원본 graph가 필요한 속성 읽기·직렬 순서·계약 조회를 호출하면 논리 코드 화면이 `undefined.find`로 중단되었다. 실제 graph가 없는 경우 해당 원본 전용 동작만 제공하지 않으며, 기존 첫 코드 작성·Save·Review/Confirm 흐름은 그대로 사용한다.

[새 기능 문서 검사](../tests/web/v821_new_function_document_ui.py)는 Linux Chromium의 실제 작업실 메뉴에서 새 기능을 만들고 논리 코드의 첫 C# 셀을 편집해 확정했다. 다른 합성 프로젝트는 변경되지 않았다. 확정된 기능의 새 코드나 선언을 변경하지 않고 별도 합성 사본의 기존 프로젝트 진입점만 그 기능으로 설정했으며, 일반 ▶ 실행으로 실제 결과 파일을 확인했다. 진입점 선택 자체를 제품 UI에서 검사한 결과는 아니며 실제 Windows/WebView2도 미실행이다.

## 논리 코드에서 직접 기능 호출 추가

확정된 직접 소유 일반 직렬 graph의 시작 또는 기존 일반 셀 바로 뒤에 **기능 호출 추가…**를 제공한다. 기존 Blueprint/모바일의 기능 검색과 선택 선언 관측, 정확한 next 연결 삽입, private Undo/Redo, Save 및 Review/Confirm을 재사용한다. 검색에서 기능만 선택할 수 있으며 새로운 호출 참조는 원래 successor를 유지한다. 호출 본문을 복제하거나 편집하지 않는다. 아직 graph가 없는 첫 작성, 미저장 입력, 복합/분기/간접 소유 문맥에는 제공하지 않는다. 다른 보기의 기능 추가나 저장 계약은 변경하지 않았다.

회귀 시나리오: [새 기능 문서 검사](../tests/web/v821_new_function_document_ui.py)에서 최초 기능 작성 및 확정 후 논리 코드 안에서 등록 기능을 선택하고 입력 37을 연결한다. 검색 취소, private Undo/Redo, Save, Review 취소와 최종 Confirm, 작성 프로젝트 재시작, 별도 실행 사본의 일반 ▶를 검사한다. 실제 Windows 및 전체 패키지 검증은 별도이며, 호출 자체의 공개/참조/충돌 검증은 기존 호스트 경로를 그대로 사용한다.

실제 경량 Linux 호스트/Chromium 실행에서 새 기능의 선언 및 코드 작성·Confirm, 호출 삽입 및 값 연결·Undo/Redo·Review/Confirm, 재시작 후 동일 ID·값 복원, 실행 결과 파일 두 개(새 기능 표식과 호출된 기능의 37)를 확인했다. 기존 `v821_internal_flow_document_ui.py`의 보호된 내부 C# 래핑·복원·실행 결과 11과 `v821_document_structure_ui.py start`의 첫 일반 셀 삽입·외부 변경 Save/Confirm 거절·실행 검사를 별도로 통과했다. 구 `v508_feature_call_renderer.py`는 수정 전 42d54a6과 수정 후 모두 첫 비표시 Blueprint 값 컨트롤 클릭에서 동일하게 시간 초과하여 통과로 집계하지 않았다.
