# Private C# 미사용 long→void 반환과 기존 out 연결

기존 v666 고정7/8행의 소유 qualified next-code에서 원래 두 long 인자(첫 값, 마지막 out)를 유지하고 사용되지 않는 long 반환만 void로 명시한다. 원래 methods-v1 scope, 첫 입력 연결·out 역할/타입/이름과 모든 기존 out 소비·부모 frame/public/native 계약·locals·배치·실행선과 선택 밖 원문 bytes/mtime를 유지한다. node arguments·local source·exit의 암시적/명시적 return 포트 소비가 있으면 거절한다. out 소비는 반환 소비와 구분해 그대로 보존하며 새로운 연결이나 소비 재배정을 추측하지 않는다.

원래 out99/반환129와 최종104를 실제 실행/CLR reflection으로 확인한다. 별도의 수동 void 본문/helpers는 out25와 최종20을 직접 작성하며 실제 void/null 반환·동일한 long&/IsOut와 인자 수를 확인한다. 기존 out 결과를 직접 유지한 수동 void 본문은 최종104를 실행한다. 원래 값 반환 본문을 그대로 준 void 후보(CS0127), out 미할당(CS0177)·할당 전 읽기(CS0269)는 compiler가 거절해야 한다. 자동 반환식 삭제·C# 변환·기본값·캐스트·저장소는 만들지 않는다.

기존 반환 타입/매개변수/본문/helpers 영역을 쓰고, 읽기 metadata로 허용된 반환 타입을 명시한다. 기존 값 인자의 long→double/void와 미사용 out 삭제는 보존하며, 다른 선언 변경은 별도 선택이다. receipt3/nativeBodyContexts의 최초 서명/source/whole/path/hash와 물리 읽기 버전을 유지해 후속 저장·cold·Review/Confirm·최종 CAS에 연결한다. schema/profile/권한을 추가하지 않는다. 취소·Undo/Redo·초안 재진입·쓰기 실패/재시도·응답 유실·늦은 입력·창/프로젝트 경계를 검증한다.

다른 타입·역할·인자 수·사용되는 반환의 대응·새/alias 저장소·retained/opaque/import와 외부 관측은 잔여다. 실제 Linux/CLR·Chromium과 모의 metadata DOM, LF/CRLF·새 package/전체 ZIP 복원을 구분한다. 실제 Windows/WebView2·물리 기기·전체 UI와 일반 구 Reference reader migration/downgrade는 미검증이다. 초기 빈 화면·과거 시간 초과·전송 오류 원인은 미확정이다. main·원본·기존 증거를 보존하고 인증 임시물과 기존 latest/rollback 두 세대만 교대한다.
