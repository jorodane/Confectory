## Increment design: Save and ChangeSet

Confectory.Save::{Location,Write,Read,Restore} persists a version-1 changed-unit document under project-local `.confectory/edit-workspaces`, keyed by participant/project/work-context. Save never rewrites final declarations/bodies. Restore retains saved baselines, even when final files changed while closed.

Confectory.ChangeSet::{Review,Confirm,Preview} reviews selected true baseline hashes and performs source-copy candidate validation before selected conditional commit. Preview builds/runs copied drafts only through a separately replaceable authoring tool strategy; it never confirms. Confirm rejects detached new declarations without their manifest registration and changed drafts during validation, preserves unselected changes, then updates accepted baselines. Existing source files, project selection and View definitions are never implicitly switched. Compilation/IO is synchronous pack behavior; the engine's owned worker dispatch keeps it off the UI thread. Candidate directories and running children are cleaned up. Cooperative lease caveat remains explicit.

Outside reads: public FileStream/SchemaEditing/EditWorkspace contracts and .NET process APIs; outside edits only owned authoring helper adds a candidate run operation and new consumer/test wiring. There is no private cross-pack provider dependency. Rebuild scope is new pack contracts/providers and consumers; Save Write and ChangeSet Review provider-only locality gates separately required.

## Increment design: ElementView

Confectory.ElementView::{Create,Bind,Poll,Layout,Labels,Input,Close}. Card and table modes borrow the same workspace+element IDs. Each View owns only selection, subscription, cached projection, pressed/focus/size and redraw state; table aggregates enumerate IDs without owning models or locks. Poll updates only the element revision projection; a schema/process operation never occurs in a per-frame read. Layout/Input operate reusable renderer/input primitives. Native close disposes the borrowed View/subscription while keeping the workspace; explicit owner shutdown closes the workspace. Engine operations run as owned background jobs, with a controlled preview lifetime and reported errors.

Outside reads: RenderInput event/render signatures and public EditWorkspace Read/List/Subscribe contracts. Outside edits planned in the engine ProjectPack composition, launcher tool selection and its consumer fixtures/native probe. Existing BaseUI/runtime/window/cadence contracts remain unchanged. ElementView Labels-only body rebuild must remain isolated.

Explicit shared-contract addition: SchemaEditing::{BeginScope,Cancel,EndScope} assigns tool processes to caller async owner scopes. Cancel stops only that scope's process trees and prevents subsequent calls in the canceled scope. Engine shutdown cancels its own pending compilation/preview scope; it never cancels another scope or silently abandons a process. This changes SchemaEditing's public catalog and revalidates its engine consumer; no Core/platform cancellation policy is added.

Shared IO coordination increment: ProjectExecution Launch now imports public FileStream::LeasePath and supplies that explicit path to its owned host. Its build holds the source lease; Commit uses the same lease, so participating execution builds cannot observe a multi-file apply/rollback. Host's legacy four-argument entry remains compatibility-only on its older isolated lease. Added dependency/registry wiring and consumer fixture copies are explicit rebuild effects. The only outside implementation edit is ProjectExecution Launch/owned host: its former execution-only lease did not coordinate source Confirm, and no public lease contract existed before FileStream. Native launch/OS behavior is unchanged. FileStream LeasePath exposes its own ordinary default provider to avoid forcing every transitive consumer to name an IO provider; common target override rules remain available.
