# Next checkpoint: usable desktop editor composition

The designed editor need not wait for all optional packs. Prioritize an ordinary editor ProjectPack ahead of further physics/render-authoring expansion. This is a proposal, not a claim that the complete editor interface already exists.

Reusable and tested today: ProjectManager opens/selects project metadata and can explicitly create a new local project; ProjectExecution owns launches/status/stop. EditWorkspace owns element drafts/participants/subscriptions and creation; SourceEditor applies text as drafts. ElementView renders reusable element projections, including inherited public help. Save persists/restores drafts; ChangeSet reviews baselines/conflicts and Confirms selected declarations/bodies/manifest changes through validation/build. Existing engine consumer already opens a configured project, attaches an element, edits source, saves/reviews/confirms and launches; the authoring-workbench supplies bounded property/table workflows and independent run comparisons. Navigation now supplies configurable focus groups/consumption. These pieces are separate consumers or rely on configured paths/shortcut actions, rather than one coherent designed interface.

Smallest next integration: one ordinary `Editor` ProjectPack with a visible start screen for Open/Create, project/element selection, reusable property/source Views, a draft/changes panel with Save and Review/Confirm, and Run/Stop/status. Give each action visible scope and errors; keep selection/window lifetime distinct from project/draft/execution lifetime. Wire CreateProject into the UI; replace environment-only selection and undocumented shortcuts with explicit path/identifier controls. Reuse public discovery/projection rather than a second private catalog. Preserve drafts and pending build responsiveness across View close/reopen.

Acceptance is one fresh local project → new semantic element/body → edit → save and restart/reload → review selected changes → Confirm/build → run and stop, plus invalid source/conflict recovery, two Views sharing the intended draft, independent project state, keyboard/text routing and cancellation/cleanup. Linux native GUI and existing regression/locality gates first; Windows user acceptance runs asynchronously. Android remains a required separate app-surface target, but is not a prerequisite to this useful desktop milestone. Live AI, MeshGeneration and optional domains are not prerequisites.

Bounded decisions can use current public contracts and confirmed design. The exact designed visual arrangement and breadth of semantic widgets should be reviewed against the full specification before claiming interface restoration; a materially different design or additional service/provider requirement would need user direction. Initial scope is this minimal end-to-end editor workflow, not the whole editor or every planned pack. The semantic entry-point explorer remains a later shared discovery enhancement, distinct from focus navigation.
