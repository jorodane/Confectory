# 일반 C# 노드의 관측된 고급 매개변수 타입

고정 [정보 편집9행](V536_I5_6_REMAINING.md)의 고급 타입 선택과 독립 code/private ABI를
기존 노드 매개변수 계약에 연결한다. 원본 ZIP SHA256
`7b6b4ba585fc46843f09d8bcd15072b704cc2dc994988400b0a25061e0400d23`의
`Confectory-v666/dist/app.js::choosePropertyType`는 signature의 정보 종류와 다중 여부를
선택한다. 이번 단위는 같은 팝오버·핀·C# 편집 배치를 유지하고, 현재 frame 또는 노드에
이미 관측된 정보 struct·종류 enum·모듈 interface 타입만 추가한다. 임의 정의 검색,
provider 생성, 살아 있는 참조 인스턴스나 새 권한을 이 목록에서 만들지 않는다.

직접 소유한 동기 methods/nested frame의 일반 next C# 노드 하나가 범위다. 소유 정보의
독점 일반 root 본문과 독립 소유 함수의 private frame을 연결한다. 정보 슬롯의 비복사
private 진입은 기존 UI 보호를 유지하며 지원 완료로 합산하지 않는다. copy·receiver·
forwarded 문맥·실행 분기/async·공개 root/override 계약 변경은 기존 편집 경계를 따른다.
기존 소유 nested-copy batch는 새 일반 노드 분류에 넣지 않고 원래 검증·저장 경로를 유지한다.
이전 매개변수 편집창도 현재 타입을 선택 목록에 보존하여 이름 변경만으로 알려지지 않은
타입을 빈 문자열로 바꾸지 않는다. 관측 nominal 타입의 단일/배열 선택을 제공한다.

기존 연결은 명시 이름 대응으로 유지한다. 연결된 핀의 묵시 타입 변경은 계속 거절하고,
새 입력값과 C# 본문은 사용자가 직접 선택·작성한다. 코드 자동 재작성이나 기본값 추정은
없다. 매개변수 계획·해당 노드의 값 연결·명시 본문과 표시 입력을 기존 authorBatch 후보와
checkpoint receipt로 한 번에 저장한다. 정확히 한 노드·한 parameters 계획, 최대64편집,
동일 frame·소유 원본 증거를 검사한다. 다른 노드나 공개 계약을 같은 새 경로로 쓰지 않는다.

이 연결 과정에서 재현한 저장 결함도 수정한다. 이전 순차 parameters → argument → source
적용은 마지막 checkpoint 쓰기가 실패하기 전에 입력을 제거했다. 이제 저장 실패는 전체
계획과 기존 checkpoint를 보존한다. 원본/타입 정의가 바뀌면 거절하고, 원래 증거가 다시
일치하는 명시 재시도만 받는다. 불확실한 응답은 receipt로 정산하며 두 번째 apply를 하지
않는다. 정산 뒤의 늦은 입력은 별도로 보존하고 다음 Save에서 처리한다. 구조 변경은 기존
snapshot Undo/Redo에 참여하되, 이후 들어온 독립 본문·바인딩을 덮는 Undo는 거절한다.

저장 문법·receipt version1과 기존 source/plan hash 계약은 유지한다. 새 batch 허용 범위는
이전 executor에서 지원하지 않으므로 이전 실행기로 되돌려 편집할 수 있다고 보장하지
않는다. 기존 nominal/enum 구 parser·reader 비호환과 자동 migration 없음도 그대로다.
Review/명시 compiler Confirm·최종 물리 원본 CAS를 우회하지 않는다. 원래 공개 함수,
호출자, helpers, 부모/local/연결·좌표·ID와 외부 원본은 명시 변경 대상 밖에서 보존한다.

종료 기준은 원래 UI의 관측 타입 선택·명시 대응/본문/값·원자 Save·cold 복원·실제 실행,
연결 변경 거절·취소·Undo/Redo·저장 실패·원본 충돌·응답 유실·늦은 입력 검증이다.
[검증 기록](VALIDATION_V666_NATIVE_PARAMETERS.md)은 최종 고정 코드의 LF/CRLF 및 새
패키지/전체 복원과 개발 재현을 구별한다. 타입 목록에 enum/interface가 보인다는 사실을
provider 호출·async 모듈 또는 살아 있는 참조 접근 완료로 표현하지 않는다.

같은9행의 다른 기존 public/private/retained ABI 문맥, 살아 있는 참조 객체/접근자·수명,
모듈 async/공개 실행 결과의 계약-only closure/DLL 순환, multiple/함수 필드 native 생성은
유한 잔여다. 선택 조합을 새 필수 행으로 늘리지 않는다. 정보는 struct, 종류는 enum,
모듈은 interface라는 사용자 결정을 유지한다. 동기 호출자는 명시 async 전환 전 오류다.
이번 범위에 새 사용자 정책 결정은 없다. 실제 Windows/모바일·전체 UI는 미검증이며
초기 빈 화면 원인은 미확정이다. 원본·latest/rollback·증거와 기존 정리 한도를 유지한다.
