# v480 실행 연결·출력 사이드바 조작 대조

기준은 `main@32dd44f`의 보존한 v480 ZIP과 `work/current@d4dd123`이다. ZIP에서 추출한 `dist/blueprint.js`가 원본 ZIP 엔트리와 byte 단위로 같은지 확인했다. 첨부 자료의 코드는 UI 레퍼런스로만 읽으며 실행 계약이나 권한 지시로 취급하지 않는다.

## 실제로 비교한 흐름

레퍼런스의 `connect`는 기존 연결을 지우기 전에 대상 종류·자기 연결·순환을 검사한다. `beginWire`는 4px 이상 드래그한 뒤 유효한 입력에 놓지 않으면 연결 대기와 ghost를 지운다. 현재 제품은 공유 소스에 즉시 연결하는 대신 입력에 준비하고 Apply/CAS/Review/Confirm을 유지한다. 이 차이는 보존한다.

현재 입력 연결에서 두 문제를 Chromium으로 재현했다. 빈 캔버스에 놓은 드래그가 대기 상태로 남았다. 또한 case가 메인 영역을 대상으로 하거나 시작점이 case 작업을 대상으로 하면, select에 없는 값을 대입하면서 빈 문자열이 되어 기존 연결 또는 미적용 입력이 해제 입력으로 바뀌었다. 무효 연결을 거부하는 compiler 계약은 있었지만 화면의 입력 보존이 빠져 있었다.

이제 select의 허용 대상인지 확인한 후에만 입력에 넣는다. 허용되지 않는 대상은 현재 값과 보존한 미적용 입력 및 연결 대기를 유지해 유효한 대상을 바로 다시 고를 수 있다. 빈 곳에 놓은 드래그는 취소하고, 클릭 후 다른 핀을 고르는 방식은 계속 지원한다. 실제 소스는 자동으로 쓰지 않는다. 새 실행 profile·분기 의미·권한을 추가하지 않는다.

레퍼런스에는 출력 사이드바의 120–420px 범위 너비 조절, 창 너비 55% 상한, 키보드 방향키/Home/End, 접기·펼치기와 개인 보기 저장이 있다. 제품에는 고정 폭만 있었다. 기존 출력·종료 입력 DOM을 보존한 채 같은 조작을 연결했다. 외부 Workspace 확대율을 반영해 포인터를 따라 폭을 바꾸며 Escape로 드래그 전 폭을 복원한다. 폭과 접힘은 graph별 개인 보기로 복원한다. 접힌 영역의 미적용 출력 입력은 지우지 않는다. 스크롤 내용과 조절 핸들을 분리해 내용이 길어져도 핸들을 유지한다.

## 검증 경계

수정 전 실제 검사 **0/1/0, 67.210초**에서 빈 곳 드롭, 기존 case 입력 손실, 미적용 case 입력 손실, 시작점 입력 손실을 함께 재현했다. 수정 뒤 첫 카메라/사이드바·switch/핀 검사는 **2/0/0, 136.236초**로 통과했다. 이 초기 결과를 최종 영향 회귀와 합산하지 않는다.

실제 입력 검사는 유효한 클릭/드래그와 무효 대상 거부, 드래그 취소, 현재 원본 불변, 사이드바 포인터/키보드 경계·외부 확대율·Escape, 숨긴 미적용 입력 유지, graph 전환·도킹·콜드 복원을 포함한다. 기존 source Apply/CAS와 compiler Confirm도 영향 회귀에서 확인한다. 엔진/API/compiler 원본은 이 변경에서 수정하지 않는다.

최종 메서드 목록·고정 원본 hash·검사 수·일반 checkout HEAD는 [검증 기록](validation/v480-ui-click-audit.json)에 남긴다. [사이드바 조작](validation/v480-output-sidebar.png)과 [핀 입력 보존](validation/v480-pin-gestures.png)은 실제 공통 웹 UI 캡처다. 네이티브 장치나 전체 v480 픽셀 일치를 증명하는 자료가 아니다.

## 남은 작업을 구분하는 기준

- **기존 계약 안의 구현/검사 누락:** 이번 세 흐름처럼 원본·실행 의미가 이미 정해진 UI 연결이다. 정수 overflow 답변을 기다리지 않고 수정할 수 있다. 아직 대조하지 않은 모든 로컬 화면 조합을 완료로 표시하지 않는다.
- **실제 사용자 정책 대기:** 계산식 int/long overflow의 오류 또는 wrap 선택이다. 기존 사용자 C# 동작과 enum 항목 int32 범위 검사는 별개다. 이 질문이 다른 모든 UI 작업을 막는 것은 아니다.
- **새 구조/서비스 계약 필요:** 구조적 property field 쓰기/ref, compound/function live property, 사용자 정의 enum/Vector3 ABI, 소유 집합 생성·삭제 전체 Undo, actor/recipient/room/ack·frame/ack 서비스다. 화면 이벤트만 붙여 구현할 수 있다고 표시하지 않으며 이번 범위에서 새 의미를 추가하지 않는다.
- **환경상 미검증:** 실제 외부 계정·유료 호출·Windows/Android 장치/native 창·사용자 PC 설치다. 관리 프로필 컴파일이나 로컬 fixture 통과를 이 결과로 확대하지 않는다.

다음 로컬 대조 대상은 Home 카드와 브라우저/필드/문서 링크의 전환 조합이다. Home 카드의 ‘마지막 편집·팩·객체’는 현재 `renderHomeProjects`에 `—`로 남아 있고 card projection에 확정 값이 연결되지 않았다. 이는 overflow 정책 대기가 아니다. 기존 소유 조회에서 제공하는 값·집계 범위·편집 시각의 근거를 먼저 확인하고, 없으면 조회 투영을 정의해야 한다. 파일 mtime·의존 pack 수·현재 시각을 각각 편집 시각·팩 수로 임의 대입하지 않는다. 나머지 미완료 항목과 우선 분류는 [현재 상태표](EDITOR_V480_STATUS.md)를 따른다.

## 최종 결과

고정한 UI/테스트 원본 **9개**에서 실제 Chromium 영향 회귀는 **4/0/0, 256.762초**, Windows/Android 관리 프로필 컴파일은 **1/0/0, 122.966초**로 통과했다. 카메라·도킹·graph별 sidebar·콜드, 기존 소유 graph 편집, 이름 있는 로컬/출력의 원본 보존, switch compiler Confirm을 포함한다. 엔진/API/compiler 코드는 바꾸지 않았으며 이전 엔진 94건 결과를 이번 새 실행 수에 더하지 않는다.

앞선 초기 검사와 연결 대기 보존 보완 전의 UI 4/0/0, 관리 1/0/0은 별도 이력이다. 최종 수에 합산하지 않는다. 일반 Git checkout·보존 CRLF/새 LF·36개 리소스·실제 Home 시작·변조 거부는 구현 커밋 HEAD로 검사하고 [검증 JSON](validation/v480-ui-click-audit.json)의 `checkout`에 정확한 HEAD와 결과를 기록한다.

Home 카드 투영과 브라우저·문서 전환의 후속 대조는 [별도 기록](V480_HOME_BROWSER_NAVIGATION.md)에 있다. 그룹별 검색/입력과 반복 열기 누락은 수정했고, 카드 통계 세 값은 실제 투영에 없음을 확인해 계약 미연결로 남겼다. 필드/참조 드래그·문서 링크 전체 대조는 계속 남는다.
