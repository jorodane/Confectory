# I5-6 6행: 직접 소유 전체 본문의 계약 변경

기존 v536 함수 상세창과 C# Script·호출 계약 갱신 창을 사용한다. 함수 상세창에서 현재 기본형/배열 선택기의 타입·핀 수·반환을 고르고, C# 창의 형식 매개변수에서 native 이름과 값/ref/out을 직접 명시한다. 본문은 자동 재작성하지 않는다. 선언과 본문이 일치하지 않으면 전체 후보를 거절하고 입력을 보존한다.

지원 단위는 직접 소유 함수 하나와 import 없는 원래 전체 본문 lift(코드 하나와 선택적인 직렬 반환 writer), 프로젝트 소유 일반 Blueprint 호출자다. 원래 graph/record·context·native 서명/저장소·반환 경로를 먼저 증명하고 현재 public/native ABI의 타입·모드·순서와 명시 본문을 같은 후보/CAS에 넣는다. 원래 native 이름과 public 핀 이름은 별개이며 새 native 이름도 사용자가 편집한 매개변수와 C# 본문으로 검증한다.

현재 직접 경로에서 타입/핀 추가·삭제, 값↔out, ref↔out, 값↔ref, 반환 타입 변경과 void 양방향 전환을 지원한다. 새 ref는 같은 타입의 **실제로 존재하는 호출 입력 바인딩**을 직접 선택해야 한다. ref에 리터럴이나 새 임시 셀을 만들지 않는다. 기존 호출 입력의 삭제/출력 전환은 그 원래 바인딩을 명시적으로 해제하거나 다른 현재 입력에 직접 재사용해야 한다. 기존 출력 소비자는 같은 타입의 현재 출력에 명시 대응하고, 대응하지 않은 사용처가 남으면 전체 거절한다. out은 기존 그래프의 출력 셀/스냅샷 의미를 사용하며 ref와 별칭을 스냅샷으로 추측해 바꾸지 않는다.

명시 전체 본문 계획은 원래 graph hash와 코드 ID, 선택한 반환 writer를 결부한다. 기존 반환 writer ID는 보존한다. void→반환은 사용자가 선택한 반환 계약과 코드 저장 동작에서만 직렬 반환 writer를 만든다. 반환→void는 원래의 유일한 반환 writer만 제거하며 남은 호출 소비자의 대응을 확인한다. 기존 출력 순서는 명시 핀 대응을 따라 보존하고 새 출력만 뒤에 추가한다. SourceContext 공개 목록은 실제로 남은 출력만 유지하며 새 출력은 자동 공개하지 않는다. 이는 프로젝트 접근/공유 권한과 관계없다.

모든 caller 입력 계획을 원래 source 기준으로 먼저 검증한 뒤 출력 대응을 적용한다. 한 함수의 두 호출이 이어지는 경우에도 앞 호출의 출력 이름 갱신이 뒤 호출의 원래 해제 증거를 무효화하지 않는다. 명시적으로 해제되어 사라지는 사용처만 제거한다. 누락된 해제와 남아 있는 삭제 출력 사용처는 계속 거절한다.

후보 준비는 직접 C#의 보호된 함수 경계와 callee/caller 모두의 실제 생성 entry/members·import 인터페이스를 Roslyn으로 검사한다. 실행하지 않는다. 파일/체크포인트 저장은 기존 원자 거래와 CAS, 결과 조회·재시도·Review/Confirm을 사용한다. 레이아웃·CSS·권한·자동 Confirm은 변경하지 않는다.

이 단위의 종료 조건은 위 직접 경로의 실제 화면 편집·저장·Undo/취소·실패/충돌·응답 유실·재시작·명시적 Review/Confirm, 연결된 두 호출 회귀, 기존 6-field 명시 계획 호환, clean checkout와 Windows 교차 패키지다. 전체 6행 종료와 구분한다.

후속 전체 본문 caller의 프로젝트 소유 import·명시 C# 편집 단위는 `VALIDATION_V536_INFORMATION_CONTEXTS.md`에 분리한다. caller 자신의 public/native ABI와 노드·저장소는 유지하고, 편집한 callee의 import 계약과 수동 본문만 같은 후보에서 검증한다. 등록/상속/copy 문맥은 이 단위가 허용하지 않는다.

남은 6행: 추가 코드/제어 노드·locals/별칭이 있는 callee, `forwardCallerStorage`의 별도 문맥, postCall 래퍼의 명시 본문/import 계약 갱신. 현재 기존 호출 바인딩에 없는 새 ref 저장소를 임의 선택/생성하지 않는다. 5행 nested/private path, 7행 copy/등록 receipt, 8행 여러 함수의 공유 caller, 9행 고급 타입/표시명은 기존 별도 잔여다. 실제 Windows/모바일 기기 실행과 Library 전달도 미검증이다.

후속 고정 C1/C3/C4의 직접 소유 수용 경계와 현재 잔여는 `V536_I5_6_RETAINED_SCOPE.md` 및 `VALIDATION_V536_INFORMATION_RETAINED.md`로 갱신했다. 이 문서의 이전 미완료 기록과 이후 마감 결과를 구별한다.
