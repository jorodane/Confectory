# M4: 직접 소유 내부 그래프의 Task 경계

저장소 v666 `dist/blueprint.js:blueprintSetAsync`의 명시적 전환·ref 거절·내부 호출자
검사와 기존 내부 흐름 진입을 따른다. 프로토타입의 자동 C# 재작성은 채택하지 않는다.
사용자가 확정한 규칙대로 상위 함수/내부 호출자가 동기라면 오류이며, 명시적으로
바꾸기 전에 동기 대기하거나 호출자를 자동 전환하지 않는다.

## 이번 지원

- 직접 소유한 기존 ordinary Root의 중첩 profile과 private `graph` 노드에 명시적인
  Task 계약을 연결한다. 내부 창의 Root/leaf 메뉴도 같은 소유 경로를 사용한다.
  깊이별 새 UX 제한을 넣지 않으며 기존 트리 예산과 소스 읽기 예산은 유지한다.
- 공개 입출력 계약을 새로 발급하지 않는다. 기존 private compiler identity와 생성
  결과 저장소를 사용해 await 뒤 반환값/out을 공개하고 완료 → 결과 분기 → 다음
  동작을 실행한다. private 실행 분기의 기존 ID/값과 원본 C#·helpers를 보존한다.
- 내부 선택은 해당 물리 Root·소유 함수/구현·모든 코드 record를 기존 원자 그룹과
  관측 receipt에 연결한다. 부모/참조 원본·copy에서 편집 권한을 얻지 않는다.
  ref 저장소나 원래 instance receiver를 private static Task에 빌려 주지 않는다.
- private 전환만 하거나 이미 async인 함수의 노드만 바꾸면 공개 함수 헤더 원문을
  다시 포맷하지 않는다. 명시적인 공개 실행 방식 변경과 내부 구현 변경을 구분한다.
- 메뉴·시계·완료 포트와 Save/저장 결과 재조회·Undo/Redo·취소·cold·Review→Confirm을
  기존 경로에 연결한다. 실제 쓰기는 원래 전체 Review와 최종 CAS 뒤에만 수행한다.

상위 호출자가 이미 async여야 한다. 현재 UI는 부모 Task 전환을 Save한 뒤 내부 창에서
leaf를 전환한다. 첫 생성 Save 전 입력 결합을 포함해 이 순서 제한을 영구 UX 정책으로
확정하지 않는다. 잘못된 소유 경로/소스 hash/누락 record/부모 구현은 거절한다.

## 동기 복귀와 남은 원본 흐름

내부 async 동작을 먼저 명시적으로 동기로 바꾼 뒤, 완료 실행선이 연결되지 않은
private Task를 동기로 돌릴 수 있다. 기존 일반 Result·입출력과 C#을 보존한다.
연결된 완료 실행선을 묵시적으로 지우거나 다른 기본 분기로 대체하지 않는다.

**연결된 private 완료 실행선을 일반 결과 분기로 보존하는 동기 복귀는 아직 남는다.**
원본은 completion 표식을 제거하면서 그 분기를 일반 결과로 유지한다. 현재의 안전한
거절은 구현 경계이며 그 원본 흐름까지 완료했다는 의미가 아니다. 이 항목은 같은
유한한 내부 Task 흐름의 잔여이며 타입/문맥마다 새 요구를 추가하지 않는다.
다른 유한한 M4 잔여는 첫 생성 Save 전 입력 결합이다.

override 공개 IO 변경, 비소유 원본 쓰기와 선택적 legacy 자동 migration은 요구로
추가하지 않는다. M11/M12는 구체적 회귀 없이 다시 열지 않는다. 고정 V1 검증/V2–V9,
기존 ABI/고급 타입/표시명·팩/backend·종류 호환성과 실제 기기/전체 UI/Space 전달은
이 단위와 별도다.

## 개발 확인과 최종 검증

실제 실행에서 private 반환값/out 공개·반복·예외 전파·동기 호출자 거절·실행 분기 ID를
확인했다. 실제 API와 기본 UI의 메뉴/Undo·cold·원자 Save·부분 Review 거절·Review 뒤
충돌·취소/Confirm·실행을 확인했다. 늦은 입력도 이전 receipt 재조회와 별도 Save로
보존했다. LF/CRLF·새 패키지/전체 복원 최종 수치는 별도 최종 기록에서 확정한다.

개발 중 발견한 실제 누락은 private async 배치 진입 거절과, 노드만 전환해도 공개
헤더를 다시 포맷하던 처리였다. 각각 명시 async 배치의 진입 연결과 실제 함수 실행
방식이 바뀔 때만 헤더를 쓰도록 좁게 수정했다. 기존 nested profile의 동기 복귀에서
명시 완료 어댑터가 switch를 요구하면 그 profile만 보완한다. 권한·원문·최종 CAS 검사는 유지한다.
초기 fixture의 소유 경로 누락, Review 이전 비교 기준과 불완전 분기 종료점은 제품
보호를 낮추지 않고 검사 준비만 수정했으며 실패 기록도 보존한다.

이전 rollback은 새 private Task 노드/receipt를 거절할 수 있다. 코드 롤백으로 새
초안/데이터가 자동 이행되는 것은 아니며, 원문·checkpoint와 보관 증거를 유지한다.
