# v666 기존 속성의 소유 복합 전환

기준은 저장소 v666 ZIP의 `renderObjectSchema` → `choosePropertyType` → `convertPropertyValue`다. 원본에서 일반/named/참조 타입을 `복합`으로 바꾸면 **필드를 복제하지 않고 빈 복합 기본값으로 초기화**한다. 기존 기능 계약을 복제하는 작업이 아니며 공개 override 입출력 계약 유지 합의는 바뀌지 않는다.

## 이번 유한한 지원 단위

1. 직접 소유 일반 속성 → 빈 소유 복합. 기존 native 속성 키·이름·아이콘과 다른 입력을 유지한다.
2. named 정보 속성 → 빈 소유 복합. 원본의 필드·부모·기본값을 가져오거나 원본을 수정하지 않는다. declared dependency의 원래 타입 증거를 검증한다.
3. 객체/함수 참조 값 → 빈 소유 복합. 선택된 속성의 연결만 명시적으로 초기화하며 대상 객체·함수·구현·본문을 유지한다.
4. 단일/다중 전환. 다중 유지 시 항목 수를 유지한 빈 복합들로 초기화하고, 단일로 바꾸면 한 빈 복합으로 초기화한다. 단일→다중 및 빈 배열은 같은 native 계약으로 처리한다. 전체 ref/array 조합을 새 작업으로 늘리지 않는다.
5. 저장된 소유 복합 안의 일반/named 자식도 같은 팝오버에서 명시 초기화한다. 새 자식 정의와 새 값은 기존 소유 트리 거래로 저장한다.
6. 이전 소유 복합을 일반 타입으로 바꾼 뒤 되돌아오는 경우, 정확한 owner/path의 보관 schema ID·해시를 다시 관측한다. 기존 source를 재사용하며 중복 생성·영구 삭제하지 않는다.

객체에서 전환하는 정의는 그 객체의 기존 private 로컬 속성 source(legacy owner-prefix/12자리 ID 및 기존 경로, 또는 정확한 새 소유 프로필)여야 한다. 객체에 연결된 public named 정보의 정의를 객체 전환으로 바꾸지 않는다. 그런 정보는 정보 원본 창에서 명시적으로 편집한다. private source가 다른 객체에 직접 재사용된 경우에도 전체 미적용한다. 부모/외부 source를 소유한 것으로 취급하지 않는다.

## 값 손실의 명시성과 원자성

원본 타입 팝오버의 기존 경고/적용 영역을 사용한다. 의미 있는 값이 있거나 저장된 속성을 전환할 때는 초기화·연결 해제를 표시하고 **전환 적용**을 눌러야 한다. Escape/팝오버 취소는 타입·다중 선택을 적용하지 않는다. 초기 기본값뿐인 새 미저장 속성은 기존 새 복합 생성 흐름을 유지한다. 새 별도 JSON 편집 UI나 inferred migration을 추가하지 않는다.

적용 전 입력을 기존 private Undo 스냅샷에 보존하고, 동일 속성의 이름·아이콘·값 입력을 하나의 소유 트리 입력으로 옮긴다. 다른 속성 입력은 유지한다. 확인하는 사이에 같은 속성에 새 입력이 생기면 전환을 적용하지 않는다. 임시 저장 전에는 Undo/변경 취소가 원래 입력을 복구한다. 임시 저장과 최종 Review→Confirm은 별도 동작이다.

native는 `reset-empty-v1` 의도, 원래 값의 정확한 typed JSON, 원래 타입의 증거, root/보관 source 해시·경로·소유를 검증한다. 숫자를 JS Number로 변환하지 않는다. 다른 저장 데이터·기본값·소비자가 새 타입과 호환되지 않으면 전체 후보를 거절하며 그 데이터나 C#를 자동 수정하지 않는다. 정의·값·등록·새 소유 schema는 기존 후보/최종 CAS로 원자 저장한다. 응답 유실과 저장 중 새 입력은 기존 receipt로 복구하며 수락된 뒤에는 초기화 의도를 소비해 재실행하지 않는다.

## 실제 결함과 검증 경계

- 복합 배열의 하위 속성 추가를 원본처럼 각 배열 항목 도구 영역에 배치했다. 루트 헤더에 배치하여 삭제 버튼과 겹치던 누락을 수정했다.
- 원본 CSS에도 남은 `.is-complex` 우선순위 때문에 마지막 `display:block` 규칙이 복합 배열에 적용되지 않았다. 같은 의도된 마지막 규칙에 해당 하위 클래스를 포함시켰다. 새 간격/색/디자인 없이 기존 value-box의 추가·접기·삭제가 가려지지 않도록 했고 실제 클릭·Undo/Redo로 확인했다.
- 내부 전환 Undo 검사에서 정상적으로 private 입력이 사라진 상태를 잘못 조회하던 검사 오류를 수정했다. 실제 저장값 복원을 확인하며 실패 로그를 남겼다.

집중 native 전환 검증 8개와 기존 소유 중첩 회귀 9개가 통과했다. 기본/독립 정보, 외부 named 정보, 객체 private source, 내부 자식, 객체 참조 배열·함수 참조·배열 축소, 취소·쓰기 실패·소스 충돌·응답 유실·독립 창 늦은 입력·실제 별도 프로젝트 cold 왕복을 실제 엔진에서 확인했다. 집중 증거는 `runs/0a6a79dd58724165964e67952d83d639.{json,zip}`에 보존했다. 앞서 수정한 두 진단 실패 로그도 같은 보관본에 남겼으며 통과로 계산하지 않는다.
