# Windows Editor double-click batch entry

Baseline is published CP13 `831fd45da3bd6f15170a8ad2bc450f82b6626aaa`; bounded correction lives on `fix/editor-windows-launcher`. New normal Windows entry is repository-root **run-editor-windows.bat**. Double-click it: no terminal navigation and no PowerShell call. It finds the checkout using `%~dp0`, selects existing dotnet/PATH or the explicit CONFECTORY_DOTNET full path, checks the SDK selected by unchanged global.json, calls the already-working build-windows.bat and uses ordinary CLI run for examples/editor/project.cpack windows. The structured emitted run command and process lifetime remain the existing CLI's responsibility; the batch does not guess output folders or manually launch a guessed DLL.

That happens before run-editor.ps1 executes, so it proves script-policy rejection, not a parse, SDK, Editor or Win32 runtime defect. Later user clarification permits batch files/general apps and the ordinary existing .NET workflow; the batch route is a native alternative explicitly requested for that environment. No execution-policy bypass/change or blocked ps1 wrapping, installation, new credentials or prebuilt-editor delivery. The ipconfig observation does not prove Windows components were removed; no such inference is required.

All three external steps append stdout+stderr to ignored `.confectory/editor-launch.log`, whose absolute path is displayed. The log includes checkout, selected host and SDK output. Failure prints the retained diagnostics, preserves the actual exit code and pauses unless CONFECTORY_NO_PAUSE=1 is explicitly selected for automation. A missing/unwritable checkout/log directory reports directly and pauses. Success restores caller cwd and exits0 after the actual Editor process finishes. setlocal and disabled delayed expansion keep environment changes scoped and preserve exclamation marks; executable/project/log/checkout paths are quoted. Initial pack compilation can take minutes and the launch window explains that wait; CLI heartbeat/progress remains in the log. Each launch replaces this local log, so preserve an error before retry if needed.

The existing ps1 stays unchanged as an optional developer entry only where scripts are allowed; primary docs now use the batch and no execution-policy override. Existing SDK8 is required, as before.
