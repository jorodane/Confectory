# Existing authoring contracts connected to the actual product

Continues `6f0a692` on `lazy-edit-materialization`. All four authorized independent operations are connected in dependency order through the existing actual `EditorHome.Model::Command(session,"workspace",payload)` route. Main/layout/native controls are unchanged. Generic schema encoding remains a user decision; no schema-field grammar or JSON schema contract is implemented.

## Public commands

All requests require the currently open explicit project context. The existing stale-context guard rejects another context before opening an editing workspace. Read/selected unit revisions are the existing per-unit revisions, not invented property-level revisions.

- `action:"value", field:"count", value:0, expectedRevision:N`: formats the selected owned declaration through public SchemaEditing SetValue and applies text with public SetTextIfRevision. Native JSON string/number/bool is preserved, including empty string/0/false. Null/array/object, manifest/body selection and invalid declaration syntax are rejected. No schema/default/type inference. Stale revision reports conflict and invalidates review; parse/format failure leaves the existing review/draft/selection intact. Same resulting text does not require a new revision.
- `action:"follow", id:"Namespace::Element", expectedRevision:N`: parses the current selected declaration and permits only its explicit target/function/import-scope relationships. Destination must already be in public owned List; Read must succeed. Rechecks source revision/text before changing selection. A registered imported locator alone does not authorize editing or opening that project. Success borrows the existing destination draft and clears the selected-source review, exactly as ordinary selection; failure preserves selection/review and all source drafts. Filters remain independent. This is navigation only: no rename, file move, source-reference rewriting or migration.
- `action:"create", kind:"object", id:"CurrentNamespace::NewID"`: calls existing EditWorkspace Create/Register. Existing supported kinds are category/concept/function/module/object/schema; this does not invent schema fields, function bodies/providers or typed defaults. Stable IDs and namespace/owned destination rules remain in the public authoring contracts. Success selects the staged new declaration and clears the prior review. Duplicate IDs, unsupported kind, another namespace or occupied destination fail without adding a registration. Only drafts change; no final declaration/manifest is written before Confirm.
- `action:"review", ids:["ID1","ID2",...], target:"linux"`: explicitly chooses 1–256 distinct owned units. Omitted ids preserves the existing selected-single-source behavior. At least one must be dirty; clean members may be included. Duplicate physical destinations are rejected consistently with conditional Commit. A new declaration must explicitly include its changed root manifest registration; there is no automatic inclusion of another dirty unit. Each review row contains identity/kind/path/revision/baseline/current hash/before/after/dirty. Selection is preserved. Save retains all local drafts; review token and selected rows belong only to this View.
- `action:"confirm", token:"reviewToken", ids:["ID1","ID2",...]`: groups with more than one member must echo the reviewed IDs in review order. This prevents the unchanged single-source UI from confirming a group without an explicit group scope. Single-source callers keep the old token-only contract. Wrong/missing token or group IDs preserves a still-valid review. Changed draft/selection invalidates the token and requires fresh review. Candidate failure or baseline conflict consumes the token but retains review details and drafts for an explicit retry. Cancel-review removes only review state. Successful confirmation applies only the reviewed changed units and acknowledges only those saved changes.

Model errors reproject the already-open current workspace through public Snapshot. They do not open another context, select a fallback unit or discard draft text. A stale-context failure does not reproject another project's workspace. Existing optional `text` submission remains a separate explicit revisioned pending-buffer edit before the requested action; failure of a subsequent action does not roll back the user's submitted text.

## Reviewed change contract and race boundary

New `Confectory.ChangeSet::ConfirmReviewed(handle, selected:string[], target:string, reviewed:string[]) -> string[]` accepts the existing flat Changes records `[id,path,baseline,text,...]`. It defensively copies arrays, compares current public Changes to the reviewed records before candidate preparation, and compares again after validation. A different draft returns `stale`; it never substitutes the latest unreviewed draft. Conditional Commit still checks every selected final hash under the existing source lease and retains its rollback behavior. Accept and Save Acknowledge remain unchanged.

Old `Confirm` delegates to this same implementation after capturing current public Changes, preserving its signature and ordinary direct-call semantics. There is one candidate/commit policy implementation, not a duplicated compiler or write path. PackWorkspace stores the change records captured during Review and calls ConfirmReviewed; it also checks all review rows' revisions/text/baseline/path and selection. This closes the interval where a shared View could change a draft between a consumer-level token check and an old Confirm's fresh Changes call. It does not claim a whole-project/dependency snapshot or semantic merge.

Review checks current filesystem symbolic-link components before reading its before-image, and the original conditional Commit checks destinations again. No delete, overwrite of a conflicting user file, unreviewed source application or automatic Run is added. Actual source-changing verification uses disposable test projects, not user projects or repository source files.
