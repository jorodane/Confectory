# v821 분기 내부 수직 셀 편집

## 구현 경계

- 명시된 non-primary `case:<ID>` 진입선과 같은 `branchOwner`를 가진 일반 직렬 C# 셀만 편집한다. 해당 분기의 셀 전체와 원래 `return:소유자` 또는 `exit:이름` 종료점을 보존한다. 두 분기가 같은 셀로 진입하거나 다른 경로가 셀을 공유하면 거절한다. default/암묵적 진입, 중첩 분기·복합 그래프·슬롯·복사본·private·비동기 문맥은 이번 대상이 아니다.
- 분기 탭의 ‘이 분기에 동작 추가’는 기존 명시 진입선을 보존한 인수 없는 void C# 셀을 추가한다. 일반 셀 뒤에서도 추가할 수 있고 기존 보호 C# 편집기로 실제 본문을 작성한다. 위·아래 이동은 선택 분기의 시작·모든 next 연결을 하나의 후보로 적용한다. 조건은 기존 탭 이름으로 유지하며 설명 행을 추가하지 않는다.
- `BlueprintCellRegion`은 기존 그래프와 정확한 계획을 읽어 검사하는 순수 metadata 작업이다. 소스 권한을 부여하거나 원본을 쓰지 않는다. 실제 author batch는 관측한 소유 그래프·소스 closure와 권한을 확인한 격리 후보에서 이를 호출한다. 직접 serialRoutes 호출로는 이 권한을 얻을 수 없다. 최종 기존 FeatureBlueprint 검증으로 값 생산자의 지배 관계, 스코프·타입과 완전한 실행 경로를 확인한다.
- 이동은 개인·공유 Undo/Redo를 제공하고, 새 셀 추가는 저장 전 개인 Undo/Redo를 제공한다. 새 소유 본문이 생기는 Save는 기존 `OWNERSHIP_CHANGED` history 경계를 유지하며 저장 후 공유 Undo로 새 소스를 없애는 기능은 추가하지 않는다.
- 수직 분기 계획은 요청의 `documentBranch` 명시 표시를 개인 저장 시도와 확인용 해시에 묶는다. 기존 표시 없는 typed/일반 Blueprint 생성 API는 새 분류기가 가로채지 않는다. 프로젝트와 체크포인트에는 새 필드/버전을 추가하지 않는다.
- 기존 공유 초안, 저장된 history, source proof, Review/Confirm·최종 원본 CAS를 유지한다. 임시 author 상태만 사용하고 기존 route/생성 편집과 ownedRoute receipt를 재사용한다. 새 런타임 분기, enum 의미, 프로젝트 그래프/체크포인트 버전은 추가하지 않는다.

## 2026-11-22 직접 소유 복합 내부의 case 순서
