# Local Agents and global Helper conversations

The sidebar counts registered Agent configurations. Installed provider declarations are available under the separate provider settings list and in **Agent 연결**. Saving or registering configuration does not authenticate an account, run a model, or grant project access. The supported reply transports remain Codex and OpenAI Responses; the ChatGPT plugin route continues to manage the separate MCP engine connection.

From **Helper 추가**, create a Helper with an immutable personality and speciality, or import the existing Main Helper template. A Helper can exist without an Agent or project. Display profiles, recruitment templates, project membership, memory and Agent assignment remain separate. Choose a registered configuration in the Helper's **사용할 Agent 선택** field; project-only Helpers can be reassigned only in their own open project.

Global Helpers have **전역 대화** independently of the selected project. Review the exact message, Helper profile, completed conversation history, model and provider permissions before each request. Common memory is excluded by default and selected for each turn. Project memory, legacy private memory, project references, filesystem/process capabilities and development tools are absent from this request. Codex still requires its existing preflight and six separate request approvals. Unsupported methods or unverified models cannot be enabled by approving the content.

Only actual provider events become replies. Draft saving, configuration registration and conversation history saving have separate states. A failed or cancelled request keeps the input, carries its original request identity and does not display a previous answer as the new result. Closing and reopening a conversation reads its local journal without replaying a provider request. History pages affect display only; the complete approved context is shown again before each transmission.

`Confectory.EditorHome.Model::HelperAgents` owns the registry, Helper store reference, approval preview, request handles, cancellation and history CAS. `ProjectAI.Configuration` / `Permission` supply existing configuration and consent contracts; `Agent` dispatches the existing provider adapters. Global consent pins an empty project ID plus `contentScope.kind=helper-global`, the Helper identity and conversation identity. A global grant cannot authorize project tools. Project chat still uses the existing ProjectContext, Helper selection, AI owner and Review/Confirm flow; the selected Helper's assigned Agent configuration can be bound there explicitly.

The registry is `helper-agents.json`; conversations use hashed Helper identities under `helper-conversations`. Neither file stores approved rights or credential values. Configuration contains the existing external credential references. CAS conflicts preserve the original files. Malformed registry data leaves Home available with a fixed diagnostic. A failed history save retains the current response and reports the persistence failure separately.

Current bounds are two supported provider configurations, 256 Helper assignments, eight retained global request owners per engine, 24 records per conversation, an 8,192-character message and a 49,152-character reviewed context/message budget. The UI reads two history records per page. Reaching a context or retention limit refuses the next request; it does not silently drop history or replay an old request.

The v508 startup layout waits for the actual initial model snapshot, offers Agent connection or **나중에**, and respects reduced motion. Creation uses the project/packs tabs, native parent-folder ticket, retained input and the existing empty ProjectPack creator. One global main Helper may be selected and connected after explicit project creation. Arbitrary pack combinations, generated images, account login and unsupported providers are not simulated. A creation proposal owns a separate draft from the ordinary creation form.

Validation uses the actual public model, HTTP/stdio adapters and Chromium UI with owned loopback HTTP and Codex protocol fixtures. It does not use a paid inference service, a user account, permanent permission creation or a user project. Linux checks and Windows compilation do not establish behavior on a user's Windows PC.
