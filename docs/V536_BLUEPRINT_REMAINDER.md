# v536 Blueprint 후속 작업 단위

Browser 잔여 묶음 이후 수행할 고정 UI 연결 목록이다. 이 문서는 구현 완료/사용자 권한 승낙이 아니며 이번 Browser 변경에서 아래 기능을 새로 구현하지 않았다. 원본 v536 레이아웃과 자연어 Blueprint 좌→우 직렬 실행, 사용자 초안/소유권/CAS·명시적 compiler Confirm을 유지한다. 새 시각적 분기/반복 모델을 도입하지 않는다.

1. **다중 구현·C# 변환 실제 화면 완주 — 지원 원본 문맥 묶음 검증.** 기존 `blueprintFeatureBodies`/conversion/정확한 source proof API를 원본 선택·추가·전환에 연결한다. 각 구현/실행 대상별 미저장 입력을 분리하고 다른 구현/부모/등록 팩 원본을 보존한다. UI 선택→미리보기→취소/저장→cold→명시 Confirm, 실패/응답 유실/늦은 새 입력을 유한 회귀로 수용한다. 기존 서버 검사가 실제 UI 전체 완료를 뜻하지 않는다. 실제 3문맥(두 소유 슬롯+전역 provide)의 선택·전환·cold·응답 유실/늦은 입력·개별 Save/Review/compiler Confirm·provider 변경 차단 9건과 controlled renderer10건을 확인했다. 원본에 없는 전역 ID picker/추가, 외부 source 직접 편집, 모든 native/target/View 조합은 확대하지 않았다. 정확한 한계와 결과는 `VALIDATION_V536_MULTIPLE_IMPLEMENTATIONS.md`를 따른다.

2. **검증된 범위 밖의 호출 ABI.** 현재 검증은 단일 소유 호출의 값↔ref, typed import, 생산자 공개 출력→소비자 검토·공동 명시 Confirm이다. 후속에서 소유 슬롯의 같은 단일 root/본문/호출 값↔ref와 typed import 원자 저장, 슬롯 변경 차단·입력 보존·cold·명시 Confirm을 연결했다. 지원 행렬과 실제 검사 범위는 `V536_CALL_ABI_SCOPE.md`, `VALIDATION_V536_SLOT_CALL_ABI.md`를 따른다. 후속 직접 등록 callable의 함수/manifest receipt와 명시적 재확인도 실제6건으로 연결했다(`VALIDATION_V536_REGISTERED_CALL_ABI.md`). 복사본·다중 target/호출·일반 ABI 재매핑은 여전히 미지원이다. 원본이 요구하는 다른 호출 소유 문맥/형태를 먼저 실제 목록으로 고정하고 하나씩 연결한다. 비호환 연결을 추측해 변경/삭제하지 않고 명시적 갱신에서만 일관되게 갱신한다. 공개 출력은 호출 후 SourceContext 읽기이며 외부 공유/프로젝트 권한이 아니다.
3. **모바일/데스크톱 원본 특수 계약.** 후속 wrapper enum의 핀 ID/순서·모바일 분기 소유 편집은 실제8건으로 수용했다(`VALIDATION_V536_ENUM_PINS.md`). 원본 property의 무실행 핀/현재 node-time backend 차이, local Set과 field Set 구별 및 일반 code enum 본문 연결은 `V536_REMAINING_BACKEND_MAP.md`의 잔여다. 소유 단일 whole-body root의 모바일 C# 값/ref·out 및 native 이름 대응은 실제390폭6건으로 수용했다(`VALIDATION_V536_MOBILE_SPECIAL_PINS.md`). 이번은 기존 경로 검증이며 runtime을 바꾸지 않았다. 아래 전체 특수 계약은 여전히 남아 있다. 공유/고정 반환 이름, 잠정 빈 출력, 영역·다중 선택, 내부 흐름/async, 특수 핀·readonly 핀의 원본 의미를 실제 소스와 대조한다. 지원 backend와 UI만 미연결인 항목을 분리해 카드/상세와 기존 desktop 편집의 동일 초안에 연결한다. 원본에 없거나 실행 모델이 없는 동작을 데모 성공으로 표시하지 않는다.
4. **혼합 Save와 입력 보존.** 속성 편집+복사본 혼합 저장은 현재 안전하게 차단된다. 필요한 원본 의미·서버 원자 저장 단위를 먼저 확인한 뒤 실제 UI에 연결하고 일부 슬롯/다른 객체 입력 유실·동시 저장 덮어쓰기가 없음을 확인한다. 기존 batch 저장·취소·cold 보호를 약화하지 않는다. 새로운 저장 내구성 범위로 확장하지 않는다.
5. **최종 원본 조작·정밀 수용.** 위 동작에 연결된 줌/검색/키보드·핀/노드 선택/삭제·밀집 rail과 모바일 폭 전환의 고정 목록을 원본과 대조한다. 기존 통과 동작을 반복 구현하지 않고 새 입력/한글 IME·취소/저장/cold/명시 Confirm·프로젝트/창 전환을 영향 범위에서 확인한다. 브라우저 합성 입력과 Windows/Android 실기기 결과를 구분한다.

작업 단위마다 실제 지원/부분/백엔드 부재와 테스트를 기록한다. 전체 UI 완료 후에만 Helper 에디터 도구의 실제 누락을 별도 감사한다. UI API가 있다는 이유로 Helper에 자동 노출하거나 Confirm/프로젝트 실행/다른 프로젝트 접근을 추가하지 않는다.
