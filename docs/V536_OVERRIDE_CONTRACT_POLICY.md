# v536 오버라이드 계약: 확정 범위 — 2026-10-25

사용자 결정은 오버라이드가 원본의 매개변수·출력 계약을 유지하고 구현만 바꾸는
것이다. 타입·핀 수·전달 역할·반환 구조를 바꾸면서 같은 상속 계약으로 취급하는
요청은 정상적으로 거절한다. 이를 기존 명세의 미구현이나 사용자 답변 대기로
집계하지 않는다. 독립 계약 복제·새 계약 ID 발급 기능은 필수 복원에서 제외한다.
별도 새 함수 생성과 직접 소유 함수의 기존 계약 편집은 계속 지원한다. 본문 내부의
다른 직접 소유 callee 편집/명시 호출 갱신도 오버라이드 root 계약과 구별한다.

## 현재 소스와 보호

- `Resolution.cs`의 effective 상속은 서명이 부모와 맞지 않으면
  `CONTRACT_MISMATCH`, 구현의 함수 ID가 달라지면 `IMPLEMENTATION_ID`로 거절한다.
- `FunctionSignature.Matches`는 매개변수 타입/역할/순서와 반환을 비교한다. 기존
  공개 표시/핀 별칭 대응은 원래 native 매개변수·계약을 보존하는 범위와 구별한다.
  표시 이름을 별도 계약을 만드는 근거로 사용하지 않는다.
- `BlueprintCopyAbi`는 실제 fn/slot/module 서명과 소유 copy·배정을 대조한다.
  `InformationFunctionCopies`는 후보에서 provenance를 복원하고 다시 검증한다.
  부모/외부 원본은 읽기 관측이며 쓰기 대상으로 바꾸지 않는다.
- 정보 함수 상세창은 `ownMethods`에서 현재 정보 origin의 자체 함수만 편집하고,
  모듈/받은 기능의 표시와 구현 편집은 분리한다. 기존 `＋ 기능` 생성은 그대로다.

기존 상속 계약 guard 검사에 핀 수 변경을 추가하여 부모/자식 원문 쓰기 위조,
타입·수·역할·반환·순서 변경 거절과 실제 부모 파일 경합을 격리 fixture 3확인으로 검증했다.
이 회귀의 타입/핀 수/역할/반환/순서 및 부모 쓰기 거절은 정상 보호다. 이번 정책 정리로 엔진 보호나 UI 레이아웃을 바꾸지 않는다. 직접 소유 함수의
입력 추가·삭제 양성 검사는 별도 8행 경로를 유지함을 함께 확인한다.

## 7행 상태 해석

현재 검증된 동일 ABI의 상속/소유 copy 본문·공개 별칭·등록 receipt 연결은 유지한다.
계약을 깨는 오버라이드는 정상 금지이며 독립 계약 복제 제안은 제외된 선택 확장이다.
따라서 기존 문서의 '부모를 보존한 타입/핀 수/역할/반환 변경'은 필수 잔여가 아니다.

기존 7행에서 아직 전체 수용 완료로 확정하지 않은 실제 경계는 **원래 계약을
유지하는** 새 미확정/외부 함수/여러 target copy의 편집·배정 연계, 부모와 다른
native 별칭/import를 가진 whole-body 본문의 명시 대응, 기존 직렬 copy whitelist
밖 원본 지원 그래프의 연결이다. 이 경계는 현재 guard/검증 범위와 원본 조작을
대조하여 판정할 대상으로 남기며, 계약 위반을 허용하는 새 기능으로 바꾸지 않는다.
이번 8행 단위가 그 경계를 구현/검증했다고 표시하거나 7행 전체 완료로 집계하지 않는다.
8행 공유 caller와 9행 고급 타입/표시명은 별도다.
