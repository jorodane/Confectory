# 명시 native 입력 타입·본문 공동 저장

고정 [정보 편집7/8행](V536_I5_6_REMAINING.md)의 여러 직접 소유 함수 편집을
같은 정보 창·한 Save에서 결합한다. [원래 유한 잔여](V536_I5_6_RESIDUAL_RECONCILIATION.md)와
[기존 명시 이름·본문 그룹](V666_NAMED_BODY_GROUP.md)에 이어 실제 값 입력 타입 교체를
연결한다. 기존 상세창 타입 선택, 호출 계약의 새 값/기존 연결 해제, C# 본문 직접 편집을
사용하며 새 문법·권한·변환 정책·C# 자동 재작성은 추가하지 않는다.

게시8436cb7에서 두 단일 후보는 각각 유효하고 원래 프로그램70도 실행되지만, 공동
후보는 native 본문 계약 제한으로 거절된다. 두 함수의 amount를 long에서 string으로
각각 선택하고 원래 amount 연결을 명시적으로 해제한다. 호출 값은 `첫째😀`, `second`로
직접 지정한다. 표시된 새 native 선언에 맞춰 본문을 각각 `amount.Length+count`,
`amount.Length*2+count`로 직접 편집한다. 기존 count 연결은 유지하며 두 번째 count는
첫 번째 결과를 소비한다. 실제 새 결과21은 두 본문과 유지된 연결을 함께 확인한다.
기존 nativeAmount/nativeCount를 새 타입으로 추측 변환하거나 원문에서 치환하지 않는다.

범위는 직접 소유 동기 scalar 함수2~8개, 각 직접 native 구현의 단일 target과 평범한
직접 Blueprint 호출자다. 모든 값 입력의 이름·위치·수, 반환과 역할은 유지하고 scalar
타입을 바꾼 입력은 기존 mapping.args에서 null로 교체한다. 모든 새 호출 값·끊는 원래
바인딩·C# 선언/본문을 기존 단일 후보 검증으로 완전히 증명한다. 정·역순 동일한 내부
후보를 결합하고 원래 쓰기 해시로 한 Save/CAS를 수행한다. 구현 선언과 caller import의
타입도 기존 계약 갱신기가 처리하며 나머지 코드와 ID·실행선·출력 계약은 보존한다.

저장한 native 선언·본문·caller와 이미 관측한 원본은 기존 version3 receipt/readGuards에
결합한다. 후속 설명 Save가 읽기 기준을 바꾸거나 누락시키지 않게 보관하며 cold Review와
최종 Confirm에서 원래 해시를 다시 확인한다.64-member Review,240 source checks,2048 known
source 예산, 부모/외부 소유권, override 계약, 권한·authored layout·Review/Confirm은 유지한다.

역할·반환/출력·입출력 수 변경과 opaque/private C# 명시 계획, 선택 native callee 사이
의존성 및 다른 원래 import/등록 외부 관측 결합은 같은 고정7/8행의 별도 잔여다.
이번 경로가 이들을 묵시적으로 변환하지 않으며 optional 조합을 새 필수 목록으로 늘리지
않는다. M11/M12/M4는 구체적 회귀 없이 다시 열지 않는다. 구 Reference reader 제약은
그대로이며 같은 게시 세대 도구를 사용해야 한다. 초기 빈 #app의 과거 원인은 미확정이다.

[검증 기록](VALIDATION_V666_NATIVE_INPUTS.md)에 개발 실패/수정과 최종 신규/재사용,
LF/CRLF·취소/Undo·쓰기 실패/복구·경합·응답 유실·늦은 입력/후속 Save·재시작·실제 실행,
새 패키지/전체 복원·보관 증거를 구별한다. Linux native/Chromium 자동화와 Windows 교차
패키징은 실제 Windows/WebView2·물리 기기·IME·GPU/audio·전체 UI 전수 검사와 별개다.

이 명시 native 입력 타입·본문 공동 저장 단위의 [최종 신규 39·재사용0 검증과 보관](VALIDATION_V666_NATIVE_INPUTS.md)을 마쳤다.
