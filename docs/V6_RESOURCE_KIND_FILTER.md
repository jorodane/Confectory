# V6 자료 종류 필터

고정 v666 ZIP의 `app.js::renderResourceBrowser/resourceItems/navigateResources`가 기준이다.
원본은 정렬 앞의 `자료 종류` 버튼과 `모든 자료/문서/그림/메시/기타 파일` 메뉴를 노출한다.
현재 폴더의 이름·설명 검색/정렬과 함께 적용하며 카테고리는 어떤 종류에서도 보인다.
메시는 실제 등록된 kind의 필터이며 새 renderer/형식 해석/가짜 결과를 만들지 않는다.

창별 `resourceFilter`를 기존 private workspace metadata에 보존한다. 프로젝트 자산이나
공개 실행/override/권한·저장 형식은 바꾸지 않는다. 미지/잘못된 preference는 모든 자료로
표시하며 실제 데이터는 재작성하지 않는다. 구 UI는 이 preference를 사용하지 않으므로
모든 종류를 표시하고 자신의 저장 시 preference가 사라질 수 있다. 최신 UI/engine을 함께 쓴다.

필터링으로 보이지 않는 선택은 표시 목록에서 제외해 숨겨진 삭제 대상이 남지 않게 한다.
현재 이름/설명 편집이나 자료 변경/복구 요청 중에는 종류 선택을 적용하지 않고 기존 입력과
대상을 보존한다. 닫힌/전환된 창·오래된 메뉴·나중 검색/선택 이후의 콜백은 적용하지 않는다.
상위 카테고리의 명시 항목 선택은 원본처럼 종류를 모두로 초기화해 대상이 보이게 한다.
일반 폴더 왕복은 기존 종류 선택을 유지한다. 검색의 미확정 입력은 자동 확정하지 않는다.

이 단위는 원래 자료 탐색 UI의 누락을 마감한다. 기존 크기·관측/권한/CAS·Review/Confirm,
원본 파일/다른 미리보기·개인 입력과 M11/M12/M4는 유지한다. 최종 독립 LF/CRLF와 새 교차
패키지/전체 복원·실패 수명/최신롤백 보관 검증으로 마감하며 실제 기기/전체 UI·큰 자료/
신원 권한·기존 종류 정책과 초기 빈 화면 원인 미확정은 별도다.

같은 cold 검사에서 게시본52a5785의 실제 자산 bytes로 Data 설명 초안이 현재 자료와
같은 생성 세대임에도 임시 orphan 표시에서 다시 연결되지 않는 결함을 재현했다. 최신
native metadata가 ready이고 현재 표시 목록에 같은 ID/세대가 있으며 연결된 필드가 모두
읽기 전용 orphan일 때만 재결합한다. 실제 편집 필드·다른 세대/프로젝트·실행 중 저장은
교체하지 않으며 원래 revision·value·pending command를 유지한다. 자동 저장/재기준화는 없다.

차단된 종류 버튼의 실제 pointerdown이 필드를 blur해 먼저 설명/이름 저장을 유발하지 않도록
기본 포커스 이동도 차단한다. 실제 포인터로 변경 전 현상을 재현했고, 수정 후 입력/포커스와
native metadata bytes가 유지되는지 검사한다. 정상 명시 저장·기존 다른 제어의 의미는 바꾸지 않는다.
