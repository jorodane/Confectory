# 대규모 창 복원 fallback·필터 검증 경로 감소

기준: `9f1acb97` (저장 필터 뒤 기본 속성 창 외부 스키마 갱신 결함 수정). 실제 Linux EditorHome 호스트, Chromium, .NET SDK 10.0.401. Windows 실기는 미검증.

## 범위

- 128경로 준비 모델 상한은 변경하지 않는다. 대규모 복원은 기존 `preparePropertyModels` 확인 및 필요한 `openEditorView` 소유자 검증을 수행한다. 각 ordinary open admission에는 이미 허용된 제한 시간 completion 응답을 요청하여 반복 전송 대기를 줄인다. 느린/구버전 응답은 기존 acknowledgement 및 update 경로로 돌아간다. 요청 ID, scope, generation, activation, stale revision, 정확한 바인딩과 상태 증명은 그대로다.
- 작업 사본 `filter`는 목록 이동일 뿐 소스 변경이 아니다. 기존 `RefreshViews`의 `reuseVerifiedSchema`를 사용해 독립 속성 창의 완전한 기존 schema proof를 다시 검증한다. `FreshProof`의 키, 소스/manifest hash, 모든 소유권 경로의 링크 점검 및 관찰 dependency hash 검사와 자체 기존 상한을 유지한다. 변경, 부재, 증명 불가 시 기존 전체 읽기로 돌아간다. 준비 모델 상한을 확장하거나 새 권한을 부여하지 않는다.

### 저장 작업 사본 필터 400개·8창 교차 계측

두 표본의 host `objects` consumer 시간은 cold 113/123ms → 13/14ms였다. Warm의 세 실제 필터 전환은 기준 65/58/57 및 76/70/72ms, 후보 12/6/7 및 16/8/7ms였다. 완전한 fresh proof를 검사했으며 전체 모델을 다시 준비하는 것으로 대체하지 않았다. 외부 스키마가 바뀐 뒤에는 기존 증명이 재사용되지 않고 전체 `inspectEffective` 세 번이 실행된 것을 별도 호스트 로그에서도 확인했다(그때의 filter consumer 114ms).

두 번째 후보 표본 이후 별도의 추가 외부 편집 검증에서 오래된 관계 투영 검색 결과까지 요구한 최초 테스트는 실패했다. 실제 filter 호출은 완료했고 외부 변경으로 full schema read가 실행되었다. 이 추가 검증은 필터 자체의 새 schema 및 미저장 입력 확인과 명시적 map reload를 분리하도록 수정했다(최초 실패는 통과로 집계하지 않음).

## 최종 실제 보호 검증

- `--working-copy --verify-restored-map --verify-filter-freshness` 40·400개: 실제 필터 호출 후 독립 속성 창의 외부 추가 필드 및 별도 미저장 입력 확인, 명시적 지도 재조회 후 기본/독립 창의 새 필드와 두 미저장 입력 확인. 모든 원본 바이트 확인.
- `--verify-restore-completion` 400개·8창 교차: 정확히 세 개의 기존 `restoreSaved` 소유자 요청에 bounded completion 요청이 사용됨.
- Worker Review: 오래된 검토 채택 비활성화, 근거/원본 유지, 명시적 검토 후 두 번째 Worker 소스만 채택.
- 400개 삭제/복구: 역참조 거절, 취소, 삭제 확정, 재시작·복구, 동일 이름 상대 프로젝트 격리. strace 컴파일러 0, 프로젝트 DLL open 0.
- 400개 통상 문자열/정수 및 참조 저장: 컴파일러 0, 프로젝트 DLL open 0; 읽기 불가/외부 소유자 변경 시 저장 거절 및 입력 보존. 명시 Run에서 컴파일러 7, 프로젝트 DLL open 84 및 새 연결 값으로 정상 종료.
- `primary-external-during`, `primary-close-persist`, `stale`, `detached-close-restore` 모두 통과. 외부 변경과 stale admission 거절, 정확한 소유자 복원, 닫힌 창 및 미저장 입력 보존.
- 동일 namespace 두 프로젝트의 이름 검색과 별도 분류, 외부 이름 변경/포커스/스크롤/입력 유지 통과.

모든 개별 브라우저 검증에 저장소의 Linux 격리 실행기를 사용했다. 잔류 테스트 자손은 합계 0. 최초 추가 필터 테스트의 잘못된 stale 관계도 검색 결과 기대 1회는 실패로 별도 기록했고 수정된 실제 freshness 검증은 두 규모 모두 통과했다.

이번 결함 수정 및 성능 검증의 전체 격리 실행 41회 중 40회 통과, 위 최초 추가 검사의 실패 1회; 잔류 테스트 자손 0. 일반 편집 밀리초화 전체 목표는 아직 미완료이며, 400개 전체 인벤토리/관계 projection 및 증명을 통과하는 세 개의 실호스트 창 복원 자체는 남는다.
