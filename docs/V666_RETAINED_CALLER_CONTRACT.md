# 공유 retained 호출자의 자체 계약과 callee 공동 저장

고정 7/8행의 다음 단위는 기존 C# 계산을 가진 일반 Blueprint 호출자의 자체 공개 입력 이름 변경과 직접 소유 native callee의 공개 입력 이름·명시 본문 변경을 같은 정보 창 Save로 묶는 흐름이다. 원래 유효한 프로그램42와 두 개별 후보를 먼저 확인했고 직전 패키지의 공동 후보 거절을 재현했다.

이번 범위는 같은 정보에 직접 포함된 동기 함수 두 개, caller의 단일 ordinary Blueprint target과 callee의 단일 native C# target, scalar 값 입력의 명시 이름 대응이다. caller에는 callee 호출과 독립 C# 계산·지역값·원래 배치가 있고, 두 함수를 공유하는 바깥 caller도 있다. 상속된 정보의 기존 부모·선택 밖 상속 구현과 읽기 전용 함수는 보존한다. caller의 별도 원문은 편집 대상으로 추론하지 않는다. callee의 native 별칭·위치·타입·역할·반환 ABI도 유지하고 사용자가 본문을 직접 편집한다.

기존 단일 계약 검증으로 각 원본 closure를 증명하고 기존 내부 overlay로 typed 변경만 차례로 적용한다. 독립적으로 생성한 그래프 문자열을 임의 필드 병합하지 않는다. cold 검증은 캡처된 최초 두 계획으로 전체 후보를 다시 만들고 source·group·원본 읽기 scope를 대조한다. 기존 nativeBodyContexts 안에 저장하고 workspace1·receipt3와 권한·Review/Confirm·최종 CAS를 유지한다. 새로운 저장 형식·profile·receipt 필드나 자동 C# 생성은 추가하지 않는다.

대표 요청은 caller의 amount→leftAmount, callee의 amount→rightAmount 및 callee의 수동 덧셈→뺄셈이다. caller의 retained C# source/record·exact64 local·좌표·edges, 선택 밖 C# 및 원래 orphan csbody bytes/mtime를 보존한다. 변경 순서가 바뀌어도 최종 후보가 같다. Review/Confirm 뒤 실제 결과22를 확인하는 검증을 둔다. 누락·잘못된 before/map/hash/source·외부 소유·copy/opaque 문맥과 malformed receipt 및 Review 뒤 관측 원본 경합은 전체 거절한다.

이 단위는 caller의 type/ref/out/반환 구조, native alias 변경이나 whole/private/opaque caller 자체 ABI를 일반화하지 않는다. 그 조합은 기존 명시 계획·지원 경계와 함께 별도로 검토한다. 다음 우선순위는 같은 retained/opaque source에 모이는 여러 변경 계약의 명시 일치 계획, 실제 소비되는 private 반환의 명시 대응 및 copy/registered/forwarded 관측 closure다. 구 pending reader migration, 실제 Windows/물리 기기·전체 UI와 초기 빈 화면의 미확정 원인도 남는다.
