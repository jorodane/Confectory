# Private 본문·선택 callee out→값 공동 저장

고정 v666 [정보7/8행](V536_I5_6_REMAINING.md)의 한 정보 창·한 Save에서 private C# 본문/helpers와 원래 호출하는 직접 소유 callee의 out 하나→값 전환·수동 C#을 결합하는 유한 단위다. [기존 out→값 단독 계획](V666_PRIVATE_OUT_VALUE.md)을 [선택 callee 원본 결합](V666_PRIVATE_CALLEE_VALUE_OUT.md)에 연결한다.

원래 long out count 하나를 같은 타입의 값 입력으로 명시 전환한다. nativeAmount/nativeCount·타입·순서·기존 반환과 private/frame/code ABI를 보존한다. 두 원래 caller는 새 리터럴5와 실제로 소비하던 이전 out의 같은 타입 반환 대응을 각각 선택한다. 입력 해제나 기본값·저장소·형변환·새 C#·연결을 추론하지 않는다. 두 본문/helpers와 새 값 소비 코드는 사용자가 직접 작성한다.

직전 온전한 package에서 원래 실행40과 두 단독 계획이 유효하고 공동 후보만 거절되는 경계를 먼저 측정한다. scoped caller가 있는 callee의 원래 out 매개변수가 UI에서 읽기 전용으로 거절되고 입력·원본을 보존하는 경계도 기록한다. 종료 기준은 두 실제 out 소비자·리터럴5의 명시 대응, 정·역순 같은 후보, 실제 실행15·callee를 내부 호출하는 private 직접 반환20·callee 직접 native 반환25·값5의 보존, 후속 Save/cold에서 최초 out→값·source/flow/import·물리 읽기 버전 유지다.

기존 OutValue·단독 Contracts/Graphs·assembled compiler가 각 원래 계획과 결합 후보를 검증한다. 해당 selected-callee 그룹만 같은 원래 snapshot에서 source closure를 검증·결합한다. unchanged 관측은 한 명시 변경과 결합하고 서로 다른 변경은 거절하며 receipt를 overlay에 rebase하지 않는다. 현재 편집 receipt는 검증한 pending graph의 같은 노드와 일치해야 한다.

기존 구현 선택기·C# 매개변수 영역은 원래 out 하나를 값으로 전환하는 방향만 추가 허용한다. ref·다른 역할·native 이름/타입 변경은 거절한다. 첫 owner Save 전 재진입은 같은 원본 hash/path·서명·명시 역할 plan에 한해 native 이름·값 역할·원문을 유지하고 readonly draft의 기존 parameters marker로 fresh 재진입을 검증한다. 기존 값→out 및 scalar 반환 흐름을 보존한다. 범용 native available·권한·authored layout은 바꾸지 않는다.

취소/Undo·실패/재시도·응답 유실·늦은 입력·독립 창/프로젝트·후속 Save·Review 취소/Confirm·실제 원본 경합을 검사한다.
