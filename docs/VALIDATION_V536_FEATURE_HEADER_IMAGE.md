# v536 직접 소유 기능 헤더의 로컬 이미지

기준은 `9534914`와 원본 v536 ZIP의 `editObjectIcon → editIconValue`다. 원본 공통 헤더는
기능 요소에도 PNG/JPG/WebP 선택을 제공한다. 현재 기능 헤더는 기호/이모지만 연결돼 있어,
이번 최소 단위를 **기능 탭 F2 → 헤더 이미지 편집 → 설명과 Save → cold → Review 취소 →
명시적 Confirm**으로 정했다. 부모가 있는 직접 소유 기능의 표시도 같은 경로를 사용한다.

기존 5,000,000바이트 입력 한계·128×128 canvas WebP quality `.9`·65,500자 metadata 한계와
RIFF/ICCP 검증을 그대로 재사용한다. 원래 파일명/경로나 원본 파일은 저장하지 않는다.
제품 이미지 codec, 자산 store, 외부 업로드, AI 호출, 새 메뉴·레이아웃·CSS는 추가하지 않는다.

함수의 이미지 허용은 직접 등록/소유를 검증하는 `FunctionPresentation`에서만 요청한다.
기존 정보 함수 생성/contained 카드나 속성 이미지 허용을 넓히지 않는다. 같은 후보/CAS의
기존 표시 merge와 receipt를 사용하고 함수·핀 identity, 입출력 계약, 구현 C#, typed caller,
부모/외부 원본, 정확한 수치와 설명을 보존한다. 오버라이드는 원계약을 유지하고 구현만
변경하며, 독립 계약 복제는 필수 범위가 아니다. Browser와 관계 맵도 검증된 inline 값만 표시한다.

첫 독립 checkout의 Release/엔진 빌드는 통과했으나 실제 UI 기동이 변경 JS와 pinned resource
manifest의 불일치로 거절됐다. 실패 fixture/로그는 지속 증거 ZIP으로 보존했고 manifest의 정확한
크기/SHA를 갱신했다. 보호를 완화하거나 실패를 통과로 세지 않았다.

저장 응답 대기 중 설명만 새로 편집되고 아이콘 팝오버는 owner-attempt 가드에 막히는 실제
누락도 재현했다. 같은 기능의 진행 중 owner 저장에 한해 로컬 표시 입력을 허용한다.
서명 편집과 다른 작업의 busy 가드는 유지하고, 이미 수락된 요청의 receipt 조회·최종 CAS를
변경하지 않는다. 늦은 이미지는 수락한 이미지와 별도 입력으로 cold 뒤 명시적 Save한다.

## 공간 정리와 검증 경계

사용자가 승인한 초기20개 하위폴더만 원본 파일 목록/전체 SHA/모드·링크·소유·사용 여부를
재확인한 뒤 정리했다. 9개 과거 검사 세트의 runtime/build 18개와 중복 전개본2개다.
ZIP으로 보존한 reviewed 전개본은145개0700 디렉터리 모드를 기록하고 CRC/전체 파일 모드·SHA
및 실제 RAM 복원을 먼저 확인했다. 실제 df 증가2,288,582,656바이트(2.131GiB), 정리 직후
여유2,440,355,840바이트다. 상위폴더·SDK·보존원본·Git·로그·프로필·fixture와 당시 최신9534914/
롤백00abd44/index는 그대로다. 다른 기존자료나 과거32세대 압축/정리는 이번 범위가 아니다.

검증 전용 빌드·독립 LF/CRLF checkout·NuGet/엔진 cache·패키지는 승인된 실행별 RAM 수명관리로
만든다. 지속 증거 보존과 자식 종료 확인 뒤 해당 실행이 만든 임시물만 정리한다. 최신 검증본과
정상 롤백본은 기존 managed index의 원자 승격으로 지속 보관한다. 실제 Windows apphost/WebView2,
실제 모바일 기기, 전체 UI, Library/Space 전달은 이 교차 패키지/복원 검사와 구별한다.

I6 자체 중첩 정의와 원본에서 실제 편집을 노출하는 별도 아이콘, 속성/contained 함수 카드의
로컬 이미지는 별도 잔여다. 숨긴 root/mobile 핀·정보 참조 하위 값의 정상 readonly를 새 필수
작업으로 추가하지 않는다. 고정7/8행의 아직 미검증인 영향 closure·9행 고급 타입/표시명,
B2·M4/M11/M12도 이번 표시 편집과 구별한다.
