# v666 종류 정의 전체 보관·복구

## 원본과 이번 경계

기준은 저장소 `reference/site-ui/Confectory-Editor-Prototype-v666.zip`이다. SHA-256은 `7b6b4ba585fc46843f09d8bcd15072b704cc2dc994988400b0a25061e0400d23`이다. ZIP `dist/app.js`의 `objectContext`(2253행)는 종류에도 공통 삭제 메뉴를 제공하고 `deleteObject`(2240행)는 프로젝트 쓰기 검사를 거친다. 원본의 데모 삭제를 그대로 영구 삭제하지 않고, 현재 앱의 기존 선언 보관 계약에 연결한다. 새 메뉴·레이아웃·종류 실행 표현을 만들지 않는다.

이 단위는 저장된 직접 소유 종류 정의 전체의 등록 제외와 동일 ID 복구다. 기본 Browser 삭제/삭제 항목 복구/변경 취소, 편집된 종류 초안 보관, 명시 Review→Confirm을 사용한다. 물리 원문은 삭제하지 않는다. 미확정 새 선언은 기존 생성 그룹 취소를 사용하며 새 보관 정책을 추가하지 않는다. 부모/외부·다른 namespace의 원본을 변경하지 않는다.

참조가 남은 종류는 기존 선언 관계 검사로 보관을 차단한다. 종류 타입을 쓰는 속성·기본값·객체 값의 owner/항목 ID를 다른 값으로 바꾸거나 자동 제거하지 않는다. 서로 다른 종류의 동일 항목 문자열을 전역 참조로 추정하지 않는다. 사용 중 **항목** 삭제의 명시적 소비자 대응 UI 및 C# 타입/실행 표현은 별도 잔여다.

## 저장·복구 보호

종류 보관은 기존 정보 함수 저장 게이트의 후보·체크포인트 CAS·결과 receipt 수명을 재사용한다. 기존 버전 1의 선언 보관 기록에 `enum-definition-v1` 범위 증거를 넣으며 함수의 버전 2 거래와 구분한다. 선택한 선언과 manifest 외부로 걸친 미완결 편집 그룹은 먼저 완료하도록 거절한다. 해당 범위 안의 기존 원자 편집 그룹은 보관 중 숨긴 멤버를 참조하지 않게 처리하고, 취소 시 그대로 복구한다. 확정 후 복구는 기존 retirement 그룹으로 선언과 등록을 함께 검토한다.

보관 및 미편집 복구의 원문/BOM/CRLF·정확한 정수·항목 ID/이름/아이콘·적용된 초안은 보관한다. 원문 변경, 체크포인트 경쟁·쓰기 실패, 그룹 불완전, 잘못된 소유/경로/토큰은 부분 적용을 허용하지 않는다. 수락 응답이 유실되면 같은 범위의 저장된 증거를 조회한 뒤 처리하며 무조건 재전송하지 않는다. 보관된 편집 초안을 복구해 확정하면 선택한 정의에는 기존 UTF-8 소스 쓰기 규칙이 적용되며, 미편집 원문은 다시 쓰지 않는다. 실제 최종 소스 반영은 기존 compiler Review/Confirm과 최종 CAS 경계를 유지한다.

독립 선언창 열기는 기존 idempotent 연결 함수를 재사용해 **미실행 transport stale_revision**만 재조회한다. 본문/CAS 충돌이나 불확실한 결과를 자동 재시도하지 않는다.

## 호환성 및 미검증

새 enum 속성 문법은 과거 parser가 읽지 못하는 기존 제한을 유지한다. 이전 종류 속성 지원 패키지라도 이번 enum 보관 기록의 cold 복원은 지원하지 않으므로 보관 기록에는 이 단위를 포함한 패키지를 사용한다. 원본 파일·체크포인트·보관 패키지를 그대로 보존하며 자동 마이그레이션을 하지 않는다.

집중 검증과 최종 독립 LF/CRLF·새 Windows 교차 패키지·전체 압축 복원 결과는 아래에 확정값으로 기록한다. Linux에서의 패키지 콘텐츠 실행을 실제 Windows apphost/WebView2 실행으로 취급하지 않는다. 실제 Windows·물리 모바일·전체 UI 및 Library/Space 전달은 미검증이다.

## 집중 검증

실제 엔진의 기본/독립 창·일반 선언 회귀·참조 보호·private Undo/Redo·변경 취소·확정 보관/복구·복구 취소 후 재복구·체크포인트 쓰기 실패(보관/복구)·원문/체크포인트 경쟁·보관 및 복구 응답/조회 유실·프로젝트 왕복·cold·늦은 입력 후 명시 Save·보관 원문 변경 거절·미편집 BOM/CRLF 바이트 보존을 순차 검증했다. 선택한 최종 12개 집중 실행이 통과했다. 초기 fixture/선택자 오류, 원자 그룹 결함, 독립 창 stale admission 및 진단 로그도 같은 실행 기록에 보존한다. 통과를 위해 native guard나 최종 검토를 생략하지 않았다.

최종 코드 commit을 기준으로 기존 86단계와 새 5단계(미편집 복구 포함)를 모두 재실행하는 91단계 검증을 이어서 수행한다. 결과와 패키지/증거 SHA는 완료 후 기록한다.
