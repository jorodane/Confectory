# retained 필수 본문과 독립 코드 계획의 공동 저장

고정 [7/8행](V536_I5_6_REMAINING.md)의 한 정보 창에서, 기존 retained native 문맥의 본문·출력 대응과 같은 그래프의 독립 root C# 노드·helpers를 모두 명시하고 다른 소유 함수의 일반 C# 본문과 한 Save로 보관하는 흐름이다. [일반 root 코드 공동 저장](V666_ROOT_CODE_GROUP.md)의 다음 유한 단위다. 정보별 C# struct·종류 enum·모듈 interface와 명시 async 전환 전 sync caller 오류를 유지한다.

직접 소유 함수 2~8개, 함수별 구현·target 하나, 명시 본문 1~8개와 기존 member64/source240 예산을 사용한다. 공개·native·독립 노드의 계약은 각각 정확히 그대로다. retained native 인자 이름과 공개 이름이 달라도 원래 위치 계약을 유지한다. long 상위 함수와 void/out 독립 노드의 서로 다른 경계를 추측해 맞추지 않는다. 기존 root 문맥 하나의 원래 본문과 모든 출력 identity 계획을 명시해야 독립 코드 계획을 함께 받는다. 필수 계획 누락·wrapper·새 계약/연결 변경은 이 경로에서 거절한다.

원래 소스 선택 UI·보호 본문/helpers 편집과 version3 nativeBodyContexts/readGuards를 재사용한다. source-only 후보라도 기존 retained root/output/binding 검증과 전체 assembled C# 컴파일을 모두 통과해야 한다. null 출력 exit의 표기만 추가되는 정규화는 기존 검증 후 원래 graph bytes를 유지한다. 수동 본문 세 개 외 graph·배치·locals·구현 헤더·공유 caller·등록된 독립 원문은 보존한다. helper 삽입·자동 C# 치환·ABI 변경이나 암묵적인 필수 source 보충은 없다.

후속 metadata Save는 원래 계획을 유지하며, 후속 본문 Save도 두 필수 계획과 각각의 현재 draft hash를 명시해야 한다. 부분 source 계획으로 기존 receipt를 대체할 수 없다. Review/Confirm·최종 CAS·경로/소유권/권한·원본 보존 규칙은 그대로다. 기존 retained 단독 편집도 새 목록에서 원래 문맥을 명시 선택한다.

종료 기준은 이 사용자 흐름의 정상 UI 편집·취소·Undo/Redo·미저장/저장 cold·한 Save·실패/재시도·응답 유실·독립 창·프로젝트 경계·늦은 입력·후속 명시 source Save, Review 취소와 Confirm 및 graph/context/독립 노드/독립 원문의 경합이다. 원래 실행41과 직접 작성한 세 본문의 실행22, 각 ABI·graph bytes·배치·정확한64비트 local·다른 원문 bytes/mtime를 검사한다. LF/CRLF restore/build·새 package·전체 추출본과 일반 root/기존 retained UI·등록 helper·retained ABI 회귀를 구분한다. 가능한 타입 조합을 새 의무로 늘리지 않는다.

실제 계약 변경 callee/import와 등록 외부 관측의 결합은 별도 유한 잔여다. 이전 reader의 새 다중 source pending 후보 수용은 보장하지 않으며 같은 세대 authoring/runtime을 사용한다. 자동 migration/downgrade나 구 Reference parser 변경은 없다. Linux 엔진/portable 실행·Chromium 자동화와 실제 Windows/WebView2·물리 기기·IME/GPU/audio·전체 UI 검증을 구분한다. 과거 간헐 초기 빈 화면 원인은 미확정이다. main은 사용자 검토/merge에 남긴다.
