# Bounded UI Navigation work queued alongside preserved Rig/Motion work

Actual Windows acceptance evidence (2026-10-06): the user reported that the original native window interactions, buttons and retained focus now work. This is user-observed Windows evidence, separate from Linux X11/ABI tests, and does not establish native Windows acceptance of the new Rig/Motion or physics consumers.

Confirmed current cause: packs/base-ui/Input.csbody handles key-down code9/flags0 by unconditionally toggling its private focus slot between controls1/2. Input returns void, so this primitive offers no handled/consumed result. Engine routing calls the basic controller after other controls unless an earlier editor branch returns; a global unconditional Tab policy cannot safely express inventory toggle versus internal navigation.

Bounded separation: BaseUI owns its persistent focus state, public focus query/set/eligibility and basic activation operations. An optional UI Navigation pack owns traversal/group/binding priorities, activation input reservation and restoration through public callbacks; it must not inspect BaseUI's opaque View arrays. Introduce only the necessary shared public focus/control contracts, test their consumers, remove unconditional Tab interception, and preserve default demo traversal by explicit ProjectPack composition. Other render/physics/Stage/Helper packs are not forced dependencies.

Bindings and groups are consumer configuration, not a universal keyboard convention. The inventory example explicitly binds Tab to toggle inventory with higher priority and binds internal traversal separately. Text-editing permission is explicit per binding. Route once per event identity, return handled/consumed before lower-priority controller/editor/game delivery, ignore repeated toggles and prevent one event opening and immediately closing. View/window scope is independent. Restoration selects the saved focus only if still visible/enabled/eligible; otherwise use configured group order or clear focus. No claim of general text/IME/accessibility navigation completeness.

Required gates: same-key open/close, duplicate dispatch, two windows/groups, Unicode/text input and traversal suppression, disabled/hidden controls, focus restoration after removal/disable, pointer and keyboard activation retained, cancellation and owner/subscription cleanup. Keep the scoped navigation increment and publication separate from local CP12 Rig/Motion. Rig source/preview/Save/Confirm work remains intact; finish and verify its current runnable flows while preparing this fix. No main merge or CP12 publication is implied.
