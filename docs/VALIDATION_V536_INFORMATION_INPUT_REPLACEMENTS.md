# v536 I5-6: 사용 중인 일반 입력의 명시적 대체

직접 소유한 정보 함수 하나에서 입력을 삭제하거나 타입을 바꿀 때, 그 입력을 직접 읽는 일반 code 값 인자의 대체 연결과 호출자의 값/저장소 대응을 같은 후보/CAS에 결합했다. 삭제와 새 입력 추가를 함께 하면서 기존 호출자 저장소를 새 입력으로 옮기는 경로도 연결했다. C# 매개변수·본문은 유지한다. 전체 I5-6 완료 문서는 아니다.

## 지원하는 사용자 조작

- 입력 삭제: 본문의 기존 code 인자가 읽을 명시 값을 선택하고, 각 호출에서 제거할 기존 입력 연결을 확인한다.
- 입력 타입 변경: 기존 타입으로 쓰는 code 인자에는 정확히 호환되는 다른 현재 입력이나 명시 값을 선택한다. 호출자의 새 타입 값도 직접 선택하며 원래 연결은 명시적으로 해제한다. 새 타입을 C# 본문에 추정 적용하지 않는다.
- 삭제/추가 혼합: 본문은 새 입력을 명시적으로 읽고, 호출자의 옛 저장소 연결을 새 입력으로 대응할 수 있다. 재사용 중인 연결을 해제한다고 동시에 선택하면 거절한다.

원본 상세창과 기존 ABI 선택창을 재사용한다. 본문 사용처가 있는 경우 제목은 `입력 연결 갱신`이고 본문/호출의 선택을 구분한다. CSS·화면 배치·실행/Agent/Confirm 권한은 변경하지 않았다. 값 원문은 typed JSON 문자열로 보관한다. 이전 형태/소스의 불완전한 선택도 입력 셀 안에 보관하며, 새 형식은 형태/원본 해시별로 선택을 보관한다. 이전 형식은 같은 signature 형태일 때만 복원하며, 모든 선택은 명시적 수락과 실제 저장의 원본 검사/CAS를 거친다. no-op 편집으로 pending 셀이 없으면 새 선택창을 열지 않는다.

## 서버 계약

`readOwnerEdits.includeFunctionInputs`의 기존 직접 소유 함수 검사를 거친 뒤 추가 읽기 전용 사용처를 조회한다. `InformationFunctionInputUses`는 code/next, value 모드, 명시적 구현 문맥/호출자 저장소 전달이 없는 노드에서 직접 root input을 읽는 값 인자만 나열한다. 클라이언트가 다른 프로젝트나 임의 units를 제공하는 경로는 추가하지 않았다.

선택은 graph/node/argument ID, 원래 graph hash, 원래 바인딩 문자열, 새 값/입력으로 한정한다. 타입 변경은 기존 핀 연결을 새 타입에 암묵적으로 재사용하지 않도록 이전 대응을 명시적으로 분리한다. 서버가 정확한 기존 바인딩을 확인한 뒤 순수 후보 안에서 선택된 연결만 잠시 비우고 root 계약을 준비한다. 즉시 사용자가 선택한 대체를 복원한 다음 전체 graph/record/source를 검증한다. 이 중간 상태는 저장하거나 반환하지 않는다. 나머지 사용처에 대한 기존 root 계약 거절은 유지한다.

현재 입력을 선택하면 code 인자와 이름/타입/모드가 호환되는지 검사하고, 직접 값은 기존 전체 graph 타입 검사에 넣는다. C# 노드의 매개변수 계약과 본문은 변경하지 않는다. 호출자/typed import/모든 관련 target·require·기존 출력 연결, source 관찰과 저장 직전 CAS는 기존 한 후보 경계에 있다. 누락·모순·다른 소유·원본 변경·사용 중인 미대응 입력은 전체 미적용이다. 최종 반영은 별도 Review/컴파일/Confirm을 거친다.

## 실제 검증

격리 fixture, 실제 엔진/Chromium/compiler를 사용한다. 사용자 프로젝트, 실제 계정·유료 추론·프로젝트 Run은 사용하지 않는다. 실행 근거는 `/workspace/scratch/v536-information-input-replacements`다. 숫자는 각 시나리오의 check 수다.

- Native SDK 컴파일 경고/오류 0, 최종 Linux engine-3 stderr 0.
- API: 사용 입력 삭제 3, long→string 루트 타입 변경과 별도 long code 연결 3, 삭제/추가와 저장소 재사용 3, 여러 target의 전체 후보 3, 실제 caller 파일 충돌 2 PASS. 누락된 본문/호출자 선택, 잘못된 hash/원문/값/다른 소유 및 모순 해제 거절과 원문/checkpoint 보존을 포함한다. 다중 target은 모든 후보/record 검증 및 portable 컴파일 결과이며 Windows 실행을 뜻하지 않는다.
- 실제 UI: 독립 창의 혼합 저장·Undo/Redo·cold·Review 취소/Confirm 2, 독립 창의 타입 변경 쓰기 실패/재시도/Confirm 3, 삭제 저장·조회 응답 유실과 receipt/cold 복구 2, 기본 창의 명시 변경 취소/cold 2, 타입 변경 뒤 실제 동시 편집 보존/저장 거절 2 PASS.
- 기존 Native 계약 회귀 7, 일반 ABI 어댑터 3, out 이름 변경 실제 API/컴파일 회귀 2 PASS.

초기 혼합 UI 검사는 실제 저장 후, 타입 벡터가 같아 그대로 보존된 import 선언까지 변경 그룹에 포함해야 한다는 fixture 기대 때문에 실패했다. 첫 보완도 그 선언이 dirty checkpoint에 존재한다고 잘못 가정했다. 변경 그룹은 실제 바뀐 선언/graph를 확인하고, 바뀌지 않은 import는 원문 byte 보존과 저장본 존재 시 동일성을 별도로 확인하도록 수정했다. API와 UI의 전체 저장·재시작·컴파일 Confirm을 다시 통과했다. 엔진의 source/CAS 검사를 완화하지 않았다.

## 남은 조작

이번 지원은 root input을 **직접 읽는 일반 code 값 인자**다. 같은 입력이 call 노드의 인자, 수식/복합 바인딩, 별칭/locals, exit/내보내기 또는 switch/중첩 문맥에서도 쓰이면 해당 연결의 명시 대체 어댑터가 아직 없어서 전체 후보를 거절한다. 다음 연결 단위는 그중 **일반 call 인자의 직접 root 값 연결**과 이후 **code 값 표현식 전체의 명시 대체**다. 원래 값/연결의 증거와 타입 검사를 같은 후보에 추가하는 기존 설계 범위다.

C# 본문 자동 재작성·전체 구현 문맥·복잡한 ref/out은 별도 잔여다. 출력 타입/추가삭제·반환 편집, 등록/복사/중첩 경로, 여러 함수 동시 후보와 외부 타입 선택도 [고정 목록](V536_I5_6_REMAINING.md)에 유지한다. I6/B2 및 A4~A6/M4/M11/M12, Helper 실제 작업은 이번 범위가 아니다. 실제 Windows apphost/WebView2·모바일 기기·Library 전달은 별도 미검증이다.
