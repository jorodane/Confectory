# 입력·노드 결과 슬롯의 별칭 로컬

`sync-acyclic-alias-locals-v1` / `feature-blueprint-source-v8`은 기존 입력 또는 노드 결과 저장 슬롯에 로컬 이름을 붙인다. 값을 복사하거나 별도 저장 공간을 할당하지 않는다. 기존 v5 초기값 로컬과 v7의 외부 ref/out·종료 경고·전체 본문 전환 계약은 유지하며 기존 graph를 읽기만으로 올리지 않는다.

```json
{"id":"borrowed","name":"계산결과","type":"long","source":{"node":"calculate","output":"return"}}
```

기존 `{id,name,type,initial:{constant:...}}`은 그대로 호출별 독립 저장 공간을 만든다. 새 `source`는 현재 함수의 값/ref 입력 `{"input":"n"}` 또는 노드의 주 반환/이름 있는 out 결과만 허용한다. out 매개변수 자체는 입력 슬롯으로 취급하지 않는다. source에 상수·다른 local·property·배열 원소·계산식을 넣지 않는다.

별칭 선언의 원본 존재와 타입은 미사용 상태에서도 확인한다. 실제 읽기·ref 인수·구조적 set의 대상은 모든 사용 경로에서 생산 노드가 먼저 실행되어야 한다. 형제 분기나 나중 노드의 결과를 사용하면 `GRAPH_VALUE_UNAVAILABLE`로 거부한다. 선언만으로 노드를 실행하지 않으며 새 수명·공유 상태·루프를 만들지 않는다.

`{"local":"borrowed"}`를 읽으면 현재 원본 슬롯을 읽는다. set으로 쓰거나 ref로 전달하면 같은 원본 슬롯이 바뀐다. 값으로 이미 전달해 다른 노드가 반환한 결과는 기존 값 스냅샷을 유지한다. 배열 요소를 공유하는 것과 배열 변수 자체를 참조하는 것은 구분하며, 별칭을 ref로 넘겨 새 배열로 교체하면 원본 결과 변수도 바뀐다. 외부 ref 입력을 원본으로 삼으면 실제 caller 저장소를 따르고, 값 입력이면 현재 함수의 값 매개변수 슬롯만 바꾼다.

노드 out 결과에 붙인 별칭은 그 노드 결과 슬롯이다. v7의 직접 전달 노드가 호출 후 만든 out 스냅샷을 외부 out 매개변수 자체의 별칭으로 바꾸지 않는다. 기존 초기값 로컬과 별칭의 저장 방식·타입은 생성 뒤 암묵적으로 바꾸지 않으며 새 로컬을 명시적으로 만든다. 별칭의 이름·동일 타입의 source 연결 편집은 기존 소유 소스 CAS와 명시적 Apply를 따른다.

소스가 있는 노드는 연결선·값 사용뿐 아니라 미사용 별칭에서도 참조되면 제거를 거부한다. 먼저 별칭 또는 그 사용을 명시적으로 정리해야 한다. 기존 C# 원본 파일은 graph 제거 후에도 보존한다. 별칭이 set/인수/반환에서 사용되면 로컬 삭제를 거부한다.

공개 편집의 새 별칭 행은 `sourceJson`을 문자열로 제공하며 기존 초기값 행의 `initialJson`과 긴 정수 원문을 바꾸지 않는다. 폼은 현재 입력·정확한 타입의 노드 결과를 선택해 미적용 JSON 입력에 준비한다. cold 복원은 입력을 보존하고 basis 권한을 되살리지 않는다. graph-only Save/Review/Confirm과 compiler 검사를 유지하며 읽기·복원으로 Run·AI·Task를 시작하지 않는다. 외부 ref 계약을 재검토해도 v8 profile을 v7로 내리지 않는다.

남은 계산식의 고정 폭 정수 범위 초과 동작은 사용자 결정 대기 중이다. v480 원본의 숫자/문자열 연산 목록은 확인했으며 이 단위에서 추정하거나 구현하지 않는다. property, 중첩 graph, enum/복합 타입·확장 실행 포트, split C#·외부 helper, loop/async 등은 별도 후속이다. main·원본 ZIP·Android 설정·실제 계정·유료 모델·사용자 PC·native/device 경계는 유지한다.

## 실행 검증

동일한 제품 소스에서 엔진·공개 편집 **53/0/0 (862.12초)**, Chromium UI **11/0/0 (809.751초)**, Windows/Android 관리 대상 컴파일 **1/0/0 (139.887초)**을 확인했다. 초기 집중 6/0/0 (188.177초)과 중복 합산하지 않는다. 이후 제품을 바꾸지 않고 이름 있는 out 결과 별칭의 실제 저장소 구분 및 창 경계·화면 캡처 시험을 보완해 별도 2/0/0으로 확인했다. 각 단계의 소스 해시와 차이는 [검증 근거](evidence/v480-integration/alias-locals.json)에 보존한다. 일반 Git 체크아웃·리소스 시작은 구현 커밋 후 별도로 확인한다.

실제 결과 별칭 ref/set은 `32,20`을 반복 호출해 캡처 값 20과 현재 원본 슬롯 32를 구분했다. 입력 별칭은 같은 caller ref일 때 `30,15`, 다른 caller일 때 `21,10,11`, 배열 결과 변수 교체는 `40,20`을 반복 확인했다. 직접 전달 노드의 이름 있는 out 스냅샷을 40으로 바꿔도 외부 caller 슬롯은 `640,6` / `540,5,6`으로 보존했다. 공개 편집은 graph-only Confirm 전 `5,5`, 후 `32,5`를 확인했다.
