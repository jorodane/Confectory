# v480 현재 지원 범위와 검증 지도

`main@32dd44fbec6e9e39a7e3e68c0ca61d62bb47176f`의 v480 ZIP을 읽기 전용으로 대조했다. 원본 SHA-256은 `0489844c8c6d90f7cdc8ea0e80628f487dcfb27f2c871b19367a635212d3c5bd`다. 이 문서는 이전 단계의 “미구현” 표시를 최신 범위로 교체한다. 과거 단계의 검사 수는 현재 합계에 더하지 않는다.

**전체 v480 완료 또는 모든 화면·클릭의 전체 회귀를 뜻하지 않는다.** 아래 “지원”은 적힌 계약의 범위이며 나머지는 [하나의 우선순위 목록](V480_REMAINING_WORK.md)에 모았다. [기계 판독 지도](validation/v480-scope-map.json)는 각 행의 ZIP 함수, 실제 구현 파일, 정확한 최종 검사 메서드를 연결한다. 행별로 반복 인용한 메서드를 별도 검사로 합산하지 않는다. 최종 결과와 기준 소스는 [통합 검증 기록](V480_INTEGRATED_VALIDATION.md)을 따른다.

[후속 ENV4 진단](V480_ENV4_DIAGNOSIS.md)에서 실제 Run PID와 조회 PID, 두 runtime의 lease 사용 순서, 4 CPU의 gate 스케줄을 별도로 측정했다. 이후 검사 보정은 새 runtime 기능/ABI 확장이 아니며, 이전 235개 결과와 후속 관련 회귀 수를 합산하지 않는다.

## 해석과 보존 조건

- `property-set`은 명시적 receiver/value와 owner/field hash를 검사한다. 실제 `property-ref`는 general 단일 bool/int/long만 지원하며, 값 읽기 결과의 일반 슬롯과 구분한다. 기존 profile·v1 instance는 자동 이관하지 않는다. [Set 계약](BLUEPRINT_PROPERTY_SET.md)과 [field ref 계약](BLUEPRINT_FIELD_REFS.md)을 따른다.
- 실제 Run은 최종 compiler 산출물을 별도 프로세스로 실행한다. frame/ack는 협력적 callback 완료의 관측이다. 새 호스트의 기록 복원은 실행 권한 복원이 아니다. [제어](V480_LOCAL_RUN_FRAME_CONTROL.md)와 [비권한 기록](V480_RECORDED_RUN_HISTORY.md)을 따른다.
- 동일 소스의 6 gate 동시 부하 실패와 낮은 부하 재검사는 ENV4에서 별도로 추적한다. 단독 재검사 통과는 동시 부하 안정성의 증거가 아니다.
- 소유 fixture, 무실행 compiler probe, 관리 프로필 컴파일, Linux X11 dummy native, 실제 계정/장치는 각각 다른 근거다. 컴파일과 fixture를 실제 서비스·장치 성공으로 확장하지 않는다.
- main·원본 ZIP·Android 설정을 보존한다. 새 ABI·제약 field ref·overflow 정책·소스 삭제/참조 치환·영속 실행 권한·CSP·실계정 설치는 이번 범위에 추가하지 않는다.

과거 개별 단계의 근거는 [v480 통합 연혁](EDITOR_V480_INTEGRATION.md), [호환성 검토](EDITOR_V480_COMPATIBILITY_REVIEW.md), 각 기능 계약 문서와 `docs/validation/`의 이전 기록에 남는다. 해당 시점의 수치와 미완료 표시는 현재 표를 덮어쓰지 않는다.
