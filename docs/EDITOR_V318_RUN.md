## Restart boundary and required contracts

Execution records are owned in-memory by a ProjectExecution session. Observe/Stop accept a handle in that session; there is no public persistent execution identity, PID/start-time observation, owner rebind or stale-host reconciliation port. Cold restoration re-reads the new actual host state and reports no owned execution record. It does not claim a previous process stopped, exited or belongs to the new host; it never automatically builds/runs/stops it. Actual owned fixture process observation is kept as test evidence, not imported as product authority. Crash survivors cannot safely be adopted or killed by guessed PID/process-name scanning.

For durable process recovery the provider needs a bounded, validated persistent launch identity and explicit observation/rebind lifecycle with PID plus start identity, project/entry/target/owner identity, lease/concurrency and stale-owner handling; existing Stop authority must remain explicit. Embedded rendering needs a public child render-surface acquisition/attach/release and input routing contract across supported hosts. Pause/step needs runtime scheduling/control capability and acknowledged state, not OS signal approximation. Standalone build needs a public owned build-job start/observe/output/stop contract that cannot launch a child. None is added or silently inferred in this increment.

## Next increments: Yogi then augmentation

YogiBox Snapshot contains actual semantic item IDs/revisions/metadata, description/sealed state and pending capture records, but Create is session-only and no bounded durable load/import port exists. A provider-owned persistent Open/Save/Load/Close contract should use the ordinary FileStream CAS and bind project/owner identity, validate schema/capacity and preserve item identity. Reload should query actual semantic IDs/revisions to mark stale/deleted entries. Pending captures must become unavailable/interrupted, never recapture automatically. Restoring local items must not replay Exactly, Seal, Receive/Handoff, approval or delivery. Existing send/merge policy remains undecided. The current consumer retains only unsubmitted description input and cannot claim package content persistence.

Augment already has local `custom` (bounded text, current semantic scope and durable record) and `skip` (reason plus clear current batch) commands. Their owning Augment view is private to ProjectAI; the public consumer has Propose/Select/Work, not a scoped local custom/skip bridge. A public owner/lifecycle-safe forwarding port can reuse those operations without provider calls. It must retain actual Helper/project/scope, CAS and command idempotency, and must not invent cards or next offers. Local custom/skip should remain available through a deliberate local lifecycle rather than requiring a live paid provider. Existing `cancel` applies to a selected task only before staged/confirmed source; it cannot implement general proposal discard. Mapping a UI discard to skip of the current unselected batch versus cancellation of a selected task is a separate policy decision. No new policy is fixed here.
