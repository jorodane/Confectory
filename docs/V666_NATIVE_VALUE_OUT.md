# 원래 C# 값 입력의 명시 out 전환과 공동 저장

고정7/8행의 역할·계약·본문 결합 중 직접 소유한 동기 scalar-return C# 기능의
값 입력→out을 기존 C# Script 매개변수 영역에서 편집한다. 이름·타입·수·순서·반환과
다른 인자의 역할을 유지하며, 기존 Blueprint 호출 입력의 정확한 해제를 직접 선택한다.
이전 출력과 나머지 입력은 identity로 유지하고 새 out은 자동 연결하지 않는다.
이는 원래 v666 Blueprint C# 형식 매개변수 편집과
[V536 whole-contract 범위](V536_I5_6_WHOLE_CONTRACT_SCOPE.md)의 명시 역할/입력 해제 원칙을 따른다.
상세 팝오버에 새 역할 메뉴나 다른 레이아웃을 만들지 않는다.

공동 저장은2~8개의 직접 소유 기능·각 구현의 단일 native target·일반 직접 Blueprint
호출자 범위다. 원래 source에서 각 기존 단일 후보를 독립 검증하고 동일한 caller를
내부 overlay에서 합친다. 원래 hash·선택한 바인딩·컴파일 검사를 생략하거나 live source에
계획을 rebase하지 않는다. ref·반대 방향·이름/타입/순서/반환 동시 변경은 이 단위 밖이다.
전체/retained C#의 기존 역할 편집과 원래의 단일 계약 경로는 유지한다.

본문은 사용자가 직접 편집한다. 매개변수 역할만 바꾼 경우 textarea의 줄바꿈 정규화가
원문을 바꾸지 않도록 원래 C# 텍스트를 보존한다. 값/out 양쪽에서 유효하도록 이미
할당한 원문을 검증 fixture에 사용한다. 명시 계획의 unchanged body도 기존 atomic group의
read member로 보관하여 후속 설명 저장·cold·Review/Confirm에서 동일한 source proof를
유지한다. 실제 본문 파일은 쓰지 않는다. 새 baseline/경로/권한/profile/저장 문법을 만들지 않는다.

거절·취소·Undo/Redo·미저장/저장 cold·checkpoint 실패/재시도·응답 유실·늦은 입력·
후속 설명/기능 메타데이터 저장·source CAS를 검증한다. C# BOM/CRLF·바이트와 파일 metadata,
실제 IInvoke value/out ABI·반환·호출 실행을 확인한다. Linux 자동화와 Windows 교차 package는
실제 Windows/WebView2·물리 기기·전체 UI 전수 검증을 뜻하지 않는다.

남은 같은 고정7/8행은 다른 역할/입출력 정의 결합, opaque/private 명시 계획,
선택 native callee 사이 의존성과 다른 원래 import/등록 외부 관측 결합이다.
구 Reference reader의 새 타입 거절은 역사적 호환 제약이며, 새 group 재검토는 같은
게시 세대 도구 기준이다. 과거 간헐 빈 #app 원인은 미확정이다. M11/M12/M4를 회귀 없이
재개하거나 optional 조합·migration을 새 필수로 추가하지 않는다. 부모/외부 원본·override·
권한·Review/Confirm·최종 CAS·main과 보관 증거를 보호한다.
