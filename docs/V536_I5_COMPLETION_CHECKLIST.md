# v536 I5: 정보 기능 영역의 완료 조건

기준은 저장소 `reference/site-ui/Confectory-Editor-Prototype-v536.zip`의 v536 화면과 기존 선언 문법이다. 새로운 사이트나 새로운 레이아웃을 구현 기준에 섞지 않는다. 이 표는 정보 카드의 I5 조작을 분리한 것으로 전체 v536 UI 완료 표가 아니다.

아래 여섯 항목을 고정 잔여 수용 목록으로 관리한다. 새 조합을 추가하여 완료 조건을 넓히지 않는다. 이 여섯 항목 밖의 I6/B2, A4~A6, M4/M11/M12 및 Helper 실제 작업은 별도 후속이다.

| 번호 | 고정 잔여 | 현재 상태 |
|---|---|---|
| I5-1 | 독립 창 모듈 편집/가져오기 | 기본 창과 같은 지원 경로 완료. 직접 본문·선택·등록/상속 C#/Blueprint 복사·import와 창별 입력/CAS/복원을 검증했다. 기본과 동일한 기능 가져오기+일반 값 혼합 차단은 유지한다. |
| I5-2 | 공유·상속·복사 구현 삭제 수명 | 지원 경로 완료. 공유/상속/사용 중 copy는 소유 연결만 보관하고 원본을 유지한다. 명시적 로컬 연결·등록/출처·독점 참조가 확인된 소유 copy는 등록/본문 closure를 복구 가능하게 보관한다. 기본/독립 창·오류/유실/경합·cold·Review/Confirm 검증은 VALIDATION_V536_INFORMATION_COPY_RETIREMENT.md 및 연결 수명 문서 참조. |
| I5-3 | 삭제 후 새 구현 생성 | 직접 소유 정보 함수의 지원 경로 완료. 새 고유 ID/경로와 이전 archive를 분리하고, 새 provider가 있으면 이전 복구가 덮어쓰지 않는다. 상세 범위는 VALIDATION_V536_INFORMATION_REIMPLEMENTATION.md. |
| I5-4 | 독립 창 함수 전체 삭제 | 지원 경로 완료. 기본/독립 창·미확정 생성 함수·복구 취소 후 재복구·실패/경합/응답 유실/재시작·Review/Confirm을 검증했다. |
| I5-5 | 함수 순서 변경 | 지원 경로 완료. 원본 제목 드래그·Alt+↑/↓, 기본/독립 창·Undo/Redo·취소·원자 저장·응답 유실·충돌·프로젝트 전환·cold·Review/Confirm을 검증했다. 함수 식별자·핀·본문·참조는 바꾸지 않는다. 상세 범위는 VALIDATION_V536_INFORMATION_FUNCTION_ORDER.md. |
| I5-6 | 연결된 함수 전체 계약 편집 | 기본 미연결 핀 편집과 별개로 구현·호출자 계약 변경은 미완료. |

기존 지원 및 각 항목의 구체적 완료 조건은 다음 표에 유지한다.

| 조작 | 현재 상태 | 완료 조건 |
|---|---|---|
| 독립 정보 창의 자체 함수 `직접 작성`·`편집` | 직접 단독 소유 Blueprint의 C# 본문·노드 설명·구현 설명을 연결했다. API 7/실제 화면 normal 5 및 쓰기 실패·경합·응답 유실·프로젝트 전환을 검증했다. 상세 범위는 VALIDATION_V536_INFORMATION_VIEW_BODIES.md. 모듈/copy/구조 변경은 포함하지 않는다. | 첫 본문 생성과 기존 본문 열기, 창별 입력/receipt, C# 취소·Undo, 저장·실패·충돌·응답 유실·cold·프로젝트/창 전환·Review/Confirm·같은 창 재편집을 통과한다. primary 선택/미저장 입력을 바꾸지 않는다. |
| 독립 정보 창의 모듈 슬롯 `편집` | 기본/독립 창의 직접 단독 구현 및 저장 copy 본문 편집을 연결했다. source/intent/구현 설명을 해당 정보 provide/basis로 검증한다. 상세 검증은 VALIDATION_V536_INFORMATION_MODULE_VIEWS.md. | 해당 정보에 직접 연결되고 단독 소유하는 지원 본문만 수정한다. 공유·상속·등록 팩 원본은 복사 선택 경계를 유지하고, 다른 슬롯/target/창 입력을 보존하여 동일 저장·검토 흐름을 검증한다. |
| 독립 정보 창의 모듈 슬롯 `직접 작성`·`기능 가져오기`·구현 선택 | 기본 선택창을 독립 창 surface에 연결했다. 기본·상속·등록 C#/Blueprint 선택, private copy와 exact64 정보 값/여러 슬롯 원자 저장, 등록 callable import, 실패/충돌/유실/cold/Review/Confirm을 검증했다. 기능 가져오기 선택+일반 정보 값 혼합은 기본 창과 같이 명시적으로 거절한다. | 원본 선택창에서 기본·상속·등록 구현과 실행 대상을 선택하고 해당 정보의 새 private copy 또는 import만 저장한다. 원본/부모/다른 target 불변, 여러 슬롯 원자 저장, 취소·cold·명시적 Confirm을 검증한다. |
| 자체 함수/모듈 슬롯의 `구현 삭제`와 복구 | 확정된·미변경 자체 함수 + 직접 단독 구현의 기존 closure 보관을 유지한다. 공유/상속/저장 copy와 모듈에는 현재 정보의 직접 provide만 보관·복구하는 수명을 연결했다. 물려받은 연결만 있으면 삭제하지 않는다. 공유/부모/등록 팩과 다른 사용처는 유지한다. 독점 소유가 증명된 로컬 copy는 등록·구현·모든 본문 closure를 원자적으로 보관·복구하며 파일은 영구 삭제하지 않는다. 다른 원자 편집 그룹이 진행 중이거나 소유/계약 근거가 부족하면 먼저 완료하도록 차단한다. 연결·단독 구현·copy 수명의 검증 문서를 구분한다. | 함수 이름·입출력 정의와 함수 선언/contain 등록은 유지한다. 해당 정보의 구현 연결/본문 수명만 분리하고 원문을 보관한다. 공유·상속·참조 대상 원본을 영구 삭제하지 않는다. 원본 확인창·취소·Undo/Redo·저장·복구·재시작·명시적 Confirm을 기본/독립 창에서 검증한다. |
| 구현 삭제 후 새 구현 작성 | 확정된 직접 소유 함수 선언의 첫 구현 이름은 호환 유지한다. 이전 unit/파일/디렉터리/archive가 이름을 예약하면 새 GUID 구현·본문을 생성한다. 기본/독립 창·미확정/확정 archive·실패/경합/생성 응답 유실·C# 및 Review 취소·cold·Confirm을 검증했다. 공유/상속/copy 삭제 수명은 I5-2로 분리한다. | 새 고유 구현/본문 후보를 명시적으로 생성하고 기존 archive/다른 target을 보존한다. 새 provider가 있으면 이전 archive 복구가 덮어쓰지 않으며 저장/취소/cold/Confirm을 별도로 검증한다. |
| 독립 정보 창의 자체 함수 × 삭제·복구 | 기본 창의 기존 거래를 bound 독립 창에 연결했다. 직접 소유 자체 함수와 단독 구현/본문의 복구 가능한 삭제·복구를 검증했다. 공유·상속·copy 원본의 확장 수명은 I5-2로 분리한다. 상세 검증은 VALIDATION_V536_I5_DETACHED_ARCHIVE.md. | bound view/정보에서만 함수·단독 구현의 완전한 archive 거래를 허용한다. 다른 창 입력, 참조 보호, 원자 변경 취소·응답 유실 조회·cold·Review/Confirm을 기본 창과 같은 경계로 검증한다. 구현만 삭제와 혼동하지 않는다. |
| 자체 함수 제목 드래그 및 키보드 순서 변경 | 원본 `bindOwnFunctionReorder`의 제목 드래그와 Alt+↑/↓를 기존 정보 기본/독립 창에 연결했다. 읽기 전용 행의 상대 순서와 상속 정의는 보존하며 정확한 로컬 contain permutation만 저장한다. | 직접 소유 함수만 정렬하고 상속·override 행은 보존한다. 저장된 contain 순서·Undo/Redo·취소·cold·Confirm까지 원래 행/핀 식별성을 유지한다. |
| 구현/호출이 연결된 자체 함수의 입출력 계약 변경 | 미연결 기본형 핀의 기존 생성/편집과 구별되는 미완료 경로다. | 원본 핀 편집에서 이름·타입·순서·추가/삭제·값/ref/out을 바꿀 때 구현·호출자·기존 연결·정확한 값을 함께 검증한다. 비호환 변경은 원문을 보존하고 전체 미적용한다. 새 언어 타입을 임의로 추가하지 않는다. |
| `설명으로 작성`의 실제 Helper 작업 | 현재 차단. UI 완료 후 에디터 도구 감사/실제 작업 구현 단계로 사용자가 별도 순서를 정했다. | 실제 제공 도구와 없는 도구를 감사한 뒤 범위 있는 초안 편집·저장으로 연결한다. 실행/최종 Confirm 권한을 자동 부여하지 않으며 이번 UI 검증에서 실제 계정·유료 모델을 호출하지 않는다. |

원본 구현 삭제 근거: `confirmFunctionImplementationDeletion`은 이름과 입출력 유지, 필요 시 상위 구현 fallback을 안내한다. `deleteFunctionBody`는 blueprint/compiled/body/codeLanguage/importedFeatureId/importedFeatureName/implementationRevision을 지우며 함수 정의 자체를 삭제하지 않는다. 엔진 연결은 이 수명 차이를 보존하고 복구 가능한 기존 저장·초안 모델로 처리해야 한다.

각 지원 단위는 검증된 뒤에만 완료로 바꾼다. Windows 교차 패키지 검사, 실제 Windows apphost/WebView2 실행, 브라우저 폭 검사와 실제 모바일 기기 검증은 서로 구분한다. I6 아이콘, B2 실제 배지와 A4~A6/M4/M11/M12는 이 I5 표 밖의 기존 후속 목록을 유지한다.
