# M4: 정보 자체 함수의 비동기 생성·배정

저장소 v666 `app.js`의 정보 자체 기능 직접 작성/편집과 `blueprint.js`의 명시 async
메뉴가 기준이다. 기존 소유 정보의 `contain function`과 단독 `provide`로 연결한
직접 함수/구현을 다룬다. 새 함수·첫 구현·graph·C#이 아직 물리 파일이 아니어도
그 생성 그룹 전체를 비동기 후보/Save/Review→Confirm에 연결한다.

## 계약과 소유권

- 정보의 실제 원본 hash, 동일 namespace의 등록, 직접 contain 및 함수의 소유 ID를
  확인한다. 구현은 그 함수의 직접 구현이고 같은 정보가 단독 배정해야 한다.
- 새 함수/구현의 원본 ID·경로 부재, graph/body locator와 코드 record를 함께 증명한다.
  이미 Confirm한 자체 함수의 첫 구현도 동일한 증명에 따르며, 기존 IO를 유지한다.
- 함수의 첫 명시 전환 계약과 정보 owner를 receipt에 보관한다. 생성 그룹은 정확한
  정보·함수·구현·graph·코드·프로젝트 등록 전체가 일치할 때만 합류시킨다.
  다른 미완료 편집 그룹을 묵시적으로 끌어오지 않는다.
- 전환 후보/복원/Review/최종 CAS가 정보의 contain/provide, 원본, 등록과 모든 새
  파일의 `missing`을 유지한다. 다른 owner·공유 구현·참조/부모·기존 ID 재사용을
  정보 편집 화면의 권한으로 바꾸지 않는다.

새 직접 소유 정보 함수의 빈 scaffold만 현재 method/switch 프로필을 사용한다.
요구 슬롯의 참조 구현이나 기존 legacy 본문을 자동 전환하지 않는다. 직접 소유
함수의 Root 계약 전환과 단순히 어떤 정보에 배정한 다른 함수의 계약 변경을 구별한다.
권한/독립 창 연결은 기존 서버의 owner/view binding과 실제 최종 저장 검사를 따른다.

C#은 사용자가 명시적으로 편집한다. 비동기 호출자를 명시 전환하기 전에는 오류이며
자동 대기/전환하지 않는다. 공개 override IO·원본 C#·연결·레이아웃을 유지한다.

## 유한한 잔여

이 경계는 정보/프로젝트 원본이 이미 존재하는 직접 소유 함수다. 새 정보 컨테이너와
첫 생성 Save 전 여러 입력의 결합을 현재 순서 제한의 영구 UX 정책으로 확정하지 않는다.
private/internal graph의 명시 Task 계약과 첫 생성 Save 전 입력 결합은 다음 M4다.
M11/M12는 구체적 회귀 없이 다시 열지 않는다. 기존 고정 V1 검증/V2–V9·팩/backend·
종류 호환성과 실제 기기·전체 UI·Space 전달은 별도 잔여다.

## 검증과 호환성 경계

개발 단계에서 소유/위조/공유/등록/IO/그룹 거절, 실제 생성·cold·Review 뒤 정보/등록
충돌·Confirm·같은 정보 scope의 실제 await 실행과 동기 호출자의 거절을 확인했다.
독립 정보 창의 정상 UI와 기본 창의 응답 유실/늦은 입력 UI를 확인했다.
검사 초기 창 겹침은 입력 전에 본문 창만 실제 드래그로 옮기는 생성 fixture로 분리한다.
카드 크기/배율/제품 배치는 바꾸지 않는다. 메뉴/Save/Confirm은 실제 브라우저 경로다.

UI의 정보 본문 분류에서 단일 async 입력이 누락돼 기존 순차 편집 분기로 들어가던
실제 연결 누락을 수정했다. 서버의 직접 소유 capability가 확인된 경우에만 공통
원자 배치·receipt 저장 경로로 보낸다. 다른 입력과의 자동 결합은 하지 않는다.
최종 source를 동결한 뒤 LF/CRLF·새 패키지/전체 복원은 별도 최종 기록으로 확정한다.

이전 롤백 편집기는 새 정보 소유 async receipt를 거절할 수 있다. 코드 롤백과 이
미확정 생성 초안의 호환성을 구분하고 checkpoint/원문을 보존한다. 새 문법 migration이나
부모/참조 원본 편집 권한을 추가한 것은 아니다.
