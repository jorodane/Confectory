# v536 미확정 same-contract copy 본문 재편집

기존 7행의 **생성·선택·저장한 직접 소유 단일 target copy를 Confirm 전에 다시 열어 같은 계약의 본문을 편집**하는 단위다. 최초 복사·배정은 기존 private copy 거래이며 새 기능이 아니다. v536의 같은 개수·타입·순서 계약 유지와 기존 정보 함수 편집 진입을 따른다. 독립 계약 복제나 새 ID 정책을 만들지 않는다.

실제 화면에서 `missing` baseline을 이유로 본문 조회가 실패했다. 이제 graph/implementation 모두 새 생성 기준이고 original이 빈 값이며 원래 provenance가 같은 경우에만 현재 소유·유일 배정·provider·모듈/직접 포함 함수와 출처를 기존 검증기로 확인한다. 미확정 receipt에는 공개/native 서명을 보관하고 최종 후보에서도 완전히 같은 계약을 요구한다. 부모/외부 원문은 편집 권한이 아니다.

재편집 Save 뒤 Review에서 변경되지 않은 새 구현 header가 빠지는 결함도 발견했다. 기존 Save 후보에서 선택된 새 copy ID의 선언·graph·record 전체만 Review 그룹에 결부한다. 관련 없는 새 선언을 쓸어 담거나 CAS를 완화하지 않는다. 모든 검증과 checkpoint 저장이 성공한 뒤에만 live 상태를 교체하며 Review/Confirm은 별도다.

집중 9흐름과 영향 4흐름, 총 **53개 확인**을 통과했다([실제 기록](evidence/v536-information-pending-copy/focused-verification.json)). 기본/독립 정보 창의 재진입·팝업 취소·불완전 입력 cold·Undo/Redo·저장·Review 취소/재검토·명시 Confirm, 실제 checkpoint 쓰기 실패/재시도, 다른 창 경합·cold 후 재거절, 응답/조회 유실 후 결과 확인·중복 방지, 재편집 취소 후 원래 생성/배정 유지, 두 프로젝트 전환과 닫힌 저장 동작의 문맥 보호를 확인했다. C#/Blueprint 부모 API, receipt 누락/변조·계약 변경·잘못된 C# 및 실제 부모 파일 변경 거절도 포함한다. 원래 부모/함수/호출자·정확한 64비트 값·복사 ID/출처를 보존한다. 기존 confirmed-copy·오버라이드 보호·공유 본문 회귀는 영향 검사로 구분한다.

첫 UI 검사에서 pending 키·보호된 헤더 범위·escaped JSON 비교 오류가 있었고 검사 입력/해석을 바로잡았다. Review 결함은 제품 문제로 수정했다. 실패 로그·fixture는 보존했고 미완료 검사를 통과로 집계하지 않았다. Native Release와 새 Linux 엔진 빌드가 통과했다. UI/adapter/WebBundle **75파일은 이전 게시와 바이트 동일**하며 기존 460px 정보 창과 조작을 재사용한다. 모든 화면의 pixel equality를 주장하지 않는다.

7행의 외부 함수/다중 target copy 및 다른 native 별칭/import·직렬 범위 밖 원본 graph의 실제 연결 경계는 [고정 범위](V536_I5_6_COPY_INHERITANCE_SCOPE.md)에 남긴다. 오버라이드 타입/핀 수/역할/반환 변경은 정상 금지이며 독립 계약 복제는 필수 제외다. 8행의 다른 실제 다중 함수 문맥·9행 고급 함수 타입/표시명, I6/B2·A4~A6·M4/M11/M12는 별도 후속이다. 전체 UI와 실제 Windows/WebView2·모바일 기기·Library 전달 완료가 아니다. 기존 자료는 삭제하지 않았고 이번 검사 소유 복사본만 증거 보관 후 정리했다.
