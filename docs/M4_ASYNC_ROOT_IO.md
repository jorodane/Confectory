# M4: 첫 Confirm 전 공개 IO와 Task 결합

기준은 저장소의 `reference/site-ui/Confectory-Editor-Prototype-v666.zip`
(SHA256 `7b6b4ba585fc46843f09d8bcd15072b704cc2dc994988400b0a25061e0400d23`)이다.
`Confectory-v666/dist/blueprint.js`의 `renderSignatures`, `bindExportOutput`,
`requestDeleteOutput`, `pruneInputLinks`와 기존 M4 명시 async 동작을 연결한다.
원본 입력/출력 편집과 값 선택 팝오버·실행선·C# 편집의 배치를 유지한다.

## 이번 경계

아직 물리 원본이 없는 직접 소유 전역 함수의 한 구현·한 Blueprint target에서
공개 입력/출력 계획, 값/연결, 명시 C#과 Task를 같은 첫 저장 후보에 결합한다.
선언 자체가 미저장인 미리보기와 최초 저장 뒤 Confirm 전의 명시 IO 재편집도
같은 소유 증명으로 다룬다. 기존 C# 원문을 공개 핀 이름에 맞춰 자동 재작성하지 않는다.
지역 동작의 식별자·서명·원문은 유지하고 root 입력 연결만 명시 대응으로 갱신한다.

생성 노드를 먼저 준비하고, 명시적으로 해제한 입력 연결, 공개 계약, 지역 핀/값,
원문, Task 순서로 검증한다. 최종 저장은 기존 authorBatch의 한 checkpoint CAS다.
Review·컴파일·Confirm의 전체 그룹과 최종 물리 CAS는 그대로 사용한다.

신규 계약의 증명은 단순히 파일이 없다는 사실에 의존하지 않는다. 선언·구현·본문의
원래 baseline이 모두 `missing`, 원래 text가 빈 값이어야 하고, 기존 manifest 원본과
hash·새 등록·ID/소유 경로·선택 provider가 일치해야 한다. 부모·copy·다른 owner·기존
경로 별칭·등록 누락·다른 target은 허용하지 않는다. 확인된 새 root 그룹만 async
그룹으로 합친다. 기존 함수/override·공유 계약에 이 생성 예외를 적용하지 않는다.

새 함수가 아직 Confirm되지 않았을 때는 기존 root 계약 계획을 통해 공개 IO를
다시 명시 편집할 수 있다. 검증된 같은 생성 그룹의 현재 선언이 새 계약 관측이며,
이전 Task 생성 당시의 서명을 영구 원본으로 고정하지 않는다. 이미 존재하는 원본의
서명·권한·호출자를 이 방식으로 바꾸지 않는다. 동기 호출자의 오류는 명시 async
전환 전까지 유지하며 자동 대기·호출자 전환을 하지 않는다.

## 보호와 검증

첫 생성 전 Undo/Redo·코드 취소·실패 입력 보존·원래 checkpoint·응답 유실·늦은 C#·
재시작을 기존 개인 입력과 receipt로 연결한다. 관측이 바뀌면 자동 대응을 추정하지
않는다. 최종 확정은 기존 원본·부모/외부·다른 초안과 물리 충돌 자료를 보존한다.
새 입력/출력을 원래 값 선택기에서 편집할 수 있도록, 아직 graph가 없는 미리보기의
출력을 기존 출력 타입 적응으로 오인해 조회하던 오류를 막는다.

[최종 검증 기록](VALIDATION_V666_ASYNC_ROOT_IO.md)에 신규/재사용, 실제 실행·패키지·
복원·보관의 확인 범위를 확정한다. 현재 구현/개발 검사와 최종 동결 검사를 구분한다.

## 남는 범위

완료/결과 분기선에 생성한 새 동작의 첫 Task 결합은 다음 단위이며 여기서 구현하지
않는다. 비소유 원본 편집·override 공개 IO 변경·ref async 거절은 정상 보호다.
정보 owner·이미 있는 원본·복수 구현의 계약은 기존 공동 갱신 경계를 유지하고,
독립 새 계약 복제나 legacy 자동 변환을 필수 요구로 추가하지 않는다.
M11/M12·기존 V2–V9·팩/backend·종류 호환성 결정과 실제 기기/전체 UI/Space 전달은
이번 단위로 완료 처리하지 않는다.
