# Project Chat

`Confectory.ProjectChat::OpenHost(hostStorage, projectId, hostParticipant)` is an optional local text model. The trusted composer supplies a private, machine-local storage directory, the existing durable project UUID, and the host identity. It holds one active owner per project and storage directory and closes that owner when the host stops. The model does not authenticate caller-supplied identities.

The returned native handle is a tuple of `Join`, `Send`, `Read`, and `Close`. Only the composer holds that handle. After admitting a participant, it gives the connection only the tuple of `Send`, `Read`, and `Leave` returned by `Join`. The connection uses the admitted identity for every send and can read only messages committed after it joined, including its own messages. `Leave` revokes that connection. `Close` revokes all connections. Each `Read` returns ordered JSON rows containing `id`, `sender`, and `text`.

The host commits to `project-chat/<projectId>.json` inside its local storage before a successful send becomes visible. All public messages use that one journal. The model does not open a participant or Helper store. Reusing the same lowercase GUID in `N` form with the same sender, text, and attachment snapshot acknowledges the original commit without appending or delivering a message. Reusing it for a different submission fails. A conflict between host writes requires reopening the host. The bounded model rejects more than 256 messages, 4 MiB of journal data, or 16 simultaneous connections per host.

`OpenHostWithAttachments(hostStorage, projectId, hostParticipant, manifest)` uses the same host model. Its host and connection handles append `SendAttachment(messageId, text, box)` and `ReadAttachment(messageId)`. The trusted composer supplies the canonical manifest of the already selected project. A send requires a sealed YogiBox bound to that exact manifest, project, and sender. The local receiver commits the frozen description, LaY image data, and EY references with the message. Attachment reads require access to that message in the host history or in the connection's own inbox. Message lists only expose an attachment ID. A consumer resolving an EY still needs its own authorized workspace access. The original YogiBox receiver selection and default refusal remain in place.

The existing text handle and v1 text-only journals still work. The first attachment upgrades the same journal to v2 and binds attachment access to a hash of the canonical manifest path. Readers predating v2 refuse that journal. No separate attachment file is created.

The desktop EditorHome bridge declares the read-only `readPublicChatHistory` observation. It accepts an empty input and uses the active session's verified Linux creator, original manifest, and profile storage. It reads the journal bound to the local editor participant `local-user`. It returns ordered message rows and attachment IDs with the current `projectActivation`. Home, revoked authority, and an unreadable journal return an unavailable status without message data. An authorized view with no journal returns an empty list without creating a file. A new activation invalidates older mounted scopes, including after reopening the same project. The Chat surface displays stored rows in its existing list with a public sender prefix and keeps the existing Helper output and composer independent.

`readPublicChatAttachment` accepts the exact `messageId` and `attachmentId` from a history row. It returns the frozen description and item metadata. `readPublicChatFirstImage` and `readPublicChatSecondImage` take the same pair and read at most one bounded LaY capture per observation. An EY target is exposed only when both the active owned draft and the current manifest identify the registered declaration. The viewer rereads that authorization before invoking the editor's existing selection action. On project activation change or authority loss, it discards pending replies and clears the display. The bridge does not retain a host handle, write a journal, or send a message.

Build the Release CLI, .NET target, and element-authoring tool, then run `python3 tests/packs/project_chat_model.py`. The script accepts a checkout containing prebuilt tools as its optional argument. It uses disposable projects and starts a second .NET process to check recovery and connection scope.

Run `python3 tests/packs/editor_public_chat.py` with Linux Chromium and Playwright to verify the actual editor bridge against those storage and activation boundaries.
