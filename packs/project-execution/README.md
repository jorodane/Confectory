# ProjectExecution

A reusable session/handle capability for any ProjectPack, including the engine itself. No editor entry, game/host hierarchy, Helper or multiplayer dependency. Supply exact ProjectPack path, entry ID and target. Desktop Launch returns immediately with a unique stable handle; an owned worker builds via existing public compiler APIs and selects the entry in-memory, then runs the linked result. A per-project exclusive build lease prevents concurrent workers racing the same cache.

Session tokens and handles are opaque. Observe returns `[handle,state,project,entry,target,exitCode,error]`; states are building, running, exited, failed or stopped. Stop affects one owned worker tree and is idempotent for terminal handles. Poll consumes terminal notifications once as `[handle,state,exitCode,error]` records. Observe after Poll still retains state. Unknown/cross-session handles fail. Disposing a caller-owned session stops all workers, releases host resources and rejects later calls. View or project-context closure does not dispose an execution session. Operations are caller-serialized; worker status completion synchronizes on the private session registry. Host objects use session-specific AppDomain keys, released at disposal; no global shared project/model is inferred.

Configure `CONFECTORY_PROJECT_EXECUTION_HOST` to the built `targets/project-execution-host/bin/Release/net8.0/Confectory.ProjectExecutionHost.dll` and `CONFECTORY_DOTNET` to the host. Arguments are passed structurally, without a shell. Build output is retained in the project's local `.confectory` cache; source is never rewritten. Errors are limited to 4096 characters; stdout is drained and not interpreted as commands. Child work is trusted local ProjectPack code, with the same permissions as its caller.

DescribeProject reads declaration metadata without compiling or executing project code. Capabilities explicitly report runtime inspection/calls unavailable; future AI adapters must bind explicit read/call contracts and independently authorized source-edit capabilities. Runtime calls must never masquerade as file edits.

Android overrides keep the same Launch/Capabilities IDs and explicitly produce a failed stable handle with unavailable app-provider diagnostics. No desktop process launch is pretended on Android; platform app/surface launch needs a later provider. Shared handle/state contracts compile for Android, but native app execution is not covered.

LaunchConfigured adds explicit child environment name/value pairs to the same owned launch path. Invalid/duplicate names fail before registration. Launch delegates with empty settings; no ambient project switching. Output drains a bounded 256-line diagnostic queue, truncating each line to 4096 characters and dropping oldest lines on overflow; it never treats output as commands. Engine self launch uses an explicit source ProjectPack, entry and target and distinct native window titles. Android LaunchConfigured reports the unavailable app provider.


`Build(session,project,entry,target)` starts a separate build-only job using the configured execution host and the existing source lease/compiler. It builds confirmed physical source; draft Save is not publication. It never launches the linked application or changes a Run handle. Desktop capabilities advertise build-only, build-job-history and inspect-build-artifacts. Android/browser providers return explicit unavailable failed handles and do not invoke desktop compilation. Their managed-profile probes are not device execution.

Build status adds queued/building/stopping/built/failed/stopped. Observe remains the existing seven-string record; built is terminal for Poll and Stop. Each build record has its own owned cancellation callback. Stop kills and joins that worker tree, then conditionally records cancellation; an already terminal receipt retains its actual outcome. A failed metadata write retains cleanup for retry. `StopBuilds(session)` retires build owners independently of ordinary running projects. Dispose still retires all owned records.

`BuildQuery(session,project,"info",{job,verify})` and `BuildQuery(session,project,"history",{page})` are bounded read-only metadata operations. Facts live in the selected project's private `.confectory/build-jobs/<job>/job.json`, scoped to its exact normalized manifest and a private owner nonce. Host writes use a per-job lock and atomic replacement; terminal outcome is monotonic. A new failed job cannot borrow a previous success report. History is32 rows/page, newest updated first, capacity1024 jobs without silent deletion. New sessions can read historical facts but cannot recover process authority. Active foreign/cold records report owner-unavailable; they are never resumed, killed by guessed PID, or presented as current owned execution.

Successful receipts record final output file names, byte sizes and SHA-256. Explicit verification distinguishes recorded/verified/changed/missing/unavailable; it does not rebuild. Private ownership nonces and filesystem locator fields are excluded from public metadata; diagnostics retain compiler source locations. File enumeration refuses links and path escapes, depth over32, more than4096 files/8192 entries, files above512MiB, total above1GiB or a manifest above1MiB. Oversized receipts report unavailable instead of silently truncating. These are resource bounds, not source/node decomposition rules. Artifact download/export and runtime reconnect remain separate work.
