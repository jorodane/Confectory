# Durable Worker tasks and supervision

Optional project Task/Worker state is separate from persistent Helper memory and Agent execution configuration. Public Open/Assign/Start/Inspect/Checkpoint/Pump/Finish/Cancel/Close manage real task lineage and borrowed Agent runs. Lease/Detach/Recover/Handoff govern explicit Controller/Epoch authority. Authorize gates chief-only augmentation permission; it does not implement augmentation generation. Journal exposes task history; ChiefJournal independently records chief directions/recovery reasons and responsibilities. Worker has no direct user-chat contract. Helper Talk does not recruit a Worker or create a project.

Explicit existing storage directory/project/owner/chief and a borrowed Helper store are required only when this optional pack is selected. Keep Helper store and caller-owned Agent alive until all Task store owners close. Each owner has a distinct handle. Extra owner close preserves live work; final close cancels/drains/releases owned Agent runs, not borrowed Agents. Close failures retain the owner for retry. Provider waits never hold the global store lock. In-flight callback batches are cached until conditional persistence succeeds; sequence identities prevent duplicate application. Idle polls do not rewrite state.

Versioned tasks.json maintains current goal/stage/completion, Worker, owning Helper/project, execution key, progress, checkpoint, verification, remaining work and blocker alongside append-only task history and separate chief journal. Stable command IDs deduplicate directives; mismatched payloads fail. Start persists a dispatch reservation before Agent invocation and uses the stable Worker execution key. Actual request envelope is explicitly worker-task with project/task/Worker/owning-Helper/specification identity; private Helper memory is not implicitly included. Agent completion moves the task to awaiting-verification. Explicit current-controller Finish calls the consumer-selected VerifyCompletion policy on coherent specification/progress/evidence; the default refuses completion. Rejected evidence leaves current state intact. A model response alone does not complete its task goal. No silent replay of running/dispatched tasks. Failed dispatch is durable; failed activation after invocation cancels/releases that execution before reporting persistence failure.

Chief may direct/recruit across teams; ordinary current connected Helper controllers recruit their own Workers. Temporary recovery is explicit chief-only after failed/ended supervisor disposition; slow/unreachable cannot silently become death. Immutable recruitment template supplies temporary Helper personality/expertise. Team ownership/task/Worker/run identities remain intact while controller changes and epoch advances. Old supervisor can inspect as observer but cannot issue new stale-epoch commands. Explicit current handoff is required to restore authority. No live Worker duplication or Worker-to-user-Helper promotion.

Process restart preserves task lineage and journal, marks unavailable process executions interrupted and reports explicit recovery required. It does not resurrect an Agent process or claim exactly-once execution across arbitrary external providers. Pending dispatch cannot be replayed automatically. Chief failure, permanent promotion/return merge, implicit takeover, arbitrary provider resumability and automatic task retry remain undecided/deferred.

First local limits: 1024 tasks, 4096 commands/task events/chief events, 65536 progress characters. Capacity fails explicitly; no silent history deletion. Local caller identities/handles are not internet authorization. No network/account/credential changes. examples/supervision uses an explicitly simulated selected provider while performing actual durable I/O, asynchronous execution, authority checks and lifecycle cleanup. WorkerTasksTests additionally kill an actual private process and verify restart without duplicate provider execution, selected body-only locality and managed Windows/Android target builds. No APK/native Android or native Windows execution claim.

Context(session) returns a fresh project/owner/chief string array for a live borrowed session. Optional consumers can verify project/chief scope before performing any Task side effect; the query neither assigns a Task nor reads private Helper memory. Context is unavailable while the owning Task session is closing.
