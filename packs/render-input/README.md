# RenderInput contracts 0.1

`Confectory.RenderInput::Pump(long[] surfaces) -> int[]` and `Draw(long[] surfaces, int view, int[] rectangles, string[] labels) -> void` are reusable contracts. Native ownership and platform implementations live in Window. BaseUI produces requests; it does not reference a native implementation class. The ProjectPack explicitly selects providers by ID.

Surface tokens are opaque and provided by the platform session. Pump is nonblocking. Each input record is six integers `[view,eventType,x,y,code,flags]`. Types: 1 primary pointer down, 2 up, 3 motion, 4 wheel intent, 5 key down, 6 key up, 7 logical-size change, 8 logical View close, 9 focus/app cancel, 10 expose, 11 source-local pointer cancel, 12 Unicode text scalar (code). Coordinates are View-local logical units. Wheel code uses units of 120 per notch; key code normalizes arrows to Win32 values or X11 keysyms, Enter to 13/0xFF0D, Space to 32, Tab to 9. Key flags mark repeat; Android pointer flags retain pointer identity. Pointer cancel does not release held keyboard sources. Adapters serialize all events on the host UI thread.

A Draw request has five integers per stable render slot `[x,y,width,height,rgb]` and one label per slot. Validate complete shape and positive sizes before native painting. Draw affects one persistent surface; it does not create windows or model instances. The initial renderer is an immediate rectangle/text renderer, not a GPU scene renderer or full accessibility/text-edit system. CP14 Linux text uses installed Cairo/Pango Unicode shaping and Windows uses GDI. Android text metrics/drawing still require app-owned providers. Device scale and safe-area/full accessibility support remain explicit adapter work.

Android overrides the exact same function IDs/contracts. The app-owned native bridge is registered by a per-session opaque token, containing only Draw/Pump delegates in a host context. It is removed on Activity destruction. This is a platform resource capability, not a global model registry or cross-pack implementation reference. Android models, Views, subscriptions, cadence and camera state remain per consumer instance.

## Measured clipped text contracts

`MeasureText(surfaces,view,text) -> string` returns JSON with exact `text`, insets, ascent, font height, line height and lines `{start,text,positions}`. Start/positions use UTF16 indices; each valid scalar boundary has its actual full-run pixel position; surrogate interiors use -1. Limits:65536 UTF16 units,2048 lines. Providers must measure the same font/shaping/style as painting. This is a rendering contract, not a domain or Editor dependency.

`DrawText(surfaces,view,clips,origins,labels)` overlays full shaped lines on the base Draw frame; each line has an xywh clip and xy origin. Consumers construct both from a coherent Field snapshot. Linux Window uses installed Cairo/Pango; Windows Window measures and draws using the same GDI DC/font. Android requires app-owned native text providers; current explicit unavailable providers do not claim Android typography/runtime support. The portable target remains managed build verification only.

`DrawText` origins are the top-left pixel positions of the shaped text layout, in the same client coordinate space as clips. They are not baseline positions. `MeasureText.ascent` is font metadata; callers must not add it to a top-left origin. BaseUI TextLines/Field already produce compatible origins. EditorHome native pixel acceptance checks button text in the upper half of its box to catch baseline-offset clipping.
