# Windows x64 TextServices rendering proof

Public contract: Request(host, operation, payload, parentWindow) -> string. This explicit native pack retains an ITextHost/ITextServices pair created by Msftedit.dll CreateTextServices. It has no child RichEdit HWND and draws native text/selection through Window's public buffered canvas lease. It is **not a completed interactive input provider**; snapshot reports interactiveReady=false. Existing NativeUI desktop consumers remain unchanged.

Operations: create with text, bounds and optional readonly (default true), draw with surfaces/view/bounds/regions, snapshot, focus, pointer, wheel, input-begin/input-end, send and close. Create borrows a live parent on its creating OLE STA UI thread. Successful OleInitialize leases (including S_FALSE) are balanced at close; incompatible apartment creation fails before service allocation. Snapshot projects native WM_GETTEXT/EM_EXGETSEL and host-supplied caret geometry; it does not manually measure text or selection. Draw updates the native client/extent cache on movement, clips each published region, calls TxDraw into the same owned backbuffer and releases the canvas in finally. Native services and default formats persist between draws. Close is idempotent and UI-thread owned. It retires input/focus/timers/capture, releases its queried interface and calls ShutdownTextServices on the retained factory IUnknown before releasing callbacks, formats and measurement DC; it never closes the borrowed parent. No glyph/clipboard/shortcut/Hangul editing implementation is supplied.

Pointer forwards parent-client down/move/up packets after the consumer's common hit/capture decision. Focus sends native focus messages and invokes native UI activation. An attached input bridge routes raw keyboard/IME; host callbacks implement bounded per-object native timers, capture/cursor ownership and buffered invalidation. The proof consumer owns its Window capture and render cadence. Do not select this as an ordinary editable BaseUI NativeInput provider or infer OS keyboard/IME readiness from managed compilation. The raw send operation is a trusted native capability, not a user-text command interface. Coordinates/selection offsets are native UTF16/pixels, not the complete normalized BaseUI bridge contract.

The initial C++ vtable binding explicitly requires Windows x64, where the Windows x64 calling ABI is uniform. It rejects x86. Method ordering/signatures were checked against [Microsoft TextServ.h](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/TextServ.h) and [windowless RichEdit documentation](https://learn.microsoft.com/en-us/windows/win32/controls/about-windowless-rich-edit-controls). Engine composition owns background/border and visible regions; ITextHost requests transparent background and native layout supplies drawing/selection and caret geometry. Real font/layout/focus/IME/DPI correctness requires actual Windows checks.

Linux ABI fixture tests validate host slots/default formats, exported IID query/refcounts, retained independent objects, public-canvas DC/layout/clip consistency, moving layout, native selection projection, thread guards, late-use rejection, cleanup and provider locality. The fixture does not emulate actual RichEdit editing or prove Windows runtime behavior.

Experimental input bridge: input-begin/input-end install and retire a rooted parent HWND subclass on the creating UI thread. Focus explicitly sends WM_SETFOCUS/WM_KILLFOCUS plus native UI activation; only one service owns native focus for a parent. Raw keyboard/Unicode/IME/input-language messages go to TxSendMessage without reimplementing shortcuts. S_FALSE returns to the parent chain; other successful results return the native LRESULT. Tab/Escape remain parent navigation. Pointer forwarding still follows the consumer's common UIOrder hit/capture decision. External parent focus loss and WM_NCDESTROY retire activation/subclass ownership. Callback failures are caught at the unmanaged boundary and surfaced at the next request. inputAttached reports connection; interactiveReady stays false: actual Windows native editing/IME/clipboard/DPI and full normalized directional model integration remain unverified or unfinished, and no actual Windows behavior is asserted. Existing NativeUI/Home is unchanged.

Host composition: native caret create/show/position callbacks determine a rectangular caret (bitmap 0/1 supported). Draw fills it in the borrowed engine buffer after TxDraw, with the same published regions and system blink cadence; no foreground/native child painting is introduced. Custom/rotated caret bitmap support is not claimed. Caret updates mark IMM geometry dirty; focus, composition start and snapshots outside native callbacks request CFS_POINT/CFS_EXCLUDE from the borrowed parent HIMC. Snapshot reports imeContextAvailable/imePositioned; unavailable HIMC or rejected requests remain explicit. This does not prove modern TSF/candidate placement or mixed DPI behavior. Wheel packets use native screen coordinates/signed delta/modifier state, after common consumer hit eligibility. Callers compose a fresh base frame before native draw. Timer/capture/subclass/OLE leases retire with the owner; callbacks never scroll or repaint foreground widgets directly.


Host disconnection and failure safety: [ShutdownTextServices](https://learn.microsoft.com/en-us/windows/win32/api/textserv/nf-textserv-shutdowntextservices) consumes the factory reference and disconnects the borrowed host pointer, allowing outstanding native/OLE service references to work or fail gracefully without touching freed host memory. The separate queried ITextServices reference is released once, never in place of shutdown. OLE teardown runs after disconnection while host roots and native code remain valid; explicit host AddRef leases use atomic counts and prevent host free until released. Each borrowed host HIMC is tracked and balanced, including leases surviving native teardown. Retiring callbacks cannot reacquire timers/capture/focus/IME contexts.

A failed disconnect preserves native pointers, callback roots, resources and OLE lease and rejects new operations; close can be retried on the creating UI thread. If constructor rollback itself fails, the exception exposes TextServicesRecoveryHost in Data and a readable token for the same close operation. Successfully disconnected hosts with explicit outstanding host AddRef leases also retain roots for close retry; OLE is already balanced. Activation/focus retirement errors are reported after attempting safe disconnection rather than skipping it. COM Release return counts are advisory, so they do not decide DLL unloading: after any created service, one bounded Msftedit module lease is kept for process lifetime for unobservable external service references. Repeated objects reuse that module lease rather than accumulating one lease each. It contains no host roots or per-View resource state.

Successful close replaces full host state with a small thread tombstone, preserving idempotence and thread/late-use guards without retaining per-host callbacks or resources. Process module lease coordination is synchronized across UI threads.
