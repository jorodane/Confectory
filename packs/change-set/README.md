# ChangeSet

Review compares only selected dirty units with their original exact-byte hashes. Confirm prepares a copied source candidate, applies selected drafts, relocates candidate registry references, performs structural/owned-body/consumer validation and conditionally commits selected final files through FileStream. New declarations require their ProjectPack registration. Unselected drafts remain live. A stale draft or baseline conflict leaves the final sources and drafts intact; compilation failure never confirms.

Preview separately builds/runs a copied draft candidate. The owned authoring tool stops a preview after 15 seconds and captures its output/exit status. Candidate copies are removed afterward. This is an explicit execution action, not inspection or Confirm. Source-copy and final Commit coordinate participating consumers with FileStream's public lease, including ProjectExecution builds. External nonparticipating editors and crash-proof multi-file transactions are not guaranteed. The engine schedules these operations off its native UI thread with owner cancellation.

ConfirmReviewed(handle,selected,target,reviewedChanges) pins the existing flat Changes records and rejects a different current draft before candidate preparation and after validation. Confirm now delegates to that same policy after capturing current Changes. Token-owning consumers should supply the records they actually reviewed; neither method is a global dependency snapshot or semantic merge. See [actual product composition](../../docs/EDITOR_EXISTING_AUTHORING_COMMANDS.md).

A reviewed creation of a pure inherited data object can use source-only validation when the manifest adds exactly that object, the direct owned parent uses exactly one direct owned primitive schema, and no executable or other declaration metadata changes. Parent and schema observations participate in the final source CAS; every other creation uses ordinary candidate compilation. This does not change the explicit Review/Confirm policy or the Run build. The Linux Chromium trace regression is `tests/web/project_existing_schema_object_creation.py` (after `project_runtime_configuration.py`, pass its disposable evidence root and a unique child name as the fourth argument; requires strace). Use `--baseline` for the legacy compiler-count comparison or `--conflict` for an external manifest edit after Review. The host proof regression is `tests/packs/existing_schema_object_creation_validation.py`.

A pending ordinary retirement of exactly one pure data object can also use a source-only Confirm proof. The proof requires exact unregister-only manifest change, matching retained source bytes, a direct owned primitive schema (or a single pure parent), unchanged registered authority, the shared declaration validator and the same execution Planner for all declared targets. The removed ID must be unreachable with identical remaining plans, and retained declarations, bodies and Blueprint nodes must not have unclear references to it. All observed files are byte-hash guarded in the existing CommitPlan. A proved missing execution reference such as an active-target `always` blocks Confirm; any ambiguous shape falls back to ordinary candidate validation. The new path does not compile unrelated unchanged C# or invoke a target tool; explicit Run/Build and mixed/contract edits retain ordinary compilation. Run `tests/packs/existing_schema_object_retirement_validation.py` with the authoring host DLL, or `tests/web/project_existing_schema_object_retirement.py BUILD_REPORT OVERLAY UI_CREATED_EVIDENCE_ROOT` after the actual Timing Puzzle creation test has produced TimingRulesVariantCandidate. The latter supports `--always`, `--conflict` and `--baseline` and retains its disposable trace evidence.

The existing single-long-value proof can run before candidate preparation: the ordinary object registration, captured original manifest/schema and registered manifest snapshots are passed to the same Registry and SchemaContracts validator through an in-memory document overlay containing the exact reviewed new object text. The final CommitPlan checks the original object baseline, manifest, schema and registered manifest observations before writing. No source directory is copied or link receipt attempted on this path. Unsupported or ambiguous inputs fall back to the existing copied-candidate path. Creation/retirement continue their current candidate workflows. Regression: `tests/packs/long_data_overlay_validation.py` and `tests/web/project_long_data_overlay_save.py BUILD_REPORT OVERLAY UI_CREATED_EVIDENCE_ROOT` (after Timing Puzzle configuration, with confirmed OpenMilliseconds=1000). Use `--trace --assets` for candidate/compile/DLL tracing on a 32 MiB synthetic asset fixture; `--baseline` permits the previous candidate copies; omit `--trace` for ordinary timing. `--guard-object`, `--guard-schema`, and `--run` exercise conflict and cold native execution separately.

The same overlay proof can classify a single existing declared-reference data value when both old and new targets are exact local registered leaf objects applying the same direct primitive schema. Their declarations and schema bytes join the atomic read guards. Reference edges can otherwise reach executable implementations, so inheritance, additional links/providers, nested/nonprimitive target fields or unclear identity retain regular validation. A single clean local user Save may obtain the existing transient direct-save receipt only when this exact overlay proof also matches the original workspace. Its read proof is retained in the existing durable slot receipt and must still match at final Confirm/CAS; loss or stale state does not authorize automatic reapplication. All unproved, mixed and collaborative/proposal paths retain explicit Review. Explicit Run still builds the current linked catalog. Regression: `tests/packs/reference_data_overlay_validation.py` and `tests/web/v821_reference_data_run_ui.py REPO BUILD_REPORT 40|400 [--detached]` and `tests/web/v821_direct_reference_guards_ui.py`.
