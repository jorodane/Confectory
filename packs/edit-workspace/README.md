# EditWorkspace

Open requires a selected ProjectPack path, participant and work-context. Identical identity shares a live opaque session; different participants keep independent drafts. There is no null-context fallback or automatic project/chat switching. Owned declarations and implementation body units use stable element IDs; runtime body-unit IDs append `/body:target` to their owner implementation ID.

Read returns coherent draft and revision; subscriptions are exact unit tokens. SetText preserves ID/kind, SetValue uses SchemaEditing, Create stages a declaration and its manifest registration. No View or table owns these models. Native View close only releases its borrowed subscription. Explicit workspace owner Close releases the session without implicit Save or Confirm; repeated Close and late Poll are safe.

Export emits version-1 identity and modified units only, including original text/hash. Restore preserves saved baselines and rejects a different identity/version/path. Accept is called after successful selected source commit. Caller mutations are serialized in the milestone; conflicting parallel property intents need caller coordination rather than a general merge claim. There is no migration, collaborative transport or generic conflict merge.

Open now defers declaration/body text and hashes until first Read; owned manifest drafts remain available for creation. Status exposes metadata without materialization. DiscoverBodies reads the current implementation draft and adds owned target source locators without reading their bytes; loaded path changes are rejected and removed body drafts retained. See [lazy edit semantics](../../docs/LAZY_EDIT_MATERIALIZATION.md).

Explicit Blueprint implementations expose `blueprint` graph and `blueprint-node` source units with stable target/node IDs. These are authored JSON documents, validated by the metadata provider before editing/restoring, and use the same revision/CAS/durable draft/source Confirm lifecycle. They are never passed to the declaration parser or interpreted as final C# bodies. Body discovery uses loaded graph drafts, preserves removed loaded units, and refuses loaded locator/kind changes. Creating/migrating a new graph still requires an explicit source/ownership workflow; opening a legacy project never converts it.

`CreateVariation(handle,parent,id,revision,hash)` stages a new root-owned object extending the explicitly displayed owned object parent. It checks the parent source ID/kind, revision and UTF-8 SHA-256, prepares the ordinary empty declaration, parent relation and manifest registration before staging, then rechecks parent/manifest versions, handle lifetime and the destination under the shared draft gate. New source and registration are staged together; failures leave neither partial creation nor registration. Parent data, description and implementations are inherited by reference rather than copied into the new source. File writes remain the ordinary explicit Review/Confirm workflow. This first contract accepts owned object parents only; it is not feature graph conversion, imported-pack editing or a new runtime type.


`Conflict(handle, operation, payload) -> JSON` compares an existing owned unit's saved baseline, current physical file and shared draft. `inspect {id}` is read-only and rechecks the source revision/content and current file hash before returning. It exposes `baseText`, `fileText`, `draftText` plus revision, draft UTF-8 hash, baseline/current file byte hashes and eligibility. The selected source path is revalidated against the owner and symbolic links are refused even after lazy materialization.

`resolve {id,text,revision,draftHash,fileHash}` explicitly stages the reviewed candidate against those exact versions. It parses the candidate with the ordinary identity/kind rules, checks the source and physical file again, and changes only original/baseline/draft/revision under the owner gate. It never writes the final source. A no-op preserves revision. Saved export/restore includes the new baseline and candidate; a reset numeric revision cannot bypass a content hash mismatch. Normal Save/Review/compiler Confirm remain responsible for persistence and publication.

Manifest candidates use pure `inspectManifest` metadata and must retain the exact owned ID/kind/path locator map, including pending registrations. A peer creation during validation is refused. This permits merging metadata while preserving editing ownership; adding/removing/remapping owned sources uses the separate creation/removal workflow. Pending new sources and missing physical files return explicit unavailable codes. Blueprint source validation reuses its existing profile and does not add global completion-node or data-wire rules. Per text limit is262144 characters, physical file limit1MiB and serialized complete preview limit1MiB. Oversized comparisons are refused; no truncated candidate is silently accepted. This is a guarded draft rebase, not a filesystem transaction against independent writers.


`History(handle,operation,payload)` owns bounded source-edit transactions for existing units. Successful `SetTextIfRevision`/`SetText`/`SetValue` writes and each atomic `EditBatch` record their actual before/after draft under the same owner gate. No-op and refused CAS edits add no entry. A new edit clears Redo. Creation/registration and accepted changed conflict rebasing explicitly invalidate this source-only journal; source Undo never pretends to remove a registered element.

`inspect {}` returns metadata, source IDs/hashes/revisions and separate exact Undo/Redo tokens, without source text or host paths. `undo {token}`/`redo {token}` validate every inverse candidate, recheck the journal and all current source identities/contents/revisions, then edit the entire transaction atomically. Each changed source receives a new revision. A stale displayed token refuses the whole operation. Final files and baseline are unchanged. After compiler Confirm, an explicit inverse is another unconfirmed draft, requiring its own Save/Review/Confirm.

The owner-local recorder is installed/released with the opaque EditWorkspace session and requires no new provider import on legacy writer contracts. Different participants retain separate journals. Optional history in version-1 Export/Restore preserves old saved-draft compatibility and uses a new restoration epoch, so displayed tokens cannot cross a cold owner. Restore checks the complete journal owner/kind/path set before replacing drafts. Retention is the most recent32 transactions and2MiB serialized history; a single entry above1MiB explicitly clears source history with ENTRY_BUDGET while retaining the accepted draft. No collaborative undo or ownership-creation inverse is claimed.

`BlueprintNode(handle,operation,graphId,nodeId,definition,ids,revisions,hashes)` stages `create` or `remove` inside an existing owned Blueprint graph. It checks all observed sources (at most64 and2MiB UTF-8), validates the current implementation→graph locator and definition, and rechecks versions, handle lifetime and owned destinations under the same draft gate. Creation atomically appends one code node and a missing-baseline independent source at a fresh owned `nodes/<opaque>.node.json` path. The empty body has an unset definition stamp; it is neither implemented nor compiled. Save/Restore retains the complete graph/body draft without creating files.

Removal requires the start connection, execution edges and all argument/output references to be disconnected first. An existing dirty body refuses removal. The existing clean body's editable identity is retired while its physical file is preserved. Removing a pending creation explicitly removes its graph node and unpublished body draft together; any newly appeared physical destination refuses that operation. Ownership changes clear source-only history with `OWNERSHIP_CHANGED`. These roles never write final files, run the project or dispatch an Agent.

`ValidateReviewSelection(handle,selected)` is shared by PackWorkspace Review and ChangeSet ConfirmReviewed. A new node body and its changed owning graph must be selected together; selecting that graph requires all its pending new bodies. The current node/graph/implementation locators are checked again. An unrelated manifest selection cannot waive this group. Ordinary new declarations retain their manifest registration requirement. No graph/function allocation, physical source-file deletion or profile conversion is added here.

Node membership changes observe the current owned code sources and related owned contracts. They reserve the next read's source count and complete UTF-8 size before touching ownership, including the new node record and changed graph; a refused budget check preserves all drafts and revisions. New unit paths use the host's normalized relative path while authored graph references remain portable. These are the existing transport limits, not a rule about a node's meaning or code length.

A subscription that observes explicit source retirement becomes `retired` and returns no replacement text. ElementView preserves its last projection and reports retirement once. A private live-owner revision floor prevents same-ID creation, explicit restore or body rediscovery from reusing an old source revision. Observed retired subscriptions require an explicit new binding; cold owners never restore these handles or grants. The source-only version-1 saved draft format is unchanged.
