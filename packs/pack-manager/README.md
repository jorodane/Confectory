# PackManager

Project-local source-pack registration, explicit version/provenance pins, updates and removal. Open uses an explicit ProjectPack. Stage copies a source pack into a new managed local folder and journals a proposal; it does not activate or run hooks. Inspect uses public Registry/Planner metadata without invoking target fingerprint tools or project runtime. It reports registered vs reached packs and pin optional/ownership/provenance/local-fork state. Global source changes cannot silently replace a selected local pin.

Apply validates the candidate with actual compilation/linking, then dispatches ordered public hook IDs through the consuming ProjectPack's typed Dispatch provider. Priority ascending, ordinal ID ties. Discovery/staging never dispatch lifecycle code. Hook payload includes transaction/idempotency key, operation, namespace and candidate selection. Registration is not runtime loading; removal is not unloading. Unrouted hooks are errors. Completed hooks are journaled; Restore/Retry resumes the same transaction and skips completed hooks. External hook side effects require adapter idempotency; arbitrary side effects are not rollbackable.

Failed validation/hook/conditional commit preserves prior selection. Once conditional filesystem activation begins it completes rather than aborting half-way; journal failure after activation returns applied with a warning. Cancel stops owned pre-activation validation; Close releases live session only. Journals, old/failed source versions and user saves are retained. There is no implicit deletion or cache/save cleanup. Rebase of a conflicted transaction requires a new explicit Stage.

Source-only import rejects build-target packs requiring SDK artifacts; keep bootstrap tools explicit until packaging exists. No dependency download, global update, native loader, semantic save migration or compiler self-hosting is claimed. Core version ranges are warning predicates only; actual public contract/link failures remain errors.

Stage journals hashes of project-owned declarations/bodies and explicitly editable active pins through SchemaEditing description and FileStream snapshots. Apply rejects a changed owned source baseline before hooks and checks again before conditional registration activation. A conflict retains selection and completed-hook receipts; explicit retry after reconciliation uses the original baseline. External bootstrap/source tools remain separately owned.
