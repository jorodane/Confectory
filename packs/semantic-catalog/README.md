# SemanticCatalog

`Confectory.SemanticCatalog::Query(project,requestJSON)->replyJSON` is an ordinary role pack over public SchemaEditing Call. Query `list {query,kind,page}` returns stable qualified ID/kind rows from only the selected confirmed manifest, in pages32. Query `read {id}` opens only that owned declaration and returns existing Inspect-shaped metadata/direct relations/required signatures. Imported namespace IDs are unavailable; no automatic project opens. Public Core Documents supplies per-document cache/checksum/change-stamp validation. No implementation bodies, dependency graph, editing workspace or effective resolution are loaded by this role.

Actual EditorHome.Model Command operation catalog supplies current explicit project context. `catalog {context,action:"list",kind:"concept",query:"",page:0}` or `catalog {context,action:"read",id:"Namespace::Element"}` returns catalog.context/result. Switching/leaving contexts clears the prior reply. Query does not open PackWorkspace/EditWorkspace or modify final/draft files. SourceScope confirmed-files distinguishes this catalogue from existing workspace draft inspection/effective operations.

Replies expose namespace/version, opaque metadataVersion, scope/status and observed reads(manifest,declarations,relative paths). Read element also has metadataVersion; tags are metadata fingerprints, not content-byte hashes or global IDs. Location changes can change tags while qualified identity remains stable. The reused Core cache is private under temp/confectory-semantic-catalog-v1 keyed by project path. It persists as disposable cache across model lifetimes, with no subscriptions/open handles or semantic state. Retention/pruning is future maintenance. On Linux reliable stat stamps permit warm reuse; platforms without reliable change stamps safely reread the requested documents. No constant cache-hit guarantee is made there.

Ledger: new Query/QueryBody public contracts; direct dependency on SchemaEditing. Outside reads: public Documents/Parser/manifest locator APIs establish safe on-demand metadata; existing EditorHome.Model active context and eager PackWorkspace Open establish why browsing needs an independent route. Outside edits: desktop authoring tool and identical Android/browser metadata templates implement catalog; EditorHome.Model imports Query, registers dependency and clears context-owned replies; actual EditorHome manifests/entry bindings compose this new ordinary pack. Core/shared resolver and layouts unchanged. New contract/implementation DLLs belong to SemanticCatalog; consumer model implementation rebuilds and final links include that contract. Implementation-only QueryBody and model CommandBody locality gates expect their own physical pack only and zero contract compilations.
