# Codex stdio connection

Connection/Settings inherit the common AI declaration. ValidateConfig(config)->JSON is inert local validation. ProviderBody implements the existing Agent::Provider contract with a real child-process stdio adapter. This is implemented transport code with an owned protocol fixture, **not live-model verification**; opt-in installed unauthenticated startup coverage is recorded separately. Desktop/browser/Android support flags remain false until installed-version protocol and sandbox enforcement are verified; selecting settings never launches a process.

Open requires separate explicit grants pinned to the absolute executable, model and project: processApproved, managedCredentialApproved, contentApproved, usageApproved and protocolVerified. The approved managedHome directory is also pinned; separate managed configuration read and storage permissions are required. Only codex:managed is supported; no literal key, login action, credential inspection, PATH discovery, arbitrary command arguments, install or migration API. A trusted consumer must obtain these grants through its actual user permission boundary; caller-supplied booleans are not internet authorization. Existing sign-in does not imply permission to use it. The installed app-server has been tested only with an owned empty home, ephemeral credential store and child network denial; no model request or real account use occurred. Existing account/configuration files were not manually inspected.

The adapter clears inherited environment variables, sets only minimal process paths, owned temporary storage and the explicitly approved CODEX_HOME. It cannot opportunistically inherit an API key or select an implicit user home. The adapter starts app-server without a shell, in an owned empty temporary directory rather than the project root. It explicitly disables unnecessary command/browser/app/hook/subagent features through child arguments, reads approved effective configuration to request thread-local plugin/MCP disable overrides, rejects returned environment access before a turn, initializes an experimental dynamic-tool connection, and sends `environments: []` on both an ephemeral thread and a read-only turn with sandbox network access disabled and no approval expansion. Read-only is a write policy, not a file read allowlist: the installed schema has no `sandboxPolicy.access.readableRoots`. The empty cwd and environment clearing do not prevent other filesystem reads, account/configuration side effects, or model-service traffic. Native item refusal is protocol detection, not OS containment. The official no-environment route is now requested, but a complete model-facing tool inventory and runtime tool behavior are not observed without inference, so the actual EditorHome capability gate remains false. Only declared DevelopmentTools functions can execute in the host, after exact project/thread/turn checks. Other server requests fail closed. Native command/file/MCP/web/subagent items abort the connection. These requested policies are not proof of enforcement by an unverified installed version. No unsupported native provider behavior is advertised as a usable connection.

Only the explicit message, curated caller context and Worker task projection are sent; local capability handles and authorization/binding metadata are omitted. Stable tool call IDs deduplicate responses and reject changed payloads. Tools stage CAS drafts and cannot Confirm, build, execute processes or finish tasks. Agent text is bounded32KiB; protocol lines1MiB, input64KiB,4096 messages,32 tool calls and90s connection lifetime. Events carry no raw stderr or server error details. Unexpected termination/errors do not silently succeed.

Cancel is sticky and fences late output. Cleanup attempts scoped turn interruption, closes stdin, then terminates the owned process tree if needed. Close waits1500ms and retains retryable ownership on incomplete cleanup. Scratch deletion and stderr draining are part of cleanup. This does not roll back an already staged draft or replay work after restart. A final model turn does not mark Worker tasks completed.

The default Linux transport test launches its own Python protocol fixture. An explicit opt-in also launches the installed CLI against captured actual adapter initialize/thread requests, with no account, no turn/start and irreversible child-only network syscall denial. It verifies handshake/order, ephemeral/read-only policy requests, a real public draft-tool roundtrip with duplicate calls, foreign-project and out-of-namespace refusal, native approval refusal and cancellation. Separate explicit consumer Review/Confirm checks final-source changes and compiler feedback. The model side is simulated; the process, stdio, public tools, draft model, Review/Confirm and compilation are real local operations. Windows/Android portable managed target compilation is separate from native/device evidence.

Ledger: own ValidateConfig, public Provider/AdapterBody and compatibility ProviderBody added, Connection metadata declares transportImplementation while keeping unsupported runtime status. Outside reads: Agent Provider lifecycle and DevelopmentTools Definitions/Snapshot/Invoke contracts, PackWorkspace explicit review/confirm consumer contracts and official protocol sources. No Agent/Helper/Worker/Augment implementation, Core or editor host edit. ProviderBody change locality checks rebuild its physical owner pack with zero public contracts. No executable, auth or SDK installation.

Protocol references checked2026-10-09: [app-server lifecycle, sandbox and dynamic tools](https://learn.chatgpt.com/docs/app-server), [official dynamic tool types](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/dynamic_tools.rs). Dynamic tooling is experimental and generated schemas are installed-version specific. Product binding, installed protocol/sandbox validation and a separately approved managed sign-in boundary remain required.

Public Provider is a separately qualified function backed directly by the same owned body source, so a consumer can call either concrete provider without changing the default Agent role globally. The Agent ProviderBody remains available for explicit ordinary consumer composition. No generic runtime element loader was introduced.
