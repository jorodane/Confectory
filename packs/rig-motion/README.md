# Confectory.RigMotion 0.1

Dependency-free public element contracts `Validate(document)`, `Evaluate(document, action, time, loop)`, `Project(pose, plane)`, and `Capabilities()` exchange JSON strings. `RigSchema`/`RigDocument` provide a scalar document for existing workspace authoring. `Command(operation, document, arguments)` is the declared shared policy boundary; wrappers do not imply separate policy ownership.

The complete fixture is [fixture-rig.json](../../examples/rig-lab/fixture-rig.json). Schema version 1 requires a bounded ID, 1–32 joints with a single root, existing parents and an acyclic hierarchy. Every bind transform and every KeyPose has translation `[x,y,z]`, unit quaternion rotation `[x,y,z,w]`, and positive scale `[x,y,z]`. KeyPoses specify every joint. The 1–16 Actions carry stable meanings, 2–32 KeyPoses, and consecutive AnimationDeltas: `from`, `to`, duration and cubic-Bezier `curve:[x1,y1,x2,y2]`. IDs are local identifiers, not globally resolved asset references.

Translation components are finite and bounded by 10000; scales .001–100; quaternion norm tolerance 1e-5. Delta durations .001–600 seconds, Action total at most 3600. Curves have monotonic x control points in [0,1] and bounded y controls allowing overshoot. Unknown fields, dangling parents, cycles, malformed transforms, incomplete poses and invalid timings are rejected. Validation checks structure and authored transforms; evaluation additionally rejects invalid interpolated scale/translation and composed matrices, including overshoot or extreme hierarchy multiplication. Validation alone does not prove all intermediate poses valid.

Evaluation inverts Bezier x for time, evaluates its y blend, linearly interpolates translation/scale and spherically interpolates normalized quaternions. Child world matrices use local × parent under System.Numerics row-vector conventions. Output contains the coherent sampled local transforms, world matrices and positions. `loop=true` wraps at total duration; otherwise time clamps. Input time is finite [0,1e9]. Motion is the common time source for all projections, independent of any world simulation.

Projection supports front (x,y), side (z,y), top (x,z), retaining the remaining depth component. It consumes the bounded pose representation produced by Evaluate. This is geometric orthographic preview, not perspective rendering, skinning, IK, retargeting or production mesh generation. No Stage, Physics, Helper, Window, table, or editor dependency is imposed.
