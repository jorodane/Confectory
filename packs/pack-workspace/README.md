# PackWorkspace

Public role: `Open(project, participant, context) -> handle`, `Snapshot(handle) -> JSON`, `Command(handle, operation, payload) -> JSON`, `Close(handle)`. This is a bounded source-view coordinator over EditWorkspace and Save; it owns selection/page/lifetime, never filesystem or source-model semantics. Element Views can consume these contracts without a table.

Snapshot returns explicit identity, selected unit, page/pageSize/total, page metadata and selected text/revision/dirty. Pages contain 32 stable-ID-sorted units. Commands: `select {id}`, `page {page}`, `edit {text,expectedRevision}`, `save {}`, `sources {}`. Edit requires nonnegative revision and at most 1,048,576 UTF-16 characters. A stale edit returns `conflict:true` without discarding the draft. Select preserves every draft. Save persists identity-local draft differences; it does not modify final source. Sources returns `{files:[{id,kind,path,text,revision,dirty}]}` using public List/Read and includes the manifest and body metadata.

Open restores Save once for the shared explicit draft identity. Separate opaque view-owner handles share that draft, while distinct contexts remain independent. Close is idempotent per handle; final-owner cleanup failure retains the owner for retry. No automatic Save/Confirm on close. A different direct EditWorkspace owner must not close a draft borrowed by PackWorkspace while its views remain active; cross-role owner leases are a later shared-contract improvement.

Android/browser target metadata adapters expose Describe/Inspect/Create/Register/SetValue using Core's public Parser. The formatters preserve desktop tool syntax rather than introducing a second source model. They describe only selected owner-root files (symlinks rejected), never follow registries/pins, load code, compile, or claim Confirm. Each source is limited to 1MiB and description to 256 units. Desktop retains its explicit authoring process provider. Declaration editing preserves ID/kind via Inspect; scalar formatting and owned manifest registration preserve the supported statement set. Compiler-backed Confirm remains a separate explicit authoring operation.

Locality limitation: the existing public EditWorkspace Open eagerly snapshots the selected root's owned units, and List returns all IDs. PackWorkspace pages limit metadata Read calls and returned UI content, but do not claim a new lazy source index or constant-cost Open. Desktop review extension: `review {target}` persists the selected existing owned draft and returns a token, file/id/target, before/after text, baseline and frozen revision. `cancel-review {}` clears only review. `confirm {token}` requires a ready unchanged review, then composes public ChangeSet validation and conditional final commit. Stale/forged tokens, external changes and compiler failures preserve drafts. Snapshot exposes nullable review and confirmation results. Selection/page and actual revision edits invalidate review. Consumers bind the explicit ChangeSet/EditWorkspace/FileStream/SchemaEditing/Save providers declared by Command. Save alone never commits final sources. See [actual-product handoff](../../docs/EDITOR_SOURCE_CONFIRM.md) for independent functional/locality gates and limits.

Owned navigation extension: `filter {query,kind}` resets the page and returns ID/kind-filtered units while preserving selected source, draft and review. Query is an ordinal case-insensitive ID substring (max256 characters); kind is exact (max64). Empty fields clear filters. Snapshot adds query/kind/ownedTotal; total counts filtered results. Filter state belongs to the view handle, not shared draft. The actual EditorHome.Model workspace route forwards this command with its existing active-project guard. No layout change. See [contracts, scope and verification](../../docs/OWNED_ELEMENT_NAVIGATION.md); this is not a new lazy semantic graph index.

Selected declaration inspection: `inspect {}` returns ordinary snapshot plus `inspection` and `inspectionRevision`, using current owned draft text. It preserves filter/selection/review and refuses body/manifest units. Inspect's additive relations distinguish declared parent/module/include/require/default/provide IDs from effective resolution. Actual EditorHome workspace action `inspect` uses the same existing context guard. See [direct relation contract and gates](../../docs/DECLARED_ELEMENT_RELATIONS.md).

Selected `locate {}` adds locationManifestRevision and tri-state locations to the existing inspection/revision reply. It uses current owned draft manifest and explicit selected context; plain inspect remains unqueried. Registered locators do not establish source validity or compatible effective contracts. [Target registration contract](../../docs/RELATION_TARGET_REGISTRATION.md).

`effective {}` explains selected root-owned draft inheritance values/origins and Core module requirements/default candidates. Same-root dirty declaration overlays and effectiveDraftRevisions preserve parent draft edits. Provider selection/execution is not performed; unsupported scope or Core diagnostics return unavailable. [Contract, common resolver reuse and remaining order](../../docs/EFFECTIVE_METADATA_EXPLANATION.md).

Failures retain source drafts; new declaration review explicitly includes its changed manifest. See [command semantics and verification](../../docs/EDITOR_EXISTING_AUTHORING_COMMANDS.md).

BorrowDraft(handle) exposes the owned View's borrowed EditWorkspace token for reusable tool/Worker consumers. It does not acquire another lifetime reference. The consumer must own the PackWorkspace View until it finishes using that token; closing fences reject new borrowing. [DevelopmentTools](../development-tools/README.md) demonstrates shared drafts with independent selection and explicit user-only final confirmation.

`relations-map {}` reads all already-owned declaration units in 32-source metadata batches, preserves source selection/review, and returns safe node/edge/version metadata. It rechecks draft revisions/content hashes, retains malformed sources as partial nodes, and marks references outside the owned View without traversing registry entries or claiming they are missing. It never executes a project, compiles code or edits source. This projection is not a feature Blueprint execution graph.

`reference-definition {sourceId,id,expectedRevision,expectedHash}` reads a directly declared reference from an owned source without changing selection or Review. The source ID, registered kind, revision and UTF-8 source hash are fenced; the current owned manifest and source are checked again after the query. The target must be a direct dependency with an explicit root registry locator. Only that registered manifest and declaration are read, bounded to 1MiB each, with namespace/kind/ID and pack-root containment checks. Registered text is checked again before returning. The reply adds `referenceDefinition` with read-only confirmed text, content/manifest hashes and actual selected pack version, or a specific unavailable code; it does not establish compatibility or select providers. No body files, transitive registries, compiler or editable imported workspace are opened. Native adapters additionally constrain reads to their configured owner root and may report unavailable for external resources. Owned targets continue through their ordinary draft View. This read does not persist imported text or claim a filesystem transaction against external writers.

`CreateVariation(handle,parent,id,revision,hash) -> JSON` is a separate public creation role over EditWorkspace.CreateVariation. It requires this View to display the parent, holds its close fence, then selects the new owned object and returns the ordinary Snapshot/creationReviewIds. The new source and its manifest are reviewed together through existing creation rules. Its bindings are only required by consumers that call this new role; existing Command consumers keep their current dependency set. No automatic Save, compiler Confirm or parent source modification occurs.


`Conflict(handle, operation, payload)` is a separate public role, so existing Command consumers gain no new provider dependency. It fences the View lifetime and explicit selected source, then borrows its existing EditWorkspace. Inspect and unchanged resolution preserve Review; only an accepted changed draft clears that View's old Review. It does not open an imported editing owner, auto Save or Confirm. The Home consumer returns full comparison text only in the explicit endpoint result and projects conflict metadata into state, respecting the shared2MiB state budget.


`History(handle,operation,payload)` is a separate public role over the borrowed EditWorkspace journal, keeping legacy Command dependencies unchanged. It holds the View close fence. Inspection and refused stale tokens preserve selection and Review; an accepted inverse clears that View Review and leaves final publication to the ordinary compiler-backed flow. Closing a View never saves or replays history actions.

`Blueprint(handle,operation,payload)` coordinates an existing owned graph without changing source selection. `list` has explicit query/feature/page filters and 32 rows per page. `read {id}` returns the actual external signature, node definitions/source availability, execution edges, exact argument/output JSON strings and diagnostics. A `source-ready` diagnostic means source availability; it is not C# compilation or execution evidence.

Each read issues a View-local opaque `basis`, backed by graph/implementation/related owned function/node revisions and UTF-8 hashes. There are at most 16 retained bases, 64 observed sources and 2MiB of observed UTF-8 source per read. Targeted `intent`, `argument`, `route`, `entry`, `exit` and `source` edits require `{id,basis,...}`. Argument/output edits use `valueJson`; other graph numbers never pass through a browser Number. A code source edit explicitly binds the body to that inspected node definition. The node locator must still resolve to its existing owned file. File/registration creation, source removal and ABI/profile conversion are separate workflows.

Edits reuse EditWorkspace.EditBatch: all observed source revisions/hashes are checked together under the shared owner lock, unchanged observations remain unchanged, and only the selected source receives a new draft. Stale observations refuse the whole operation. A changed edit clears this View's Review; no-op edits preserve it. Existing draft history, Save and compiler-backed Review/Confirm own subsequent persistence and publication. No Agent, runtime, source file write or generated C# edit is performed by this role.

`createNode {id,basis,node,definition}` and `removeNode {id,basis,node}` use the same observed source basis but delegate ownership changes to EditWorkspace.BlueprintNode. The definition contains intent, control and typed signature only; the owner chooses the new file path. Removal has an explicit consumer preview and requires disconnected/unreferenced nodes. Existing clean files are preserved; pending creation removal discards only the explicitly reviewed unpublished body draft. Other pending inputs and shared source changes refuse without partial mutation. `entry` also accepts an existing `exit:<name>` supported by the current profile, permitting explicit removal of a last internal node.

Snapshot advertises the graph/body creation review group for a new node independently of browser filters. A peer View whose selected node was explicitly retired returns no selected unit and clears its old Review; it does not discard private presentation inputs. Final source writes still require an exact Review group and the ordinary compiler-backed Confirm. General graph/function creation and physical file deletion remain separate work.

Targeted graph/body edits also check the prospective complete source byte size before EditBatch. Successful creation or editing must not make the next bounded graph read unavailable. A source-ready read still makes no claim that every disconnected body has been written or compiled. Unfinished typed wiring is retained as a draft with diagnostics; actual compiler Confirm is responsible for refusing invalid publication.
