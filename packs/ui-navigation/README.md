# Confectory.UINavigation 0.1

Optional dependency-free policy pack. `Create(configuration)->string` validates bounded configuration and returns caller-owned per-View state. `Route(state,eventID,type,key,flags,textEditing,currentFocus,eligible)->string` returns new state with `consumed`, `focus`, `activate`, `action`, active group and reservation/restoration state. The consumer queries its own UI through public contracts, applies requested focus/activation, and sends unconsumed records onward. The pack never inspects BaseUI's opaque View arrays and owns no model, OS window or subscription. Drop its state when the View is disposed; each View needs independent state and event sequence.

Configuration: `initial`, `groups:[{id,controls:[positive IDs]}]`, `bindings:[{id,group,key,action,priority,text,modifiers?,target?}]`. Group `*` matches all. Actions are toggle (requires existing target), next, previous, activate. Larger priority wins; equal priority uses ordinal binding ID. Native key codes and Ctrl/Shift/Alt flags are consumer configuration, not platform/core policy. `modifiers` defaults zero and matches bits 1–3 exactly; bit0 is repeat. The inventory example binds both Win32 and X11 Tab codes to a higher-priority toggle, and F6 to internal traversal. Engine explicitly chooses Tab traversal for its basic demo.

Event IDs increase monotonically within one View, including key-up/cancel records. Duplicate last-event dispatch keeps consumption but clears action/activation so one record cannot open and immediately close or activate twice. Older identities reject. One winning binding runs per record. Bound key-down reserves consumption through its key-up, even if the group changes, preventing release handlers below it from toggling again. Repeated key-down is consumed without another action. Unicode text records (type12) are unconsumed. `text=false` bindings do not run during text editing; consumer text/IME delivery remains separate. Activation reserves the eligible focused control on down, executes on matching up only if focus/eligibility/text permission still agrees, and cancels on focus loss/type9, traversal or group toggle. No global unconditional Tab handling.

Toggle saves the active group/focus and restores only a still eligible target in the saved group; otherwise configured order supplies fallback or zero. This is one saved toggle return context, not arbitrary nested modal stacks. Disabled/hidden eligibility is supplied each record; empty groups clear focus. Limits: 32 groups, 64 bindings, 256 controls/eligible IDs, 32768-character configuration, 65536-character state. State is an opaque consumer-owned serialized policy token; do not manufacture/edit internal fields. Full accessibility, spatial navigation, IME and semantic element search are later work.

BaseUI adds public `Focus(view,operation,control)->int[]` (`query/set/disable/enable/hide/show`), returning `[focused,control1Eligible,control2Eligible]`; zero clears focus. `Activate(owner,models,view,control)->bool` checks eligibility and requests the existing model mutation. Pointer and legacy basic Enter/Space activation remain available; a navigation consumer intercepts configured keyboard activation first. Hidden basic controls have no hit/label/rectangle; disabled controls cannot activate. This bounded two-control API is not a universal widget schema.
