# Physics2D public contracts, v0.1.0

Namespace `Confectory.Physics2D`; only RuntimeBase dependency. All element IDs are listed in pack.cpack. Default providers call the pack-owned Command/CommandBody policy boundary; this is explicit shared policy, not semantic independence of its adapters. No core or other pack implementation changes.

CreateWorld(ownerID, configuration) returns an opaque world ID, creates a private RuntimeBase Owner and revision instance, and records the caller label (not authorization or a transferred Owner hierarchy). Epoch returns the current cancellation generation or zero after close. CreateBody reserves a never-reused world-scoped ID and queues creation. SetCollider, QueueChange and RemoveBody queue changes with the exact current epoch; their acceptance does not mean they have committed. Commit applies the entire ordered batch to a clone or rejects/discards the batch without changing live poses, tick, revision or events. CancelPending drops pending requests. Fence increments the epoch, cancels pending changes and retained contacts/events, preserving poses/tick and monotonic event sequence. DisposeWorld invalidates callbacks, clears state and disposes the private Owner; repeated disposal succeeds. All calls except QueueChange require the creating thread. QueueChange alone may be called from background threads and is serialized under the world gate; no callbacks execute inside physics.

Configuration is strict JSON with optional gravity [x,y] (default [0,0], each magnitude <=100), fixedStep (.01, range .00001 through .05 seconds), lengthUnit/massUnit (bounded labels, default unit), maxBodies (64, 1..64), maxCoordinate (10000, 100..1e6), maxSpeed (100, 1..1e4 per velocity component), motionFraction (.25, positive <=.25). Coordinates are Cartesian y-up, time is seconds. Units and gravity are pack/consumer choices, not core/platform defaults. Request JSON is bounded to 32768 characters; pending changes to 256. Unknown fields, nonfinite numbers and unsupported shapes fail.

Body definitions: type dynamic|static, position [x,y], velocity [x,y], mass (dynamic default1, 1e-6..1e6; static0), restitution (default0, 0..1). Static velocity must be zero. Collider definitions: shape circle with radius (.01..maxCoordinate) or box with halfExtents [x,y] (each >=.01); sensor false, category1 (1..65535), mask65535 (0..65535). One collider per body; dynamic circles and static circles/axis-aligned boxes only. Bodies without colliders can move. QueueChange takes operation remove|collider|velocity|transform, body ID, and respectively definition|velocity|position. Retired/cross-world IDs and stale epochs are rejected.

Step accepts only the configured fixedDelta, requires an empty pending queue, and applies semi-implicit Euler gravity. Motion must be <= motionFraction times the smallest world collider feature and obey speed/coordinate bounds. This reduces discrete tunneling risk; it is not CCD and can miss grazing contacts. Numeric body ID order determines pairs; filters are symmetric. Sensors observe without impulse. A dynamic body with more than one solid contact rejects the whole step. Isolated solid contacts use inverse-mass penetration correction and the analytic normal impulse with minimum pair restitution. Post-response overlap and numeric bounds are checked before publication; unsupported interactions reject the entire step. No iterative general solver, stacking, rotation, torque, friction, joints, constraints, polygon, kinematic or 3D capability is claimed. Capabilities exposes these limits as schemaVersion1 JSON. A broad third-party backend needs a separate dependency/version/license/platform decision; none is installed or adopted here.

Snapshot(world, alpha) returns schemaVersion1, world, ownerID, epoch, tick, revision, pendingChanges, normalized configuration, bodies, contacts count and latestSequence. Each body includes body/id/type, x/y, previousX/Y, vx/vy, mass/restitution/collider and displayX/Y. Alpha must be finite in [0,1]; display interpolation never steps simulation. Consumers Commit then fixed Step, collect events/queue next intents, and render a coherent Snapshot. RealTimeUpdate catch-up/drop policy belongs to the consumer; it must not pass accumulated elapsed as physics delta.

QueryAabb(world, [minX,minY,maxX,maxY], maximum1..64) uses current committed poses, exact circle-vs-AABB or box overlap, ordered numeric IDs, and returns schemaVersion1, tick, revision, bodies, total, truncated. Events(world, afterSequence>=0, maximum1..128) returns schemaVersion1/world/epoch, events, oldestSequence/latestSequence, historyLost and truncated. Retention is the last512 events; cursors do not consume other readers' events. Each event includes sequence/tick/epoch/kind begin|stay|end, reason, a/b handles and aID/bID, normal, penetration, sensor, normalImpulse. Contact observations use integrated pre-response poses; snapshots and queries use post-response poses. Deferred removal/collider/transform invalidates contacts and emits end. Fence clears history, so historyLost must be checked. JSON result schemas are versioned; future 3D contracts/backend should remain separately declared rather than interpret Vec2 as Vec3.
