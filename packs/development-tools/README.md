# Development tool capability

Public Open(project,projectId,namespaceId,owner,editContext), Definitions(capability), Invoke(capability,callId,operation,arguments), Snapshot(capability), Close(capability). This is the local role boundary intended for a selected real provider, not an Agent simulation or network connection.

Open owns a separate PackWorkspace View and borrows that View's EditWorkspace model. The caller deliberately chooses the same participant/context as its GUI to share drafts while keeping View selection independent. An explicit root namespace/manifest is checked. The opaque capability stays local; Definitions exposes only JSON-schema descriptions and the granted project ID. All calls must echo the assigned project ID. Only that namespace's owned paths are readable; path escape/symlink traversal is rejected before lazy content reads.

Granted operations: workspace_list (metadata, max256 rows), workspace_read, workspace_inspect, workspace_stage (CAS), workspace_create (supported declaration plus manifest drafts), workspace_changes. No Confirm, compiler/process/shell, arbitrary file, credential, or runtime invocation operation exists. Stage/create touch drafts only. Caller shows the staged IDs/manifest and invokes ordinary explicit user Review/Confirm elsewhere. Save/final validation/execution are not implied by tool success. Invoke never takes a filesystem path from a model.

Call identity+arguments are deduplicated within a bounded capability (256 calls). Replay returns the original result and does not replay a mutation after subsequent human edits. A different payload under the same identity fails. Snapshot exposes staged revisions, operation history and rights without cached source replies. Close fences future calls and releases only its owned PackWorkspace View; another GUI owner retains its draft. Serialized in-flight calls may complete before Close returns; cancelling an AI run does not silently discard already staged changes. Neither live execution nor source drafts are automatically replayed after process restart.

Necessary shared contract: PackWorkspace::BorrowDraft(handle)->string returns a borrowed opaque EditWorkspace token while the caller owns the PackWorkspace View. It neither adds an owner nor grants lifetime after that View closes. BorrowDraft checks the owning View's closing fence; callers must close their tool capability before releasing borrowed resources. No consumer inspects PackWorkspace's private state.

Outside reads: PackWorkspace Open/Command/Snapshot/Close and EditWorkspace Create/Read/Status/Identity to establish public JSON/array shapes, lazy source materialization and shared model lifetime absent from signatures. DevelopmentTools also checks FileInfo path ancestry/link metadata because the source contracts do not expose a link-safe read operation. Only PackWorkspace's own BorrowDraft implementation reads its private state; no Core/platform/other domain implementation is edited.

Functional/locality proof uses actual public local roles and owned fixtures, with no Agent/provider: independent project ID/namespace, shared GUI draft, revision conflict, replay fence, final files unchanged, creation+manifest staged scope, denied Confirm/shell, closed capability and preserved GUI owner. Definitions pins the project and omits ungranted operations. Invoke-only source changes rebuild its owning body with zero contracts. This foundational gate is not live AI or completed EditorHome AI UI coverage.

Snapshot adds `dirty`, the current owned workspace draft IDs and revisions. This differs from `staged`, the current capability’s staging history: a replacement capability can have empty staged/log entries while dirty project drafts remain. Dirty metadata does not attribute drafts to a particular Worker or authorize Confirm.

Worker provenance contracts: BindOrigin(capability, task, worker, request) is host-only role binding before mutations and is immutable. ProjectAI supplies these identities from ordinary Task inspection, never from model tool arguments. Each Worker owns its own capability. The private .confectory/draft-origins journal stores project/manifest scope, hashes, call identity and origin metadata (no source or model text). Mutation intent is persisted as outcome-unknown before a draft operation; applied/conflict/unchanged outcome follows. A persisted call intent cannot replay. An interrupted journal write is conservatively unknown, not guessed from current content. Snapshot exposes durable provenance and dirty origins, compares recorded hashes to current draft hashes, and preserves unknown-current-author for later human edits and no-op tools. Contributions are history, not exclusive ownership or authority to Confirm. Historical unknown origins are not backfilled.
