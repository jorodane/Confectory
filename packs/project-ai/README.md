# Project-scoped AI composition

ProjectAI is an optional application pack assembled from Agent, DevelopmentTools, PackWorkspace, WorkerTasks and Augment. Core and platform packs do not special-case an engine or AI host. Actual EditorHome explicitly selects its Provider adapter and VerifyCompletion policy; unrelated consumers keep the default refusals.

Public contracts:

- Configuration(connection, settings): explicitly selected concrete configuration roles; ordinary scalar schema data becomes a validated nonsecret provider config. The editor never enumerates provider-specific fields.
- Open(project, projectId, namespaceId, helperContext, config): owns a project-pinned tool capability and a retained draft View. Context must be the curated public Helper.ProjectContext result, with permitted current-project/common memory. No provider starts here.
- Start(session, requestID, message, authorization), Poll/Snapshot: asynchronous Agent runs, ordered bounded output and tool draft status. Explicit current-project/model/content/usage consent is required; concrete providers also enforce exact endpoint/protocol approvals. Start identity is stable; Agent owns deduplication. Settings alone never authorize a run.
- EnableTasks(session, helpers, targets, fields): borrows the Helper store; owns Task/Augment/View handles. Only the explicitly selected global main-helper is the chief. Public declaration metadata and source revision/hash are pinned before proposal approval.
- Propose(session, commandID, direction, authorization): asynchronous genuine selected-provider generation through Augment. The model must return exactly three validated JSON cards with narrative changes:[]; ordinary selected Workers implement general code. A source change after preview refuses provider invocation. Proposal generation has no development tool capability. Binding handles, grants and credential references remain local.
- Select(session, commandID, card): preserves the existing Augment selection/ordinary Worker lineage. No implementation or completion follows from selection.
- Work(session, commandID, task, authorization): separately approved ordinary Worker dispatch with project-pinned draft tools and curated Helper context. Task specification/execution key is supplied by WorkerTasks, never inferred from visible UI selection.
- Adopt(session, task, view, token, ids, goalEvidence): human-selected ordinary PackWorkspace Review/Confirm, compiler feedback and a source-hash-bound local receipt. Worker completion requires user-stated goal acceptance as well as compiler/source verification. This does not claim automated runtime/domain tests. An in-process receipt, matching specification/progress and unchanged confirmed files are required by the explicitly selected VerifyCompletion policy.
- Close(session): fences new work; closes Augment jobs, Task-owned runs, caller-owned generation/Worker/chat Agents; saves the retained shared draft after all producers retire; then releases Views/tools and ephemeral receipts. Failed release retains the original owner for retry. The borrowed Helper store outlives this cleanup.

A bounded development-log.json in the project's .confectory/ai-development folder records accepted task/Worker lineage, source IDs, compiler status, user outcome evidence and timestamp. Subsequent separately approved proposals include that project's log. CAS failure after task completion reports an error; retry the same live adoption owner to finish logging without re-running Confirm or Worker. A process interruption in that small completion/log interval requires explicit log reconciliation; it is not claimed atomic. No Agent dispatch, proposal generation or Worker is automatically replayed after restart.

## Ownership and limits

Every owner remains bound to its original durable project, manifest, Helper context and config. Hiding a panel does not close it. Actual EditorHome polls active owners even while another panel is visible; full close prompts for active Agent/proposal/Worker work and cancellation leaves it running. User source and chat drafts, Helper memory, Task/Augment checkpoints and logs survive explicit close/reopen. Persistent account/credential ownership is outside this pack.

Agent defaults bound each run to30 seconds,256 events and64KiB/event; provider-specific request bounds are additional. Project output and proposal output each cap at64KiB. Proposal jobs have a35-second join deadline; owner cleanup is retryable. WorkerTasks/Augment retain their existing task/history/CAS bounds. Request/token limits do not enforce a currency cap. Browser/Android direct keys and Codex installed-account/protocol execution are refused by current connection capability declarations.

## Locality ledger

Intended new element IDs: Confectory.ProjectAI::{Configuration,Open,Start,Poll,Snapshot,Close,EnableTasks,Propose,Select,Work,Adopt}, their own bodies, and explicit Provider/AugmentProvider/VerifyCompletion role implementations. Concrete Responses/Codex packs own Configuration/ConfigurationBody and declare configurationFunction metadata beside their ordinary Settings schema. Existing public signatures outside these owners remain unchanged except the additive Augment.BindProvider contract.

Necessary shared contract: Augment.BindProvider(view, actor, binding) adds an idle, chief-authorized local dispatch binding. Generation payload carries it only to the selected local provider adapter; the adapter removes it before constructing model content. Cards and durable history do not store it. Public Provider's existing signature remains intact. This enables independent project/config owners without deriving private request hashes or guessing a global current project. Default unconfigured generation still refuses. Worker/Augment regression consumers and actual EditorHome consume the change.

Outside implementation reads and reasons: Agent Open/Start/Poll/Cancel/CloseRun/Close for asynchronous event, cancellation and retry ordering absent from signatures; DevelopmentTools Open/Invoke/Snapshot/Close for draft sharing/rights/status JSON; PackWorkspace Open/Command/Snapshot/Close and BorrowDraft for revisioned review/confirmation JSON, ownership and save-before-retirement; Helper Command/Talk to ensure ProjectContext is curated and avoid the older private-template Talk path; WorkerTasks Open/Command/Close for chief authority, worker-task input envelope, awaiting-verification and borrowed Agent/Helper lifetime; Augment Open/Command/Close for card shape, capture fences, generation concurrency and selection lineage; SchemaEditing DescribeView and the metadata producer's SchemaModel for the public scalar data representation (general/ scalar, not the initially assumed scalar kind). None of these reads authorize other-project/private-template model input. No Helper, Agent, WorkerTasks, Core or platform implementation is edited.

Owned edits outside ProjectAI: additive pure Configuration functions in the two concrete connection packs; additive BindProvider and its owned Augment state/payload; actual EditorHome.Model and Main composition, public bindings/dependencies, test consumers and handoff documentation. Physical owner changes rebuild their pack and affected consumer links. Functional assertions and pack/contracts locality gates are distinct; the ProjectAI body probe must rebuild only its owning pack and zero public contracts. Existing temporary Editor/SourceEditor/Multiplayer and unrelated non-editor Helper exclusions remain guarded.

## Evidence boundary

The committed test Provider is generated only in an owned test consumer; shipped Main uses the real qualified transport dispatcher. Tests exercise the actual Main UI and real Agent/Tools/Worker/Augment/storage/compiler machinery against an explicitly simulated model. This is not live creative generation, account login, paid usage or installed Codex verification. See docs/AI_DEVELOPMENT_STATUS.md for exact final commands/results and platform gaps.

Recovery contracts: CancelWork(session, commandID, task) explicitly stops only a selected active Worker. Poll enumerates durable tasks through WorkerTasks.List and retains terminal summaries; it never replays them. Proposal failures carry allowlisted proposalErrorCode and survive owner replacement. EnableTasks rejects manifests and implementation bodies before declaration inspection and publishes its owned handles only after complete initialization; failed setup closes each handle. A fresh proposal request requires explicit public declaration scope and fresh approval.

PrepareRecovery(session, commandID, task) prepares a distinct ready ordinary task for a failed/cancelled/interrupted predecessor, with the previous Worker/status/progress/blocker and current owned draft hashes/provenance pinned in its specification. It invokes no Provider and reuses WorkerTasks.Assign. The previous execution is never restarted. Actual Model approval pins this new specification and rechecks current dirty evidence before fresh Work authorization. Unknown previous external results remain unknown; the continuation must inspect preserved drafts and cannot reissue prior external operations. Worker tool capabilities remain draft-only: no external tool, shell, Confirm or completion rights. Poll exposes durable draftContributions on terminal Workers as well as live ones. No automatic recovery on Open/hidden-project restore.

Adoption recovery contracts: `AdoptionStatus(session, task)` is read-only. `ReconcileAdoption(session, task, receipt, fingerprint)` requires a fresh explicit local review. Adopt stores one bounded per-task append-only ledger before source Confirm, including exact ready review, original/expected source hashes, goal evidence and stable Worker provenance entry references. Pending records fence source reapplication. Status reports matches-original, matches-reviewed or mixed-or-changed; these are content observations, not guesses about interrupted call outcomes. Missing/changed references remain unresolved. Unrelated journal appends preserve reference identity. Current reviewed sources require compiler validation before metadata completion; an existing ordinary Task completion proof can repair its missing log without claiming current source equivalence. Original-source acknowledgement leaves the Task incomplete and requires a fresh ordinary source Review/Confirm. Mixed/unknown results receive no automatic apply, merge, rollback or completion. Existing completion proof plus log is recognized read-only without duplicating either. No record deletion/retention policy is introduced.

Outside reads for this increment: ChangeSet.ConfirmReviewed, FileStream.Commit and PackWorkspace.Command to establish commit/accept ordering, raw original hashes and interruption boundaries absent from their signatures; EditWorkspace.Accept and WorkerTasks.Command/Finish to distinguish source acceptance from durable task proof; VerifyCompletion and DevelopmentTools.Snapshot to preserve receipt and contribution integrity. Outside edits: DevelopmentTools.Snapshot adds each provenance row's owning journal filename (entry bytes unchanged); EditorHome.Model/Main and their consumer provider declarations add local receipt review using the existing approval surface. New public IDs are ProjectAI::{AdoptionStatus,AdoptionStatusBody,ReconcileAdoption,ReconcileAdoptionBody}; Adopt/Poll signatures remain unchanged. Rebuild scope is these owning bodies/contracts, DevelopmentTools.SnapshotBody, Model.CommandBody, MainBody and affected consumer links. Tests inject faults only into copied owned bodies, never shipped providers.

## Local proposal planning

`OpenLocal(project, projectId, namespaceId, helperContext)` owns the same scoped draft and tool lifetime as Open, with `providerBound:false` and no provider configuration. EnableTasks still requires an explicitly selected global Main Helper and public declaration scope; it does not bind a generation provider for this owner. Start, Propose and Work explicitly refuse this state before parsing authorization or opening an Agent. Opening, inspecting or restoring the journal cannot dispatch a model.

`LocalProposal(session, operation, commandID, expectedBatch, text)` accepts custom, skip-current or discard-custom only. It forwards to Augment's existing chief authorization, captured revisions/hashes, command fingerprint/idempotency and FileStream CAS journal. Custom stores narrative with changes:[]; selection assigns an ordinary ready task. Archive preserves proposal history and selected tasks. Clearing a generated batch compares its displayed ID under the journal lock, rejects pending generation, and preserves custom proposals and tasks. Closing a panel preserves the current batch.

`BindLocal(session, config)` explicitly binds a configured provider to an idle, unbound local owner while retaining its tasks and source scope. It cannot reconfigure an already bound or executing owner. No Agent, turn, network request or approval starts here. The consumer invokes it only from explicit Worker preflight and then creates a fresh permission preview for that chosen connection/model/task. Cancellation leaves the task ready; subsequent dispatch still requires the ordinary exact content/usage/provider approvals. Configuration and approvals are never restored from proposal history.

Outside implementation reads for this addition: Augment Open/Command/BindProvider for private provider binding, command replay/CAS and current-batch mutation order; ProjectAI Open/EnableTasks/Start/Propose/Work/Poll/Close for the owned state slots, handle cleanup and execution handoff; Home.Model Command and WebState for explicit Helper selection, project/namespace and public-secret projection boundaries. Changes remain in those owners plus ordinary Home consumer and owned tests. Core, runtime platform and Helper/WorkerTasks authority are unchanged.

`CancelPlanned(session, commandID, task, reason)` cancels only the preserved ready proposal selection using Augment and WorkerTasks.CancelReady. The consumer rechecks current Helper policy and selected project/task. Cancellation preserves source and task/specification history. It does not stop a running Worker or withdraw staged/confirmed source. Newly approved Blueprint node Workers will receive a separate node-source scope; this existing general Workspace Worker composition is the legacy path and is not presented as a node-only capability.

## Blueprint node Tasks

`NodeTask(session, operation, payload)` implements an explicit node Task inside an already enabled project task owner. It supports the existing `sync-acyclic-v1` graph/node sources; it does not create or migrate a graph.

| Operation | Required payload | Result and authority |
|---|---|---|
| `inspect` | `node` | Actual definition, signature, used imports, current node revision/source hash, assignment hash and related owned source IDs. Opens and closes a temporary node capability; no Agent request. |
| `assign` | `node`, displayed `assignmentHash`, `commandID`, `rationale` | Durable idempotent ready Task through WorkerTasks. Definition/source changes require inspection again. Local planning owners may assign without configuring a provider. |
| `work` | `task`, `commandID`, `authorization` | Exact task/assignment/project/model/endpoint plus content and usage approval, configured owner and ready state are required. A fresh `DevelopmentTools.OpenNode` capability gives only list/read/stage/changes for the assigned node. |
| `cancel` | `task`, `commandID` | Actual ready-only cancellation under the current controller lease. The durable specification remains. This does not need an Augment selection or start/cancel an Agent. |

Plans are bounded to 24 Ki characters, input to 16 Ki characters and explicit reasons to 4096 characters. The task assignment hash covers the stable node identity, definition hash and actual node source hash. Layout/topology ordering is not an instruction to regenerate a node. Dispatch observes the current graph/contracts for its capability; subsequent changes fence node staging. The ordinary `Work` role refuses node Tasks and cannot reuse broad tools for them. A retained broad capability also refuses node dispatch. Node requests carry the selected node specification and no Helper memory/context. Provider projection omits local capability and authorization values as before.

Human adoption requires the assigned node and may include explicitly selected supporting graph/implementation/contracts recorded in that plan. Other source IDs refuse. The same ordinary Review/Confirm token, compiler and current source hashes apply to the complete selected group. The receipt separates `taskSourceIDs` from `supportingSourceIDs`; supporting user changes are not attributed to the Worker. Agent completion remains awaiting verification until user goal acceptance and compiler-backed adoption. This permits changing a node definition and its implementation in one human review without granting the Worker graph authority.

Failed/stopped node work is inspected as retained draft text and assigned a fresh node Task after explicit review. Generic broad recovery refuses node Tasks. Cold owners retain task facts without restoring execution grants or replaying requests. Close uses the existing retryable task/Agent/tool owner lifecycle.

The opened node capability pins its starting source hash for the duration of the run. Source changes after approval fence both text read and raw changes output, as well as staging. The run cannot pick up a peer's later source text under an earlier assignment; its own accepted stage advances the private source pin. Inspection also refuses an inconsistent open/read pair before assignment or dispatch. These checks preserve the existing source revision CAS and do not add automatic replay or resubmission.
