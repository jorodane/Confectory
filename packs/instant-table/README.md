# InstantTable

A disposable View borrows an EditWorkspace and projects selected object IDs/columns. Legacy `Snapshot`/`SetCell` retain their original scalar-metadata behavior, including the read-only description column. Poll consumes only this View's subscriptions; Close releases subscriptions without closing the borrowed workspace or discarding drafts. Confirm delegates selected row IDs to existing ChangeSet validation and conditional source publication.

Definition contains IDs, columns and request, without row values or table-owned model semantics. Capacity is 64 rows and 16 columns. Cached UI labels are presentation data only. Reopening a View projects the same workspace drafts. This pack does not implement arbitrary computed columns, general schema widgets, semantic merge or its own lock/data authority.

`SnapshotVersioned` projects root-owned object metadata, effective descriptions and schema data paths such as `data:["amount"]` or `data:["items",0,"name"]`. It includes displayed source revision/SHA-256, the resolved view hash, type/cardinality, value/schema origin and path writability. `cellInfo.valueJson` is the authoritative JSON text: browser clients must preserve that string when editing numbers or structured values, so an Int64 does not pass through a JavaScript Number. Inherited nested paths require the existing explicit parent override. Unavailable schema projections are read-only.

`FillVersioned` and `SetCellAtVersion` require the displayed revision, source hash and view hash. `EditCellsVersioned` additionally accepts `set` or `unset`; unset removes local description/metadata/data overrides and reveals the current inherited value. The source workspace lock spans projection checks, pure candidate validation and `EditWorkspace.EditBatch`, which validates every selected declaration before staging all changed drafts. Any stale row or malformed candidate refuses the whole fill. Schema data setters require a valid resulting effective object, including reference and descendant validation; use the complete source editor to repair several existing invalid fields together. These operations never save or publish final source files.

`EditWorkspace.DescribeSchema` borrows the existing workspace rather than opening another PackWorkspace around its raw handle. Its current scope matches the existing effective schema view: root-owned dirty declaration overlays and confirmed registered sources. Imported dirty overlays require opening their owning pack. Versioned snapshots do not run provider selection, user bodies or the compiler. External filesystem writes are not a filesystem snapshot transaction; final publication retains the ordinary source hash and compiler checks.

The ordinary EditorHome consumer maintains private table handles per live project context. Its bounded object picker pages confirmed identities, and the source owner still performs Save and compiler-backed Review/Confirm. A separate definition hash fences reconfiguration; preparing a new view must succeed before retiring the previous subscriptions. UI definitions, field order/width, query/sort, selected rows and unapplied JSON inputs are private presentation, while source values are freshly projected. Closing a project/session closes tables before their borrowed PackWorkspace.

Reserved metadata names use explicit JSON-string aliases, for example `value:"description"`, independently of the dedicated declaration description column. The picker keeps its real owned-object choices available when one object has unresolved schema metadata. Table inputs survive moving into, deleting and reopening a child Workspace; deleting that private presentation does not retire the source owner. Public semantic Review includes exact JSON text for before/after values, so large numeric deltas remain visible before Confirm.
