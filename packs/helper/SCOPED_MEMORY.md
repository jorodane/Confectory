# Explicit Helper membership and project memory

AI development preparation, 2026-10-09. Additive public Helper contracts: List(store,owner), Membership(store,helper,owner,kind,projectId), RememberScoped(store,helper,owner,memoryID,scope,projectId,text), ProjectContext(store,helper,owner,projectId,allowCommon). Existing private Inspect/Remember/Talk and immutable recruitment templates remain compatible.

Membership and memory scope are independent. Membership is explicitly global or project with projectId; old recruitment records without membership remain legacy-unspecified until an owner chooses. New recruitment may supply membership in its template. Memory entries are explicitly common (empty projectId) or project (nonempty projectId). Memory IDs are immutable across scopes; attempting to relabel a legacy entry under the same identity fails. Existing unscoped entries remain private and unchanged; they are never inferred to be common or assigned to a project.

ProjectContext returns only public personality/speciality, normalized membership and current-project memory plus explicitly permitted common memory. allowCommon=false excludes common memory. Other-project memory, unscoped legacy memory and unknown private recruitment fields are excluded. Project-only membership cannot access another project. An empty project query does not gather project memory. Inspect still lets the owner access the private legacy record for deliberate future migration. Actor strings are trusted local identities, not remote authentication. A durable projectId must come from the consumer's explicit project identity; a process-local ProjectManager context token is not a durable memory key.

helpers.json remains schema1 with additive fields and the original memory array. No inference/migration rewrites old records on Open. Successful membership/memory changes use existing optimistic FileStream Commit. Failure preserves the prior live model; owner Close fences captured commands. Limits and no-silent-pruning policy are unchanged.
