# Persistent Helper pack

Optional persistent Helper identity/personality/speciality, immutable recruitment template, private owner-scoped memory and Helper Talk. Public Open/Close own distinct store references; Recruit, Remember, Inspect and Profile use public Command. Memory-only consumers do not include Agent or create project/task state. Talk authorizes private context, then uses an explicitly supplied Agent for Helper conversation; it creates no Worker and opens no project. Agent execution is borrowed and remains owned by its caller. No Agent account/connection is created automatically.

Explicit existing storage directory, versioned helpers.json and public FileStream Snapshot/Commit provide atomic conditional persistence. Failed storage CAS leaves the live memory unchanged. Close fences in-flight commands; a captured handle is rechecked under the model gate, so memory cannot persist after Close returns. Recruitment/template identity and memory-entry IDs are idempotent; conflicting payloads fail. No template-edit path; replacement uses its original template. Private Inspect/Remember require the configured owner; public Profile excludes memory/template internals. Actor strings are trusted local application identities, not an internet authentication/security boundary. No automatic disclosure of memory in project chat.

First bounded retention policy: 256 Helpers, 1024 explicit memory entries per Helper, 2048 characters per entry; full capacity requires an explicit future retention policy, never silent deletion. Helper global memory, task state and chief journal are separate. examples/helper and HelperTests prove persistence, immutable templates, private profile, independent owners, failed source CAS and Agent exclusion. No Core changes or shared-contract modifications.
