# ExecutionComparison

A disposable comparison view owns a ProjectExecution session and at most eight named stable child handles. Models remain inside independently launched ProjectPacks. Create(false, "") explicitly clears inherited comparison input in each child; Create(true, approvedLocalSource) routes only that explicit source. Configuration pairs are passed structurally through LaunchConfigured; callers cannot override the comparison's two routing keys. Snapshot observes fresh states and handles, Output drains bounded diagnostics, Stop targets one case, and Close disposes its owned session. Case names remain reserved until group close; reopen creates a new independent group.

The consumer configures the existing ProjectExecution host and SDK paths. Actual Android app execution remains unavailable through its explicit provider; named managed profiles are compilation only. Sharing an input source shares intents, never model state. Child code must consume its own bounded intents; the harvest example rejects conflicting IDs and applies each ID once. No external launch/account/network capability is added.

The executable consumer `examples/execution-comparison` checks two independent declared-game mechanics runs and stable handles. An explicitly supplied CONFECTORY_COMPARISON_TEST_INPUT path additionally enables a live-X11 gate: both owned games consume the same bounded harvest/craft/throw intents, a new input-file snapshot cannot replay old IDs, model IDs stay distinct, both advance a fuse/effect and close cleanly. This is explicit local intent routing, not cross-model state sharing or multiplayer.
