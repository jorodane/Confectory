# Optional Augment

Chief-only proposal management, not a runtime/game prerequisite. Open borrows a matching WorkerTasks project/chief session and EditWorkspace; it owns only bounded augmentation history and generation jobs. Context and Authorize("augment") enforce the existing chief-executor contract. Ordinary Helpers/Workers do not receive augmentation powers. Local actor strings/handles are trusted application identities, not internet authentication.

Reroll yields exactly three validated cards via an explicitly selected Provider(generate/cancel). Empty direction is ordinary reroll; a natural-language direction changes the request, without a complex settings panel. Default generation refuses. The consumer fixture is deterministic simulation; no live creative model or paid image call is implied. Stable request IDs and owner/source fences discard stale/late results; newer requests remain current. Failed/interrupted requests are preserved and never automatically replayed.

Cards expose core idea, 2–4 tags, relative effort/risk and rarity standard/variation/discovery/breakthrough. Rarity means deviation from the existing direction, not quality or completion. Custom prose creates a narrative-only candidate, Skip retains history, and exactly-scoped Yogi uses stable semantic targets/selected fields. Generated history and selected Task records are distinct; selected cards create ordinary ready Worker Tasks, never source changes or completed outcomes.

First draft adapter supports one existing explicitly scoped scalar metadata field. Stage edits only the shared draft at its expected revision; Review produces a version-bound review token; Confirm calls normal ChangeSet validation/publication. Narrative-only ideas require ordinary Task implementation. Source-confirmed is distinct from Worker/domain completion. Active implemented tags require a completed linked Task and unchanged confirmed source; selection alone contributes no implemented tag. Cancel is for unstaged selection and records reason; staged/confirmed withdrawal requires ordinary draft/impact/removal workflows, never deletion of a card.

Versioned augment.json preserves batches/custom ideas/selections/command identities/history using public FileStream optimistic CAS. Pending selection/staging/confirmation intent is recorded before side effects. Duplicate active selection coalesces; cancelled selections can be deliberately reselected. Closed/deleted/revised targets reject proposal use. Bounds: 8 targets/8 selected fields, 256 batches/custom ideas/selections, 2048 history/commands, 64KiB provider response and 8MiB history. Full capacity fails instead of silently pruning. Scoring, tag weights, retention beyond these limits and work/risk units remain policy questions. No automatic execution, live AI, permanent Helper recovery, Mesh or broad physics expansion.

A generate provider may return {"kind":"error","errorCode":"<safe-code>"}; allowlisted reasons persist on the failed batch. Pending generation is cleared while prior cards/history remain. This does not retry or fabricate cards. Proposal metadata scope continues to exclude project/pack manifests and implementation bodies.
