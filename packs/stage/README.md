# Optional Stage foundation

`Confectory.Stage` owns one explicitly configured local composition context. Its only pack dependencies are RuntimeBase, RealTimeUpdate and ProjectExecution. Rendering, physics, previews, editors and RuntimeBase do not depend on Stage. No global current-stage or implicit renderer/world/process is created. `examples/stage-lab` supplies separate reusable scene components and two coexisting stages; `preview.cpack` uses those components without Stage. Ballistic2D is a bounded projectile experiment, not general physics.

## Public operations and hooks

Create reserves an opaque handle, RuntimeBase Owner/diagnostic ScalarState, schedule/clock and empty execution session. Enter calls consumer-selected PrepareResources once, takes ownership of its returned opaque resource token, and activates registrations. The factory must clean its own partial construction if it throws. StopResources clears consumer pending input; ReleaseResources releases the token and must be idempotent for retry. CheckTransition preflights an explicit transition; Event routes registered public function IDs to consumer code. Default hooks make a resource-free Stage legal. Hooks may query Stage but cannot mutate it during lifecycle transactions. A hook cannot provide atomic rollback of its own irreversible external effects.

Transition requires `keep-prior` or `stop-prior`, an active source, the same creating UI thread and a phase boundary. Veto/preparation failure leaves prior state valid. Target preparation succeeds before prior Stop. Failure in the latter returns `accepted:false, committed:true`: target is active and prior cleanup requires attention. This is not cross-process atomic transition. Create configuration has `returnPolicy:preserve|forbid` (default preserve); preserved return keeps local resource/model/camera identities but obtains a new epoch. External children are never automatically restarted.

Stop invalidates epoch, drops queued intents and clock backlog, unregisters active callbacks, stops explicitly launched child handles and retains local resources/models/subscriptions/definitions. Close also disposes execution session, resources, subscriptions and Owner. Failed release keeps a closing handle for retry; late callbacks are rejected. Repeated Close succeeds. View Unsubscribe only removes its subscription. No Stage operation chooses a table-owned model or editor lifetime.

Register uses qualified function ID, phase and priority; RealTimeUpdate supplies deterministic ties and token retirement. Advance orders fixed catch-up, variable update, camera, presentation, render. Configuration defaults: variable/render periods 0 (every advance), fixed .01 seconds, maximumSteps 8 (allowed 1..64). It inherits RealTimeUpdate's documented bounded catch-up/drop policy; interpolation is presentation of retained previous/current state, not an extra physics update. Snapshot returns fresh JSON; Read returns coherent scalar value/revision. Consumer world/camera snapshots remain consumer APIs. Dispatch cancellation checks epoch/token before each invocation. Phase faults carry function/phase/priority diagnostics.

All operations except Post must run on the creating thread. Post is a bounded thread-safe intent queue: active epoch, qualified function, data <=4096 characters, 256 entries. Drain routes only live `async` registrations on the owner thread. Configuration <=16384 characters; stage ID <=256, 64 registrations, 256 subscriptions, 32 explicitly owned child executions. No promise of unbounded worlds or process reuse. Launch is explicit, asynchronous, ProjectExecution-owned; Observe is scoped to this Stage.

The Stage-owned CommandBody is the shared lifecycle policy implementation. Public adapter splitting is a compilation boundary, not semantic independence among Stage operations. Changing CommandBody rebuilds that provider and relinks consumers; no shared external contract was changed.

## Platform scope

The Stage policy itself has no native window assumptions. The lab desktop factory explicitly requires independent native windows. Android requires an app-owned surface factory, touch/cancel intents and Activity/surface lifecycle binding; do not treat two desktop windows as two Android Activities. Existing Android Window/RenderInput contracts expose the appropriate surface capability, but this lab does not implement an Activity host. Managed named-target builds are not APK or runtime evidence.
