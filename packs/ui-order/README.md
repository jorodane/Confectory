# UI Order 0.1

Public functions: Create() -> string, Update(state, operation, payload) -> string, Compose(state, viewport) -> string, Hit(frame,x,y) -> int[]. This common role pack publishes one ordered frame for drawing, native clipping and pointer hit testing. It has no editor dependency, native host or world-depth policy.

State is an immutable serialized value held by the consumer's UI-thread Owner. Updates return a new value; keep the old frame intact until the next composition. There are no retained global objects, subscriptions or native resources. Closing the consumer releases its value; clear explicitly retires all window state. Native controls remain consumer-owned and must be forgotten/closed when their semantic window closes.

Window budget is 32; each window has a unique positive id, integer order, global bounds, opaque/enabled/modal flags and up to 128 controls. Controls have unique positive IDs within that window and local bounds, visible/enabled flags. Focus identity is the window/control pair; equal control IDs in different windows are valid. Bounds use integer pixels, at most 8192 per dimension and bounded positions. Surface subtraction batches masks through the public BaseUI::ClipRegions contract; composed visible surfaces are bounded to 256 rectangles.

Update operations: open, close, clear, move, shape, order, controls, minimize, restore, show, hide, enable, disable, activate. Open payload includes id, bounds and optional order/flags/controls. Activate includes id and optional control; omitting control preserves that window's field focus. An optional frameRevision rejects stale frame-derived actions. Controls replaces the bounded per-window control layout and clears an ineligible retained field focus. Other operations require id and the relevant bounds/order. No operating-system editing is implemented here.

Compose returns windows in ascending Render Order and then monotonically increasing activation order. Activation never changes Render Order. Each row includes global bounds, final visible regions, input eligibility, active and retained focus, and control global bounds/regions/input eligibility. Render these rows forward; hit testing traverses the same rows backward. Native field clipping must use the published control regions. Noninteractive opaque windows occlude and block lower clicks even when disabled. Transparent panels allow clicks through empty space. A modal barrier excludes underlying windows from activation/input; windows above the barrier remain eligible. Hidden/minimized/closed windows are absent. Keyboard policy uses the frame's active window and eligible controls; a consumer must route native focus deliberately rather than use control ID alone.

Hit returns [windowID, controlID, blocked]. Empty space is [0,0,0]. An eligible opaque window body returns its id with control 0; a disabled opaque panel or modal outside returns blocked=1. Controls use final visible regions. Hit does not mutate state. Use its frame revision for the following activation and recompose once before publishing the resulting presentation. Capture and drag ownership should remain with the window that began the gesture until release/cancellation.

Run examples/ui-order-game through the ordinary CLI for independent public-contract checks of ordering, native field regions, modal/disabled blocking, focus identity, move/minimize/close/reopen, stale-frame rejection and state isolation. This consumer is headless contract validation; it is not native text or real GUI runtime coverage.

Optional window shape is a flat array of up to 256 positive rectangles in local bounds. Omission/null means the full rectangle. Compose and Hit use this same surface, so transparent corners and holes neither occlude nor block underlying controls. Move validates the retained shape against resized bounds; supply shape in the same move to replace it atomically. Optional control radius (0–128 pixels) uses public BaseUI::RoundedHit for matching rounded input geometry.

Opt-in common placement: open/reach can supply `reach:{handle:[localX,localY,w,h],minimum:[visibleW,visibleH]}`; `workarea:{bounds:[x,y,w,h]}` updates available surface geometry. `drag:{id,bounds}` is a user position gesture and cannot resize; `move` remains programmatic geometry/resize. Placement delegates to public WindowPlacement contracts; no anchor math lives in ordering/hit logic. `reach:null` opts out. Windows without this policy retain their previous unrestricted geometry. Stable decimal window ID is the placement key: reuse it only for the same semantic window's reappearance. Close/minimize/hide suspend dependent placement while native/Owner cleanup remains consumer-owned; restore/show/open reapply it. Clear drops placement identities as well as UIOrder state. Workarea, recovery and drag preserve field focus and activation serial. Header drag consumers should activate with retained field focus rather than the header's control zero. See ../window-placement/README.md for anchor, fold, reference, safety and identity limits.

Composed rows expose additive placement `contact` metadata from WindowPlacement’s actual anchor classifier. Consumers may highlight the contacted own edges while dragging; ordering, hit masks and native field bounds are unchanged. No signature change or separate snap heuristic is introduced.
