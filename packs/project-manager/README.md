# ProjectManager

Reusable project-data contexts with explicit active selection and an owned ProjectExecution session. No hardcoded editor host/game guest roles: any pack can be opened/edited; a standalone ProjectPack, including an engine or another editor producer, can be described/opened and run through the same capabilities. Opening/indexing metadata never executes code and games do not require an editor entry.

CreateManager(capacity) returns an opaque caller-owned token. Open requires an explicit path and returns a stable context handle; repeated Open returns the current open context. Select changes active data context only. Context returns `[handle,path,namespace,defaultEntry,targets,state,kind,effectiveStandalone]`; an empty handle means read active and returns an empty snapshot when none is selected. Close is idempotent and closes only data. Reopening creates a fresh context handle. Closed contexts remain observable until manager disposal; capacity bounds retained context history.

Executions borrows the manager-owned execution session for public Observe/Stop/Poll. Launch requires a specific open context/target; empty entry explicitly selects that context's declared entry. Multiple runs use distinct execution handles. Closing a View, stopping an execution and closing a context are independent. Manager Dispose implements caller stop-on-dispose: stop all owned executions, release their host resources, then release context state. View close alone must not Dispose the manager. Unknown/cross-manager handles and disposed callers fail. Caller operations must be serialized. The manager is thread-neutral; a consumer may serialize its metadata/build work on an owned background dispatcher while native controls stay on their creating UI thread. Do not concurrently mutate or dispose the borrowed manager/execution session.

CreateProject is an explicit source write to a new local directory, with a validated identifier and a public CreationTemplate role (desktop validates an existing compiler-target pack path); existing directories are never overwritten. New creation writes project.cproj with standalone true; legacy project.cpack remains readable and existing paths are retained. The initial generated gameplay entry returns zero and has no editor dependency. Selection/open/execution never modify source. Editing UI/Save/Confirm remains subsequent work.

Android keeps common manager contract/body architecture and binds Android execution capabilities. Native Android process/app launch and platform data-picker/create adapters remain unavailable; managed compile/selection is not native coverage. No Helper/multiplayer dependency.

PlanCreation(title,parent) returns [display title, internal ASCII namespace identifier, exact absolute destination]. The folder component retains Unicode and spaces; the internal identifier may use a sanitized fallback without changing the folder/display name. The parent must already exist. Portable reserved names, separators, control characters, unsafe trailing dots/spaces and existing destinations are rejected. This read-only planning contract creates nothing; CreateProject receives its final destination and still performs its own collision check/atomic staging. No existing project is moved or renamed.

Context metadata appends kind and effectiveStandalone without shifting legacy fields. The execution host rechecks capability/ProjectPack identity before building. A library or disabled ProjectPack remains an editable data context; declaration does not certify native tool/host readiness.

CreationTemplate(namespace,targetPack) returns owned relative path/content pairs. Android/browser create an editable standalone source project with owned portable/windows/linux .NET target metadata, without requiring a repository or runtime compiler. The compiler remains explicitly unprovisioned at build/tools; BUILDING.txt records how to provision the complete installed compatible desktop tool directory or explicitly choose another registry. Declaration is not compilation readiness. No APK/browser compilation target is promised by this minimal source template. CreateProject validates template confinement/duplicates and retains atomic rollback if Open fails.
